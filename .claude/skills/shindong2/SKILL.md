# 신동2 — 장세 전망 · 재량 제안 · 관리 · 채점 · 자가개선

## 목적 한 줄

KOSPI200 미니선물에서 **최고의 수익률 진입·청산 타점**을 잡는 것. 그래서 이 스킬은 하루를 다음 사이클로 돈다 —
**예측 → 실행 → 평가·반성 → 레슨런 기록 → (레슨 반영) 개선 예측 → 실행 → …** 이 사이클의 추이가 워크포워드로
기록되고, 개선되지 않으면 딥다이브로 해결책을 찾아 다시 반영한다. 기록이 곧 학습이다 — 적지 않은 개선은 없는 것이다.

**[683차] 사이클은 하루 한 번이 아니라 회차마다 돈다.** 계획 손익(돈)과 함께 **확률 시나리오(판단)** 도 매번 채점된다.

```
       ┌──────────────────── 회차 사이클 (장전 → 장중 매 회차 → 장후) ────────────────────┐
       │ ① 예측결과  snapshot 「시나리오 채점」 — 직전 예측의 실현·무효·진행                       │
       │ ② 반성      맞은/틀린 이유 한 줄 (외인 동향 해석이 틀렸나 · 레벨이 틀렸나 · 확률이 과했나)   │
       │ ③ 새 예측   지금까지 수집된 데이터로 시나리오 확률·경로 갱신 → record --scenarios          │
       └──────────────────────────────────────────────────────────────────────────────┘
       ┌──────────────────── 일 사이클 (장후 → 다음 장전) ─────────────────────────────────┐
       │ ④ 레슨런    evaluate(brier·BSS·기본 적중) → feedback → lesson add/set               │
       │ ⑤ 학습      trend — 워크포워드 BSS · 보정표(준 확률 vs 실현율) · 딥다이브 판정          │
       │ ⑥ 다음 예측 반영  익일 시나리오에 보정 지침·레슨 적용 → brief 가 다음 장전에 다시 띄운다  │
       └──────────────────────────────────────────────────────────────────────────────┘
```

끊기지 않게 하는 장치: 장전·장중·익일 **live 기록은 `--scenarios` 없이는 거부된다** — 채점할 수 없는 예측은 남지 않는다.

## 이 스킬이 지키는 것

1. **주문하지 않는다.** 제시만 한다(절대원칙 §6). 매매 결정은 사람이 한다.
2. **사전등록 규칙을 건드리지 않는다.** 기본·P·P2·P3 상수(`scripts/foreign_flow_pit_review.py`)는 장중·장후 어느 때도
   고치지 않는다. 내 제안은 「**신동2-AI**」라는 별개 주체로 기록·채점된다.
3. **기록은 그 순간에 남긴다.** `record` 가 벽시계로 시각을 박는다. 지난 시각으로 적지 않는다(사후 확신 금지).
   제시한 가격은 고치지 않는다 — 바꾸려면 새 기록(`plan`/`manage`)을 남긴다.
4. **뒤집기를 아낀다.** 방향 전환은 「세팅 변경」 조건일 때만 — 지금 계획의 손절이 실제로 닿았고, 반대편 구조(맥점·전일
   고저)를 종가로 넘었고, 수급 **수준**도 반대로 돌았을 때. 10분 변화량(Δ10)만으로 뒤집지 않는다
   (10/6 신동2 기본이 반등 추격 매수 두 번으로 손절 — 레슨 L1. 외인 선물 흐름은 가격을 1분 **뒤따른다**).
5. **장중에는 무거운 분석을 하지 않는다**(456차). `snapshot`/`poll`/`record`/`score`/`brief` 는 사다리와 같은 가벼운 경로다.
   `evaluate`/`feedback`/`trend`·`foreign_flow_pit_review.py` 본체·전수 분석·DB 스캔은 장후에만.
6. **모르는 것은 모른다고 쓴다.** 데이터가 없으면(`None`·미측정) 0 으로 읽지 않는다. 개선폭도 기존방식 섀도가 없으면 「미측정」이다.
7. **레슨은 다음 거래일부터 센다.** 하루를 보고 만든 레슨을 그 하루에 다시 대 보면 당연히 좋아 보인다(과적합).
   후보 → 적용중 승격은 **적용 3회 이상·적중 우세** 뒤에만. 승격·폐기는 레지스트리에 이력으로 남긴다.

## 도구

모든 명령은 저장소 루트에서, **conda 환경을 거쳐** 부른다(맨손 python.exe 금지 — 537·662차):

```
conda run --no-capture-output -n py310_64 python scripts/shindong2_live.py snapshot          # 상태 + 새 이벤트 요약 (읽고 판단)
conda run --no-capture-output -n py310_64 python scripts/shindong2_live.py poll              # 마지막 기록 이후 새 이벤트 있으면 exit 10
conda run --no-capture-output -n py310_64 python scripts/shindong2_live.py record --phase <단계> --action <plan|manage|exit|stand|note> \
      --dir <매수|매도|관망> [--entry X] [--stop Y] [--target Z] [--lessons L1,L9] [--variant legacy]       --scenarios "A|반등 후 1020 저항|45|1020|1030|1012 ; B|하락 재개|35|1000|1012 ; C|숏커버 랠리|20|1030|1012"       --comment-file - <<'EOF'
해설 본문(마크다운)
EOF
conda run --no-capture-output -n py310_64 python scripts/shindong2_live.py score             # 재량 채점(장중 잠정 · 장후 확정)

# ── 학습 사이클 (672차) ──
conda run --no-capture-output -n py310_64 python scripts/shindong2_live.py brief             # 장전: 활성 레슨 · 전일 피드백 · 추이 판정 한 화면
conda run --no-capture-output -n py310_64 python scripts/shindong2_live.py evaluate          # 장후: 익일계획·장전계획(개선/기존) 단독 시뮬 평가
conda run --no-capture-output -n py310_64 python scripts/shindong2_live.py feedback [--applied L1,L3] [--hit L1] [--miss L3] --comment-file - <<'EOF'
평가·반성 본문
EOF
conda run --no-capture-output -n py310_64 python scripts/shindong2_live.py lesson list [--active]
conda run --no-capture-output -n py310_64 python scripts/shindong2_live.py lesson add --id L14 --title "…" --rule "…" [--trigger "…"] [--status 후보] [--evidence 2026-10-08]
conda run --no-capture-output -n py310_64 python scripts/shindong2_live.py lesson set --id L9 --status 적용중 --why "적용 3회 적중 2"
conda run --no-capture-output -n py310_64 python scripts/shindong2_live.py trend             # 장후: 워크포워드 추이 + 딥다이브 판정 (문서 갱신)
```

- ⚠ **`--no-capture-output` 필수** — 빼면 conda(py37_32 의 conda)가 출력을 cp949 로 다시 찍다가 `−` 같은 문자에서
  `UnicodeEncodeError` 로 죽고 「ERROR REPORT」 프롬프트를 띄운다(스크립트는 정상이었다 — 2026-10-06 실측).
- `poll` 의 **exit 10 은 오류가 아니다**(「Claude 호출 필요」). conda 가 `ERROR conda.cli.main_run … failed` 를 한 줄 찍는데
  0 이 아닌 종료코드를 그렇게 표시할 뿐이다.
- 🔴 **`--scenarios`**(683차) — 장전·장중·익일(overnight) **live** 의 plan/stand/note 에 **필수**(보유·관리·청산·legacy 는 면제).
  형식 `키|이름|확률|목표|무효[|이후] ; …` — 확률은 5% 단위 정수, **합 100**, 2개 이상.
  · **추세형**(`이후` 없음): 무효보다 목표에 먼저 닿으면 실현. 예 `B|하락 재개|35|1000|1012`.
  · **되돌림형**(`이후` 있음): 목표에 닿은 뒤 `이후` 레벨에 무효보다 먼저 닿아야 실현. 예 `A|1020 저항|45|1020|1030|1012`.
  · 같은 봉에 목표·무효가 함께 걸리면 무효(보수적). 15:10까지 결말 없으면 「미결」 = 일어나지 않은 것으로 채점.
  · 확률이 그대로여도 **직전 명세를 그대로 다시 넘긴다**(회차마다 채점 표본이 쌓인다).
  · 🔴 **예약작업(헤드리스)에서는 명령행 `--scenarios` 대신 해설 본문 heredoc 안에 한 줄로 쓴다** —
    `시나리오명세: A|반등 후 1020 저항|45|1020|1030|1012 ; B|하락 재개|35|1000|1012 ; C|숏커버 랠리|20|1030|1012`.
    명령행에 `|`·`;` 를 넣으면 권한 패턴(`scripts/shindong2_live.py:*`) 해석에서 거부될 수 있다. 두 경로는 같은 결과다.
  · 목표·무효는 맥점·OI 벽·전일 고저·매물대·OR 같은 **이름 있는 레벨**에서 고른다. 아무 숫자나 넣으면 채점이 의미를 잃는다.
- `--entry` 를 비우면 다음 분 시가 시장가. `plan` 은 손절·청산을 **반드시** 함께 적는다(채점 불가 기록 금지).
- `manage` = 보유·대기 중 손절/청산만 갱신. `exit` = 다음 분 시가 청산. `stand` = 대기 계획 취소(관망).
  `note` = 가격 변화 없는 해설.
- **`--lessons L1,L3`** — 그 계획에 적용한 레슨 ID 를 표기한다. 표기해야 레슨 집계(적용/적중/실패)가 맞는다.
- **`--variant legacy`** — 「기존방식」 섀도. overnight/premarket 의 plan·stand 에만 쓴다. 실제 재량 시뮬·패널 최신 해설에는
  들어가지 않고 **평가 비교(개선 − 기존)에만** 쓰인다. 기본(미지정)은 `live` = 개선방식 = 실제 채점 대상.
- 🔴 **해설은 표준입력(heredoc)으로 넘긴다** — `--comment-file -` 뒤에 `<<'EOF' … EOF`. 예약작업 실행은 Write/Edit 도구가
  **막혀 있고**(허용: Read·Glob·Grep · `conda run --no-capture-output -n py310_64 python scripts/shindong2_live.py …` 만)
  파일을 만들 수 없다. 명령 앞에 다른 것(`cd`, `&&`, 환경변수)을 붙이면 권한 밖이라 거부된다.
- 사다리(`MAEKJEOM_LADDER.bat`, 127.0.0.1:8765)가 매분 다시 읽어 「신동2 해설」 패널과 차트(◆·파랑 계획선)에 그린다.
  학습 블록(계획 평가·추이 판정·전일 피드백)도 같은 패널에 뜬다.

## 학습 사이클 — 하루의 흐름

```
전날 장후   익일계획 2건: 개선(live, 레슨 반영) + 기존(legacy 섀도)      ← 예측
당일 장전   brief 로 레슨·피드백·추이를 읽고 장전계획 2건(개선 + 기존)    ← 개선 예측
당일 장중   계획 실행·관리(live 만) — 레슨 적용은 --lessons 로 표기       ← 실행
당일 장후   evaluate → feedback(잘한 점/잘못한 점/개선점/레슨) → lesson   ← 평가·반성·레슨런
            → trend(개선−기존 추이, 딥다이브 판정) → 익일계획 2건        ← 다시 개선 예측
```

**정량화 지표**(`evaluate` 가 계산, `trend` 가 창 5/10/20일로 집계)
- 방향 적중: 종가−시가 ±2pt 보합. 관망은 분모 제외.
- 계획 손익: 그 계획을 **단독**으로 1분봉에 대 본 값(효력 다음 분·지정가 고저 포함 체결·같은 봉 손절 우선·15:10 강제청산).
- MFE/MAE · **포착률**(손익 ÷ 당일 고저폭) · **진입품질**(1 − 진입가와 최악 극단 거리 ÷ 고저폭) · 목표/손절 여유 · R:R.
- **개선 − 기존**: live 계획 손익 − legacy 계획 손익. 이것이 「학습으로 향상되는가」의 지표다. 섀도가 없으면 미측정.
- 재량 실현(신동2-AI) vs 규칙(기본·P·P2·P3) — 대조군.

**딥다이브 트리거**(`trend` 판정) — 최근 5일 개선−기존 ≤ 0 · 익일계획 방향 적중 < 50% · 개선−기존 ≤ 0 이 3일 연속 중 하나.
발동하면 장후 피드백에 **「딥다이브」 절**을 쓴다: 원인 가설 3개(방향 근거 / 진입 레벨 / 손절·청산 설계 중 어디가 병목인가) ·
각 가설을 가르는 실측(eval.json 의 entry_miss·stop_margin·target_margin·MFE/MAE 분포) · 바꿀 것 하나 → 새 레슨(후보) 등록 ·
다음 날 그 레슨을 live 계획에 적용하고 legacy 는 그대로 둬 효과를 분리 측정.

## 외인 동향 · 시나리오 보고 규약 (683차 — 모든 단계 필수)

**계기 (2026-10-12)**: 화면만 보면 「외인 수급 변화가 거의 없다」로 읽혔지만, 실측은 10:02 −1,452 → 15:32 +1,515였고
14:47 이후 45분 동안 +1,863이 들어왔다. 게다가 같은 시간 현물 외인 −6,422, 기관은 선물 매도·현물 매수(차익 반대편),
먼스리 풋 외인은 수량 +297에 금액 −7,563백만(이익실현·교체)이었다. 누계 한 점이나 화면 인상으로는 이 구조가 보이지 않는다.
그래서 모든 단계 해설에 아래 두 블록을 넣는다.

### ① 외인 동향 — 「무엇이 · 언제 · 누구 반대편으로」

`snapshot` 의 「외인 동향」 블록을 읽고 다음을 쓴다(숫자는 블록에서 온 것만):
- **선물 경로**: 저점·고점 시각과 값, 큰 구간 변화(예: `10:02–14:47 −1,452 → −381 완만한 환매 · 14:47–15:34 +1,863 급반전`).
  반대편이 누구였나(기관·개인), 미결제 증감(신규 유입인가, 청산인가).
- **누적 맥락**: 직전 3거래일 합 위에서 오늘 값이 어떤 의미인지(누적 숏의 일부 커버인가, 새 방향인가).
- **현선·옵션 교차**: 선물과 현물 외인 부호가 반대면 현선 교체·헤지를 먼저 의심한다. 콜·풋은 **수량과 금액을 함께**
  본다 — 수량에 비해 금액만 크게 움직이면 행사가 교체·이익실현이다(방향 베팅의 증감과 구분).
- **결론 한 줄**: 「외인 포지션 = ○○(근거 2개)」. 예: `약세 기조 속 숏 일부 커버 + 풋 이익실현 + 콜 매도로 천장 유지`.
- 외인 선물 흐름은 가격을 1분 **뒤따른다** — 경로는 국면 판단의 맥락이고 진입 신호가 아니다(지키는 것 4).

### ② 시나리오 — 확률 + 경로 + 갈림 조건

모든 전망(장전·장중·장후, 보유 중 국면 변화 시)에 **시나리오 표**를 넣는다:

```
| 시나리오 | 확률 | 경로(레벨·시간대) | 근거 | 무효화 |
|---|---|---|---|---|
| A. 반등 후 1020 저항 | 45% | 1012–1020 반등 → 1020 콜벽서 재하락 | 숏커버 여진·콜 매도 천장 | 1020 종가 돌파 |
| B. 하락 재개 | 35% | 1005 이탈 → 1000 테스트 | 현물 외인 4일 연속 매도 | 외인 선물 +2,000 이상 |
| C. 숏커버 랠리 | 20% | 1020 돌파 → 1028–1030 | 직전 3일 −10,209 누적 숏 | 1012 재이탈 |
```

- 확률은 **합 100%**, 정수 5% 단위. 주관 확률임을 밝힌다. 기본 시나리오(최고 확률)가 기록하는 `plan`/`stand` 방향과
  맞아야 한다 — 다르면 왜 다른지 한 줄.
- **경로**는 「어디서 → 어디까지」 레벨(맥점·벽·전일 고저·매물대)과 가능하면 시간대. 「오를 것」 같은 방향만 쓰지 않는다.
- 각 시나리오에 **무효화 조건**(가격 또는 수급 수준) — 장중 갱신 때 이것으로 확률을 옮긴다.
- **갈림 체크리스트**(2–4개): 다음 회차까지 무엇을 보면 어느 시나리오로 기우는지. 예: `09:02–10:00 외인 선물 +2,000 이상 → A/C,
  0 아래 복귀 → B` · `현물 외인 매도 속도(10시 −644 → 12시 −3,341 페이스)가 줄어야 바닥`.
- **장중 갱신**은 표를 통째로 다시 쓰지 말고 `A 45→55% (1020 근접에서 콜 OI 감소)`처럼 **바뀐 확률과 그 이유**만 쓴다.
  바뀐 게 없으면 「시나리오 유지(A 45 · B 35 · C 20)」 한 줄.
- 표의 시나리오는 그대로 `--scenarios` 명세가 된다 — 표와 명세의 확률·목표·무효가 **같아야** 한다.
- 장후에는 오늘 장전·장중 시나리오 가운데 **실제로 실현된 것과 그때 붙인 확률**을 대조한다(보정 기록 — 70%를 준 것이
  자꾸 빗나가면 과신이다). `evaluate` 가 세트마다 brier·BSS·기본 적중을 계산하고 `feedback` 표에 자동으로 넣는다.

### ③ 채점·보정 — 숫자가 무엇을 말하나

| 지표 | 계산 | 읽는 법 |
|---|---|---|
| brier | 평균 (확률 − 실현)² | 낮을수록 좋다. 0 = 완벽 |
| 균등 | 같은 결과에 1/n 확률을 준 brier | 「생각 없이 나눴을 때」 기준선 |
| **BSS** | 1 − brier ÷ 균등 | **> 0 이어야 확률 판단이 기여한 것.** ≤ 0 이면 균등보다 못하다 |
| 기본 적중 | 최고 확률 시나리오 실현율 | 방향 판단의 거친 지표 |
| 보정표 | 확률 구간별 평균 준 확률 vs 실현율 | 편차 15%p 이상(n≥5)이면 `brief` 가 「과신/과소 — n%p 낮출·올릴 것」 지침을 띄운다 |

`trend` 판정: 최근 5일 평균 BSS ≤ 0(채점일 3일 이상)이면 **🔴 딥다이브** — legacy 짝 유무와 무관하게 독립으로 판정된다.

### premarket (08:52)

1. `brief` → 활성 레슨·전일 피드백·추이 판정·오늘 익일계획(개선/기존)을 읽는다. `snapshot`(장 시작 전이면 「봉 없음」 — 정상).

   (갭·해외)로 **어떻게 옮겼는지** 한 줄. **어느 레슨을 어떻게 적용했는지** 한 줄(예: L12 → 진입 1060.6 = 맥점 1060.95 − 0.35).
2-1. `brief` 의 「오늘 확률에 반영할 보정 지침」과 「오늘 익일계획 시나리오」를 읽고, 전날 시나리오 확률을 **어떻게 옮겼는지**

4. 이어서 **기존방식**을 `--variant legacy` 로 한 건 더 남긴다: 레슨 반영 전 방식(맥점 정수 지정 · 다음 맥점 손절 · 가장 가까운
   맥점/벽 청산 · Δ 가중 그대로). 해설 2–3줄이면 된다. 둘이 같으면 같다고 쓰고 **그래도 남긴다**(개선폭 0 을 측정하기 위해).
5. 익일계획(전날 장후)이 갭으로 무효가 돼도 그 레벨은 **대안으로 남긴다**(L13 — 10/7 익일계획 1104 가 장전 갱신 1091 보다
   나았다: +5.80 vs −4.50).

### intraday (09:05–10:05 10분 · 10:30–14:30 30분)

1. `snapshot`. 직전 기록과 비교해 **무엇이 바뀌었나**만 본다 — 세팅(P 계열), 전일 고저, 맥점 이탈, 수급 수준,
   외인 동향 경로(직전 회차 이후 구간 변화 · 새 플래그).
1-0. **회차 사이클 ①②**: 해설 첫머리에 「직전 예측결과 → 반성」 2줄. 예:
   `직전(09:35) A 45% 진행(1020 도달 10:02) · B 35% 무효(10:02) · C 20% 미결 → 반성: 외인 선물 환매(−1,452→−1,135)를 B 근거로 과대평가`.
   틀린 근거가 보이면 이번 갱신에서 **그 근거의 무게를 줄였다**고 명시한다(반성이 다음 예측에 들어간 증거).
1-1. 해설에 **외인 동향 3–5줄**(규약 ① — 직전 회차 이후 구간 변화 중심)과 **시나리오 확률 갱신**(규약 ② — 바뀐 것과 이유)을
   반드시 넣는다. 14:30 회차는 「장 마감까지 남은 경로」 기준으로 시나리오를 다시 쓴다(막판 수급 급변이 잦다).
   이미 실현·무효가 확정된 시나리오는 새 명세에서 빼고, 남은 경로로 확률을 다시 100에 맞춘다.
   기록은 `record --phase intraday --action note|plan|stand --scenarios "…"`(③ 새 예측).
2. 판단: 계획 유지 → `note`(짧게) / 진입가·손절·청산 조정 → `manage` 또는 새 `plan`(`--lessons` 표기) / 관망 전환 → `stand`.
   방향 전환은 「지키는 것 4」 조건일 때만.
3. 신동2 규칙(P 계열)과 다른 판단이면 **왜 다른지** 한 줄 남긴다.
4. 되돌림 지정가가 **2회 연속 미체결**이고 수급 세 축이 일치하면 L11(이탈추종 전환) 적용 여부를 명시적으로 판단해 적는다 —
   적용하든 안 하든 **그 이유**를 남겨야 장후 평가에서 레슨 적중/실패를 가를 수 있다.

### position (진입 뒤 — `poll` 이 exit 10 일 때, 10분마다 확인)

1. `snapshot` 의 「재량(AI)」 줄로 보유·평가손익을 본다.
2. 유지 / 손절 이동(`manage`) / 급청산(`exit`) — 급청산은 **세팅 변경 조건** 또는 손절선 1pt 안 접근 + 반대 구조 돌파일 때.
   만기일·피닝 구간에서 MFE ≥ 5pt 면 L10(본전 이동·부분청산 앞당김) 적용을 판단해 적는다.
3. 청산되면 그 거래를 3–5줄로 정리(`note`): 진입 근거가 맞았나, 손절·목표가 적절했나, 어느 레슨이 작동/실패했나.

### position 이 15:10 이후에 불렸을 때 (15:12 마감 실행)

강제청산 직후다. `snapshot` 으로 재량·규칙 결과를 보고 오늘 재량 거래를 정리하는 `note` 하나만 남긴다
(새 `plan` 금지 — 15:00 이후 진입은 채점되지 않는다).

### postmarket (15:55 — 정규선물 15:52 적재 뒤)

1. `score` → 재량·규칙(기본·P·P2·P3)·피터를 나란히 본다. `evaluate` → 전날 장후 익일계획(개선/기존)·오늘 장전계획(개선/기존)의
   방향 적중·체결·손익·MFE/MAE·포착률·진입품질·개선−기존, 그리고 **「시나리오 예측 채점」 표**(세트별 실현·무효·brier·BSS·기본 적중,
   하루 평균, 익일계획 세트 brier)를 본다.
2. **평가·반성을 `feedback` 으로 남긴다**(15–30줄). 반드시 이 네 절로:
   - **잘한 점** — 예측(방향·레벨)과 근거 선택 중 맞은 것. 어느 레슨이 작동했나(`--hit`).
   - **잘못한 점** — 틀린 예측·근거, 체결 못 한 레벨(entry_miss), 좁은 손절(stop_margin), 못 간 목표(target_margin).
     적용했는데 실패한 레슨(`--miss`), 적용 안 해서 손해 본 레슨.
   - **개선점** — 내일 바꿀 것 **하나 이상**, 수치로(진입 −0.4pt / 손절 개장폭 1/3 / 목표 다음 벽).
   - **시나리오 반성**(683차) — 오늘 세트들의 BSS 와 기본 적중. 확률을 가장 크게 빗나간 세트 하나를 골라
     「어느 근거(외인 동향 해석 / 레벨 선택 / 확률 배분)가 틀렸나」를 쓴다. 회차별 확률 이동이 결과 쪽으로 갔는지(갱신이
     정보를 더했는지)도 본다 — 장중 갱신이 결과 반대로 움직였다면 그것이 레슨 후보다.
   - **레슨런** — 새 레슨이 있으면 `lesson add`(후보). 후보가 적용 3회·적중 우세면 `lesson set --status 적용중`.
     실패 우세면 딥다이브 또는 폐기. 이력(`--why`)을 남긴다.
   `--applied` 는 오늘 live 계획에 표기한 레슨과 일치시킨다.
3. `trend` → 추이 판정을 읽는다. 「시나리오 확률 판단」 표(BSS 창별 · 익일계획 BSS · 보정표)와 「⚠ 보정」 지침을 확인한다. **🔴 딥다이브** 면 위 「딥다이브 트리거」 절차대로 피드백에 딥다이브 절을 **추가로** 남긴다
   (`feedback` 한 번 더 — append-only 라 괜찮다).
4. **내일 전망 — 가장 세밀하게.** 15:55 의 `snapshot` 은 선물 투자자 **마감 누계(15:34)** 까지 담는다. 아래 7절을 모두 쓴다
   (40–70줄, 표 포함):
   1. **결론** — 내일 기본 방향 한 줄 + 외인 포지션 한 줄.
   2. **외인 선물** — 최근 4거래일 마감 표(외인·기관·개인), 오늘 경로의 구간 분해(저점·고점·급변 구간과 반대편), 미결제 증감.
   3. **외인 옵션·현물** — 먼스리 콜/풋 수량·금액과 그 해석(신규 베팅 / 교체·이익실현 / 매도로 천장·바닥 형성),
      현물 외인·기관, 선물과 부호가 엇갈리면 현선 교체·차익 여부 판단.
   4. **외인 포지션 종합** — 「누적 ○○ + 오늘 ○○ → ○○ 국면」. 방향 베팅과 헤지·교체를 구분해 쓴다.
      섣불리 단정하지 않을 이유가 있으면 그것도 쓴다(예: 막판 45분 한 구간뿐 · 현물은 계속 매도).
   5. **시나리오 표**(규약 ②) — 3개 안팎, 확률 합 100, 오늘 종가 기준 경로(갭 예상 → 첫 저항·지지 → 목표 레벨),
      근거, 무효화. 레벨은 맥점·OI 벽·전일 고저·매물대·오늘 OR 에서 가져온다.
      **⑥ 다음 예측 반영**: `trend` 의 보정 지침과 오늘 시나리오 반성·새 레슨이 이 확률에 **어떻게 들어갔는지** 한 줄
      (예: `보정 — 65–100% 구간 과신 18%p → 기본 시나리오 60%→45% · L15 막판 45분 급변만으론 랠리 확률 25% 상한`).
      이 표가 `--scenarios` 명세로 그대로 기록되고, 내일 장중 회차마다 채점된다.
   6. **장 초반 확인 체크리스트** — 09:02–10:00 사이 무엇을 보면 어느 시나리오로 기우는지 3–4개(외인 선물 수준·현물 매도 속도·
      벽 첫 터치 때 OI 변화·전일 고저 지지/이탈). 이것이 내일 장전·장중 회차의 대조 기준이 된다.
   7. **주의·미측정** — 원천 한계(정규 선물 기준·미니 합산 미확인 등), 설명 안 되는 값(예: OI 불연속)은 해석에 쓰지 않았다고 명시.
   이 본문을 `record --phase overnight --for-date <다음 거래일> --action plan|stand --lessons …` 로 **내일 날짜 파일**에 미리 적는다
   (그날 08:45 이전 기록은 개장부터 유효) — 개선방식(live). 이어서 **기존방식 `--variant legacy`** 한 건. 개선방식 본문에
   「기존방식과 무엇이 다른가 · 어느 레슨 때문인가」 한 줄.
5. 오늘 해설·피드백·레지스트리·추이 문서(`docs/미륵이고도화3/신동2/live/`, `학습/`)는 커밋 대상이다 — 커밋은 사람이 지시할 때만.

## 예약작업 (3단계)

`scripts/shindong2_tasks.ps1 -Action Register` 가 `\Mireuk\Mireuk_Shindong2_*` 다섯 개를 월–금으로 등록한다
(장전 08:52 · 장중 09:05–10:05/10분 + 10:30–14:30/30분 · 이벤트 10:10–15:00/10분 · 마감 15:12 · 장후 15:55).
실행은 `scripts/shindong2_run.ps1 -Phase …` — 휴장일·중복 실행은 건너뛰고, 이벤트 단계는 새 이벤트가 있을 때만
Claude 를 부른다. 로그 `logs/shindong2_YYYYMMDD.log`. 해제는 `-Action Unregister`.
학습 명령(`brief`·`evaluate`·`feedback`·`lesson`·`trend`)도 같은 허용 패턴(`scripts/shindong2_live.py …`) 안이라 추가 권한이 필요 없다.

## 해설 쓰는 법

- 한국어. 범위는 대시(–), 물결표 금지.
- 첫 줄 = 결론(방향·한 줄 이유). 그다음 근거 · 시나리오 · 무효화 조건 · 적용 레슨.
- 숫자는 snapshot/evaluate 에서 온 것만. 지어내지 않는다.
- 장중·장전 해설 첫 2줄 = **직전 예측결과 → 반성**(회차 사이클 ①②). 그다음 결론·외인 동향·시나리오.
- 모든 전망에 **외인 동향(규약 ①)과 시나리오 표·확률(규약 ②)**. 빠뜨리면 그 기록은 장후 보정 대조를 못 한다.
- 길이: 장전 20–35줄, 장중 6–15줄(외인 동향 3–5줄 + 확률 갱신 포함), 보유 3–10줄, **장후 내일 전망 40–70줄**, 기존방식 섀도 2–3줄, 피드백 15–30줄(딥다이브 시 +10줄).
