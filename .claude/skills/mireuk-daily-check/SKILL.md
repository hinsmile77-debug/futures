## 이 스킬이 하는 일

한 문장으로: **"오늘 미륵이가 절대원칙을 지키며 설계대로 살았는가"를 로그로 심문하고, 안 그런 부분에 대해 고칠 계획과 더 나아갈 계획을 내놓는다.**

1. **이상점 정리보고** — 국면(장전/장중/장후)별 작업흐름 이상점

## 0. 시작 전 — 이 프로젝트의 세 가지 함정

미륵이는 메시아와 다르다. 이 셋을 모르면 보고서가 틀린다.

### 함정 ① 판정(verdict)과 결정(decision)은 별개다

검증 캠페인 리포트의 판정·권고는 **조치 여부와 무관하게 매주 재계산·재출력**된다.
따라서 **"FAIL이 계속 뜬다 = 미조치"가 아니다.** 양방향으로 실제 사고가 있었다.

- 이미 배포된 권고(2026-07-15 Hurst 완화)를 3주째 리포트가 다시 찍었고, 0801 결산 초안이 그걸 "승인 1순위"로 잘못 올렸다 → 코드 확인 후 철회
- 일부러 적용하지 않기로 한 FAIL이 기록되지 않아, 다음 세션이 적용을 재시도할 뻔했다

→ **어떤 권고든 "이미 코드에 있는가"를 먼저 확인하라.**
`config/settings.py:VALIDATION_CAMPAIGN_DECISIONS`(확정 결정 레지스트리)와
`dev_memory/DECISION_LOG.md`가 진실원천이다.

> ⚠ **2026-08-26 3회째 위반.** 그날 장전이 「수집기에 `--no-optional-locks` 부착」과
> 「인덱스락 3중 조건 스테일 판정」을 신규 Fix로 올렸는데 **둘 다 483차가 이미 배포**한

> `tests/test_483_git_lock_guard`). **Fix를 쓰기 전에 `grep`으로 실물을 확인하라.**

> ⚠ **두 브랜치는 이미 크게 갈라졌다** — 2026-08-26 실측 `dev`는 `v9-dev` 대비 **397커밋

> (예: 이 SKILL.md — `v9-dev` 433줄(08-24) vs `dev` 378줄(08-20)).
> **한쪽에서 커밋했다고 다른 쪽이 받는 구조가 아니다.** 파일을 건네야 한다면 `git pull`이
> 아니라 **직접 전달**을 전제로 계획하라.

- 커밋 제목 첫 단어: `[MW0601]` 또는 `[MW0602]`
- `dev_memory/DECISION_LOG.md`·`NEXT_TODO.md` 세션 헤더에도 PC명 병기
- **PC간 공유가 필요한 내용은 반드시 git에 커밋되는 문서에 적는다**
- PC별 Claude 개인 메모리는 다른 PC 세션에 보이지 않는다
- **PC별 앱 저장 스킬·예약작업도 공유되지 않는다** — 각 PC에서 따로 등록·갱신해야 한다
- **커밋 전에 프리플라이트를 돌린다** — `python scripts/git_lock_guard.py --check`
  (종료코드 0 정상 / 2 스테일 / 3 판정보류). 2026-08-21에 0바이트
  `.git/index.lock` 이 **53.5시간** 남아 저장소가 커밋 불가였는데, `git status` 는
  rc=0 으로 조용히 통과해 이틀간 아무 계측에도 안 걸렸다(같은 날 fuoption 도 동시
  발생). 실패한 **뒤에** 원인을 찾지 말 것 — git hook 으로는 못 막는다(훅은 락을
  잡은 **뒤에** 돈다). 스테일이면 `--reclaim`, **판정보류면 절대 지우지 말 것**
  (실행 중인 git 의 인덱스를 깨뜨린다). 수집기 §2·§11도 같은 판정을 자동으로 싣는다

수집기가 호스트명에서 PC를, git에서 브랜치를 뽑아 다이제스트 앞머리에 찍는다.

### 🔴 git 호출 규약 — 이 저장소에 거는 **모든** 읽기 전용 git 명령

```
git --no-optional-locks <sub> ...
```

`git status` 뿐 아니라 **`git branch` · `git diff` · `git log` · `git rev-list` ·
`git ls-files`** 전부다. **세션이 임시로 손으로 치는 명령도 예외가 아니다.**

**왜**: 이 옵션이 없으면 git 이 stat 캐시를 갱신하려고 인덱스를 **다시 쓴다** —
즉 `.git/index.lock` 을 잡는다. 2026-08-24 09:13 에 점검 세션이 만든 0바이트 락이
**3시간 21분** 남아 저장소가 커밋 불가였고, 그날 §2 는 08:59:37 스냅샷 기준으로
「인덱스락 없음」이라고 적었다. 락을 만든 것은 `status` 가 아니라 **`diff`** 였다.

483차 P1-1 이 수집기 `run_git()` 에는 이 옵션을 붙였다. **세션이 직접 치는 명령에는
아무도 안 붙이고 있었다** — 그래서 규약으로 승격한다.

⚠ **리눅스 샌드박스(코웍)에서 마운트 경유로 돌 때는 더 심각하다** — 락이 생기기만 하고
`unlink` 가 `EPERM` 으로 실패해 **세션 안에서는 회수조차 못 한다**(2026-08-26 실측:
`rm -f .git/index.lock` → `Operation not permitted`). 애초에 만들지 않는 것이 유일한 방어다.

⚠ 483차의 재현 실험 결론(Windows 에서 `git status` 강제 종료 시 잔존 0/5)을
뒤집지 않는다. 그 실험은 **다른 경로**를 봤다. 여기서 막는 것은
「샌드박스 마운트 경유 · 중단 없음 · `unlink` 거부」다.

🔵 **자가점검이 배선돼 있다**(490차 F-F ②): 수집기가 실행 **시작 시점**의 락 유무를
잡아두고 §2 에서 지금 상태와 비교해, 없다가 생겼으면
`🔴 이 수집 실행이 .git/index.lock 을 남겼다` 를 §2 와 §11 양쪽에 찍는다.
그 줄이 보이면 이 규약을 어긴 명령이 그 세션 안에 있다.
⚠ **자가점검은 「수집기가 만들었는가」만 본다.** 수집기 **실행 전에** 세션이 손으로 친
명령이 만든 락은 "내가 안 만들었다"로 **정상 보고된다** — 그 경우에도 락은 존재한다
(2026-08-26에 실제로 그렇게 찍혔다).

### 🔴 병행 세션 확인 — 자기 절을 쓰기 **전에** 두 가지를 본다

```bash
git --no-optional-locks log --format="%ci %h %s" --since="<오늘 00:00>"
ls -lt docs/정기점검/매일점검/ | head -20
```

**왜**: 2026-08-26 하루에 **네 개 세션**(장전·11:58 딥다이브·12:26 장중·커밋 2회)이
서로를 모른 채 돌았다. 장중 절이 *"물리적으로도 커밋이 불가능하다"* 라고 쓴 그 시점에
**이미 12:24:59 커밋이 성공해 있었다.** 2026-08-25에도 16:23 딥다이브가 16:22 장후 절의
대표 숫자를 무효로 만들었다(이상점 1-20). 하루 한 파일 규약은 *뒤 국면이 앞 국면을 읽는다*를
전제하는데, 병행 작성은 그 전제를 무력화한다.

**특별조사·딥다이브를 별도 파일로 낸 것이 보이면**, 그 파일을 **열어 읽고** 그날
점검리포트에 **「파일 경로 + 결론 1줄 + 그날 판정에 미치는 영향」 역링크를 append** 하라
(F-AE). 파일을 합치라는 뜻이 아니다.

## 1-B. 멀티PC 설치 — MW0601·MW0602 양쪽에서 동작한다

스킬은 **PC를 가리지 않는다.** 절대경로가 하나도 없고, 리포 루트는 `CLAUDE.md`+`dev_memory/`로

> ⚠ **단, `git pull` 로 전파된다고 가정하지 마라**(함정 ③). 두 브랜치가 397/383커밋씩
> 갈라져 있어 한쪽 커밋이 다른 쪽에 자동으로 오지 않는다. 그리고 **앱 저장 스킬과
> 예약작업은 애초에 git 으로 공유되지 않는다.**

**PC마다 따로 해야 하는 것 3종** — git 이 옮겨주지 않는다:

| 대상 | 방법 |
|---|---|
| 앱 저장 스킬(`SKILL.md`) | 그 PC 세션에서 `save_skill` `overwrite: true` |
| 예약작업 3종(장전·장중·장후) | 그 PC 데스크톱 앱에서 시작한 세션에서 등록·갱신 |
| `--discover` 인벤토리 검증 | 그 PC에서 1회 |

**`--discover`를 PC마다 돌리는 이유**: 코드는 같아도 로그 적재량·보관 정책·경로가 PC마다 다를 수
있다. 인벤토리가 다르면 `config/dailycheck_targets.json`을 공유값으로 두기 어렵다 —
그때는 두 PC의 합집합으로 `scan_dirs`를 넓히되 `priority_logs`는 그대로 둔다.

산출물은 파일명에 PC명이 들어가 서로 덮지 않는다.

| 산출물 | 이름 |
|---|---|
| 증거 다이제스트 | `docs/정기점검/매일점검/evidence_<PC명>-<YYYYMMDD>_<국면>.md` |
| 점검 리포트 | `docs/정기점검/매일점검/<PC명>-<YYYYMMDD>-점검리포트.md` |

> 호스트명에서 `MW####`를 못 뽑으면 다이제스트 첫 줄이 `UNKNOWN`이 되고 경고가 뜬다.
> 그 상태로 커밋하면 어느 PC의 관찰인지 영영 모르게 된다 — 반드시 확인하라.

> **[461차, F-6] 같은 이름이 이미 있으면 `_<HHMM>`이 붙는다 — 다이제스트는 덮어쓰지 않는다.**
> 국면까지만 구분하던 시절, 2026-08-13에 예약작업이 13:13에 `--phase post`로 오발하고
> 16:22 진짜 장후 수집이 그 파일을 덮어 13:13본이 사라졌다.
> 접미사 붙은 파일이 보이면 **그날 같은 국면이 두 번 돌았다는 신호**다 — 어느 쪽이
> 진짜 그 국면의 관측인지 생성 시각(다이제스트 첫 줄)으로 확인하고 리포트에 명시하라.

## 2. 증거를 먼저 모은다

### ⚠ 호스트명에 `MW####`가 없는 환경이면 `--pc`를 붙여라 [476차]

호스트명이 `claude`** 라 `evidence_UNKNOWN-….md`가 조용히 생기고, 그대로 커밋하면

## 4. 설계와 대조한다 — 이 스킬의 핵심

증거를 **기준**에 대야 이상점이 된다. 기준은 다섯 군데다.

1. **`CLAUDE.md`** — 절대원칙 6종(변경 불가), 계측 4원칙, 매분 9단계, 확률 판단 기준, 실전 전환 기준, 26주 재검증 항목. **충돌 시 최우선.**
2. **`CORE.md`** — 핵심 판단 규칙. 코딩 전 반드시 확인.
3. **`ROADMAP.md`** — Phase별 구현 계획과 마일스톤.
4. **`dev_memory/DECISION_LOG.md` · `NEXT_TODO.md`** — 이미 아는 문제인가, 새 문제인가. **이미 결정된 사안을 새 발견인 양 보고하지 않는다.**
5. **커밋 이력** — 당일/최근 커밋이 실제로 반영됐는가. PC명 태그가 붙었는가.

**여섯 번째 기준이 하나 더 있다 — 오늘 파일의 앞 국면 절.** 장중·장후는 앞 절이 세운
예측과 "확인 필요" 항목을 반드시 채점한다(§5-3).

> ⚠ **매분 9단계 STEP 3(GBM 배치 재학습)을 "30분마다"로 읽지 마라** — 그 문구는 코드에
> 존재한 적이 없다(483차 문서정정). 실제 트리거는 전부 **이벤트 구동**이다:
> `[ConstOut]` 재적합 후속 · `[DriftRetrain]` · `[WarmupRetrain]` · `[PreRetrain]`(08:55 1회,
> 전날 EOD 성공이면 **스킵이 정상**). 정기적인 것은 **주간(월요일 08:50~09:00)·
> 월간(매월 1일 07:00)** 뿐이다. **재학습 0회가 정상인 날이 있다** — "12회 있어야 하는데
> 0회"로 읽으면 정상을 이상으로 판정한다.
> ⚠ 브랜치에 따라 이 서술이 다를 수 있다 — **자기 브랜치 코드로 확인하라**(함정 ③).

> **퇴역한 내용을 포함**하므로 사료적 참고용으로만 쓰고 근거로 인용하지 마라.

## 5. 보고서를 쓴다

형식은 **`references/report_template.md`** 를 따른다.

### 5-0. 대원칙 — 장전·장중·장후 리포트는 **알기 쉽게** 쓴다

**정확한데 안 읽히는 리포트는 실패한 리포트다.** 하루에 세 번 나오고 한 편이 40~80KB다.
읽는 사람이 첫 30초 안에 *"오늘 위험한 일이 있었나 / 돈은 어떻게 됐나 / 내가 지금 할 일은
무엇인가"* 에 답하지 못하면, 아래의 모든 규율은 아무 일도 하지 못한다.

다음 다섯을 지킨다. **엄밀성을 낮추라는 뜻이 아니다** — 엄밀한 내용을 **앞이 쉽고 뒤가 깊은
순서**로 놓으라는 뜻이다.

1. **결론부터.** §0 「오늘 한눈에」는 **약어·로그 태그명·파일경로·절대원칙 번호·STEP 번호를
   단 하나도 쓰지 않는다.** 판정(정상/조건부/이상)·손익·P0 유무를 평문으로 먼저 말하고,
   근거는 그 뒤 표와 인용에 둔다. 전문용어가 필요해지는 순간부터가 §1이다.
   - ✗ `STEP5 체크리스트 core_pass 0건 — 절대원칙 ③ 저촉 의심`
   - ✓ `오늘 오전 내내 진입 신호가 한 건도 나오지 않았습니다. 프로그램이 멈춘 것은 아니고,
     들어갈 자리가 없다고 판단한 것인지 판단 기능 자체가 막힌 것인지는 아직 구분되지 않습니다.`
2. **약어는 첫 등장에서 한 번 풀어쓴다.** `CB③`·`P8`·`TP1 보호트레일`·`binding_gate`·
   `313차 원칙`·`함정 ①` 처럼 이 프로젝트 밖에서는 통하지 않는 말은
   `P8(EOD 재학습 뒤 스케일러 재적합)` 식으로 괄호를 한 번 붙인다. 두 번째부터는 그냥 쓴다.
3. **숫자에는 단위와 기준을 붙인다.** `pt`인가 `원`인가 · **포지션 단위인가 레그 단위인가** ·
   MDD가 **자본 대비인가 peak 대비인가**. 이 셋은 과거에 실제로 결론을 뒤집었다
   (417차·461차·470차). 표본이 작으면 `승률 41%(표본 17건 — 확정 결론 금지 구간)`.
4. **「영향」은 평문 한 문장으로 쓰고, 기술 설명은 따로 단다.** 이상점마다
   `**영향**`(사람 말)과 `**영향(기술)**` 을 **둘 다** 쓴다. 기술 설명을 지우는 것이 아니다.
5. **사람이 할 일은 한곳에 모은다.** 사용자 조치가 필요한 것(커밋·배치 실행·주간회의 상정)은
   흩어놓지 말고 리포트 **맨 끝 `## 사용자 조치` 한 절**에 모으고, 각 항목에
   **① 지금 할 일 ② 걸리는 시간 ③ 안 하면 생기는 일** 셋을 적는다.

> ⚠ **줄이라는 뜻이 아니다.** 근거·인용·표본 수·313차 판정 보류는 그대로 다 쓴다.
> 쉽게 만드는 대상은 **순서와 표현**이지 **내용**이 아니다.
> 증거를 덜어내서 읽기 쉬워진 리포트는 이 스킬의 실패다.

### 5-1. 그 밖에 작성 시 지킬 것

- **이상점 하나 = 증상 → 근거(로그 인용 + 시각) → 기준 위반(CLAUDE.md 절대원칙 번호 / 계측 4원칙 / 9단계 STEP) → 영향(평문) → 영향(기술)**.
- 심각도는 **P0(오늘 거래에 직접 위험·절대원칙 위반) / P1(정확성·관측 훼손) / P2(운영 부담·기술부채)**.
- **불확실한 것은 불확실하다고 쓴다.** 표본 부족이면 "확정 결론 금지"(313차 원칙)를 명시하라.
  **확정된 결함과 "확인 필요"를 같은 절에 섞지 않는다.**
- Fix 계획은 파일·함수 수준까지. "게이트를 개선한다"가 아니라
  "`strategy/entry/checklist.py`의 `_core_pass()`에서 entry_horizon 그룹 판정을 …".
- **Fix를 쓰기 전에 `grep`으로 "이미 있는가"를 확인한다**(함정 ①).
- **장전·장중에는 코드 변경을 제안만 하고 실행하지 않는다.** 라이브 프로세스가 돌고 있다.
  장전 예약은 개장 직전에 돌므로 **커밋·배포·재기동도 하지 않는다.**
- 고도화 방안은 **당일 관측에서 출발**해야 한다. 일반론 금지.
- **장후면 제4부(승패 사후검증)·제5부(수익률 향상방안)를 이어 붙인다** — `references/postmortem.md` 절차대로.
- **P0(오늘 거래 자격에 직접 위험)이면 리포트 맨 위에 `⚠ P0`로 올리고**, 사람이 개장 전에
  판단할 수 있도록 조치 선택지와 각각의 손익을 한 줄씩 제시한다.

### 5-2. 산출 규약 — **하루에 리포트 파일은 하나다. 국면마다 append 한다.**

```
docs/정기점검/매일점검/<PC명>-<YYYYMMDD>-점검리포트.md      ← 이 파일 하나뿐이다
```

PC명은 수집기 첫 줄에 찍힌 값(`MW0601`/`MW0602`)을 쓴다.

| 국면 | 하는 일 |
|---|---|
| **장전 `pre`** | 파일을 **새로 만든다**. `# 미륵이 일일 점검 — <PC>/<날짜>` 헤더 + `# 장전(pre)` 절 |
| **장중 `intra`** | 같은 파일 **끝에 `# 장중(intra)` 절을 append.** 장전 절을 읽고 **반영**한다 |
| **장후 `post`** | 같은 파일 **끝에 `# 장후(post)` 절을 append.** 장전+장중을 **종합**해 그날의 최종본을 완성한다 |

> 🔴 **`-pre` / `-intra` / `-post` 접미사 파일을 만들지 마라.** (구 관행. 2026-08-19 폐지)
> 하루가 세 조각으로 흩어지면 다음 세션·주간회의·다른 PC가 어느 것이 최신인지 알 수 없다.
> 실제로 0818은 3파일, 0819는 2파일로 갈렸고 그때마다 "어느 게 그날의 결론인가"를 다시 물었다.

**절대 규칙 — append 는 append 다.**
- **앞 국면 절의 본문을 고쳐 쓰거나 지우지 않는다.** 장전이 틀렸으면 **장중 절에서 정정**하고
  장전 절은 그대로 둔다(그래야 *왜 그때 그렇게 판단했는가*가 남는다).
  ⚠ 유일한 예외: 앞 절에 **한 줄짜리 정정 포인터**를 다는 것은 허용한다 —
  `> ↩️ 12:30 정정 — 2-3 참조.` 오탈자·깨진 링크처럼 의미를 바꾸지 않는 수정도 허용한다.
- **기존 날짜본을 덮어쓰지 않는다** — 주간점검이 지난주 리포트를 잃은 사고가 실제로 있었다.
- 같은 국면을 하루에 두 번 돌면 **새 파일이 아니라 같은 파일에 절을 하나 더 붙인다**
  (`## 제2부-B. 장중 재점검 (14:10)`).
- 파일이 없는데 `intra`/`post` 를 돌리게 되면(앞 국면 미실행) **새로 만들되 맨 위에
  `⚠ 장전 미실행 — 이 파일은 <국면>부터 시작한다` 를 적는다.** 조용히 시작하지 마라.
- **한 PC의 리포트가 다른 PC의 국면 절을 이어 붙이지 않는다** — 서로 다른 브랜치의 관찰이다.

### 5-3. 국면 간 이월 — 뒤 국면은 앞 국면을 **반영**해야 한다

리포트를 이어 붙이기만 하고 앞 내용을 안 읽으면 같은 이상점이 세 번 새 발견으로 올라온다.
**뒤 국면 절은 반드시 앞 국면 항목의 처분을 먼저 적고 시작한다.**

각 국면 절 앞머리에 **이월 처리표**를 둔다(양식은 `references/report_template.md`).

| 처분 | 뜻 |
|---|---|
| ✅ **해소** | 앞 국면 이상점이 사라졌다 — **무엇으로 확인했는지 근거를 적는다** |
| 🔄 **지속** | 그대로다 — 번호를 새로 붙이지 말고 **원 번호를 계승**한다(`1-6` → `1-6(지속)`) |
| ⬆️ **격상/⬇️ 완화** | 심각도 변경 — **왜 바뀌었는지** |
| ↩️ **정정** | 앞 국면 판단이 틀렸다 — 원 항목 번호를 밝히고 뒤집는다. 앞 절은 그대로 두고 포인터만 단다 |
| 🆕 **신규** | 이 국면에서 처음 나온 것만 새 번호 |

- **이상점 번호는 하루 안에서 이어진다.** 장전 `1-1~1-5` → 장중 `1-6~1-8` → 장후 `1-9…`.
  국면마다 `1-1`로 되돌리지 않는다.
- 🔴 **관측 번호는 `O-<국면><일련>` 이다** [498차 F-11] — `O-p1`(장전) · `O-i1`(장중) ·
  `O-t1`(장후). 국면 접두 없이 `O-8` 로 쓰지 마라.
  **왜**: 2026-08-26 하루 안에서 `O-8`·`O-9`·`O-10` 이 **두 번씩 다른 뜻으로 발급**됐다
  (12:30 장중 절 / 14:55·15:10 재점검 절). "8번 항목"이 어느 것인지 알 수 없어 이월 표의
  기계적 대조가 불가능해졌고, 다음날 장전이 엉뚱한 항목을 닫을 수 있었다(이상점 1-12 —
  0825 이상점 1-20 병행 세션의 **번호 축 변종**).
  같은 국면을 하루에 두 번 돌면 **일련만 이어 붙인다**(`O-i5` → `O-i6`).
  이상점 번호(`1-N`)는 현행 유지한다 — 그쪽은 충돌하지 않았다.
- **각 국면 절 끝에 「이 절이 발급한 번호 범위」 한 줄을 쓴다** [498차 F-11] —
  예: `이 절이 발급한 번호: 이상점 1-9~1-13 · 관측 O-t1~O-t4`.
- **관측 예정(`O-p*`/`O-i*`/`O-t*`/`P-*`)은 다음 국면이 판정한다.** 장전이 등록한 것을
  장중·장후가 그대로 두면 안 된다 — **판정 / 판정 보류(사유) / 다음 거래일 이월** 셋 중
  하나로 닫는다. 보류·이월이면 **무엇을 더 보면 닫히는지**와 **언제 닫는지**를 반드시 쓴다.
- **미처분 0건**을 이월 표 끝에 명시한다.
- ⚠ **이월 처리 전에 「병행 세션 확인」(§0)을 먼저 하라** — 앞 국면 이후 커밋이나 별도
  산출물이 있었으면 그것이 앞 국면 판정을 이미 뒤집었을 수 있다(2026-08-25·26 연속 실측).

### 5-4. 장후 = 그날의 **종합 완성본**

장후 절은 자기 국면 관측만 쓰는 것이 아니라 **하루 전체를 닫는다.** 아래를 반드시 포함한다.

1. **종합 판정표** — 장전/장중/장후 3행. 각 국면 판정과 **최종 판정** 한 줄.
2. **당일 이상점 통합 대장** — 1-1부터 끝번호까지 **한 표에 모아** 최종 상태를 찍는다
   (발견 국면 · 최초/최종 심각도 · 최종 처분 ✅🔄⬆️⬇️↩️). 세 국면에 흩어진 것을 여기서 한눈에 본다.
3. **당일 최종 손익·절대원칙 6종 최종 판정** — 장중 중간 판정이 아니라 **종가 기준**.
   실현/평가 손익(원 · 자본 대비 %), MDD(peak 대비 · 자본 대비 **병기**), 진입/청산 건수
   (**포지션 단위와 청산 레그 단위를 구분해 병기**), 종가 포지션(계약 수),
   차단·사이저·CB 발동 건수, 한시예외 적용 현황, 9단계 STEP 중 걸린 것,
   **15:10 강제청산 이행 여부**, EOD 재학습 성공 여부.
   ⚠ 손익 판정 원천은 **브로커 실측 net** 을 우선한다(엔진 net은 수수료 가정에 의존).
   자기 브랜치에 `utils/db_utils.py:fetch_daily_net_for_verdict()` 가 있으면 그것을 쓰고,
   없으면 **엔진 net임을 명시**하고 가정 요율을 함께 적는다.
   ⚠ **수수료율 세대가 다르면 시계열을 직접 비교하지 마라** — 행별 세대는
   `trades.commission_rate_used`(있는 브랜치)가 명시한다.
4. **제4부 승패 사후검증 · 제5부 수익률 향상방안** (장후 전용, `references/postmortem.md`).
   제4부는 케이스 단위 딥다이브 + 요인 귀인, 로그·수집기§5·DB 3원 대사 건수 일치 확인.
   제5부는 제4부 요인 집계에서만 도출(일반론 금지), 각 항목 6칸
   (근거/변경대상/기대효과/회귀위험/검증/표본상태).
5. **사용자 조치 절** — 하루치 사용자 할 일을 **여기 하나로 모은다**(§5-0 규칙 5).

## 실행을 요청받았을 때

"fix 항목 구현해" / "고도화 방안 구현해" 로 이어지면:

1. 구현계획을 먼저 항목별로 — 변경 파일, 변경 내용, 회귀 위험, 검증 방법.
2. **장전·장중이면 실행하지 않는다.** 라이브 프로세스가 돈다. 계획만 확정하고 장후 적용을 권고한다.
3. **절대원칙 6종은 변경 대상이 아니다.** 저촉되는 제안은 내지 마라.
4. **COM 콜백 안에는 `dynamicCall`·`emit`을 넣지 마라** — 0xC0000409 크래시(절대원칙 4).
5. 커밋 메시지 첫 단어는 `[MW0601]` / `[MW0602]`.
5-B. **§5-2(하루 한 파일 · append)가 템플릿보다 우선한다** —
   `references/report_template.md` 가 `-pre`/`-intra`/`-post` 접미사 방식을 말하고
   있으면 그쪽이 낡은 것이다. 산출물은 `<PC명>-<날짜>-점검리포트.md` 하나이며
   국면마다 append 한다.
6. 재학습 코드를 건드리면 `py310_64` 전용임을 잊지 마라 — `py37_32`로 돌리면 OOM 재발(191차 결정).
7. 게이트·차단 로직 신설은 **섀도 계측을 거친 뒤** 승격한다.
8. 구현 결과는 **그날 파일의 해당 국면 절에 이어 붙인다.** 별도 파일을 만들지 않는다.
9. 🔴 **스킬 자체를 고쳤으면 세 곳을 모두 갱신한다** —
