# 보고서 템플릿 — 미륵이

산출 위치: `docs/정기점검/매일점검/<PC명>-<YYYYMMDD>-점검리포트.md` — **하루에 이 파일 하나뿐이다.**

> 🔴 **`-pre`/`-intra`/`-post` 접미사 파일을 만들지 마라** (구 관행, 2026-08-19 폐지 — SKILL.md §5-2).
> **장전이 만들고 · 장중이 append 하고 · 장후가 append 해서 그날의 종합 완성본이 된다.**
> 기존 날짜본을 **덮어쓰지 않고**, 앞 국면 절의 본문도 **고치거나 지우지 않는다**
> (정정은 뒤 국면 절에서 하고 앞 절에는 한 줄 포인터만 단다).

### 하루치 파일의 골격

```
# 미륵이 일일 점검 — {PC명} / {YYYY-MM-DD}      ← 장전이 1회만 만든다

# 장전(pre)      ← 장전 세션
  0 … 8

# 장중(intra)    ← 장중 세션이 append. 절 번호에 i 를 붙인다 (0i, 1i, 2i …)
  0i-C 이월 처리표  ← 장전 항목 처분을 먼저
  0i … 8i

# 장후(post)     ← 장후 세션이 append. 절 번호에 p 를 붙인다 (0p, 1p, 2p …)
  0p-C 이월 처리표  ← 장전+장중 항목 처분
  0p … 5p (제4·5부 포함)
  9p 종합 — 오늘 하루 (종합 판정표 · 이상점 통합 대장 · 사용자 조치)
```

**이상점 번호는 하루 안에서 이어진다** — 장전 `1-1~1-5` → 장중 `1-6~1-8` → 장후 `1-9…`.
국면마다 `1-1`로 되돌리지 않는다.

아래 구조를 그대로 쓰되, 해당 없는 절은 "해당 없음"으로 남기고 삭제하지 않는다.

> 🟢 **대원칙 — 알기 쉽게 쓴다 (SKILL.md §5-0).**
> 정확한데 안 읽히는 리포트는 실패한 리포트다. **결론부터 · 약어는 첫 등장에서 한 번 풀어쓰기 ·
> 숫자에 단위와 기준(pt/원, 포지션/레그, 자본대비/peak대비) · 「영향」은 평문 한 문장 +
> 그 아래 `**영향(기술)**` 을 **따로 · 둘 다** · 사용자 조치는 맨 끝 한 절에 모으기.**
> ⚠ 줄이라는 뜻이 아니다 — 쉽게 만드는 대상은 **순서와 표현**이지 **내용**이 아니다.

## 장중·장후 절 앞머리 — 이월 처리표 (SKILL.md §5-3)

**뒤 국면 절은 이 표부터 쓴다.** 앞 국면 항목을 하나도 빠뜨리지 않고 처분한다.
안 그러면 같은 이상점이 하루에 세 번 "신규"로 올라온다.

```markdown
## {0i|0p}-C. 이월 처리 — 앞 국면 항목 처분

| 원 번호 | 제목(줄임) | 원 국면 | 처분 | 근거 |
|---|---|---|---|---|
| 1-1 | G-1 사이드카 `label_scheme` 유실 | 장전 | 🔄 지속 | EOD 사이드카 6/6 여전히 `null` |
| 1-2 | 수집기 DB 축 실패 | 장전 | ↩️ 정정 | 원인이 샌드박스가 아니라 라이브 WAL 점유 — §1p-11 |
| 1-6 | `ofi_norm` 축퇴 | 장중 | 🔄 지속 | `[CORE준비도]` 42/42(100%) |
| O-5 | ConfFloor 관측률 | 장전 | ✅ 해소 | 앙상블 축 306/306 — 가설 기각 |

처분 기호: ✅해소 / 🔄지속(원 번호 계승) / ⬆️격상 · ⬇️완화 / ↩️정정 / 🆕신규(새 번호)
```

- **지속 항목에 새 번호를 붙이지 않는다.** `1-6(지속)` 으로 계승한다.
- **앞 국면이 등록한 관측 항목(O-*/P-*)을 남겨두지 않는다** — 판정 / 판정 보류(사유 명시) /
  다음 거래일 이월 셋 중 하나로 닫는다.
- 정정(↩️)이면 **앞 국면 절의 해당 항목 아래에 한 줄 포인터**를 단다:
  `> ⚠ [장후 정정] 이 판단은 §1p-11 에서 뒤집혔다.` **앞 절 본문은 고치지 않는다.**

## 작성 시 주의

- **하루 한 파일 · append 전용 (§5-2).** `-pre`/`-intra`/`-post` 파일을 만들지 않는다.
  **앞 국면 절의 본문을 고치거나 지우지 않는다** — 정정은 뒤 국면에서 하고 앞 절에는
  한 줄 포인터만 단다.
- **뒤 국면은 앞 국면을 반영한다 (§5-3).** 절 앞머리에 이월 처리표. 이상점 번호는
  하루 안에서 이어진다. 지속 항목에 새 번호를 붙이지 않는다.
- **장후는 그날의 종합 완성본이다 (§5-4).** 마지막 절에 종합 판정표 · 이상점 통합 대장 ·
  사용자 조치를 모은다. **이 파일 하나만 읽고 그날이 재구성돼야 한다.**
- **알기 쉽게 쓴다 (§5-0 대원칙).** §0이 전문용어 없이 읽히는가 · 약어를 첫 등장에서
  풀었는가 · 숫자에 단위와 기준이 붙었는가 · 「영향」이 평문 한 문장인가 ·
  **모든 이상점에 `**영향**` 과 `**영향(기술)**` 이 둘 다 있는가** ·
  사용자 조치가 맨 끝 한 절에 모였는가. **정확한데 안 읽히면 실패한 리포트다.**
  ⚠ 쉽게 쓴다며 **증거나 기술 내용을 덜어내지 않았는가** — 덜어냈다면 대원칙 위반이다.
- **인용 없는 이상점은 쓰지 않는다.** 로그 시각과 파일명이 반드시 붙는다.
- **"개선한다"류 동사를 쓰지 않는다.** 어느 파일 어느 함수에서 무엇을 어떻게 바꾸는지 쓴다.
- **재발 항목은 무조건 P0 맨 위.** 원래 고쳤다는 커밋 sha와 차수까지 찾아 붙인다.
- **"이미 반영된 사안" 절을 비워두지 마라.** 비어 있으면 "확인했는데 없었다"고 명시한다.
- **재인용 금지 수치를 쓰지 마라** (`invariants.md` §3).
- **표본이 부족하면 확정 결론을 내지 않는다** (313차). 대신 "몇 건 더 쌓이면 판정 가능"을 쓴다.
  판정 단위는 **건수가 아니라 거래일**이다 — 누적 수치가 극적이어도 일자 부호가 갈리면
  "일자단위로 재현되지 않는다 — 채택 보류"라고 쓴다 (`postmortem.md` §4-2).
- **승패를 `exit_reason` 만으로 세지 마라.** `하드스톱`에 TP1 보호 이익 청산이 섞여 있다.
- **전일 리포트가 있으면 델타를 쓴다.** `docs/정기점검/매일점검/` 에서 직전 날짜본을 찾아 비교한다.
- **다른 PC의 리포트와 대조할 때**는 같은 코드 세대인지 먼저 확인한다.
