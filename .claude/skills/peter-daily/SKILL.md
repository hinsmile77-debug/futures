# 피터 사료 일일 수집

## 이 스킬이 지키는 것

1. **옮겨 적기이지 예측이 아니다.** 레벨을 만들어내지 않는다. 그가 쓴 숫자를 옮긴다.
2. **없는 시각을 지어내지 않는다.** 체결 시각이 트윗에 없으면 거래줄을 비워 두고
   사람에게 알린다. 미측정과 0건은 다르다.
3. **오프셋은 이 PC 의 캔들로 잰다.** 가져오지도, 추정하지도 않는다(596차).
4. **장중에는 미륵이 DB 를 건드리지 않는다.** append-only 파일만 쓴다.
5. **실패를 삼키지 않는다.** 못 한 것은 보고서에 적는다.

## 왜 장중에도 받아 적나

그는 트윗을 **지운다**(본인 표현: "지금은 지웠음"). 실측 2026-08: 13 매매일 중
08-18 장중 전체와 08-11 10:17 이전이 X 에서 사라졌다 — 둘 다 손실이 컸던 날이다.
장 마감 후에만 긁으면 그 날들은 영구히 못 건진다.

## 하루의 맞물림

```

09:00~15:40  [장중] 받아 적기만 — _raw/*.jsonl append, DB 안 건드림
15:35  마흐디 장마감 종료 (Chrome 은 살아 있다)
15:52  정규 10100 수집(595차) → 이때부터 당일 오프셋을 잴 수 있다
16:00  [장후] 오프셋 실측 → _lv/_tr → peter_paste → 문서 → peter-feed **로컬 ref**

16:30  MW0602 「피터 사료 수신」 → 저쪽 DB 재생성
```

🔴 **장후는 두 대의 기계에 걸쳐 있다.** 수집·판정·문서는 Cowork(원격 마운트)가
하고, **git push 는 Windows 가 한다** — 마운트에는 GitHub 자격증명이 없다.
10번을 보라. 이 갈림을 모르면 「다 했는데 저쪽은 어제」가 된다.

🔴 **16:00 보다 이르게 장후를 돌리지 마라.** 정규 10100 이 아직 없으면
`peter_build_day.py` 가 「정규 10100 미수집」으로 **저장을 거부한다**(옳은 동작이다).

## 절차

### A. 수집 (장중·장후 공통)

1. 오늘 날짜(KST)와 장중 구간의 unix 시각을 구한다.
   ```
   s=$(TZ=Asia/Seoul date -d "<날짜> 08:30" +%s); e=$(TZ=Asia/Seoul date -d "<날짜> 15:45" +%s)
   ```
2. Chrome 새 탭에서 연다 — **시각 범위를 반드시 좁힌다.**
   ```
   https://x.com/search?q=from%3APeterLeejoa%20since_time%3A<s>%20until_time%3A<e>&f=live
   ```
   ⚠ `since:`/`until:` (날짜형)은 **한 페이지(16건)만 주고 멈춘다.** `since_time`/
     `until_time` 으로 장중만 좁히면 대개 한 페이지에 들어온다.
3. 4초 기다린 뒤 수집 → **물리 스크롤** → 수집 → 스크롤 → 수집.
   ⚠ X 는 목록을 가상화한다 — 스크롤하면 지나간 트윗이 DOM 에서 **사라진다.**
     스크롤 **사이사이** 모아야 한다. JS `scrollTo`/`scrollBy` 로는 다음 페이지가
     안 불러와진다 — `computer` 의 실제 휠 스크롤이라야 한다.
   🔴 **휠 스크롤조차 안 먹는 날이 있다**(실측 2026-09-21: `scrollY` 가 1500 에서
     고정, DOM 10건에서 정지). 두 번 굴려도 `window.C()` 가 안 늘면 스크롤을
     포기하고 **구간을 쪼갠다** — 08:30~15:45 를 1~1.5시간짜리 4~5구간으로
     나눠 `since_time`/`until_time` 을 바꿔 가며 각각 따로 검색한다. 구간이
     좁으면 한 페이지에 다 들어와서 스크롤이 아예 필요 없다. 구간마다
     `window.S` 를 새로 만들고 결과를 합친다.
     ⚠ 이때 「Latest」 탭을 다시 누르지 마라 — f=user 로 튀면서 모은 것이 날아간다.

   ```js
   window.S={};window.C=()=>{for(const a of document.querySelectorAll('article')){
     const t=a.querySelector('time');if(!t)continue;
     const h=t.closest('a')?.getAttribute('href')||'';const i=h.split('/status/')[1];if(!i)continue;
     const x=a.querySelector('[data-testid="tweetText"]')?.innerText||'';
     const p=window.S[i];if(!p||x.length>p.text.length)window.S[i]={id:i,dt:t.getAttribute('datetime'),text:x};}
     return Object.keys(window.S).length};window.C()
   ```
4. `JSON.stringify(Object.values(window.S))` 로 꺼낸다. 길면 `.slice(n)` 로 나눠 받는다.
5. 탭을 닫고 보관한다.
   ```
   python tools/peter_capture.py --date <날짜> --json <파일>
   ```
   멱등이다 — 몇 번을 돌려도 같은 결과다. 장중에는 **여기까지만** 한다.

### B. 장후 산출 (16:00 이후)

6. ```
   python tools/peter_build_day.py --date <날짜> --dry
   ```
   지시/예고/결과/미분류/레벨선 건수와 오프셋을 먼저 눈으로 본다.
   - 「오프셋 실측 불가: 정규 10100 미수집」 → 아직 15:52 수집 전이다. 기다린다.
   - 「기존 _lv.txt 와 다르다」 → 사람이 손본 사료가 있다. 확인 후 `--force`.
7. **② 거래줄을 채운다.** 이것만은 자동이 아니다.
   `_raw` 의 체결·청산 트윗에서 시각과 가격을 읽어 `data/peter_feed/<날짜>_tr.txt` 에
   한 줄에 하나씩 적는다. **가격은 그의 정규 숫자 그대로** — 오프셋은 파서가 더한다.
   ```
   09:07 L 1067 / 09:14 X 1062 손절
   09:20 S 1062 / 10:09 X 1068 손절
   14:26 L 1046 / - 미결
   ```
   🔴 체결 시각이 트윗에 **없으면 그 거래는 적지 않는다**(실측 08-04). 지시(①)만
     그려지고 띠는 안 그려진다 — 그게 정직한 화면이다.
   🔴 그가 마감에 공개한 손익과 **맞춰 본다.** 09-17 은 −5 −6 −5 +9 = −7P 로
     그의 요약과 일치했다. 안 맞으면 방향이나 가격을 잘못 읽은 것이다.
8. 저장한다. `python tools/peter_build_day.py --date <날짜>`
9. 월간 문서를 낸다.
   ```
   python tools/peter_month_report.py <YYYY-MM> --out "C:\Users\82108\PycharmProjects\Peter\트윗원문\피터리_<N>월매매_<YYYYMMDD>_<MMDD>.md"
   ```
   🔴 **문서는 출력이지 입력이 아니다.** 문서를 고쳤다면 `_lv/_tr` 과 DB 에 먼저
     반영하고 다시 낸다 — 아니면 다음 재생성에서 사라진다.

10. **올린다 — 이 절차의 마지막 칸이다.** 여기까지 안 하면 MW0602 는 아무것도
    못 받는다. 9번까지 해 놓고 여기서 멈춘 날은 **완료가 아니다.**
    ```
    python tools/peter_feed_push.py --push
    ```
    🔴 **Cowork(원격 마운트)에서는 push 가 인증에서 죽는다** —
      `fatal: could not read Username for 'https://github.com'`(실측 2026-09-21).
      자격증명은 Windows 자격증명 관리자에 있고 이 마운트는 그것을 못 본다.
      그래도 **이 명령은 반드시 돌린다** — 로컬 `peter-feed` ref 가 여기서
      갱신돼야 Windows 가 올릴 것이 생긴다. 종료코드 1 은 「로컬은 갔고 origin 은
      아직」이라는 뜻이지 안 해도 된다는 뜻이 아니다.
    🔴 **실제 push 는 MW0601 의 Windows 작업 「피터 사료 송신」이 한다.**
      `scripts\peter_feed_push_MW0601.bat` · 등록은
      `scripts\peter_feed_push_task_register.ps1`(관리자 PowerShell 에서 한 번).
      평일 **16:00~16:25 에 10분마다** 돌고 올릴 것이 없으면 무동작이다.
      16:25 에 멈추는 것은 MW0602 의 수신이 16:30 이라서다.
      🔴 **수집을 16:25 보다 늦게 끝냈으면 그날 사료는 하루 늦는다.** 그때는
        사람에게 그 사실을 알리고 `schtasks /Run /TN "피터 사료 송신"` 을 권한다.
        (작업이 아직 등록 전이면 위 .ps1 을 먼저 돌리라고 알린다.)
    🔴 **「푸시했다」를 믿지 말고 ref 를 맞춰 본다.** 이것이 완료 판정이다:
      ```
      git rev-parse refs/heads/peter-feed
      git ls-remote origin peter-feed
      ```
      두 sha 가 같아야 저쪽이 오늘 것을 받는다. 다르면 아직 안 올라간 것이고,
      보고서의 **「못 한 것」에 적는다.** 사료가 안 올라가면 저쪽 차트는 어제에
      멈춰 있는데, 그쪽에서는 아무 에러도 안 난다.
    🔴 코드(파서 규칙 등)는 여기 안 실린다. `peter-feed` 는 `data/peter_feed/`
      만 드는 고아 브랜치다. 파서를 고쳤으면 `dev` 체리픽은 **따로** 한다 —
      사료는 자동으로 흘려보내도 되지만 규칙 변경은 사람이 판단한다.


### C. 보고 (짧게)

- 지시·예고·결과·미분류·거래 건수와 오프셋(오전 n봉)
- 그의 공개 손익 vs 거래줄 합계
- **origin/peter-feed 가 로컬과 같은가** — 같지 않으면 MW0602 는 오늘 것을 못 받는다
- **못 한 것**: 캡처 실패 횟수, 거래줄을 비운 이유, 오프셋을 못 잰 이유,
  푸시가 아직이면 그 이유와 사람이 할 일

## 흔한 함정

| 증상 | 원인 | 대응 |
|---|---|---|
| 트윗이 16건에서 멈춘다 | 날짜형 `since:`/`until:` 의 페이지네이션 한계 | `since_time`/`until_time` 으로 장중만 |
| 스크롤해도 안 늘어난다 | JS 스크롤은 무한스크롤을 못 깨운다 | `computer` 실제 휠 스크롤 |
| 앞 트윗이 사라진다 | X 의 목록 가상화 | 스크롤 **사이사이** 수집 |
| 「확장이 연결되지 않음」 | Chrome 은 떠 있어도 확장 연결은 별개 | 그날 캡처를 건너뛰고 **보고서에 적는다** |
| 오프셋 저장 거부 | 정규 10100 미수집 | 15:52 이후에 다시 |
| 장중 트윗이 통째로 없다 | 그가 지웠다 | `_raw` 에 남은 것만 쓰고 **그 사실을 적는다** |
| 휠 스크롤도 안 먹는다(`scrollY` 고정) | X 가 그 세션에서 더 안 불러온다 | 08:30~15:45 를 1~1.5시간 구간으로 쪼개 따로 검색(A-3) |
| DB 저장이 `disk I/O error` | Cowork 마운트가 sqlite 잠금을 못 받아준다 | DB 를 마운트 밖(`~/`)으로 복사 → 거기서 저장 → 파일을 되돌려 씀. 남은 `-journal` 은 삭제가 막히면 **0바이트로 비운다**(0바이트는 hot 이 아니다) |
| push 가 `could not read Username` | 마운트에 GitHub 자격증명이 없다 | 로컬 ref 까지만 하고 Windows 작업 「피터 사료 송신」에 맡긴다(10번) |
| 새로 만든 `.bat` 가 cmd 에서 `DO was unexpected` · 주석이 명령으로 실행 | 마운트로 직접 쓴 파일은 **LF** 다 — git 의 `core.autocrlf=true` 를 안 거친다 | `.bat`/`.ps1` 은 **CRLF 로 저장**한다(실측 2026-09-21). `.ps1` 은 BOM 도 함께 |

## 다른 PC(MW0602)

`_lv/_tr` 텍스트와 `_raw/*.jsonl` 만 공유한다 — **피터가 한 말은 PC 와 무관하다.**
`peter_levels.db` 와 `offset` 은 **내 계약과의 차이**라 PC 의 속성이다. 옮기면
조용히 틀린 가격을 그린다.

🔴 **푸시하는 주체는 Cowork 가 아니라 MW0601 의 Windows 다**(10번). 장후 수집이
  끝나도 origin 은 아직 안 움직인 상태일 수 있다 — 16:25 까지는 기다려도 된다.

🔴 **git 은 우체국이 아니라 사서함이다.** MW0601 이 푸시해도 저쪽 작업 폴더는
  그대로다. 그리고 파일이 와도 차트가 읽는 것은 `peter_levels.db` 이지 텍스트가
  아니다 — **받는 것과 반영하는 것은 다른 일이다.** 둘을 한 번에 하는 것이:

```
python tools/peter_pull.py          # fetch → data/peter_feed 만 받기 → DB 재생성
python tools/peter_pull.py --dry    # 무엇이 바뀔지만 본다
```

MW0602 는 이것을 평일 16:30 에 자동으로 돌린다
(`scripts\peter_pull_MW0602.bat`, 등록은 `scripts\peter_pull_task_register.ps1`).
16:30 인 이유는 **저쪽 정규 10100 수집과 이쪽 푸시가 둘 다 끝난 뒤**여야 오프셋을
잴 수 있어서다. 아직이면 그날은 이유를 찍고 건너뛴다 — 0 으로 채우지 않는다.
