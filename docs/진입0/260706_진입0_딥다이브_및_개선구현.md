## 0. 요약

오늘(2026-07-06) 진입 0건의 원인을 딥다이브해 **2개의 실제 배선 버그**(FQAdj 완화

```
추가 개선안 (일일 자동화)         → 진입 퍼널 리포트 · 표본 기아 경보+완화 사다리
```

### 1-1. 진입 퍼널 (오늘, 약 365분 기준)

7/3(정상 거래일, C등급 65분·다수 체결)과 비교하면 이례적 — conf 분포 자체가

Hurst 0.23~0.32(횡보)와 정확히 겹쳐 전멸했다.

### 1-2. 발견 1 — FQAdj 완화 배선 버그 (실효 0, 로그만 363회)

- `main.py`가 fq(피처 품질)≥0.9일 때 `zone_mc`를 0.37→0.34로 완화해 앙상블에
  전달했지만, `model/ensemble_decision.py`의 등급 컷은 `REGIME_MIN_CONFIDENCE
  [regime]`만 사용하고 전달받은 `zone_mc`를 무시하고 있었다.
- `main.py`의 `actual_min_conf = max(decision["min_conf"], zone_mc)`가 완화를
  재차 무효화 — "min_conf 0.37→0.34 (완화)" 로그가 하루 363번 찍혔지만 실제
  컷은 항상 완화 전 값(0.37)이었다.
- 268차 커밋 의도("앙상블·체크리스트 동일 mc 기준")는 절반만 구현돼 있었다.

### 1-3. 발견 2 — CB③-P4가 퇴역된 30m 정확도로 정상 신호를 차단

- 296차가 30m 호라이즌을 앙상블·CoherenceGate·CascadeCoherence에서 전면
  퇴역 확정(EOD full_cv acc=0.3052 — 랜덤 이하)했지만, CB③-P4(등급 C 이하
  자동차단)는 여전히 그 퇴역된 30m 정확도만으로 RESTRICTED를 판정하고 있었다.
- `CB_ACC_RESTRICTED_MIN`(0.30)이 30m의 확정된 구조적 성능(0.3052)과 거의
  같아 정상 샘플링 변동만으로도 상시 RESTRICTED에 붙박이는 상태 — 오늘
  14:37 acc30m=0.0%로 무관한 C등급까지 차단된 사례를 실측.

### 1-4. 발견 3 — 감사 매트릭스 공백: 구형 MetaGate가 실차단 게이트인데 미등재

- `docs/260705_..._AND_NEXT_PHASE.md` §1 매트릭스 6번 "Meta-labeling → 섀도우"는
  신형 `EntryQualityScorer`(entry_quality_prob) 얘기였는데, 같은 "meta_gate"
  용어를 쓰는 **구형 MetaGate**(`strategy/entry/meta_gate.py`, action=skip)가
  실제로는 이미 ON인 하드차단 게이트라는 사실이 매트릭스에서 누락돼 있었다.
- 오늘 244분이 `action=skip`으로 X등급 강제 전환됨을 실측 — 감사 §3-2가
  "차단형 게이트는 이미 충분히 많다"고 진단한 바로 그 유형의 게이트가 정작
  ablation 논의에서 빠져 있었다.

### 1-5. 부수 발견 — Hurst 게이트가 오늘의 유일한 conf 피크를 차단

- 14:33~14:41(conf 38~46%, 오늘 최고 구간)이 Hurst 0.23~0.32(횡보 판정,
  임계 0.45)와 겹쳐 전멸. 추세추종 설계상 "의도된 동작"이지만, 그 의도가
  실제로 손실을 회피하는지 실측 근거가 없었다는 것이 공백으로 확인됨.

### P1-4. Hurst 게이트 counterfactual 섀도우 (§3-6)
- **목적**: "Hurst만으로 차단된 신호"의 가상 결과를 실측해, 차단 유지 vs
  사이징 배수(×0.5) 완화를 4주 표본으로 판정.
- **구현**:
  - `utils/db_utils.py`: `hurst_gate_shadow` 테이블 신설(signal_decay_exits와
    동일 패턴).
  - `main.py`: Hurst만 차단하고 다른 모든 게이트는 통과 + 등급 A/B/C인 분봉에
    한해 가상 진입가·손절·TP1(HURST_REGIME_ATR_MULT의 mean-revert 배수 반영)
    기록. 읽기 전용 — 실거래 미관여.
  - `scripts/generate_validation_campaign_report.py`:
    `resolve_and_eval_hurst_gate()` — signal_decay와 동일한 STOP/TP1/NEITHER
    판정으로 매주 사후 판정.
- **판정 기준**: 존치(PASS) = 누적 `hyp_pnl_pts` ≤ 0. 완화(FAIL) =
  `hyp_pnl_pts` > 왕복비용×2 이고 승률 > 기준선 → 사이징 ×0.5부터(즉시
  언블록 아님).
- **검증**: 실제 오늘 14:00~14:30 분봉으로 STOP/TP1/NEITHER 3케이스를 합성
  삽입해 resolve 로직을 수동 계산값과 대조 확인(정확히 일치).

## 4. 추가 개선안 구현 (일일 자동화)

### 4-1. 진입 퍼널 일일 자동 리포트
- **목적**: 오늘 수동으로 만든 퍼널(FLAT→conf미달→게이트별→후보→진입)을
  자동화해 "진입0이 어느 층에서 발생했는가"를 매일 자동으로 남긴다.
- **구현**: `utils/db_utils.fetch_daily_entry_funnel()` —
  `ensemble_decisions`(매분 무조건 기록, dedup 없음 — 로그의 ZeroDiag/
  entry_block_reason 출력보다 정확)를 이용해 5단 퍼널 재구성:
  `FLAT → conf미달 / CoherenceGate(앙상블 X) → 게이트차단(STEP7·체크리스트,
  세부 breakdown) → 후보(entry_final_ok) → 진입(entry_executed)`.
- **부수 버그 발견·수정**: `coherence_blocked`가 DB에 저장되지 않아
  `grade=='X' AND regime_ok==1`로 역추정했더니, 로그 대조 결과 CoherenceGate와
  conf미달이 같은 분에 동시 발생하는 케이스(09:10:59 등)를 조용히 누락함을
  확인 — `ensemble_decisions`에 `coherence_blocked` 컬럼 신설,
  `learning/prediction_buffer.py` STEP9 저장에 배선. **오늘 데이터는 소급
  불가(컬럼이 없었으므로 0으로 표시)** — 내일부터 정확.
- **표시**: `strategy/ops/daily_exporter.py` 일일 리포트에 퍼널 한 줄 + 게이트별
  breakdown 상시 노출.
- **문서화**: §4-2 주간 판정회의 고정 안건 ⑥번으로 등록.

### 4-2. 캠페인 표본 기아 조기경보 + 완화 사다리 사전등록 (§3-8)
- **목적**: §2 원칙("사후 완화는 반드시 과적합")을 진입 게이트에도 적용 —
  주간 진입이 너무 적으면 4주 뒤 KPI 표본 미달이 확정되므로, 완화 순서를
  지금(데이터를 보기 전에) 고정한다.
- **트리거**: 주간(7일) 진입 체결 < `ENTRY_STARVATION_WEEKLY_MIN`(10건).
- **완화 사다리** (`config/settings.py:ENTRY_STARVATION_MITIGATION_LADDER`,
  순서 고정 — 각 단계 최소 5거래일 관찰 후 미회복 시 다음 단계):
  ① 관찰만 — FQAdj 배선 수정(본 세션)의 자연 회복 효과 확인
  ② 구형 MetaGate take_ceil(C등급) 완화: 0.570 → 0.52
  ③ Hurst 횡보 차단 완화(최후 수단): 0.45 → 0.40
- **구현**: `scripts/generate_validation_campaign_report.py:
  eval_sample_starvation()` — 주간 진입 수 계산, 4주 투영치를 Meta-Gate/
  레짐배수 KPI의 min_samples와 대조해 위험 채널 표시, Hurst 임계값 실측으로
  3단계 적용 여부 자동 감지(나머지는 날짜 경과 기반), 리포트 최상단 [0]
  섹션(다른 모든 채널의 전제조건이므로).
- **검증**: 실제 데이터로 확인 — 주간진입 20건(하한 10 통과) → "정상" 판정.
- **원칙**: 사다리 적용은 항상 사용자 수동 결정 + `dev_memory/DECISION_LOG.md`
  기록 — 자동 변경 없음.
