## 1. 근거

### 1-1. 사전등록 판정이 이미 「채택 후보」였다 (주 근거)

632차 사전등록(`spec.LATE_SHADOW_START` · `X4NF_JUDGE_AFTER_DAYS = 10`)의 기준은
「같은 거래일 집합에서 섀도 순손익 > MAIN **그리고** 섀도 최악일 > MAIN 최악일 → 채택 후보 — 새 SPEC_VERSION 개정 뒤 재채점」이다.
2026-10-20 장후 `scripts/shindong_scorecard.py` 실측(v2 창 09-30–10-20, 13거래일):

| 변형 | 순손익 | 최악일 | 판정 |
|---|---|---|---|
| MAIN(v2) | +65.4만 | −140.3만 | — |
| **SHADOW_TR44** | **+519.9만** | **−95.9만** | **채택 후보** |
| SHADOW_X4NFA | +225.5만 | −121.9만 | 채택 후보 |
| SHADOW_X4NF | +188.8만 | −121.9만 | 채택 후보 |

셋 다 기준을 넘었다. 순손익·최악일 모두 TR44가 1위라 TR44를 고른다. 이 판정 규정은 **결과를 보기 전(09-28)에 고정된 것**이다.

### 1-2. MW0602 신동 MAIN(HYBR60)의 보완 후보 1순위 (부 근거)

MW0601 신동이 MW0602 신동을 보완할 수 있는지 2026-10-20에 분석했다.
방법은 MW0602 v3 엔진(`origin/dev`)을 이 PC DB로 재생하고, 두 MAIN 일손익을 50:50으로 섞는 것이다. v2 창 13거래일 결과:

| MW0601 후보 | HYBR60과 상관 | HYBR60 손실일(10-01·10-07) 합 | 50:50 최악일 | 50:50 평균/표준편차 |
|---|---|---|---|---|
| **TR44** | **−0.01** | **+175.5만** | −46.9만 | 0.93 |
| X4NFA | −0.24 | +121.6만 | **−36.9만** | **1.16** |
| (TR44+X4NFA)/2 | −0.11 | +148.5만 | −41.9만 | 1.09 |
| MAIN(v2) | +0.33 | +26.5만 | −111.1만 | 0.68 |
| (대조) MW0602 FLOWR60 | +0.68 | −132.2만 | −84.2만 | 1.16 |
| (기준) HYBR60 단독 | — | — | −140.9만 | 1.12 |

현행 MAIN(v2)은 보완 효과가 가장 낮았고, TR44는 신호원이 달라(맥점 R3 vs 콜−풋 흐름) 상관이 사실상 0이었다.

⚠ **이 부 근거는 「손익을 늘린다」는 뜻이 아니다.** 같은 13일에서 HYBR60과 섞으면 FLOWR60(+1,346만)이 TR44(+1,031만)보다 많이 벌고 효율도 높다.
TR44의 몫은 **꼬리 방어**다(최악일 −84 → −47만).

### 1-3. 앞선 분석 수치 정정 (재인용 금지)

같은 날 대화에서 인용한 「TR44 18일 +883만 · 상관 +0.05 · 50:50 최악일 −46.8만」은 **09-21–09-29 를 v1 규격 일일 리포트 값으로 섞은 것**이다.
같은 엔진(v2 목표)으로 18일을 일관 재생하면 다음과 같다.

- TR44 18일 합: **+717.3만**
- HYBR60과 상관: **+0.16**
- 50:50 최악일: **−115.0만**(09-29 — v2 TR44 −171.6만)
- 50:50 평균/표준편차: **0.86**

**09-30 이후 13일 수치는 두 방식이 같다**(일일 리포트도 v2 규격이었다). 판정 근거로는 13일 창만 쓴다.

## 2. 실집행 영향 (MW0601 거래주체 신동 — 685차)

- 실집행기(`strategy/shindong/live_legs.py`)는 매분 재생의 `stop_now`가 유리해지면 `sync()`의 `('set_stop', 가격)`으로 따라간다.
  트레일 손절도 **그 경로 그대로** 집행된다. 실집행 코드 변경은 없다(docstring만 갱신).
- 트레일 갱신은 **매분 1회**다. 엔진이 봉 극값을 다음 봉부터 반영하기 때문이며, 2초 단위 트레일이 아니다.
- ⚠ **실계좌는 1계약이다**(`SHINDONG_LIVE_QTY = 1`, 2026-10-13 사용자 결정). 1차 목표에서 전량 청산되므로 v3 효과 중 두 몫의 반영이 갈린다.
  - **「1차 뒤 최종 레그를 트레일로 끌고 가는 몫」**: 가상 2계약 기록에만 나타난다.
  - **「1차 전 +4pt 달린 뒤 되밀림을 이익으로 끊는 몫」**: 실계좌에도 반영된다.
  - 따라서 v3 가상 손익은 실계좌 손익의 상한 쪽 추정이다.
- 가상 집행기(`_shindong_virtual_*`)도 같은 판단 함수를 쓰므로 동일하게 따라간다.
- 적용 시점: `main.py`가 `spec`을 import할 때다. **10-21 장전 새 프로세스부터 적용**되며, 장중 재기동이 없으면 그날 내내 같은 규격이다.

## 4. 판정 기준 (사전등록 — 결과 보기 전에 고정)

### 4-1. v3 채점 (기존 규정 그대로, 시계만 재시작)

- **R3 중단 판정**: 10-21부터 10거래일. MAIN R3 순손익 < 0 **그리고** 승률 < 35% → R3 중단.
- **섀도 판정**: `SHADOW_V2` · `SHADOW_X4NF` · `SHADOW_X4NFA` — 10-21부터 10거래일. 순손익 우위 **그리고** 최악일 개선.
  - `SHADOW_V2`가 통과하면 **「되돌림 후보」**다. v2 복귀는 새 SPEC_VERSION 개정으로만 한다.
  - X4NF·X4NFA가 통과하면 「채택 후보」다.
- 자동 승격·자동 되돌림은 없다.

### 4-2. MW0602 보완 판정 (신설)

- **질문**: MW0601 신동 MAIN(v3)이 MW0602 신동 MAIN(v3 HYBR60)을 보완하는가.
- **측정**: `python scripts/shindong_complement_mw0602.py --fetch`(장후).
  - MW0601 쪽은 `shindong.db` v3 라이브 기록이다.
  - MW0602 쪽은 **이 PC DB로 `origin/dev` 엔진을 재생한 값**이며, MW0602의 실기록이 아니다. 리포트 머리에 dev sha를 남긴다.
- **창**: 2026-10-21부터 **20거래일**(`COMPLEMENT_JUDGE_AFTER_DAYS`).
- **판정**: B = (HYBR60 + MW0601 MAIN)/2.
  - B 최악일 > HYBR60 최악일 **그리고** B 평균/표준편차 ≥ HYBR60 평균/표준편차 → **보완 유효**
  - 하나만 충족하면 **부분**, 둘 다 아니면 **보완 무효**
  - 표준편차가 0이면 **미측정**이다(효율 0이 아니다).
- **대조**(표시만 — 판정 아님, 다중비교 방지): MW0602 FLOWR60 · MW0601 X4NFA · (MAIN+X4NFA)/2.
- ⚠ **이 기준은 TR44에 유리하게 맞춘 것이 아니다.** v2 창 13일 재생에서 TR44는 최악일만 개선했고 효율은 낮았다(0.93 < 1.12).
  그 창에 적용했다면 판정은 **「부분」**이다. 같은 창에서 FLOWR60은 두 조건을 모두 충족한다.
  즉 이 판정은 「꼬리 방어 + 효율 유지」를 둘 다 요구하는 엄격한 쪽이다.
- 「보완 무효」나 「부분」이 나와도 v3 MAIN을 되돌리는 근거는 아니다. v3의 주 근거는 §1-1(MW0601 단독 판정)이다.
  다음 개정에서 (MAIN+X4NFA)/2 운영 등을 검토하는 근거로 쓴다.
