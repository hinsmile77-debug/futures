## 2. 설계 — Sindong-V4 대비 변경점

### 2-1. 설정 (`config/settings.py` 「미륵 휴면 스위치」 절 신설)

| 설정 | 전환 후 값 | 뜻 |
|---|---|---|
| `MIREUK_ENGINE` | `"off"` | 9단계 파이프라인 대신 `_light_minute_pass`. **기동 시 1회** 읽음 |
| `PRINCIPAL_ALLOWED` *(신규 — Sindong-V4 에 없음)* | `("SHINDONG", "PETER")` | 선택 가능한 주체. 밖의 값(미륵)은 전환 요청 거부 |
| `PRINCIPAL_DEFAULT` *(신규)* | `"SHINDONG"` | 파일 없음·깨짐·허용 밖 값일 때. `measured=False` + 경고 로그(계측 4원칙 ④) |
| `PRINCIPAL_LOCK` | `None` | Sindong-V4 호환용으로 두되 쓰지 않음(피터 선택권 때문) |
| `LIGHT_PASS_DRY_RUN` | 검증기간 `True` → 전환 시 `False` | full 에서 경량 패스를 계산만 병행 대조 |
| `SHINDONG_FLOW_STALE_GUARD` | `"shadow"` | 7222 흐름 지연 계측만 |

> ⚠ `MIREUK_ENGINE="off"` 인데 허용 집합에 `MIREUK` 이 들어 있으면 **기동 거부**(모순 설정). 반대로 `full` 이면 허용 집합을 무시하고 종전 3종(되살림 경로).

### 2-2. 주체 모듈 (`strategy/runtime/trade_principal.py`)

- Sindong-V4 의 `locked_principal()` · `load_file()` 를 가져오고, 그 위에 `allowed_principals()` · `load()` 정규화(허용 밖 → 기본값, `reason="not_allowed:MIREUK"`)를 얹는다.
- `save()` 는 허용 밖 값을 `ValueError`. 전환은 종전대로 **FLAT·대기주문 없음**일 때만.
- 대시보드 헤더 `[미륵]` 버튼 비활성(툴팁 「미륵 휴면」), `[신동][피터]` 만 활성.

### 2-3. 경량 분봉 패스 (`main.py`) — 손 이식

Sindong-V4 의 12부품(P1–P12)을 **v9-dev 줄번호로 다시 찾는다**: 1분봉 저장 · 08:50/09:30 맥점 · 중복/유효성 가드 · 대기주문 타임아웃·고착 해소 · 틱 하드스톱 폴백 · STEP 8 청산 감시 · 15:10 청산 패스·거래소 CB(밖) · 분봉 ATR(CB④·실주문 atr·가상 장부) · CB⑤ 입력 · 화면 갱신.
여기에 v9 전용 후보(V10)를 **하나씩 판정**해 표로 남긴다 — 「파이프라인 안에 있나 / 신동·피터가 쓰나 / 경량 패스에 넣나」.

- 원칙(Sindong-V4 그대로): 부품은 **공유 메서드로 추출**해 파이프라인·경량 패스가 같은 함수를 부른다(두 벌 금지). 추출 커밋은 **동작 무변경**으로 따로 끊는다.
- 휴면 중 `SYSTEM_AUTO` 진입은 `_ts_execute_entry` 입구에서 ERROR 거부(`[MireukOff]`).
- 휴면 중에도 원천 수집(1분봉·7222·외인 선물·9842·맥점·연결선물·옵션 체인)은 끄지 않는다. 미륵 모델·스케일러·학습 상태 파일은 **덮어쓰지 않는다**(되살림 = 마지막 실가동 상태). 스케일러 재적합 3경로(`[EarlyWarmup]`·`[StartupWarmup]`·거래소 CB 해제)도 차단하되 **08:45 실시간 선행 구독은 남긴다**(Sindong-V4 2026-10-25 교훈).

## 6. 수량 — 711차 규칙과 전환의 관계

711차 규칙(`config/settings.py` `SHINDONG_STOP_RISK_*`, `main.py:_shindong_risk_qty`):

```
수량 = max(1, min(계획 수량, 위험 수량, 진입 직전 주문가능수량))
  계획 수량 = min(최대허용수량, 장시작 주문가능수량)   (장시작 미측정이면 min(최대허용, SHINDONG_LIVE_QTY=3))
  위험 수량 = floor(위험자본 × 1.5% ÷ ((손절거리 + 1pt) × 5만원))
  위험자본 = min(3,000만, 시가 예탁금) → 45만 ÷ ((d+1) × 5만) = floor(9 ÷ (d+1))
```

| 손절거리 d | 위험 수량 | 한 거래 최대 손실(대략) |
|---|---|---|
| ≤ 2.0pt | 3 (상한) | ≤ 45만 |
| 2.0–3.5pt | 2 | ≤ 45만 |
| > 3.5pt | 1 | (d+1) × 5만 |

**전환과 겹치는 지점 — 확인 결과**

| 입력 | 어디서 오나 | 미륵 off 영향 |
|---|---|---|
| 손절거리 `rec["stop"]` | 신동 재생(`_run_shindong`, 7222 타이머) | 없음 |
| 위험자본 | 시가 예탁금 `_broker_dep_base_today`(잔고 경로) — **미측정이면 3,000만 정책값**(`config/capital.py:risk_capital`) | 없음. 미측정이어도 수량이 커지지 않는다 |
| 장시작·직전 주문가능수량 | `_capital_monitor_refresh`(30초 스케줄러·진입 직전, CpTd6722) | 없음 — 단 P1 전수표에서 30초 스케줄러가 파이프라인 밖임을 재확인 |
| 1pt 원 `_pt_value` | 심볼 확정 시 | 없음 |

**의견**

1. **711차와 전환을 같은 날 겹치지 않게 한 것이 맞다.** 711차는 10-26(월)부터 적용되고 전환은 11-02 다 →
   10-26–10-30 **5거래일은 「수량 식만 바뀐 상태」**, 11-02 부터 「엔진까지 바뀐 상태」로 원인이 갈린다.
   첫날 이상이 나와도 수량 탓인지 엔진 탓인지 구분된다.
2. **Sindong-V4 의 「전환 첫날 1계약」 권고는 따르지 않는다.** 711차가 이미 꼬리를 막는다(21일 재생 최악 단일 거래
   −108 → −54만, 일일 손실 한도 60만 이하). 1계약 고정은 v9 2레그 규격을 「1차 목표 전량 익절」로 바꿔 거동을
   하나 더 바꾸는 셈이라 전환일 변수만 늘린다.
3. ⚠ **711차의 「10거래일 실측 뒤 X 2.0% 승격 판정」 창(10-26–11-06 전후)이 전환일을 가로지른다.**
   수량 식은 같으므로 창을 끊지는 않되, 전환 뒤에는 CB⑤ 자가유발(미륵 파이프라인 지연)이 사라져 **진입 표본 구성이
   바뀔 수 있다.** → 판정 때 표본을 「11-02 전/후」로 나눠 함께 적는다(불연속 마커와 같은 날). 승격 판정 자체를
   전환 전 5일만으로 당기지는 않는다(10일 사전 결정 유지).
4. ⚠ 711차에서 손절이 넓은 R2 는 대개 **1계약**이 된다 → 그 거래는 2레그 규격이 아니라 「1차 목표 전량 익절」로 집행된다
   (`_shindong_apply` 의 `qty_all >= 2` 분기). 711차가 의도한 동작이며 전환과 무관하지만, **장후 재생 대조(P4)에서
   실집행 ≠ 재생 차이로 오판하지 않도록** 대조 기준에 수량별 거동을 넣는다.
5. 피터를 선택하면 수량은 `PETER2_QTY` 다(711차 대상 아님). 피터에도 위험 수량을 적용할지는 이번 범위 밖.

**회귀 고정**: `tests/test_711_shindong_stop_risk_qty.py` 를 경량 패스(off) 상태로도 한 번 돌리는 케이스를 추가해,
엔진 스위치가 수량 경로를 건드리지 않음을 고정한다.
