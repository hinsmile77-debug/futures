## §0. 이 문서는 왜 있나 — MW0601에서 이미 돌고 있는 것을 옮긴다

MW0601은 2026-08-26부터 **장후 점검리포트의 「사용자 조치」 항목을 사람이 말하지 않아도

라고 치던 것을 무인화한 것이다.

MW0602에도 같은 설계를 배선한다. **단, 코드를 옮기는 것이 아니다** — 그 PC 기준으로
새로 등록하는 것이다. 2026-08-23 멀티PC 정책 폐기로 두 PC는 브랜치·차수·안건을 조율하지
않으며, 예약작업은 애초에 git으로 공유되지 않는다(`SKILL.md` §1-B).

> ⚠ **이 문서를 `dev` 브랜치에 머지하거나 체리픽하지 마라.** 읽고 실행하면 끝이다.
> 굳이 남기고 싶으면 MW0602가 자기 문서로 새로 쓰는 편이 낫다.

### 0-1. 지침서 정본을 먼저 읽는다

### 0-2. 🔴 모든 읽기 전용 git 명령에 잠금 방지 옵션
```
git --no-optional-locks <sub> ...
```
`status`뿐 아니라 `branch`·`diff`·`log`·`rev-list`·`ls-files` 전부다. 이 옵션이 없으면
git이 인덱스를 다시 써서 `.git/index.lock`을 만들고, 남으면 저장소가 커밋 불가가 된다.
작업 종료 시 `.git/index.lock`이 없는지 확인하고, 있으면 지워라.

### 0-3. 병행 세션 확인
```
git --no-optional-locks log --format="%ci %h %s" --since="<오늘 00:00>"
```
+ 당일 `docs/정기점검/매일점검/` 산출물 목록. **다른 세션이 이미 같은 항목을 구현·커밋했으면
다시 하지 마라.** 딥다이브 파일이 따로 나와 있으면 열어 읽어라 — 그 결론이 장후 절 판정을

## §2. 항목 추출

### 2-A. 「사용자 조치」 절을 찾는다
제목이 **`사용자 조치` 를 포함**하는 제목 중 **파일 끝에서 가장 가까운 것**을 쓴다.
(이 PC는 `## 9p. 사용자 조치 (여기만 보면 됩니다)` 처럼 번호·꼬리말이 붙는다 — 정확일치로
찾지 마라.) 하루 한 파일에 국면마다 append 되므로 앞의 것은 이미 취소·정정됐을 수 있다.

절이 **표(table)** 로 돼 있으면 각 행이 항목 하나다. 셀 안의 `F-<번호>`·`§2 F-4` 같은
참조를 뽑아 **Fix 절**(제목에 `Fix 작업 구현계획`)의 정의와 짝지어라. 참조가 없는 행은
문장 그대로 읽어 아래 3분류에 넣는다.

「사용자 조치」 절이 아예 없으면 **Fix 절의 F항목**을 대상으로 하되, `(이월)`·`완료`·
`이미 반영` 표기가 붙은 것은 제외한다. Fix 절도 없으면 종료한다.

1. **리포트에 append** — 그날 리포트 맨 끝에 `## 장후 자동조치 구현 결과 (<시각> · 자동)` 절.

   **사용자 몫으로 남은 손 작업**. §5-0 평문 원칙 적용 — 항목마다 "왜·걸리는 시간·안 하면".

3. **`dev_memory/NEXT_TODO.md`** — C등급·이월분을 체크박스로 등록.
