## 13. 다중 안전장치(게이트) 구조 재검토 [핵심]

**Q. 6~8겹 게이트가 "진입0"을 10차례+ 유발했다. 어떻게 재설계하나?**

## CB③ 대체안 확정 — "오늘 그만" 판단 기준

### 결론: 고정 임계값(N, M) 대신 통계적 유의성 기반 + 점수 합산(soft gating) 구조로 확정

CB③이 실패했던 원인(acc 지표 표본부족·버퍼 기아)을 반복하지 않기 위해, 
"몇 번 지면 끈다"는 고정 숫자가 아니라 "이게 우연히 일어날 확률이 얼마나 
희박한가"를 판정 기준으로 삼습니다.

### 1. 연속손절 기준 (N)
고정값 대신 이항검정(binomial test)으로 대체:
- 최근 30일 실제 승률(p_win) 기준, 현재 연속손절 횟수(n)가 우연히 
  발생할 확률 = (1-p_win)^n
- 이 확률이 5% 이하로 떨어지면 트리거 (승률 55% 기준 대략 N=5 근처, 
  단 매일 자동 재계산되어 모델 승률 변화에 따라 유동적)

### 2. 일일 PnL 기준 (M)
- 20 거래일 롤링 윈도우 (기관 VaR 계산 표준과 동일선)
- 단순 평균 비교가 아닌 z-score 방식 (기존 ATR z-score 작업과 
  동일 프레임 재사용)
- z-score ≤ -2 (20일 분포 하위 2.3%) 시 트리거 후보

### 3. "감"(시장 역행 인식)의 정량화
CUSUM(누적합 변화점 탐지) 도입 제안:
- 단일 시점 오차가 아니라, 예측-실제 오차가 특정 방향으로 
  연속 누적되는지 추적
- conf_inversion(275차 구현)과는 별개 축 — conf_inversion은 
  "확신도 역전"이고 CUSUM은 "오차의 방향성 누적"이므로 상호 보완재로 
  같이 사용

### 4. 최종 결합 로직 (Part 3 원칙 1: soft-gating과 동일 철학)
단일 조건으로 즉시 정지하지 않고, 4개 신호에 점수를 매겨 합산:

    이항검정 유의(p<0.05)     → +2
    PnL z-score ≤ -2         → +2
    CUSUM 방향성 누적 플래그  → +1
    conf_inversion 플래그    → +1
    합산 3점 이상 → 당일 자동정지

CB③처럼 지표 하나(acc)의 표본부족이 곧바로 시스템 정지로 이어지는

```
│   출력: 오늘 상태 = TREND_UP/TREND_DN/RANGE/CHAOS     │
│         (매분 갱신, 히스테리시스로 플립 억제)            │
├─────────────────────────────────────────────────────┤
│ L2. 조건부 예측 앙상블 (기존 GBM/SGD/RF 유지·개선)      │
│   레짐별로 다른 호라이즌·다른 임계값 활성화:             │
│     TREND → 10·15m 주축, 홀딩 편향, 익절 완화          │
│     RANGE → 1·3·5m 축소 사이즈 or 관망                │
│     CHAOS → 전면 관망 (기존 CB 역할 흡수)              │
├─────────────────────────────────────────────────────┤
│ L3. 소프트 게이트 + 리스크 예산 (기존 게이트 체인 대체)   │
│   · 직렬 AND 7겹 → 점수 합산 단일 게이트                │
│   · 일일 리스크 예산 상태기계 (하우스 머니 규칙)          │
│   · PnL 기반 당일 정지 (CB③ 대체)                     │
│   · 15:10 강제청산 등 절대 원칙은 불변                  │
└─────────────────────────────────────────────────────┘
```

## 3-3. 단계별 구현 계획 (12주 기준)

```
Phase 0. 진단·기반 (1~2주차)
  [ ] 게이트별 차단 로그 30일 전수 집계 — 겹별 통과율·결합 통과율 실측
  [ ] 일별 레짐 라벨링(사후) 30일치 — TREND/RANGE 일에 기존 시스템 PnL 분리
  [ ] conf_inversion 해소 확인 (Platt WINDOW=200 수렴 후 재측정)
  [ ] 트레이더 인터뷰 3문항 결과 반영

Phase 1. L1 데이 레짐 엔진 (3~5주차)
  [ ] 기존 신호(Hurst·ADX·ATR·GEX·시가이격) 통합 상태머신 구현
  [ ] 히스테리시스·최소 유지 시간 (EKS 273차 패턴 재사용)
  [ ] 사후 라벨 대비 레짐 판정 정확도 백테스트 (목표: TREND일 재현율 ≥70%)
  [ ] 대시보드 레짐 배지 (기존 UI 패턴 재사용)

Phase 2. L3 소프트 게이트 전환 (5~7주차)  ※ L1과 부분 병행
  [ ] 7겹 게이트 → 점수화 리팩토링 (각 게이트 로직은 보존, 차단→점수로 출력만 변경)
  [ ] 일일 최소 기회 예산 + 하우스 머니 리스크 상태기계
  [ ] CB③ 대체: PnL 기반 당일 정지 + conf_inversion 가드 연결(275차 구현 재사용)
  [ ] A/B: 구게이트 vs 신게이트 쉐도우 병행 2주

Phase 3. L2 레짐 조건부 앙상블 + 청산 재설계 (7~10주차)
  [ ] 레짐별 호라이즌 활성화·임계값 프로파일 (config 분리)
  [ ] TREND일 청산 재설계: ATR 트레일링 확폭 + 부분청산 후 러너(runner) 유지
      — 트레이더 인터뷰의 청산 방식 이식 지점
  [ ] 스태킹 메타러너 파일럿 (레짐 라벨을 입력 피처로, blended_conf 대체 후보)

Phase 4. 검증 (10~12주차)
  [ ] Walk-Forward 26주 (수정 기준: 손익비≥2.0, 상위10%일 평균≥+2.5%, MDD≤15%)
  [ ] 모의 6주 (레짐 2종 이상 포함 확인)
  [ ] 실전 전환 게이트 심사 → 통과 시 30% 사이즈 실전 개시
```

## 3-4. 예상 리스크와 완화

| 리스크 | 발생 시나리오 | 완화 |
|---|---|---|
| 레짐 엔진 오분류 | RANGE일을 TREND로 오판 → 대형 사이즈로 횡보 왕복 손절 | 레짐 확신도 연동 사이징(낮으면 0.3배), CB② 유지 |
