## 전체 그림: 이 4종은 "9항목 체크리스트 통과 후"에 오는 2차 관문

파이프라인 STEP 6(진입 판단)에서 9항목 체크리스트가 먼저 A/B/C/X 등급(`grade`)을 매기지만,
실제 주문 직전(`main.py` 5847~5922행)에 **Degraded Mode → ExecutionGovernor → MetaGate →
ToxicityGate** 순서로 한 번 더 걸러진다. 이 4종 중 하나라도 `block`을 내리면 체크리스트
등급이 A였어도 `_final_grade = "X"`로 다시 깎여 수량이 0이 된다.

`qty_ok=False`나 `mode_filter_ok=False`가 설정 버그가 아니라 이 4종 중 하나가 뒤에서
조용히 차단한 결과인 경우가 많다 — [qty_ok_mode_filter_근본원인](qty_ok_mode_filter_근본원인_2026-07-04.md)이
지목한 근본원인이 바로 이 캐스케이드다.

## ① Degraded Mode (`main.py`, HealthPolicy)

**역할**: 시스템 자체의 "건강 상태"를 감시해서, 인프라가 불안정할 때 자동으로 안전모드에 들어간다.

**입력 지표 4개** (`_classify_health_level`):
- 파이프라인 지연(latency_ms) — WARN 1000ms / CRIT 5000ms
- 피처 품질 점수(quality_score) — WARN 0.70 / CRIT 0.55
- 캐시(매크로·투자자 동향) 노후도(cache_age_sec)
- 최근 10분 WARNING/ERROR/CRITICAL 로그 밀도

**동작원리**:
1. 매분 위 4개 중 하나라도 WARN/CRIT 기준을 넘으면 `health_level`이 WARNING/CRITICAL로 판정됨
2. `_health_warn_streak`이 누적되어 **연속 2분(HEALTH_DEGRADED_ENTER_STREAK)** 이상이면 Degraded Mode ON
   - 단, 09:00~09:10 장 시작 워밍업 구간은 진입 유예 (구조적 지연 오탐 방지)
3. Degraded 상태에서는 최근 5분 윈도우 중 WARNING 비율이 50%(HEALTH_DEGRADED_EXIT_RATIO) 미만으로
   떨어져야 해제
4. 진입 시 효과: `conf < max(zone_mc, 0.30)`면 완전 차단(X등급), 통과해도 수량
   ×0.60(HEALTH_DEGRADED_SIZE_MULT)로 축소

즉 이건 **"신호 품질"이 아니라 "시스템 자체가 믿을 만한가"**를 보는 게이트다.

관련 코드: `main.py` `_classify_health_level` / `_update_degraded_mode` / `_is_degraded_entry_blocked`
(1546~1720행), 진입 적용부 5857~5873행. 기본값: `config/settings.py` `HEALTH_*` 상수.

## ② ExecutionGovernor (`strategy/runtime/execution_governor.py`)

**역할**: "지금 이 순간 주문을 넣어도 되는 실행 환경인가"를 confidence·데이터품질·API지연
3요소로 종합 판단.

**계산식**: `tradability = confidence×0.40 + quality×0.35 + latency_score×0.25`
- ≥0.65 → pass (그대로 진입)
- 0.45~0.65 → reduce (수량 ×0.6)
- <0.45 → block
- **하드블록**: latency_sec ≥ 5초면 점수 무관 즉시 block (CB⑤ API지연 규칙과 동일 기준)

toxicity는 코드 주석에도 명시돼 있듯 **의도적으로 제외**되어 있다 (ToxicityGate와 중복
차감 방지). 즉 이 게이트는 "신호 자체의 확신도 + 데이터가 신선한가 + API가 느리지 않은가"만
본다.

## ③ MetaGate (`strategy/entry/meta_gate.py`)

**역할**: 메타 레이블링 — "앙상블이 낸 신호를 실제로 따라도 될 만큼 신뢰할 수 있는가"를
별도 학습기(`MetaConfidenceLearner`)로 재검증.

**동작원리**:
1. 레짐·허스트지수·ATR비율·시간대·최근정확도·호라이즌합의도로 `meta_features` 구성 →
   학습된 회귀모델이 `meta_conf` 산출
2. `meta_conf < 0.20`이면 과소추정으로 보고 규칙기반 하한(0.45)으로 보정 (5회 연속이면
   다음 배치재학습 대기 로그만 남김)
3. 체크리스트 등급(A/B/C/X)별로 **다른 블렌딩 가중치**를 적용:
   - `blended_conf = confidence×ens_w + meta_conf×meta_w`
   - A등급은 ens_w=0.75(구조적 신호 신뢰 ↑), C/X는 ens_w=0.60(메타 의존 ↑)
4. `blended_conf`를 등급별 take/reduce 임계값과 비교해 take(수량 유지)/reduce(축소)/
   skip(차단) 결정
5. 부가 로직: 최근 30예측 중 같은 방향이 70% 넘으면 방향편향 패널티(최대 -0.05),
   STABLE_TREND/LUNCH_RECOVERY 시간대는 reduce 임계값 완화

즉 이건 **"앙상블 확신도를 그대로 믿을지, 과거 실측 정확도 패턴으로 한 번 더 깎을지"**를
보는 2차 확신도 필터다.

## ④ ToxicityGate (`strategy/risk/toxicity_gate.py`)

**역할**: 미시구조가 "독성"(toxic) 상태인지 — 즉 지금 체결하면 불리한 가격에 물릴 위험이
큰 호가 환경인지 판단.

**입력**: `toxicity_score`(및 이동평균), `spread_ticks`, `cancel_stress`(취소비율 스트레스),
`flow_stress`(주문흐름 스트레스)

**동작원리**:
- score ≥ 0.78 (또는 이동평균 ≥ 0.73) → block
- score ≥ 0.58 (또는 스프레드 ≥ 8틱) → reduce (×0.7)
- 그 외 → pass

ExecutionGovernor와 역할이 겹치지 않도록 설계되어, "체결 환경의 독성"만 전담한다.

---

## 4종이 겹칠 때: JointGateBlock

MetaGate와 ToxicityGate가 **둘 다 동시에 reduce**를 내리면 (각자 독립적으로 "위험하다"고
판단한 상황), 두 size_multiplier를 곱한 값이 0.50 미만이면 그냥 진입 자체를 차단한다
(실거래 손실 사례 2건 근거로 추가된 규칙, `main.py` 6431행).

## 최종 적용 순서 요약

```
9항목 체크리스트 grade 결정
      ↓
Degraded Mode (시스템 건강) → conf 미달 시 X, 통과해도 ×0.60
      ↓
ExecutionGovernor (확신도+품질+지연) → block/reduce/pass
      ↓
MetaGate (메타확신도 재검증) → skip/reduce/take
      ↓
ToxicityGate (호가 독성) → block/reduce/pass
      ↓
JointGateBlock (Meta×Tox 동시 reduce 조합) → 차단 여부
      ↓
IntradayRegime L2 (DAY_RISK_OFF/CRASH 사이즈 축소)
```

문서에서 지적한 대로, 이 4종+체크리스트 조합이 v9 설계안(§13) L3 소프트 게이트 점수화에
아직 명시적으로 반영되지 않았다는 게 다음 재설계 대상이다.
