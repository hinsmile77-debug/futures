# 2. 엣지 갭 분석 및 처방 (문답 12번 요청 1~3에 대한 답변)

## 2-1. 갭 분석 (요청 1)

### G1. 학술 미시구조 이론과의 갭 — "옳은 지표를 틀린 시간축에 쓰고 있다"

CVD/OFI/MLOFI 채택 자체는 이론적으로 정확하다(Cont, Kukanov & Stoikov 2014 — 주문흐름 불균형의 가격 영향). 그러나 문헌상 OFI류의 예측력은 **수 초~수 분의 극단기에 집중되고 호라이즌이 길어질수록 급감**한다. 미륵이는 CORE 호라이즌 분리(CLAUDE.md)로 이를 부분 해소했지만, 두 가지 갭이 남아 있다:

- **레벨 vs 변화율**: 옵션 피처(opt_gex_bn, PCR)를 절대 레벨로 쓰고 있다. 딜러 감마 이론의 예측력은 레벨이 아니라 **"현재가가 감마 플립 지점 대비 어디 있는가(상대위치)"와 "GEX가 어느 방향으로 변하고 있는가(변화율)"**에서 나온다.
- **상태의 지속시간 상실**: 스냅샷 분류는 "지금 임밸런스가 크다"만 보고 "임밸런스가 몇 분째 유지되고 있다"를 못 본다. 큐 다이내믹스 문헌에서 유효 신호는 후자다.

### G2. 상위권 개인 트레이더 접근법 중 재현성이 가장 높은 것 — 추세일 식별형

세 유형의 학술적 재현성 비교:

| 유형 | 학술 근거 | 개인 재현성 | 판정 |
|---|---|---|---|
| **추세일 식별형** | 일중 모멘텀(첫 30분 수익률이 마지막 30분을 예측 — Gao, Han, Li & Zhou 2018), 오프닝 레인지 브레이크아웃, 변동성 군집(GARCH) | **높음** — 인프라 경쟁 없음, 일 단위 판단 | **주축 채택** (경로 B와 정합) |
| 틱 타이밍형 | OFI 극단기 예측력 | 낮음 — HFT와 레이턴시 경쟁, 32bit COM 수백 ms에서 열세 | 보조로 격하 |
| 옵션 포지셔닝 해석형 | 딜러 감마 헤징 플로우, 만기일 효과 | 중간 — KOSPI200 옵션 시장 특성상 유효하나 단독 엣지는 아님 | 추세일 식별의 **입력**으로 흡수 |

### G3. 기관 표준 관행과의 갭 — 가장 큰 갭은 라벨링이다

| 기관/학술 표준 | 미륵이 현재 | 갭 크기 |
|---|---|---|
| **트리플 배리어 라벨링** (Lopez de Prado, *Advances in Financial ML*): 손절/익절/시간 3중 배리어 중 먼저 닿는 것으로 라벨 | 고정 시간 라벨("N분 뒤 방향") | **최대** — 고정 시간 라벨은 노이즈가 크고, 학습 목표가 실제 거래 PnL과 괴리됨. 6월 "acc는 랜덤인데 패치는 계속" 악순환의 구조적 원인 후보 1순위 |
| **라벨 중복(uniqueness) 보정**: 겹치는 라벨에 샘플 가중치 축소 | 1분마다 생성되는 30m 라벨이 29/30 중복 — iid 가정 위반 상태로 학습 | **큼** — 장기 호라이즌일수록 심각. 30m이 유독 랜덤급인 것과 정합하는 설명 |
| **메타 라벨링**: 1차 모델이 방향, 2차 학습 모델이 "실행 여부+사이즈" 판단 | MetaGate가 규칙 기반 고정 가중치 (240차에서 수동 재보정 반복) | 중간 — 이미 로드맵(스태킹)에 반영됨 |
| 변동성 타게팅 사이징 | 역변동성 사이징 + 적응형 켈리 구현됨 | 작음 — 충족 |

### G4. 문제 설정(problem formulation) 자체의 전환 — 리모델링 견적

현재 구조("정지 사진 한 장 → N분 뒤 방향 3분류")의 근본 한계는 ① 라벨 노이즈(G3), ② 시계열 맥락 상실(G1), ③ 그 결과를 확률 보정(Platt)으로 사후 수습하는 의존 구조다. 대안 스펙트럼과 비용·이득:

| 경로 | 내용 | 비용 | 이득 | 판정 |
|---|---|---|---|---|
| (a) **라벨만 교체** | 스냅샷·GBM 유지, 라벨을 트리플 배리어로 | **낮음** (py310_64 재학습 경로만 수정, 32bit 런타임 무변경) | 학습 목표를 PnL에 정렬 — 정확도 지표의 의미 자체가 복원됨 | **채택 (1순위)** |
| (b) **시퀀스 정보를 피처로 압축** | k분 롤링 윈도우 파생 피처(기울기·변화율·지속시간)를 스냅샷에 추가 | **낮~중** (피처 파이프라인 확장, 모델 클래스 무변경) | "동영상 정보"의 상당 부분을 주방 리모델링 없이 확보 | **채택 (2순위)** |
| (c) 진짜 시퀀스 모델 | LSTM/Transformer가 원시 시계열 직접 입력 | **높음** (32bit 제약 → 별도 프로세스 추론, 과최적화 위험 최대) | 이론상 최대, 실무상 불확실 | **제외 확정** (문답 14번) |

**결론: (a)+(b) 조합이 (c)가 약속하는 이득의 상당 부분을 1/5 이하의 비용으로 가져온다.** 미륵이의 6월 문제는 모델 클래스가 낡아서가 아니라, 좋은 모델도 배울 수 없는 라벨과 정보가 빠진 피처를 주고 있었기 때문일 가능성이 높다.

### G5. 스냅샷 유지 전제의 피처 개선 (식재료·조미료 교체)

(b)의 구체 목록 — 전부 기존 수집 데이터로 계산 가능, 신규 데이터 소스 불필요:

| 신규 피처군 | 예시 | 근거 갭 |
|---|---|---|
| 지속시간 | `ofi_persistence`(OFI 부호 연속 유지 분수), `cvd_slope_k`(k분 CVD 기울기) | G1 상태 지속시간 |
| 변화율 | `gex_change_5m`, `pcr_change_15m` (레벨 → 변화율) | G1 레벨 vs 변화율 |
| 상대위치 | 현재가-감마플립 거리, VWAP 밴드 z-위치 | G1 상대위치 |
| 일중 모멘텀 | 첫 30분 수익률·레인지, 시가 대비 누적 방향 지속률 | G2 추세일 식별 문헌 직결 — **L1 레짐 엔진 입력과 겸용** |
| 상호작용 | 레짐 라벨 × 주요 피처 (레짐 조건부 엣지를 명시적 항으로) | 276차 "엣지는 레짐 조건부" 결론 |

# 3. CB③ 대체 스펙 확정 — "통계적 당일 정지" (CB③v2)

사용자 제시 스펙을 그대로 채택하고, 요청된 미결 1건(장 후반 발동 시 잔여 포지션 처리)을 확정해 완성한다.

## 3-1. 4신호 점수 합산 (사용자 확정 스펙)

| 신호 | 판정 방식 | 점수 |
|---|---|---|
| ① 연속손절 | 고정 N 대신 **이항검정**: 최근 30일 실측 승률 p_win 기준 연속손절 n회의 우연 발생 확률 (1-p_win)^n ≤ 5%면 발동 (승률 55%면 N≈5 근처, 매일 자동 재계산) | +2 |
| ② 일일 PnL | 20거래일 롤링 분포 대비 당일 PnL **z-score ≤ -2** (하위 2.3%) — 기존 ATR z-score 프레임 재사용 | +2 |
| ③ 오차 방향성 누적 | **CUSUM 변화점 탐지**: 예측-실제 오차가 한 방향으로 연속 누적되는지 추적 | +1 |
| ④ 확신도 역전 | conf_inversion 플래그 (275차 구현 재사용) — ③과 독립 축(③은 오차 누적, ④는 확신도 역전)이므로 상호 보완 | +1 |

**합산 3점 이상 → 당일 자동 정지.** CB③(단일 acc 지표의 표본 부족이 곧장 시스템 정지로 이어지던 단일 장애점)의 실패 구조를 다신호 합산으로 회피 — L3 소프트 게이트와 동일 철학.

## 3-2. 잔여 포지션 처리 (미결 확정 — 아키텍트 결정)

**발동 즉시 시장가 청산 + 당일 신규 진입 금지**로 확정한다. 발동 시각(14:00~15:10 포함) 무관.

- 근거: 정지 발동은 "오늘 시스템의 판단력을 불신임한다"는 통계적 선언이다. 불신임한 시스템의 청산 로직에 잔여 포지션 관리를 계속 맡기는 것은 자기모순이며, CB⑤(API 지연→즉시 청산)의 기존 관례와도 일치한다.
- 15:10 강제청산은 이와 **독립된** 최후 안전망으로 불변 유지 (이중 안전).
- 예외 없음 — "수익 중인 포지션은 트레일링 유지" 같은 예외는 CB의 단순성 원칙을 훼손하므로 두지 않는다.

# 4. 아키텍처 (3계층 — 확정)

```
┌────────────────────────────────────────────────────────┐
│ L1. 데이 레짐 엔진  (신규 — 기존 신호 통합, 처방 P4)        │
│   입력: Hurst, ADX, ATR ratio, 시가이격, 야간지표,        │
│         opt_gex 변화율·감마플립 상대위치, 수급,             │
│         일중 모멘텀(첫 30분), MicroRegimeClassifier      │
│   출력: TREND_UP / TREND_DN / RANGE / CHAOS             │
│         + 레짐 확신도 (매분 갱신, 히스테리시스 플립 억제)     │
├────────────────────────────────────────────────────────┤
│ L2. 조건부 예측 앙상블  (기존 GBM/SGD/RF 유지, P1~P3 적용) │
│   · 트리플 배리어 라벨 + 롤링 윈도우 피처 + 중복 가중치      │
│   · TREND → 10·15m 주축, 홀딩 편향, 트레일링 확폭+러너     │
│   · RANGE → 1·3·5m 축소 사이즈(경로 A 보조) or 관망       │
│   · CHAOS → 전면 관망                                    │
│   · (후행) 스태킹 메타러너가 blended_conf 대체 (P5)        │
├────────────────────────────────────────────────────────┤
│ L3. 소프트 게이트 + 리스크 예산  (기존 게이트 체인 대체)      │
│   · 직렬 AND 7겹 → 점수 합산 단일 게이트 (로직 보존)        │
│   · 하우스 머니 규칙: 손실 -1% 도달 시 축소 모드,           │
│     수익 +1.5% 확보 시 이후 리스크는 확보 수익 내에서만       │
│   · 일일 최소 기회 예산 (14:00까지 진입0 → 0.3배 강제 검토) │
│   · CB③v2 통계적 당일 정지 (§3) — 발동 시 즉시 청산        │
│   · 추세일 반자동 모드: 감지 알림 → 1클릭 승인 → 자동 관리   │
│   · 15:10 강제청산 등 절대 원칙 불변                       │
├────────────────────────────────────────────────────────┤
│ 사이징 (파라미터화 — 문답 3번 확정)                         │
│   ACCOUNT_EQUITY: config+대시보드에서 유동 설정 (5천만 시작) │
│   MAX_CONTRACTS: 10 → 3 하향 / 증거금 사용률 상한 % 신설    │
│   모든 사이징은 금액이 아닌 % 기반 → 계좌 증감 시 자동 스케일  │
└────────────────────────────────────────────────────────┘
```

# 5. 구현 계획 — 8주 압축안 (12주 → 1개월 단축)

단축 원리: ① 처방 P1~P3(라벨·피처·가중치)은 py310_64 **오프라인 재학습 경로만 건드리므로 운영 리스크 없이 1~3주차에 전진 배치**, ② L1/L3를 순차가 아닌 병행 트랙으로, ③ 쉐도우 A/B를 2주→장중 1주+로 압축하되 종료 조건을 기간이 아닌 표본 수(진입 판정 200건)로 대체.

```
W1     Phase 0 진단 + P1 착수
       [ ] 게이트별 차단 로그 30일 전수 집계 (겹별·결합 통과율 실측)
       [ ] 일별 레짐 사후 라벨링 30일 (TREND/RANGE별 기존 PnL 분리)
       [ ] conf_inversion 해소 확인 (Platt WINDOW=200 수렴 후 재측정)
       [ ] 트리플 배리어 라벨 생성기 구현 (ATR 연동 배리어)

W2~3   트랙 A: 학습 기반 정화 (P1+P2+P3 — 오프라인, 운영 무접촉)
       [ ] 신 라벨 + 롤링 윈도우 피처 + 중복 가중치로 병렬 재학습
       [ ] 신구 walk-forward 비교 (판정 기준: 손익비, PnL — acc 아님)
       [ ] 통과 시 운영 모델 교체 (기존 pkl 교체 절차·마커 파일 재사용)

W3~5   트랙 B: L1 데이 레짐 엔진 (P4)
       [ ] 통합 상태머신 + 히스테리시스 (EKS 273차 패턴 재사용)
       [ ] 사후 라벨 대비 TREND일 재현율 ≥70% 백테스트
       [ ] 대시보드 레짐 배지 + 추세일 반자동 승인 UI

W4~6   트랙 C: L3 소프트 게이트 + CB③v2 (트랙 B와 병행)
       [ ] 7겹 게이트 점수화 리팩토링 (로직 보존, 출력만 변경)
       [ ] 하우스 머니 리스크 상태기계 + 일일 최소 기회 예산
       [ ] CB③v2: 이항검정·PnL z-score·CUSUM·conf_inversion 합산 구현
       [ ] 사이징 파라미터화 (ACCOUNT_EQUITY 유동 설정, MAX_CONTRACTS=3)

W6~7   L2 레짐 조건부 프로파일 + 청산 재설계
       [ ] 레짐별 호라이즌·임계값 프로파일 (config 분리)
       [ ] TREND일 청산: ATR 트레일링 확폭 + 부분청산 후 러너 유지
       [ ] 스태킹 메타러너 파일럿 (P5 — 오프라인만, 운영 투입은 검증 후)

W7~8   통합 쉐도우 A/B + 안정화
       [ ] 구게이트 vs 신게이트 장중 쉐도우 병행 (종료: 진입 판정 200건)
       [ ] 크래시·레이스·블로킹 회귀 점검 (281차 자산 보존 확인)
       [ ] v9 전환 스위치 (문제 시 v8 롤백 가능 구조)

W9~    모의 검증 6주 (개발과 별개의 달력 시간 — 압축 불가)
       [ ] 레짐 2종 이상 포함 확인, 수정 검증 기준(§6) 심사
       [ ] 통과 시 실전 30% 사이즈 개시
```

> **정직한 주의**: 8주로 압축되는 것은 **개발**이다. 모의 6주 검증은 시장이 레짐을 보여줘야 하는 달력 시간이라 압축할 수 없으며, 이를 줄이는 것은 검증을 안 하는 것과 같다. 총 소요는 개발 8주 + 검증 6주(일부 W7~8과 겹침 가능) ≈ **12~14주**로 보는 것이 정확하다.
