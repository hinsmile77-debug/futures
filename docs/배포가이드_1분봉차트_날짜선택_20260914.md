### B — 레이어 배지

「미측정」과 「0건」은 다르다. `_gp_status_text` 가 GP 한 층에 하던 구분을 5개 층으로 넓혔다.

| 문구 | 뜻 |
|---|---|
| `n건` / `384+27` | 측정값 (뒤 숫자는 마감구간) |
| `0건` | 원천이 돌았고 그날 실제로 0 (무포지션일) |
| `0건?` | 0 은 맞지만 가동 여부를 못 읽어 사유 미확정 |
| `미수집` | 그날 그 원천이 없었다 — **0건이 아니다** |
| `보관밖` | 레짐 EOD purge(30일) 이전 — 설계상 없다 |
| `기록없음` / `원천없음` / `미배선` / `미조회` | 테이블 빈값 / DB 못 읽음 / GP 미등록 / 조회 전 |

- 커버리지는 **날짜 집합**으로 읽는다(경계 min/max 로는 구간 안의 구멍을 못 잡는다).
- 거래·GP 가 0행일 때는 `direction`(ensemble_decisions)을 **증인**으로 써
  무포지션일과 미수집을 가른다. 증인을 못 읽으면 `0건?`.
- 배지에 마우스를 올리면 전체 판정표가 툴팁으로 뜬다.

### C — 마감구간

### 2-2. ⚠ 동시 세션 주의

배포 작업 중 **다른 Claude 세션이 같은 저장소에 동시에 커밋**하고 있었다.
`git add` 와 `git commit` 사이에 남의 파일이 인덱스에 들어와 **16개 파일이 섞인
커밋이 한 번 만들어졌다**(즉시 `reset --soft` 후 `commit --only -- <경로>` 로 복구).

교훈: 이 저장소에서는 **`git commit` 에 반드시 경로를 명시한다.**
인덱스 전체를 믿지 않는다.
또한 이 VM 의 git 은 `core.autocrlf=false` 라 **모든 명령에
`-c core.autocrlf=input` 을 붙여야 한다** — 안 붙이면 641 파일이 개행만으로
전부 변경으로 잡힌다.

## 6. 검증 방식에 대한 기록

이 변경은 **오프스크린 PyQt5 렌더**(`QT_QPA_PLATFORM=offscreen`)로 실제 위젯을 띄워
검증했다. 그 과정에서 **속성 검사로는 안 잡히는 결함 3건**이 나왔다.

1. `QDateEdit::drop-down` 을 스타일시트로 덮자 화살표가 사라졌다 —
   `calendarPopup()` 은 `True`, `calendarWidget()` 도 정상. **API 는 멀쩡하고 픽셀만 비었다.**
2. `gp_rule_challenger_ids` 는 dict 인데 인덱스로 읽어 GP 층이 통째로 죽었다.
   같은 파일 안 `_load_gp_trades` 가 올바른 접근을 하고 있었다.
3. 무포지션일을 「미수집」으로 오판 — 날짜 집합만으로는 "왜 없는지"를 못 가른다.

**상호작용 요소는 열어서 찍어야 한다.** 속성만 보면 통과한다.
