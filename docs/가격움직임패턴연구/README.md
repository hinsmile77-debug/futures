2026-10-21 MW0601에서 시작했다. **MW0601(`v9-dev`)과 MW0602(`dev`)가 같은 연구를 진행하고 결과를 양방향으로 공유한다**(사용자 지시 2026-10-21).

> 2026-08-23 결정으로 두 PC 사이의 상호 조율 의무는 폐기됐다(CLAUDE.md 「멀티PC 작업 컨벤션」).
> **이 폴더만은 사용자 지시에 따른 예외로 양방향 공유한다.** 범위는 이 폴더와 아래 「공유 코드」뿐이다.

## 공유 규약

1. **데이터 산출물은 PC별 하위 폴더에만 쓴다** — `표본실측/MW0601/`, `표본실측/MW0602/`.
   스크립트가 `utils.db_utils.pc_id()`로 폴더를 고르므로 그냥 실행하면 된다. 남의 PC 폴더는 고치지 않는다.
2. **새 문서 파일명에는 PC명과 날짜를 붙인다** — `..._MW0602-YYYYMMDD.md`. 같은 이름을 두 PC가 따로 만들지 않게 하기 위해서다.
3. **공용 문서를 고칠 때는 고친 절에 PC명과 날짜를 적는다** — 예: `**[2026-10-22 MW0602]** …`.
   정정은 덮어쓰지 말고 정정 표기로 남긴다(사료 보존 원칙).
4. **수치를 인용할 때는 어느 PC의 DB인지 밝힌다.** 두 PC는 계좌와 DB가 다르다.
   - **같아야 하는 것**: `regular_candles`(서버 정규 연결선물 10100). 다르면 수집 결함이다 — 좋은 교차 검증 대상이다.
   - **달라도 되는 것**: `raw_candles` 결손·복구봉, `ensemble_decisions`, 수급 수집 시작일, 미륵이 판단 기록.
5. **이 폴더를 바꾸는 커밋은 이 폴더만 바꾸고, 제목에 `[가격패턴]`을 넣는다.**
   예: `[MW0602] 7xx차 [가격패턴]: 1단계 라벨러 v0 빈도표`. 상대 브랜치에서 `git log origin/dev --grep 가격패턴`으로 찾아 그대로 체리픽할 수 있게 하기 위해서다.
   다른 변경과 섞인 커밋은 체리픽할 때 남의 코드를 끌고 간다.
6. **상대 PC의 결과를 가져오는 방법** — 위 5번 커밋을 체리픽한다.
   - MW0601: `git fetch && git log origin/dev --grep 가격패턴 --oneline` → `git cherry-pick <sha>`
   - MW0602: `git fetch && git log origin/v9-dev --grep 가격패턴 --oneline` → `git cherry-pick <sha>`
   - 공용 문서가 충돌하면 **양쪽 절을 모두 살린다**(한쪽을 버리지 않는다).
