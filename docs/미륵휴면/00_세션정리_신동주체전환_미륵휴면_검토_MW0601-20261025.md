## 4. 수량 — 711차 규칙과 전환 (논의 ③)

```
수량 = max(1, min(계획 수량, 위험 수량, 진입 직전 주문가능수량))
  계획 수량 = min(최대허용수량, 장시작 주문가능수량)   (미측정이면 min(최대허용, SHINDONG_LIVE_QTY=3))
  위험 수량 = floor(위험자본 × 1.5% ÷ ((손절거리 + 1pt) × 5만원)) = floor(9 ÷ (d+1))   (위험자본 3,000만)
```

| 손절거리 d | 수량 |
|---|---|
| ≤ 2.0pt | 3(상한) |
| 2.0–3.5pt | 2 |
| > 3.5pt | 1 |

**미륵 off 영향 없음(코드 확인)** — 손절가는 신동 재생, 위험자본은 시가 예탁금(미측정이면 정책값 3,000만 — `config/capital.py:risk_capital`, 수량이 커지는 쪽으로 틀어지지 않음), 주문가능수량은 30초 스케줄러·진입 직전 `_capital_monitor_refresh`(CpTd6722).

의견:
1. 711차(10-26)와 엔진 전환(11-02)을 **다른 날**에 두는 것이 맞다 — 10-26–10-30 은 「수량만 바뀐 상태」라 원인이 갈린다.
2. Sindong-V4 의 「전환 첫날 1계약」은 **따르지 않는다** — 711차가 이미 꼬리를 막고(21일 재생 최악 단일 거래 −108 → −54만), 1계약 고정은 2레그 규격을 「1차 목표 전량 익절」로 바꿔 변수만 늘린다.
3. ⚠ 711차 「10거래일 뒤 X 1.5% → 2.0% 승격 판정」 창(10-26–11-06 전후)이 전환일을 가로지른다 → 창은 끊지 않되 판정 때 **11-02 전/후를 나눠** 적는다.
4. ⚠ 손절이 넓은 R2 는 대개 1계약 → 「1차 목표 전량 익절」로 집행(`_shindong_apply` `qty_all >= 2`). 711차 의도대로이며, 장후 재생 대조에서 차이로 오판하지 않게 대조 기준에 넣는다.
5. 피터 선택 시 수량은 `PETER2_QTY`(711차 대상 아님).
