
**결론**: 지금 필요한 것은 게이트를 하나 더 쌓는 것이 아니라,
① 문제 정의 전환("방향 맞히기" → "이 진입이 수수료 차감 후 돈이 되는가"),
② 15겹 보정 레이어의 기여도 검증(ablation),
③ 집행 비용 절감이다. 월 5%는 연 80% 복리 — 현재의 방향 엣지 0 상태에서
파라미터 튜닝으로는 도달할 수 없고, **유일한 실측 엣지(1m 마이크로구조)에 집중 +
비대칭 청산 + 집행 개선**이 가장 현실적인 경로다.

## 1. 데이터 축적·채용 모델의 적정성 — "더 나은 모델이 있는가"

### 1-1. 현황 진단

| 구성 | 현재 | 평가 |
|---|---|---|
| 배치 모델 | sklearn `GradientBoostingClassifier` × 6 호라이즌 | 구식·저속. 동일 sklearn 1.0.2에 `HistGradientBoostingClassifier` 존재 (batch_retrainer에 이미 import됨) |
| 온라인 모델 | SGD (호라이즌별 독립, 1m/15m/30m 블렌딩 OFF) | 288차 개편은 정직하고 우수 — 유지 |
| 레이블 | 3클래스 (UP/FLAT/DN), rolling σ×k 임계 | **가장 큰 구조적 약점** — 아래 참조 |
| 데이터 | raw_data.db 73,421행 / 43주 / 26주 슬라이딩 학습 | 최소선 확보. 레짐 혼합 문제 잔존 |
| 재학습 | 30분 장중(py310_64 서브프로세스) + EOD | 환경 분리 결정(226차)은 올바름 |

### 1-2. 근본 문제: 레이블이 손익과 무관하다

현재 레이블은 "N분 후 수익률이 ±threshold를 넘는가"다. 그러나 실제 손익은
**진입 후 경로**가 결정한다 — 5분 뒤 +0.15%로 끝나도 중간에 -1.5×ATR을 찍으면
하드스톱으로 손절이고, 반대로 3분 만에 TP1을 치면 5분 뒤 하락해도 이익이다.
즉 모델이 배우는 것과 시스템이 버는 것이 다른 함수다.
conf 0.7+에서 정확도가 역전되는 기현상도 이 괴리의 증상일 가능성이 높다.

### 1-3. 권고 — 우선순위 순

**① [P1·최우선] Triple-Barrier 레이블 전환**
- 레이블 = 진입 가정 후 {TP 배리어 / SL 배리어 / 시간 배리어} 중 무엇이 먼저 닿는가.
- 배리어를 실제 청산 규칙(`ATR_STOP_MULT=1.5`, `ATR_HORIZON_TP1_MULT`)과 **동일하게** 설정
  → 모델이 예측하는 것 = 시스템이 실행하는 것.
- 작업: `model/target_builder.py`에 triple-barrier 빌더 추가, `batch_retrainer.py`에
  병행 학습 경로(섀도우) 신설. 기존 3클래스와 2~4주 병행 후 예측-손익 상관으로 판정.

**② [P1] Meta-Labeling 2단 구조 승격**
- 이미 `learning/meta_labeling.py`, `strategy/entry/meta_gate.py`가 존재하고
  rollout 리포트가 "meta labels 65,183건 준비 완료"라고 말한다 — **자산이 놀고 있다.**
- 구조: 1차(방향) = 기존 앙상블 유지 / 2차(진입 여부) = "이 신호로 진입 시
  수수료 차감 후 수익 확률"을 학습하는 이진 분류기.
- 9항목 체크리스트가 하던 역할을 데이터가 대체하고, 체크리스트는 하드 리스크
  veto(시간·손실한도·독성)만 남긴다.

**③ [P2] GBM → HistGradientBoosting 전환**
- sklearn 1.0.2에서 지원, 학습 5~10배 빠름, 결측 native 처리, 성능 동급 이상.
- py310_64 학습 → py37_32(sklearn 1.0.2 동일 버전) 로드이므로 pickle 호환 유지.
- LightGBM/XGBoost는 32-bit 런타임 wheel이 없어 **채택 불가** — ONNX 우회는
  onnxruntime 32-bit 제약까지 겹쳐 과공학. 보류가 옳다.

**④ [P2] 분류 → 분위 회귀(Quantile Regression) 보조 채널**
- `GradientBoostingRegressor(loss="quantile")`로 N분 후 수익률의 q10/q50/q90 직접 추정.
- 기대: (q50의 부호)=방향, (q90-q10)=불확실성 → 사이징·TP 거리 산정과 직결.
  "확률 60%"보다 "기대 +0.08pt, 하방 -0.21pt"가 트레이더의 언어다.

**⑤ [P3] SGD 대안 검토 — 급하지 않음**
- 3m/5m/10m 한정 유지가 옳다. 개선하려면 SGD보다 **온라인 Bayesian logistic**
  (Laplace 근사, numpy만으로 구현 가능)이 불확실성 추정까지 제공해 우월.
  또는 레짐×호라이즌 Beta-Binomial 승률 추적(해석 가능, 파라미터 2개)이
  선형모델보다 강건하다. 단, ①·② 완료 전에는 착수 금지 — 레이블이 바뀌면 다시 해야 한다.

**⑥ [P2] 데이터 축적 개선**
- 체결 틱 원본(가격·수량·방향) 보존을 시작하라. 현재 분봉 집계 후 버리는 정보
  (틱 도착 강도, 대량 체결 클러스터)가 1m 엣지의 원천인데 복원 불가능하다.
- 학습 창에 레짐 태그(이미 `strategy/regime_fingerprint.py` 존재)를 붙여
  "유사 레짐 가중 학습"으로 26주 레짐 혼합 문제를 완화.

## 2. 진입 흐름 — "최적 조건·최적 타이밍인가"

### 2-1. 잘된 것
- FLAT 즉시 X등급, conf floor의 EV 근거(실거래 5일 분석), 시간대×호라이즌 2D min_conf,
  cold-start 2단계, MR 약한탈진 사이즈 축소(273차) — 모두 실측 기반 의사결정.

### 2-2. 문제점

**① 타이밍: 구조적 1분 지연.** 신호는 항상 봉 마감 후 계산되고(STEP 4~7) 시장가로
나간다. 1m 스캘핑 TP1이 ATR×0.3(≈1pt 내외)인데, 신호 발생~체결 사이에 가격이
이미 이동한다. **엣지의 상당 부분이 집행에서 증발하는 구조.**

**② 비용: 전 주문 시장가.** 미니선물 스프레드 1틱(0.02pt) + 슬리피지 왕복이면
TP1 거리의 4~10%를 매 거래 상납한다. 승률 52~55% 게임에서 이 비용은 치명적.

**③ 게이트 과잉.** conf floor → MC table → CoherenceGate → CascadeCoherence →
TrendGate 예외 → HCGuard → Hurst → ATR 범위 → 시가이격 → toxicity → Degraded …
진입 차단 장치가 10겹 이상이다. 각각은 사고의 사후 대응으로 정당하나,
**총합의 한계 기여를 아무도 모른다.** 기회 자체가 희소해져 학습 표본 축적도 저해
(30m 하루 13건 문제의 원인 일부).

**④ 체크리스트의 경직성.** 9항목 등가 카운트는 항목 간 중요도·상관을 무시한다.
"외인 콜 순매수"와 "직전 봉 방향"이 같은 1표라는 건 데이터가 동의하지 않을 것이다.

### 2-3. 권고

| 순위 | 작업 | 내용 | 대상 |
|---|---|---|---|
| P1 | **지정가 우선 집행** | 진입: microprice 기준 유리한 쪽 1틱 지정가 → N초(예: 10~15초) 미체결 시 취소 또는 시장가 전환. `features/technical/microprice.py` 재활용 | `main.py` 주문부, broker 서비스 |

## 3. 청산 흐름 — "최적 조건·최적 타이밍인가"

### 3-1. 잘된 것
- P1~P6 우선순위 체계 명확, 15:10 강제청산 절대원칙, 틱 단위 하드스톱(289차),
  호라이즌별 TP1 단축(스캘퍼 배수), 부분청산 → 트레일링 구조 자체는 표준적.

### 3-2. 문제점

**① 청산이 순수 가격 기반 — 예측 시스템인데 예측을 안 쓴다.** 보유 중 앙상블이
반대 방향 고신뢰로 전환돼도 청산 트리거가 없다. 손절가까지 풀로 얻어맞는 구조.

**② TP/SL 배수의 근거 부재.** ATR×1.5 스톱, ×0.3~0.7 TP1은 설계값이지 실측값이
아니다. trades.db에 전 체결 이력이 있는데 **MAE/MFE 분석이 한 번도 반영된 흔적이 없다.**
승리 거래가 최대 몇 pt까지 갔다가 얼마에 청산됐는지(이익 조기 실현),
패배 거래가 스톱 전에 얼마나 회복 기회를 줬는지(스톱 과소/과대)를 모르는 상태.

**③ TP1 33% 부분청산의 EV 검증 없음.** 부분청산은 승률·심리를 사고 기대값을 파는
거래다. 손익비가 낮은 1분봉 스캘핑에서 "TP1에서 1/3 익절"이 총 EV를 깎고 있을
가능성이 상당하다.

**④ 트레일링 업데이트 순서.** `check_and_exit`에서 P5 트레일링 갱신이 P2~P4 이후에만
실행 — TP 체크가 발동한 분에는 트레일 갱신이 누락된다(경미하나 무료 수정).

### 3-3. 권고

| 순위 | 작업 | 내용 |
|---|---|---|
| P1 | **MAE/MFE 기반 배리어 재산정** | trades.db 전 체결의 MAE/MFE 분포 → 스톱은 패배 MAE 분포의 굴절점, TP는 승리 MFE 중앙값 근처로. 분기 1회 정기화. 스크립트 1본이면 됨 (`scripts/analyze_mae_mfe.py` 신설) |

## 4. 챔피언/챌린저 운영

### 4-1. 잘된 것
- **자동 승격 금지** 원칙과 그 준수. 레짐 전문가 트랙("20 거래일"이 아닌 "레짐 내
  20거래" 기준)은 세련된 설계. variants 5종 + shadow 평가 인프라.

### 4-2. 문제점 — 통계적 검정력 부족

**① min_trades=30으로 승률 +2%p 판정은 수학적으로 불가능.** 승률 55% 전략의
30거래 표본오차는 ±18%p. 승률 델타 +2%p 기준은 이 노이즈 안에서 동전 던지기다.
현재 기준은 "우연히 잘 나온 챌린저"를 승격시키는 장치가 될 수 있다.

**② Sharpe ≥ 1.5를 20거래일로 추정하는 것도 동일 문제.** 연환산 Sharpe의 표준오차는
√(1/T) 수준 — 20일이면 ±1.0을 넘는다.

**③ 챔피언 강등 기준 부재.** 승격 심사만 있고, 현 챔피언의 성능 붕괴를 감지해
사이즈를 줄이는 체계적 경로가 없다 (CB는 당일 이상만 잡는다).

**④ 다중 비교 문제.** 챌린저를 5종+ 동시 운용하면 그중 하나는 우연히 기준을
통과한다. 보정 없는 다중 후보 비교는 과적합 선택 장치다.

### 4-3. 권고

| 순위 | 작업 | 내용 |
|---|---|---|
| P2 | **부트스트랩 승격 판정** | 승률/샤프 점추정 대신: 챌린저-챔피언 거래별 PnL 차이를 5,000회 리샘플 → "챌린저 우위 확률 ≥ 95%"를 승격 조건으로. `promotion_manager.py`에 함수 1개 추가 |
| P2 | min_trades 30 → 100 (전역), 레짐 트랙은 50 | 표본오차를 ±10%p 이내로 |
| P2 | **챔피언 heartbeat** | 챔피언 최근 60거래 롤링 승률 CI 하한이 기준선 미달 → 자동 사이즈 50% + Slack 알림 (강등은 여전히 수동) |
| P3 | 다중 비교 보정 | 동시 챌린저 수 n에 대해 승격 유의수준을 α/n (Bonferroni)로 — 설정 상수 1개 |
| P3 | 챌린저 가상체결에 슬리피지 반영 | shadow 체결가에 스프레드 1틱 + 보수적 슬리피지 부과 — 승격 후 실계좌 성능 하락(승자의 저주) 방지 |

## 5. 대시보드 — "3초 내 시장 파악"

### 5-1. 진단

`main_dashboard.py` 11,621줄, mid_tabs **15개+ 탭**. 정보의 총량은 훌륭하나
구조가 "분석가용 드릴다운"이지 "트레이더용 상황판"이 아니다.
현재 구조에서 3초 파악은 불가능하다 — 핵심 정보가 탭 클릭 뒤에 숨어 있다.

**3초 테스트** — 다음 4개 질문이 마우스 클릭 0회, 시선 이동 1회로 답해지는가:
1. 지금 포지션이 있는가? 얼마나 물려/벌고 있는가?
2. 오늘 얼마 벌었나/잃었나?
3. 시스템은 정상인가? (CB·헬스·데이터 지연)
4. 모델은 지금 어느 쪽을 보고 있고 진입이 임박했는가?

### 5-2. 권고: 상단 고정 상태 스트립 (탭 무관 상시 노출)

```
┌────────────────────────────────────────────────────────────────────────┐
│ ▲LONG 2계약 +1.24pt(+310K)   │ 당일 +0.8% (+1,240K)  │ ● CB정상 ● 헬스OK │
│ 스톱 1289.4 · TP1 1293.2      │ 승 4 / 패 2           │ 데이터 지연 0.8s   │
├────────────────────────────────────────────────────────────────────────┤
│ 모델: ▼DOWN conf 61% [████████──] B등급 │ 차단: CoherenceGate(2/4)      │
│ 레짐: NEUTRAL · Hurst 0.52 · ATR 2.1pt  │ 다음 액션: 진입 대기          │
└────────────────────────────────────────────────────────────────────────┘
```

구현 원칙:
- **숫자 위계**: 미실현 PnL·당일 PnL 두 개만 대형(2배) 타이포. 나머지는 보조.
- **신호등 3개 고정**: CB / 헬스 / 데이터 신선도 — 색+아이콘 병행(색각 대응).
- **차단 사유 1줄**: 진입이 안 나가는 이유(어느 게이트가 막았나)를 항상 표시.
  현재는 로그를 뒤져야 안다 — 운용자 신뢰도에 직결되는 항목.
- **conf는 숫자보다 게이지**: min_conf 임계선이 그려진 수평 바. "61%"보다
  "임계선을 넘었는가"가 트레이더의 질문이다.
- 색 의미론 통일: 상승/이익=적색, 하락/손실=청색(국내 관례)으로 전 패널 일관.

### 5-3. 탭 재편 (15개 → 4그룹)

| 그룹 | 통합 대상 |
|---|---|
| **운용** (기본) | 진입 관리 + 청산 관리 + 포지션 + 손익 추이 |

## 7. 기타 종합 지적 — 아낌없이

### 7-1. [P0·안전원칙 위반] CB②가 사실상 꺼져 있다

`config/settings.py:581` — `CB_CONSEC_STOP_LIMIT = 9999`.
CLAUDE.md 절대 원칙 "② 5분 내 손절 3연속 → 당일 정지"가 **현재 비활성 상태**다.
주석은 "3→2 강화"라고 적혀 있어 이력과 값이 모순된다(테스트용 임시값 잔재로 추정).
**즉시 양자택일**: 값을 2~3으로 복원하거나, 비활성이 의도라면 CLAUDE.md 원칙을
개정하고 사유를 문서화하라. 원칙 문서와 코드가 다른 상태가 가장 위험하다.

### 7-2. [P0] 평가 지표를 "방향 적중률"에서 "거래당 순기대값"으로

모든 자기평가(CB③, F1 가중, HCGuard, 대시보드)가 방향 적중률 기반이다.
그러나 시스템의 목적함수는 **수수료·슬리피지 차감 후 pt/거래**다.
- 매일 EOD에 "등급별·게이트별·호라이즌별 순기대값(EV) 테이블" 자동 생성
  (`strategy/ops/daily_exporter.py` 확장).
- 대시보드 상태 스트립에 "최근 20거래 평균 EV" 상시 노출.
- 적중률 55%여도 EV 음수인 셋업, 적중률 45%여도 EV 양수인 셋업이 반드시 존재한다
  — 그걸 아는 것이 5% 트레이더와 그렇지 않은 트레이더의 차이다.

### 7-3. [P1] 앙상블 보정 레이어 15겹 — ablation 없이는 유지보수 불능

`ensemble_decision.py`의 신호 경로: Decorrelator → F1 가중 → 30m 필터 → 시간대
정책 → EarlyDirDamp → CLOSE_VOLATILE 감쇠 → ConstOut → TrendBoost → FlatCap →
AdaptiveGater → StuckBreaker → ShortHorizonOverride → 합의도 패널티 →
CoherenceGate → CascadeCoherence → Platt → HCGuard.
각각은 실제 사고의 정당한 대응이지만, **상호작용을 아무도 검증한 적 없고**
(TrendBoost가 올린 점수를 StuckBreaker가 깎고 CoherenceGate가 면제하는 식),
새 레이어 추가 비용이 기하급수로 커지고 있다.
- 권고: 레이어별 ON/OFF 플래그화 → 주 1회 shadow에서 leave-one-out 실행 →
  기여 없는(또는 음의 기여) 레이어 분기별 퇴역. **이것이 triple-barrier 전환 다음으로
  수익 개선 기대값이 큰 작업이다** — 복잡도는 그 자체로 리스크다.

### 7-4. [P1] 백테스트-실거래 정합 리포트 부재

Walk-Forward 26주(Phase 2 미완) 이전에라도, 동일 신호에 대한
"백테스트 체결가 vs 실제 체결가 vs shadow 체결가" 3자 대사를 자동화하라.
집행 비용의 실측 없이는 2절(집행 개선)의 효과도 측정할 수 없다.

### 7-5. [P2] 사이징 이중·삼중 곱셈 체인 점검

grade size_mult × REGIME_SIZE_MULT × Kelly × vol targeting × Degraded 0.6 ×
PRE_RETRAIN 0.6 × MR weak 0.5 × HALT half … 배수가 8개 이상 곱해진다.
극단 조합에서 0.1× 이하로 수렴해 "진입은 했는데 의미 없는 사이즈"가 될 수 있고,
반대로 상한 검증이 없다. **최종 수량 결정 직전에 배수 체인 전체를 로그 한 줄로
남기고, 하한(예: 곱 0.2 미만이면 진입 포기)과 상한을 명시하라.**

### 7-6. [P2] 30m 호라이즌의 존재 이유 재심사

30m은 filter_only인데 그 필터마저 비활성(2026-06-25, CV acc 0.28)이다.
현재 30m은 학습·검증 비용만 쓰고 의사결정 기여가 0에 가깝다.
need_add 피처(opt_gex_bn 등) 탑재 후 acc 회복 실패 시 퇴역을 검토하라.
호라이즌 6개는 목표가 아니라 수단이다.

### 7-7. [P3] 알파 리서치 봇 연결

Phase 6(유전자 진화)이 코드 완성 후 장외 스케줄 미연결 상태다.
챌린저 통계 기준(4절) 강화가 선행돼야 안전하게 연결할 수 있다 — 순서 유지 권고.

### 7-8. 칭찬 — 유지해야 할 문화

사고 → 원인 분석 → 커밋 메시지에 차수 기록(289차) → 설정 주석에 근거 명시.
이 문서화 문화가 이 시스템의 최대 자산이다. 위 개선안들도 같은 방식으로:
**한 번에 하나, 근거 수치와 함께, 되돌릴 수 있게.**
