## 1. 한 줄 요약

`origin/dev` `strategy/position/position_tracker.py:1368`

```python
"tp1_reached": 1 if self.partial_1_done else 0,
```

`partial_1_done`은 **청산 사유를 보지 않고** 누적 청산수량 ≥ TP1 목표수량이면 선다(`:1303`
`_sync_partial_progress()`). 그래서 **2계약 이상 하드스톱이 거래소에서 1+1(또는 1→2→1)로
분할 체결되면** 첫 체결이 플래그를 세우고, 최종 레그가 `tp1_reached=1`로 기록된다.
**진짜 최초 손절이 「TP1 보호 트레일(이익 청산)」로 둔갑한다.**

## 4. 먼저 잴 것 — 반영 판단 근거 (읽기 전용, 장 마감 후)

CLAUDE.md 「장중 라이브 DB 분석 금지」에 따라 **15:35 이후** 실행할 것.

```python
from utils.analysis_db import guard_intraday, connect_ro
guard_intraday("f10_dev_measure")
con = connect_ro("data/db/trades.db")

# tp1_reached=1 인 손절 계열 최종 레그 중, 같은 포지션(entry_ts)에 TP 레그가 하나도 없는 것
# = F-10 오분류 후보. (TP 레그 없이 tp1_reached=1 이 되는 정상 경로는 1계약 TP1 보호전환뿐이므로
#   qty1 포지션은 별도로 본다.)
SQL = """
SELECT t.entry_ts, t.exit_ts, t.exit_reason, t.quantity, t.entry_qty, t.pnl_krw, t.exit_trigger
FROM trades t
WHERE t.tp1_reached = 1
  AND (t.exit_reason LIKE '%스톱%' OR t.exit_reason LIKE '%손절%')
  AND NOT EXISTS (
      SELECT 1 FROM trades u
      WHERE u.entry_ts = t.entry_ts AND u.exit_reason LIKE '%TP%')
  AND COALESCE(t.entry_qty, 0) >= 2
ORDER BY t.exit_ts
"""
rows = con.execute(SQL).fetchall()
print(len(rows), "건", sum(r[5] or 0 for r in rows), "원")
for r in rows: print(r)
```

판독:
- 0건이면 → dev에서는 아직 발현하지 않았다. 반영은 예방 목적이며 급하지 않다.
- 1건 이상이면 → 그 `entry_ts`의 TRADE 로그에서 `[Position] 체결부분청산 … 하드스톱` 줄이
  최종 레그 앞에 있는지로 확정한다(v9-dev 10-21 판정과 같은 방법).
- `tp1_reached`는 **2026-08-13 이후 행에만** 있다. 그 이전 NULL은 「미측정」이다.

## 5. 반영한다면 — 범위 (v9-dev `7a4f6387` 기준, 매매 경로 무변경)

🔴 **핵심 설계: `partial_1_done`은 건드리지 않는다.** 그 플래그는 TP1 재발동 가드
(`is_tp1_hit`)이자 TP2/3 진행률이라 **매매 경로**다. 507차 원계획(「partial_1_done을 TP 사유일
때만 세우고 재발동 가드를 분리」)은 매매 동작을 바꾸므로 버렸다. 대신 **라벨 전용 축을 새로 만든다.**

### 5-1. `strategy/position/position_tracker.py`

1. `__init__` — `self.tp1_protect_armed: Optional[bool] = False`
2. **리셋 5곳**(`self.partial_3_done = False`가 있는 곳 전부: dev `:238·350·530·714·1400`) 바로 아래에
   `self.tp1_protect_armed = False`
3. 1계약 TP1 보호전환 2곳(`self.partial_1_done = True`, dev `:843·896`) 아래에 `self.tp1_protect_armed = True`
4. `_sync_partial_progress(self, reason=None)` — `partial_*_done` 계산은 **그대로** 두고 뒤에 추가:
   ```python
   _was_p1 = bool(self.partial_1_done)   # ← 계산 전에 잡을 것
   ...기존 3줄...
   if self.tp1_protect_armed is True:
       return
   if reason 이 TP1/TP2/TP3 계열:            # 'TP1' in reason 등
       self.tp1_protect_armed = True; return
   if not (self.partial_1_done and not _was_p1):   # 이번 호출에서 새로 선 경우만
       return
   if reason is None:                          # 브로커 동기화 등 사유 미상
       if self.tp1_protect_armed is False: self.tp1_protect_armed = None   # WARN 로그
   elif reason 이 스톱·손절1차·시간청산 계열:
       pass                                     # INFO 로그 "[ExitStage] F-10 … TP1 보호 미승격"
   else:                                        # 수동·복구 등 — 종전 라벨과 동일하게
       self.tp1_protect_armed = True
   ```
   v9-dev는 사유 판정에 `classify_exit_stage()`를 썼지만 **dev에는 그 함수가 없다.** dev의
   `utils/db_utils.py:classify_exit()` 트리거 축을 쓰거나 문자열 조각
   (`하드스톱`/`스톱`/`손절`/`강제청산`/`시간마감`/`안전망`)으로 직접 판정하면 된다.
5. 호출부에 사유 전달: `apply_exit_fill()` 비최종 분기(dev `:656`)와 `partial_close()`(dev `:787`)만
   `self._sync_partial_progress(reason)`. **복원·브로커동기화 호출은 인자 없이 둔다.**
6. 결과 dict(dev `:1368`):
   ```python
   "tp1_reached": (None if self.tp1_protect_armed is None
                   else (1 if self.tp1_protect_armed else 0)),
   ```
   dev `main.py:4368`이 이미 `None`이면 NULL로 기록하고, `classify_exit()`이 `None`을
   **`하드스톱?`(미상)** 으로 표시한다 — **추가 수정 불필요**(계측 4원칙 ②가 이미 dev에 배선돼 있다).
7. 로그 태그(dev `:639`) — `result.get("tp1_reached")`를 읽으므로 6번으로 자동 정정된다.
   None 일 때 `[TP1미도달]`로 찍히는 것만 `[TP1?]` 등으로 구분할지 결정.
8. 상태 저장(dev `:1578` 근처)에 `"tp1_protect_armed"` 키 추가. 복원(dev `:1679` 근처):
   키가 있으면 그 값, 없으면 `partial_1_done=False → False` / `True → None`(+ WARN).
