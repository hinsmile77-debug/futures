## 3. 구현

### 3-1. `scripts/monthly_cleanup.py` — 단계 재구성

```

     · 검증 실패·크기 다른 동명 파일 → 원본·압축본 모두 보존 + 경고
     · 이전 실행이 "추가 후 삭제 전" 중단된 잔재(같은 크기) → 원본만 삭제 (멱등)
[1b] 원본 190일 컷 (기존 [1] 수정)
     · **Tier B 채널 원본은 구조적으로 제외** — 압축이 실패한 파일을 삭제 단계가
       먼저 집어삼키면 영구 소실이기 때문. 제외 사유별 개수 전부 인쇄(4원칙 ③)
[1c] 월 zip 중 말일이 190일 이전인 것 삭제 (신설) — 달의 일부라도 보관 창에
     걸치면 남긴다(보수적). HOGA 면제.
[2]~[4] shap.db / predictions.db / 백업 — 476차 그대로 (DB 프룬 기본 비활성)
```

`original_delete_target` · `archive_delete_candidates` · `compress_into_archives`)
+ `main()` 구조로 재구성 — 모듈 적재만으로는 아무것도 실행되지 않는다.

### 3-2. 발화 지점 — `scripts/campaign_steps.py` (EOD 체인 공용 모듈) 한 곳

- `monthly_cleanup_due()`: 마커 `data/monthly_cleanup_last_run.txt`(gitignore,
  PC별 로컬)의 YYYYMM이 이번 달보다 과거면 due.
- due면 주간 스텝 목록 **마지막**에 `("월간 로그 정리", monthly_cleanup.py --apply)`

  FAIL·rc=2(장중차단)면 다음 금요일 자동 재시도.
- 캠페인 스텝은 주 1회(금요일 EOD)라 실제 주기는 **매월 첫 캠페인 실행일**이다.

  `run_campaign_steps()`를 부르므로 **이 한 곳 배선으로 두 경로가 모두 덮인다.**
