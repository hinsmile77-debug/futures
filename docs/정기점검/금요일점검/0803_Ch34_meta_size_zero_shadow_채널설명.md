## 1. 무엇을 묻는 채널인가

> **모델이 "베팅하지 마라"고 한 신호로 진입한 건은 실제로 손해였는가?**

MetaGate의 사이즈 경로는 `learning/meta_confidence.py:_make_result()`가 정한다.

```python
if   conf >= 0.7: size_mult = 1.0 + (conf - 0.7) * 2.5     # 1.0 ~ 1.5
elif conf >= 0.5: size_mult = 0.5 + (conf - 0.5) * 2.5     # 0.5 ~ 1.0
else:             size_mult = 0.0                          # ← 불연속 절벽
```

그런데 **액션 밴드가 그 0.0을 덮는다** (`strategy/entry/meta_gate.py`):

```python
take:   size_mult = max(0.9,  min(1.25, learned["size_multiplier"]))          # 0.0 → 0.9
reduce: size_mult = max(0.35, min(0.75, learned["size_multiplier"] or 0.5))   # 0.0 → 0.5
skip:   size_mult = 0.0
```

`[34]`는 **`meta_size_raw == 0` 이면서 `meta_action != 'skip'`인 결정**, 즉
**모델은 "사이즈 주지 마라"고 했는데 액션은 진입을 허용한** 신호만 모아 손익을 잰다.

### 이웃 채널과 반드시 구분할 것

| 채널 | 묻는 것 | 모집단 |
|---|---|---|
| [7] `joint_gate_shadow` | meta×tox 곱이 임계 미만이라 **차단**한 게 옳았나 | **차단된** 신호 |
| [30] `toxicity_recalib_watch` | tox 밴드 분포가 재보정 후 어디로 갔나 | 전 분봉 |
| [31] `toxicity_reduce_mult_shadow` | tox 상수 0.7을 연속화하면 수량이 바뀌나 | **체결된** reduce 진입 |
| **[34] `meta_size_zero`** | **meta가 0을 냈는데 진입한 건이 손해였나** | **체결된** take·reduce 진입 |

> 🔴 **[7]과 [34]는 서로소에 가깝다.** [7]은 차단된 신호를, [34]는 진입한 신호를 본다.
> 419·420차가 `size_multiplier_raw`를 `joint_gate_shadow`에만 넣은 탓에
> **진입한 신호의 raw는 지금까지 어디에도 없었다** — 그것이 F5이자 이 채널의 신설 사유다.

## 3. F4 — `size 0`의 출처와 의미 (이 채널의 근거)

### 3-1. 출처는 규칙기반 폴백이 아니라 학습모델이다

| 항목 | 실측 |
|---|---|
| 모델 | 레짐별 독립 LogisticRegression 4개 (추세장/횡보장/급변장/혼합) |
| 학습 상태 | `data/meta_conf_state.pkl` → **4개 전부 `fitted=True`** |
| 표본 | 2,186 / 1,614 / 447 / 327 = **4,574** |
| 설정 | `class_weight='balanced'`, `max_iter=50`, `warm_start=True`, 30봉마다 배치 재학습 |

**입력 피처 7개** (`build_meta_features`):
```
[regime_code, hurst, atr_ratio, time_code, recent_accuracy, cal_gap, horizon_agreement]
cal_gap = clip(앙상블신호강도 − 최근정확도, −0.5, 0.5)     # 과신 정도
```
> 주목: **가격·수급·호가 피처가 하나도 없다.** 전부 "상황 맥락 + 주 예측기의 최근 성적"이다.

### 3-2. `conf`는 확률이 아니라 품질등급의 기대값이다

레이블은 4급이다 (`_quality_label`, `CONF_HIGH = 0.37` — 240차에 0.60에서 하향):

| 등급 | 조건 | 가중치 |
|---|---|---|
| Q3 | 맞음 + 고신뢰 | 1.00 |
| Q2 | 맞음 + 저신뢰 | 0.67 |
| Q1 | 틀림 + 저신뢰 | 0.33 |
| Q0 | 틀림 + 고신뢰 | 0.00 |

```
conf = Σ P(Qk) × weight_k
```

### 3-3. 그래서 임계 0.5는 정확히 "적중률 50%"다

적중률 `a`, 고신뢰비중 `h`로 환산하면

```
conf = ⅓·(1−a)(1−h) + ⅔·a(1−h) + 1·a·h
```

| a＼h | 0.0 | 0.25 | 0.5 | 0.75 | 1.0 |
|---|---|---|---|---|---|
| 0.3457 | 0.4486 | 0.4228 | 0.3971 | 0.3714 | 0.3457 |
| 0.40 | 0.4667 | 0.4500 | 0.4333 | 0.4167 | 0.4000 |
| **0.50** | **0.5000** | **0.5000** | **0.5000** | **0.5000** | **0.5000** |
| 0.60 | 0.5333 | 0.5500 | 0.5667 | 0.5833 | 0.6000 |

`a=0.5`를 대입하면 `0.5(1−h) + 0.5h = 0.5` — **고신뢰비중 h와 무관하게 정확히 0.5**다.

> ### `size 0`의 의미
> **"이 맥락에서 예측기 풀이 동전던지기보다 못할 것으로 추정된다 → 베팅하지 마라"**
>
> 임의로 고른 숫자가 아니라 **원리적으로 유도되는 손익분기점**이다.

### 3-4. 실측 정합 — 지금 그 신호는 옳다

| 항목 | 값 |
|---|---|
| `meta_labels` 전체 적중률 | **34.57%** (n=87,642, 3방향 랜덤 = 33%) |
| → 위 식이 함의하는 conf | **≈ 0.3971** |
| 0803 실측 `conf_raw` 범위 | 0.1706 ~ 0.5561 |

**정합한다.** 메타 모델은 예측기 풀이 랜덤에 가깝다는 것을 정확히 감지하고 있고,
그래서 reduce 밴드의 57.4%에서 "베팅하지 마라"를 낸다.

> 이는 0803 정기점검의 세 발견과 **네 번째 독립 경로로 같은 결론**이다:
> 예측 적중률 랜덤 수준 / MFE·MAE 대칭(방향 엣지 없음) / 진입 판별자 BH·Bonferroni 전멸
> — 그리고 이제 **메타 모델 자신도 같은 말을 하고 있었다**는 것.

## 4. F5 — 채널 신설 사유: `take` 밴드 계측 사각지대

```python
take:   size_mult = max(0.9, min(1.25, learned["size_multiplier"]))   # ← `or` 없음
reduce: size_mult = max(0.35, min(0.75, learned["size_multiplier"] or 0.5))
```

`take` 밴드엔 `or 0.5` 폴백이 없지만 **`max(0.9, ...)` 클램프가 같은 일을 더 세게** 한다.
`raw = 0.0` → **0.9**, 거의 풀사이즈다. `reduce`는 0.5로 눌리기라도 하는데
`take`는 **오히려 증폭**된다.

| 밴드 | raw==0의 결과 | 왜곡 크기 |
|---|---|---|
| reduce | 0.0 → **0.5** | ×∞ (0에서) — 절반 사이즈 |
| **take** | 0.0 → **0.9** | **거의 풀사이즈** |

**419·420차는 reduce의 `or 0.5`만 계측했다.** `size_multiplier_raw`는 420차가
`joint_gate_shadow`에 넣었지만 그건 **차단된** 신호 전용이라, **진입한** 신호의 raw는
어디에도 남지 않았다. 그래서 0803 딥다이브는 reduce 밴드만 확정할 수 있었고
**take 밴드는 판정 자체가 불가능**했다.

> 420차가 "덤으로 발견한 경로 불일치"로 각주 처리한 것 —
> *"액션은 blended_conf로, 사이즈는 raw conf로 결정된다"* — 이 **실은 본체**였다.

| **B** | **`raw==0` → action을 `skip`으로 강등** | ✅ 후보 — **주간회의 대상** |
| C | conf 경로 일원화(size도 floor 후 conf 사용) | △ floor가 0.45라 여전히 <0.5 → 결과 불변. 코드 위생 |

**안 B의 진입 감소폭** (캠페인 79건 기준):

| 범위 | 제거 | 잔존 |
|---|---|---|
| 하한 (`reduce`&0.500만 = raw==0 확정) | 20건 (**25.3%**) | 59건 |
| 상한 (+`take`&0.900 전부) | 46건 (58.2%) | 33건 |

> **진입이 0이 되지는 않는다.** `conf`가 항상 0.5 미만은 아니다 —
> reduce 밴드의 **42.6%가 `raw>0`**이다(교란 (c)의 balanced 보정 + `recent_accuracy` 변동).
> 평균 함의값 0.397은 **분포의 중심이지 상한이 아니다.**

### 7-2. 왜 새 테이블이 아니라 컬럼 1개인가

`ensemble_decisions`에는 **모든 결정이 이미 기록**되고 `entry_executed`·`meta_action`·
`meta_size_mult`가 함께 있다. 별도 섀도 테이블을 만들면 조인 키를 새로 관리해야 하고,
[7]이 겪은 *"차단된 신호만 보이는"* 모집단 분리가 재발한다.

### 7-3. `or` 금지 — 기록 경로에서 같은 실수를 반복하면 안 된다

```python
# [34] 클램프·폴백 이전 원 사이즈 배수.
# `or`가 아니라 `.get()` 그대로 — 0.0은 유효값이므로 falsy 승격 금지
# (그 승격이 바로 이 채널이 재는 결함이다). 키 부재는 NULL.
(decision.get("meta_gate") or {}).get("size_multiplier_raw"),
```

> MetaGate FLAT early-return 경로는 이 키를 반환하지 않는다 → NULL.
> 그 경로는 `action='skip'`이라 [34] 모집단 밖이므로 **NULL이 정직하다.**

### 7-4. 사전등록 합격선 (표본 보기 **전** 확정)

```
min_samples       = 20        raw==0 이면서 진입까지 간 포지션 최소 수
min_days          = 5         313차 — 다른 채널보다 높다 (교란 (a) 때문)
baseline_win_rate = 0.50
effective_date    = 2026-08-04    ← 이전 결정은 raw NULL (소급 복원 불가)

PASS(현행 유지) : 누적 손익 ≥ 0 — 클램프·폴백이 해롭지 않다
FAIL(변경 검토) : 누적 손익 < −(왕복비용×2 상당) AND 승률 < baseline
                  → "안 B"를 주간회의 안건화. 액션 축 변경이므로 자동 전환 금지
```

### 7-5. 밴드 분리 집계 — 합산 금지

`take`(0.0→0.9)와 `reduce`(0.0→0.5)는 **왜곡 크기가 다르다.** 한 숫자로 합치면
take의 큰 왜곡이 reduce에 희석된다. 리포트는 밴드별로 따로 렌더하고,
**합계 행은 판정용이지 해석용이 아니라고 명시**한다.

### 7-6. 소급 백필 없음

`meta_size_raw`는 **결정 시점에만 알 수 있는 값**이라 사후 복원이 불가능하다.
억지로 채우면 구 표본이 신 표본처럼 보인다. NULL은 *"그때는 안 쟀다"* 는 정직한
표기이고, 리포트는 이를 `미계측 N건`으로 분리 표시한 뒤 판정 모집단에서 제외한다.
(420차와 동일 원칙)

## 8. 판정 시 반드시 함께 읽을 교란 3종

사전등록 주석과 리포트 양쪽에 박아 두었다.

### (a) `recent_accuracy` 자기상관 — `min_days=5`의 근거

`recent_accuracy`가 meta **입력 피처**다. 따라서 `conf`는 자기상관을 갖는다.
*"size 0 구간이 나빴다"* 가 **진짜 사전 판별력**인지, 아니면 **나쁜 구간이 뭉쳐 있는
자기상관**인지 구분되지 않는다. → 그래서 다른 채널(대개 3일)보다 `min_days`를 높게 잡았다.

### (b) 퇴역 30m·FLAT 혼입

meta 학습 스트림에는 **296차가 전면 퇴역시킨 30m이 18,193건(20.8%)**으로 두 번째로
크게 들어가고, FLAT 예측도 호라이즌별 **20.4~45.2%**로 섞인다
(`_quality_label`은 `correct` 불리언만 보므로 FLAT 적중도 Q2/Q3가 된다).
→ `conf`의 기준선이 **그날 어느 호라이즌이 많이 검증됐는지에 따라 흔들린다.**

### (c) `class_weight='balanced'`

LR이 클래스 불균형을 보정하므로 `conf`는 실제 base rate 확률이 아니라
"균형 잡힌 세계"의 기대 품질이다. 실제 적중률 34.6% 환경에서는 conf를 **실제보다 높게**
낼 수 있다 → **`conf<0.5`는 오히려 보수적 추정일 수 있다.**

## 12. 읽을 때의 주의

1. **`size 0`은 "모델 고장"이 아니다** — 적중률 34.6% 환경에서 `conf≈0.40`은 정상
   출력이다. 신호는 **옳고**, 문제는 그것을 액션 밴드가 덮는다는 것이다.
2. **`take`&0.900 손실을 폴백 탓으로 계상하지 말 것** — raw 혼재 구간이다(§5).
3. **밴드를 합산해 읽지 말 것** — 합계 행은 판정용이다.
4. **교란 3종을 빼고 인용하지 말 것** — 특히 (a) 자기상관은 이 채널의 결론을
   통째로 뒤집을 수 있다.
5. **"적중률 34.57%"는 앙상블이 아니라 호라이즌 예측기 풀**이다(§3-5).
6. **`meta_labels.meta_action`과 `ensemble_decisions.meta_action`은 다른 것이다** —
   이름·값 집합(`take/reduce/skip`)이 똑같지만 전자는 **사후 채점 정답 레이블**
   (`learning/meta_labeling.py`), 후자는 **실시간 MetaGate 액션**이다.
   전자로 정확도를 재면 정의상 `reduce`·`take`가 **100%**로 나온다 — 분석 함정.
