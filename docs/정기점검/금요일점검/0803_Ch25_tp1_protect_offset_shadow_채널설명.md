## 1. 무엇을 묻는 채널인가 — 차원 D 하나

TP1에 **도달한 순간** 보호스톱을 진입가에서 얼마나 띄울 것인가.

```
protected_stop = entry_price ± protect_offset_pts
    breakeven      = 0
    breakeven_plus = alpha_pts (0.20pt 고정)
    atr_profit     = ATR × 0.25        ← 현행 (main.py:202 TP1_PROTECT_ATR_LOCK_MULT)
```
구현: `position_tracker.py:arm_tp1_single_contract_with_mode()`

### 이웃 채널과 반드시 구분할 것

| 채널 | 묻는 것 | 차원 | 모집단 |
|---|---|---|---|
| [23] `tp1_geometry` | TP1·손절을 **어디에 놓을까** | A·B | 전 진입 |
| **[25] `tp1_protect_offset`** | **TP1 시점 보호 offset 폭** | **D** | **TP1 도달 건만** |
| [12] `tp1_trail` | TP1 **이후** 트레일 폭 | E | TP1 도달 건 (기각 완료, −3.83pt) |

> 🔴 **[25]는 급행 풀스톱(TP1 미도달 손실)을 다룰 수 없다.**
> 모집단이 "TP1 **도달** 건"이므로 TP1에 못 닿고 손절된 포지션과 **서로소**다.
> 2026-08-03 점검이 [25]를 "지배적 손실 모드의 유일한 처방"으로 지목한 것은 오류였다
> (`DECISION_LOG` 421차 후속4에서 정정). 손실 축 담당은 [23]이다.
> **[25]가 개선하는 것은 손실이 아니라 이익 캡처율이다.**

### 사전등록 합격선 (관측 전 고정)

```
min_samples = 20      보호전환 건수. 미달 → 판정 보류
min_days    = 3       313차 — 단일일 판정 금지

PASS(현행 유지) : 모든 대안의 누적 순손익이 현행 이하
FAIL(변경 검토) : 현행 초과 대안 존재 + 표본 충족 → 주간회의 수동 결정
```

### 변형 6종

| 변형 | offset |
|---|---|
| `current` | ATR × 0.25 (현행) |
| `breakeven` | 0 |
| `breakeven_plus` | 0.20pt 고정 |
| `atr_lock_0.50` | ATR × 0.50 |
| `atr_lock_0.75` | ATR × 0.75 |
| `bar_range` | max(ATR×0.25, 직전 3봉 평균레인지 × 0.5) |

> ⚠ **사전등록 정직성 고지**(코드에 명시): `breakeven`은 채널 신설 **전에** 이미
> 1회 측정됐다(23건, 현행 22/23 우세). 따라서 재확인용이며 **사전등록된 검증이
> 아니다.** 이 채널의 사전등록 가치는 아직 측정된 적 없는
> `atr_lock_0.50` / `atr_lock_0.75` / `bar_range`에 있다.

### 판정 모집단 — 모드 일치 행만

`current` 변형이 "실제로 일어난 일"과 같아야 `delta_vs_current`가 의미를 갖는다.
따라서 **현행 모드(`atr_profit`) 행만** 판정에 쓴다. 다른 모드 행은 세어서
`모드 불일치 제외 N건(breakeven N)`으로 표기한다.

> 406차가 넣은 투명성 기능이며 **결함이 아니다.** 그전에는 SQL에서 조용히 걸러져
> MW0601의 `n=0`이 "표본이 아직 안 쌓였다"로 오독됐다(0801 리포트 `보호전환 0건
> (제외 0건)`). 2026-08-03 점검도 이 표기를 보고 "근거가 무효화됐다"고 오독했다가
> 반증됐다 — `DECISION_LOG` 421차 후속2.

### 판독 규칙 (421차 후속2 사전등록, 관측 전 확정)

```
(1) 두 PC가 같은 방향 + 둘 다 drop-max 생존 → 주간회의 승격 후보
(2) 부호가 반대       → 기각이 아니라 보류. 두 값을 항상 병기(유리한 쪽만 인용 금지)
(3) 한쪽만 표본 충족  → 단독 판정을 확정으로 쓰지 않고 "단일 PC 표본" 명시
(4) 어느 경우에도 자동 적용 없음 — 주간회의 수동 결정(§9)
```

**현재는 (2)와 (3)에 동시에 걸린다.**

근거: `[23]`에서 이미 PC간 부호 역전 전례가 있고, 그 결정문이
*"같은 코드·같은 기간인데 거래집합만 달라 결론이 뒤집힌다(313차)"* 였다.

## 7. ⚠ 신규 발견 — 보호모드가 장중에 바뀌는데 로그가 없다 (2026-08-03)

오늘 `synthetic_partial_exits` 16건 중 **2건이 `breakeven`** 이다.

```
13:25:41  [Position] 1계약 TP1 보호전환 | mode=breakeven  | 회계상 확정 33% @ +0.86pt
13:38:10  [Position] 1계약 TP1 보호전환 | mode=breakeven  | 회계상 확정 33% @ +0.84pt
13:46:34  [Position] 1계약 TP1 보호전환 | mode=atr_profit | 회계상 확정 33% @ +0.80pt
```

406차가 실거래를 `atr_profit`으로 통일했고 현재 `session_state.json`도
`atr_profit`인데, **13:25~13:38 약 13분간만 `breakeven`이었다가 되돌아왔다.**

- 모드는 매 호출마다 `session_state`에서 읽는다(`main.py:2341`) → 대시보드 토글로
  장중 변경이 가능하다.
- **그런데 모드 변경을 기록하는 로그가 어디에도 없다** — 전체 로그 grep 결과 0건.
  누가·왜 바꿨는지 사후에 알 방법이 없다.

### 왜 이것이 [25]에 중요한가

판정 모집단이 **모드 일치 행**이므로, 모드가 장중에 흔들리면 **표본이 조각난다.**
오늘도 16건 중 2건이 판정에서 빠졌다. 스크립트는 이를 정확히 세어 표기하므로
데이터 오염은 아니지만, **표본 축적 속도가 조용히 느려진다.**

→ `dev_memory/NEXT_TODO.md` 421차 후속6에 등록.

## 8. 읽을 때의 주의

1. **절대값은 실현손익이 아니다** — 상대비교 전용
2. **offset 확대안은 양날**이다 — 지키는 폭이 커지는 대신 스톱이 멀어져 되돌림
   손실이 커진다. 사전등록이 **승률·최대손실·`beats_current_n` 병기**를 명시한다
3. **MW0601 표본은 2026-08-03부터** — 이전 행은 `breakeven`이라 판정 모집단이 아니다
4. **`breakeven` 변형 결과는 사전등록 검증이 아니다** — 재확인용
5. **거래일 3일**이 실질 제약이다 — `min_samples` 20은 오늘 페이스면 며칠 내 도달하나
   `min_days`가 먼저 막는다
