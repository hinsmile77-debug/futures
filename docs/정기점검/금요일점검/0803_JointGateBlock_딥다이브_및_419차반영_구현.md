## 1. 데이터 딥다이브 (116행 전수)

### 1-0. 공식 판정

```
verdict = ✅ PASS   (누적 hyp_pnl_pts = -13.1632 pt ≤ 0)
승률 69.8% (n=116)  vs 기준선 49.3%
cf 분포: STOP 35 / TP1 81 / NEITHER 0
```

판정 규칙은 `존치(PASS): 누적 hyp ≤ 0` / `완화권고(FAIL): 누적 hyp > 왕복비용×2 AND 승률 > 기준선`.
아래는 그 PASS를 원본 116행으로 되짚은 결과다.

### 1-1. F1 — `tox_size`는 문자 그대로 상수 (구조 확정)

`joint_gate_shadow` 116건 전수에서 `tox_size` distinct = `[0.7]`, 예외 0건.
[`toxicity_gate.py`](../../../strategy/risk/toxicity_gate.py)의 reduce 밴드
`size_multiplier`가 고정 상수이기 때문이다. 따라서

```
joint_mult < 0.50  ⟺  meta_size × 0.7 < 0.50  ⟺  meta_size < 0.7143
```

**곱은 장식이고 실체는 `meta_size` 단일 임계 + tox reduce 여부(불리언)** 다.
419차 발견 ④와 동일한 결론에 독립 경로로 도달했다.

### 1-2. F2 — 임계 0.50은 차단표본 안에서 한 번도 구분자가 아니었다

meta reduce 밴드는 [`meta_gate.py:206`](../../../strategy/entry/meta_gate.py)에서
`max(0.35, min(0.75, ...))`로 클램프된다. 통과 구간 `0.7143~0.75`는 밴드 폭의 **4.8%** 뿐이다.

| 확인 | 실측 |
|---|---|
| 116건 최대 `meta_size` | **0.7140** → `joint = 0.49980` (임계보다 **0.0002** 아래) |
| SIGNAL 로그 `reduce×reduce` (07-15~31, 중복제거) | **82건 중 통과 6건** |
| 그 6건의 `meta_size` | **전부 0.75** (클램프 천장) |

즉 실효 규칙은 **"meta·tox 둘 다 reduce면 차단, 단 meta가 천장값일 때만 통과"** 다.
`< 0.50`이라는 숫자는 아무것도 조율하지 않는다.

### 1-3. F3 — `meta_size` 63%가 학습값이 아니라 폴백 상수다 (의미가 반전된 채로)

`meta_size == 0.500` 정확히 **73건 (62.9%)**. 우연이 아니라 코드 경로다:

```
learning/meta_confidence.py:_make_result()
    conf < 0.5  →  size_mult = 0.0        # 모델의 명시적 "사이즈 주지 마라"
strategy/entry/meta_gate.py:206
    learned["size_multiplier"] or 0.5     # 0.0이 falsy → 0.5로 **승격**
```

py37_32 실측 재현:

| meta 원 conf | raw size | reduce 분기 결과 | 폴백? | joint(×0.7) |
|---|---|---|---|---|
| 0.10 / 0.30 / 0.49 | **0.000** | 0.500 | **True** | 0.3500 BLOCK |
| 0.50 | 0.500 | 0.500 | False | 0.3500 BLOCK |
| 0.5857 | 0.714 | 0.714 | False | **0.4998** BLOCK |
| 0.60 | 0.750 | 0.750 | False | 0.5250 free |

**`meta_size=0.500`은 "conf<0.5 폴백"과 "conf=0.50 학습값"을 구분할 수 없다.**
그리고 두 버킷의 손익 방향은 **정반대**다:

| 버킷 | n | 누적 hyp | 해석 |
|---|---|---|---|
| `meta_size = 0.500` (폴백 포함) | 73 (63%) | **+3.97 pt** | 차단이 **손해** |
| `meta_size ≠ 0.500` (실학습값) | 43 | **-17.14 pt** | 차단이 이득 |

→ 리포트의 `high/low (0.55)` 분리 집계는 **해석 불가**다. low 버킷 94건 중 73건(78%)이 이 폴백이다.

> **덤으로 발견한 경로 불일치**: `meta_gate.py:146`의 과소보완(`meta_conf<0.20 → floor 0.45`)은
> **액션 판정용 `meta_conf`만** 올린다. `size_multiplier`는 `predict_confidence` 리턴 시점에
> **floor 전 raw conf**로 이미 확정돼 있다. 즉 **액션 경로와 사이즈 경로가 서로 다른 conf를 쓴다.**
> cold-start 구간에서 "액션은 reduce로 살아나고 사이즈는 0.0 → 폴백 0.5로 세탁"되는 조합이 나온다.

### 1-4. F4 — n=116은 독립 관측치가 아니다 (59 에피소드)

JointGateBlock은 조건이 유지되는 동안 **매 분봉 재차단**한다. 같은 방향·5분 이내 병합:

| 집계 단위 | n | 누적 hyp | 승률 |
|---|---|---|---|
| 신호 단위 (리포트 현행) | 116 | -13.16 | 69.8% |
| **에피소드 첫신호** | **59** | **-12.19** | 69.5% |
| 에피소드 평균 | 59 | -16.94 | **59.3%** |

연속 길이 분포: 1건×33 / 2건×13 / 3건×3 / 4건×4 / 5건×4 / **6건×2**.
같은 사건을 여러 번 세면 유의성이 그만큼 부풀려진다.

### 1-5. F5 — 통계적으로 0과 구분되지 않는다

| 단위 | 건당 평균 | sd | **t** |
|---|---|---|---|
| 신호 (n=116) | -0.1135 | 3.113 | **-0.393** (p≈0.70) |
| 에피소드 (n=59) | -0.2066 | 3.294 | **-0.482** |

판정 문턱이 `누적 ≤ 0` 이분법이라 **-13pt와 -0.01pt가 같은 PASS**를 받는다.
FAIL 문턱은 `+0.140pt`(왕복비용 0.0702×2)뿐이라 PASS 구간이 사실상 실수 절반이다.

### 1-6. F6 — 하루를 빼면 부호가 뒤집힌다

| 단위 | 최대 기여일 | 그 기여 | 제외 후 |
|---|---|---|---|
| 신호 | 2026-07-28 (**37건, 표본의 32%**) | -19.66 | **+6.49 pt** ← 부호반전 |
| 에피소드 | 2026-07-27 | -15.99 | **+3.80 pt** ← 부호반전 |

나머지 날은 어느 하나를 빼도 음수 유지. **PASS 판정 전체가 단일 거래일에 걸려 있다.**

### 1-7. F7 — 승률-손익 역설, FAIL 조건 절반은 이미 충족

승 81건 평균 **+1.78pt** / 패 35건 평균 **-4.50pt**. 승률 69.8%인데 합계가 음수인 건
`hyp`가 현행 TP1(ATR×0.3~0.5)/스톱 기하에 종속돼 있기 때문이다.

FAIL 조건은 `누적 > 비용×2` **AND** `승률 > 기준선`인데 —
**승률 조건(69.8% > 49.3%)은 이미 통과**했고 손익 조건 하나만 남아 PASS다.
F6과 겹쳐 읽으면 이 채널은 FAIL에서 **한 날짜 거리**다.

### 1-8. F8 — 리포트 고정문구가 MW0601 실측과 모순

`generate_validation_campaign_report.py`가 **무조건 출력**하던 문장:

> "MAE 평균이 MFE 평균보다 **크다** … 그건 차단이 옳았던 쪽 증거다"

| PC | MFE 평균 | MAE 평균 | MFE>MAE 건수 | 문장 참/거짓 |
|---|---|---|---|---|
| MW0601 | **11.7309** | 6.6805 | 74 vs 42 | **거짓** |
| MW0602 | 6.6303 | **8.9551** | 33 vs 45 | 참 |

MW0601 리포트는 **바로 위에 인쇄된 자기 숫자와 정면으로 모순되는 결론**을 3주째 싣고 있었다.

### 1-9. 부수 관찰 (표본 얇음, 참고만)

- 방향: SHORT 76건 -24.83pt(차단 이득) / **LONG 40건 +11.67pt, 승률 77.5%(차단 손해)**

## 2. 419차를 반영한 Action 수정

### 2-1. 철회 — 419차가 이미 가져간 것

| 원안 | 처리 |
|---|---|
| P2(a) "tox reduce 밴드 연속화" | **철회** — 419차 P1(`_reduce_mult_shadow`, 채널 `[31]`)이 이미 구현 |
| F1~F3 발견 자체 | **재등록 안 함** — 419차 발견 ④가 동일 내용을 이미 문서화 |

### 2-2. 신규 A — [7] 채널 체제 단절 (최우선)

419차 P0이 `TOXICITY_CANCEL_CHURN_CEILING`을 0.08 → 0.42로 재보정해 tox 밴드가 이동한다:

| 밴드 | 재보정 전 | 재보정 후(재생) |
|---|---|---|
| block | 23.3% | 8.6% |
| **reduce** | **76.4%** | **73.7%** |
| pass | 0.27% | 17.7% |

JointGateBlock의 발동 전제가 `tox_action == "reduce"`이므로 **이 채널의 모집단 자체가
2026-08-03부터 바뀐다.** 그런데 `resolve_and_eval_joint_gate()`는
`WHERE resolved=1 AND ts >= _campaign_start()` 하나로 집계한다 —
**구 체제 116건과 신 체제가 조용히 섞인다.**

419차는 `[30] toxicity_recalib_watch`에 `effective_date`를 넣었지만 `[7]`에는 없었다.

### 2-3. 신규 B — 419차 P1의 사각지대 = 차단 축

`[31] toxicity_reduce_mult_shadow`는 **실제로 체결된** reduce 밴드 진입만 본다.
JointGateBlock으로 **차단된** 신호는 그 채널에 아예 들어가지 않는다.

그런데 연속 배수가 실적용되면 `joint_mult`이 바뀌어 **차단 여부 자체가 뒤집힌다.**
py37_32 스모크 실측 (`HI=0.90 / LO=0.45`):

| meta_size | tox_score=0.28 | tox_score=0.36 | tox_score=0.44 |
|---|---|---|---|
| 0.500 | now 0.350 **B** / sh 0.450 **B** | 0.350 **B** / 0.344 **B** | 0.350 **B** / 0.238 **B** |
| 0.600 | 0.420 **B** / **0.540 free** ← 해제 | 0.420 **B** / 0.413 **B** | 0.420 **B** / 0.286 **B** |
| 0.714 | 0.500 **B** / **0.643 free** ← 해제 | 0.500 **B** / 0.491 **B** | 0.500 **B** / 0.340 **B** |
| 0.750 | 0.525 free / 0.675 free | 0.525 free / 0.516 free | **0.525 free / 0.357 B** ← 신규차단 |

**양방향으로 판정이 뒤집힌다.** 이 축을 지금 보는 채널이 하나도 없다.

### 2-4. 419차 P3 보류 근거의 약화 (다만 결론은 바뀌지 않는다)

419차는 P3(Joint 임계 0.50 재선정 + meta falsy 폴백 수정)을 이렇게 보류했다:

> "`joint_gate_shadow`가 현재 **PASS(존치)** … 완화를 서두를 근거가 없다"

**F5·F6이 그 PASS 자체를 흔든다** (t=-0.39, 단일일 의존). 보류 근거는 약해진다.

**그러나 결론은 "게이트를 바꾸자"가 아니다.** 방향 증거 자체가 없으므로 완화 근거도 없다.
필요한 것은 **"PASS의 신뢰도를 리포트가 드러내게 하는 것"** 이고, 그건 P3 판단 재료를
만드는 일이라 419차 결정과 충돌하지 않는다.
→ **폴백 수정·임계 변경은 이번에도 하지 않았다** (§9 사전등록 원칙).

### 3-2. 신설 컬럼 10종

```
meta_conf / meta_conf_raw / meta_size_raw / meta_size_fallback   ← F3 (meta축)
tox_score / tox_score_ma / tox_ceiling                            ← A  (체제 태그)
tox_size_shadow / joint_mult_shadow / would_block_shadow          ← B  (차단축 반사실)
```

체제는 날짜 상수만으로 가르지 않고 **발동 시점의 `tox_ceiling`을 행에 새겼다** —
ceiling이 또 바뀌면 날짜 경계가 낡는데, 자기기술적이면 리포트가 그 불일치를 감지한다.

### 3-3. 기동 마이그레이션이 핵심이다

`CREATE TABLE IF NOT EXISTS`는 **이미 있는 테이블을 갱신하지 않는다.** 그런데 `main.py`의
INSERT는 컬럼명을 명시한다. ALTER를 리포트 스크립트에만 뒀다면 —

> 매 차단마다 INSERT가 실패 → `except`가 예외를 삼키고 warning만 → **표본이 통째로 유실**

`db_utils.init_trades_db()`에 **1차 방어선**(기동 시 멱등 ALTER, 실패 시 stderr 경고),
리포트 `_ensure_joint_gate_columns()`에 **백스톱**(라이브가 안 돈 PC/백업 DB용)을 뒀다.

### 3-4. 판정 규약 (사전등록 — 신 체제 표본을 보기 **전에** 확정)

| 항목 | 규약 |
|---|---|
| **체제** | 판정은 **항상 한 체제 안에서만**. 신 체제가 `min_samples`(20)에 닿으면 자동 전환, 닿기 전엔 구 체제로 판정하되 **"구 체제 기준" 명시** |
| **통계 단위** | **에피소드 첫 신호** (같은 방향 `episode_gap_min=5`분 이내 병합) |
| **증거강도** | `evidence_t_abs = 2.0`. `SUPPORTS_GATE`(유의 음수) / `NO_EVIDENCE`(0과 구분불가) / `REJECTS_GATE`(유의 양수) |
| **verdict** | PASS/FAIL/INSUFFICIENT **하위호환 유지** — 증거강도는 별도 축 |
| **jackknife** | 한 거래일 제거로 부호 반전 시 `fragile` 플래그 |
| **폴백/반사실** | **판정 안 함, 세기만 함** |

### 3-5. 요약표가 이렇게 바뀐다

```
전: | [7] JointGateBlock | ✅ PASS | 누적 hyp=-13.1632pt 승률=69.8% (n=116, 보류 0) |

후: | [7] JointGateBlock | ✅ PASS | 누적 hyp=-13.1632pt 승률=69.8% (n=116, 보류 0)
      · ⚠증거없음(t=-0.482) · 구tox체제 · 단일일취약 |
```

### 3-6. 부수 교정 — [7]의 MFE 병기 절이 [29] 뒤에서 렌더링되고 있었다

`jg`(= `[7]`) 데이터인데 렌더 위치가 `[28]`·`[29]` **뒤**라, 출력물에서 `[29]` 아래 붙은
H3처럼 보였다. `[7]`을 읽는 사람은 자기 채널의 자기편향 계측을 두 섹션 건너에서 찾아야 했다.
**HEAD에도 있던 기존 결함**이며 `_render_joint_mfe()`로 분리해 제자리로 옮겼다 —
순수 이동, 계산 로직 무변경(F8 문구 조건부화만 별도).

## 7. 인용 시 주의사항

1. **`PASS`를 "차단이 옳다"로 읽지 말 것.** 판정 규칙이 `누적 ≤ 0` 이분법이라
   -13pt와 -0.01pt가 같은 판정을 받는다. 증거강도(`evidence`)를 함께 볼 것.

   리포트의 `judged_regime`이 어느 쪽인지 항상 확인.
