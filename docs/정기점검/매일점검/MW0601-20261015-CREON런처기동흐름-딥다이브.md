## 2. 이상점

### A. 🔴 `LAUNCH_API.bat`가 2개월째 STEP 5(preflight) 진입 순간 파싱 오류로 즉사 — **확정**

- **증상**: 10-13 이후 `creon_plus_launch.log`에 `Preflight passed` · `session ready` **0건**. 모든 실행이 `Auto-login completed` / `Already connected` 한 줄 뒤 끊긴다. `cybos_plus_launch.log`도 마지막 `session ready`가 **2026-08-06 16:04**다.
- **원인**: `LAUNCH_API.bat:348`
  ```bat
  IF "!PREFLIGHT_ERR!"=="5" (
      ECHO [ERROR] Preflight 워치독 타임아웃 -- TradeInit 응답 없음(판정 불능).
  ```
  괄호 블록 안의 미이스케이프 `)` 가 블록을 닫고, 남은 `.` 때문에 cmd가 바깥 `IF EXIST … (` 블록 전체를 파싱하다 실패한다. 배치 파싱 오류는 **그 즉시 스크립트를 종료**한다.
- **재현(이 세션)**: 같은 구조의 최소 배치 → `.은(는) 예상되지 않았습니다.` · **exit 255**. 10-13 `Cybos Plus` 작업 LastTaskResult도 **255**.
- **도입**: `2612cc3`(437차, 2026-08-06 18:36). 첫 고장 실행 = 같은 날 18:37:59.
- **영향**:
  - LAUNCH_API의 preflight · 최종 재확인 · 「session ready」가 **한 번도 안 돈다**. 실제 계좌 대조는 `start_mireuk.bat`이 자체 preflight로 하므로 **주문 안전은 유지**됐다(437차 "로그인 책임 단일화" 덕).
  - `Already connected` 분기(맨 IsConnect만 봄)는 계좌를 전혀 확인하지 않은 채 끝난다 — 10-14 08:35 "Already connected → 08:40 런처 300초 실패"가 이 경로다.
  - 성공해도 실패(255)로 기록돼 **작업 결과 코드가 신호 구실을 못 한다**.
- 다른 런처(`start_mireuk` · `SWITCH_BROKER` · `EOD_RETRAIN` · `MAEKJEOM_LADDER`)에는 같은 패턴 없음(정규식 스캔).
