### 1-2. 복원 항목 — F10 (오전 P2)

오전 보고의 *"3m 진입 편중 + 체크리스트 승격 상한"* 이 오후 F 목록에서 누락됐다.
코드 접지 결과 **성격이 다른 두 문제**임이 확인돼 F10-A / F10-B로 분리한다.

**F10-A. 진입 호라이즌 라우터가 ATR 밴드만으로 3m을 73% 선택한다**

[ensemble_decision.py:240](model/ensemble_decision.py#L240) `select_entry_horizon()`:

```python
feasibility = atr / (threshold_1m + 1e-9)
if   feasibility < ENTRY_HORIZON_LOW_BLOCK: return None
elif feasibility < ENTRY_HORIZON_B1:        return "1m"
elif feasibility < ENTRY_HORIZON_B2:        return "3m"
else:                                        return "5m"
```

오늘 실측 선택 분포: **3m 121회 / 1m 25회 / 5m 19회 → 3m 73%**.
실제 진입은 10건 중 **3m 8건(80%)**.

이 선택은 **모델 품질과 무관한 순수 ATR 밴드 함수**다. 함수 docstring 자체가
`라이브 미검증 — DECISION_LOG 374차` 라고 적고 있다.

> **F7과 겹칠 때 위험이 커진다.** 라우터가 진입의 80%를 3m으로 보내는데,
> 3m은 acc.txt 유령 기준선(0.4651, 07-22자) 때문에 EOD 교체가 4일 연속 막혀
> **CV 미검증 장중 모델이 배포된 채**이고, 오늘 적중률 34.4%(랜덤 33.3% 근방)다.
> 즉 **가장 많은 물량이 가장 관리가 안 되는 모델로 흘러간다.**

**F10-B. 체크리스트 C→A 승격에는 정렬강도 요구가 없다**

[checklist.py:350](strategy/entry/checklist.py#L350) 311차 가드:

```python
if ensemble_grade == "X" and grade in ("A","B") and pass_count < 7:
    grade = "X"   # 승격 차단
```

조건이 `ensemble_grade == "X"` 뿐이다. **`"C" → "A"`는 무제한 통과**한다.
오늘 10건 중 9건이 `raw_grade=C`, 그중 **7건이 A로 승격**됐다.

311차가 X→A에 이 가드를 넣은 근거는 재구성 백테스트(06-15~07-10, n=124)에서
`pass=6`은 +15m 평균 **−0.50pt**(t=−0.31, 승률 50%), `pass>=7`은 **+2.57pt**(승률 61%)
였다는 것이다. **그 논리가 C→A에 적용되지 않을 이유는 문서에 없다** — 다만
C→A 표본으로 재검정한 적도 없다. → 섀도 검정 후 결정(§3 Wave 4).

## §5. 왜 이 순서인가

1. **F8 최우선** — 이후 모든 Fix가 로그·DB 분석을 수반한다. 오늘처럼 CB⑤를
   유발하면 그 자체가 라이브 리스크이고, 데이터도 오염된다.
2. **F3 그다음** — 고도화 1 전체(G1-A/G1-C)와 F9가 여기 막혀 있다. 읽기전용이라
   위험이 0인데 해제 효과가 가장 크다.
3. **F1·F2는 거래 경로 무관** — 병렬 가능. 다만 둘 다 **과거 시계열 불연속**을
   만드니 DECISION_LOG 기록이 필수다.
4. **F5는 진단 먼저** — 가설 단계에서 스케일러를 손대면 3개 호라이즌이 흔들린다.
5. **F6+F7 동반** — F7 단독은 "유령 기준선이 나쁘다"는 진단만 있고 대체 기준이
   없는 상태에서 교체 정책을 바꾸는 것이라 더 위험하다.
6. **F4·F10-B는 섀도 10거래일** — 313차 원칙(하루치로 정책 변경 금지). 오늘
   TP1 7/8 절단은 **1일 표본**이고, 채널 [25]가 SUSPENDED라 오프라인 재현도 못 한다.
