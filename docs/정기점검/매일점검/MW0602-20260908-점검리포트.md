원인은 단순하다 — 이 함수는 **날짜가 아니라 조회할 일수(days)** 를 받는다

### 2. 그 확인 중에 나온 것 — 2026-09-07 손익이 136,000원 과소로 기록돼 있다

판정 원천**이다(493차 F-1). 여기가 틀리면 "실전에 나가도 되는가"의 답이 틀린다.

### 3. 구현한 것 — 진단 도구가 "찾아낸 순간에만" 죽고 있었다 (A등급)

**증상.** 위 진단을 처음 돌렸을 때, 오염을 **찾아내 놓고 출력하다 죽었다**:

```
🔴 1일 오염
Traceback ...
ValueError: unsupported format character ',' (0x2c) at index 2
```

**원인.** 금액 포매터가 `("%+,.0f" % v)` 였다. printf 계열 포맷에는 `,` 천단위 플래그가
없다(그건 `str.format` 쪽 문법이다) — 즉 **호출되면 무조건 죽는다.**

**왜 지금까지 안 드러났나.** 이 포매터는 **오염이나 불연속이 있을 때만** 호출된다.
아무것도 못 찾은 날에는 한 줄도 실행되지 않는다. 게다가 `--json` 경로는 그 앞에서
return 하므로 무사하다. 결과적으로 *진단이 무언가를 발견한 바로 그 순간에만 죽는 계측*
이었다 — FP-CRITICAL 죽은 게이트, TOX 죽은 섀도와 같은 계열이다(계측 4원칙 ④).
501차가 D1 전례 4일을 겪은 뒤 만든 도구인데, 정작 다섯 번째 오염을 사람에게 전달하지
못했다.

**고친 것.** `scripts/broker_net_chain_audit.py` — 포매터를 모듈 수준 `_fmt_krw()`로
분리하고 `"{:+,.0f}".format(v)`로 교체. `None`은 계속 `"-"`로 찍는다(미측정을 0으로
위장하지 않는다 — 계측 4원칙 ②).

**무엇을 건드리지 않았나.** 이 스크립트는 **아무것도 쓰지 않는 읽기 전용 진단**이다.
판정식·임계·DB·매매 경로·설정은 전혀 손대지 않았다. 걸리는 시간 5분, 안 하면 다음
오염도 같은 방식으로 조용히 가려진다.

**결과** — 이제 끝까지 렌더된다:

```
── D1. 롤오버(장후 정산) 판독 오염 ──
  🔴 1일 오염
     2026-09-07  장중       -164,948  vs  기록        -28,948   (마지막 롤오버줄 22:02:15)
── D2. 체인 연속성 ──  🔴 불연속 3건
── D3. 거래일 판정 음성 캐싱 ──  🔴 9일 (전부 이후 소급 적재됨)
── 부가. D1 가드 배선 여부 ──  ✅ `_scan_lines` 에 롤오버 가드 있음
```
