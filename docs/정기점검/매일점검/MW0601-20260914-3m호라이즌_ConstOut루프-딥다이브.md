## 0. 결론 (한 줄)

**GBM은 상수로 수렴한 적이 없다.** `[ConstOut] 3m 상수 출력` 은 다른 안전장치
(`[BiasReset]` uniform fallback)가 만든 **확정적 부산물**이고, 그 부산물이
「모델 붕괴」로 오진되어 장중 재학습을 부르고, 그 재학습이 **BiasReset 쿨다운을
중도 해제**해 같은 상태로 되돌린다. 사슬이 닫혀 있어서 하루 4~6회 반복된다.

즉 **재학습은 증상조차 걷어내지 않았다** — 걷어낼 증상이 GBM 쪽에 없었다.
재학습이 한 일은 ① 40,818행 CV 검증 모델을 4,800행 무검증 모델로 교체하고
② CB③ 표본을 버리고 ③ BiasReset 쿨다운을 중단시킨 것이다.

### ③이 핵심이다 — 무정보가 UP 신호로 세탁된다

`_apply_horizon_calibration()` 의 `direction==0` 분기:

```python
other_total = max(up + down, 1e-9)              # = 2/3
flat = cal_conf                                  # = calibrate(1/3) ~= 1/3
up   = (up   / other_total) * (1 - cal_conf)     # = (1-c)/2
down = (down / other_total) * (1 - cal_conf)     # = (1-c)/2   <- up 과 완전 동일
best = max([(up, 1), (down, -1), (flat, 0)], key=lambda item: item[0])
```

`up == down` 이 **비트 단위로 동일**하므로 `max()` 는 리스트 **첫 원소**를 돌려준다
→ `direction = +1`. 보정기가 미fit이면 `calibrate()` 가 passthrough
(`learning/calibration.py:336`)라 `c = 1/3` 정확, 따라서 `conf = (1-1/3)/2 = 0.3333` **상수**.

관측값과 정확히 일치한다:

```
[ConstOut] 3m 상수 출력 5분 감지 (range=0.0000 dir=+1)
[DBG-F6] ... 3m:+1@33% ...
```

⚠ `range=0.0000` 은 「거의 같다」가 아니라 **정확히 같다**는 뜻이다. 임계는
`< 0.005`(`_CONST_OUT_RANGE`)인데 실측이 0.0000 인 것은 살아 있는 GBM 이
만들 수 있는 값이 아니다 — 상수를 대입했을 때만 나온다.

## 3. 왜 항상 3m 인가 — 표본 부족이 아니라 **산수**다

ConstOut 은 버퍼 5개가 차야 판정한다(`_CONST_OUT_N=5`). 그런데 버퍼는
**배포된 분에만** 쌓인다(`if not _res_h: continue`). 배포 주기는
`HZ_DEPLOY_POLICY` + `BAR_ONLY_RELAX_MAX_AGE=1` 로 정해진다:

| 호라이즌 | 배포 | 5개 채우는 데 | 20분 창 안에 가능? | 실측(10일) |
|---|---|---|---|---|
| 1m | 매분 | 5분 | — (감지 대상 **제외**, 331차) | 0 |
| **3m** | 3분 중 **2분** | **약 7분** | **가능 — 여유** | **48** |
| 5m | 5분 중 2분 | 약 12분 | 가능 — 빠듯 | 8 |
| 10m | 10분 중 2분 | 약 22분 | **불가 — 초과** | 0 |
| 15m | 15분 중 2분 | 약 32분 | 불가 — 초과 | 2 |
| 30m | — | — | — (감지 대상 제외, 296차) | 0 |

**BiasReset 의 20분 창 안에 ConstOut 버퍼를 채울 수 있는 호라이즌이 3m(과 5m)뿐이다.**
실측 빈도 48 : 8 : 2 : 0 이 이 순서와 정확히 같다. 3m 이 특별히 병든 것이 아니라,
**3m 만 아티팩트를 완성할 시간이 있다.**

10m·15m 은 오늘도 BiasReset 이 걸렸지만(10:24 10m, 11:09 15m) ConstOut 으로는
가지 않았다 — 예측대로다.

### 미검증 가설 → **장후 확인 완료 (16:4x)**: 기전은 실재, 크기는 작고, 방향은 반대

`_bias_buf` 기록은 `if _h_name_v in self._bias_override_horizons: continue` 로
override 중에는 건너뛴다(`main.py:6658`). 그런데 판정은 **채점 시점**의 멤버십으로
한다. ⑥이 override 를 조기 해제하면, override 중에 나간 아티팩트 `+1` 예측들이
해제 후에 채점되어 `_bias_buf` 에 진짜 UP 예측처럼 재유입될 수 있다 — 가 가설이었다.

**`predictions.db` 실측(2026-09-14, 장 마감 후):**

**ⓐ 아티팩트가 DB 에 진짜 예측으로 적재된다 — §1의 산수가 행 단위로 확인됐다.**
3m 245행 중 **44행**이 `up_prob == down_prob`(비트 동일) · `flat_prob` 가 그보다
**작다**:

```
2026-09-14 11:14:00  dir=+1  conf=0.3334  up=0.3334  dn=0.3334  fl=0.3333  correct=0
```

`up == down > flat` 이라 `max([(up,1),(down,-1),(flat,0)])` 가 리스트 첫 원소를
집어 `direction=+1` 이 된다 — ③의 tie-break 가 **로그가 아니라 저장된 숫자로**
입증됐다. 배포 간격(2/3분)도 행 간격으로 그대로 보인다.

**ⓑ 재유입은 일어난다. 단 해제 경계당 1~2행이다.**
아티팩트 44행 중 채점 시점(ts+3분)이 버퍼 clear 시점 이후인 것은 **10행**:

| clear | 종류 | 재유입 |
|---|---|---|
| 09:48 | 타이머(20분) | 1 (09:46) |
| 11:17 | **재학습** | 1 (11:14) |
| 12:40 | **재학습** | 2 (12:37·12:38) |
| 13:19 | **재학습** | 2 (13:16·13:17) |
| 13:58 | **재학습** | 2 (13:55·13:56) |
| 14:37 | **재학습** | 2 (14:34·14:35) |

`_bias_buf` 판정 문턱이 `_tot >= 15` 이므로 최대 **2/15 ≈ 13%** 오염이다.

**ⓒ 방향이 반대다 — 증폭이 아니라 희석이다.**
재유입되는 것은 `predicted=+1`(UP)인데, 각 clear 이후 실제로 발동한 3m BiasReset 은
**전부 `FL편향`** 이었다(12:32 87% · 13:11 90% · 13:50 90% · 14:29 90% · 15:08 81%).
UP 행은 FL 비율을 **낮춰** 오히려 발동을 늦춘다. **"아티팩트가 다음 BiasReset 을
불렀다" 는 증거는 없다.**

⇒ **사슬은 한 겹 더 닫히지 않는다.** ①~⑥ 만으로 충분히 설명된다.
P0-1 이 재학습발 clear 를 없애면 경계는 **타이머 해제만** 남아 빈도가 1/3 수준으로
줄고, 오염도 같이 준다. **별도 조치 불필요** — 다만 P0-2 를 넣으면 아티팩트가
`direction=0` 이 되어 ⓐ·ⓑ 가 원천 소멸한다(그때 이 절을 갱신할 것).

## 5. 개선계획

### 원칙

1. **진단기와 안전장치를 분리한다.** ConstOut 은 GBM 을 진단하는 장치인데 지금은
   GBM 이 아닌 값을 읽고 있다.
2. **무정보에 방향을 붙이지 않는다.** (계측 4원칙 ② — 미측정 ≠ 0)
3. **한 번에 하나씩, 섀도 먼저.** 아래 P0-1 은 무해하지만 P0-2 는 `direction` 을
   바꾸므로 매매 정책 변경이다.

### P0-1 — ConstOut 판정에서 bias-override 호라이즌을 뺀다 · **무해 · 즉시**

`main.py:8028` 트리거 직전에서 거른다.

```python
_const_hz_raw = decision.get("const_output_horizons", [])
_co_bias  = [h for h in _const_hz_raw if h in self._bias_override_horizons]
_const_hz = [h for h in _const_hz_raw if h not in self._bias_override_horizons]
if _co_bias:
    log_manager.system(
        f"[ConstOut] {_co_bias} 억제 — BiasReset uniform fallback 구간 "
        f"(GBM 출력 아님)", "INFO")
```

- **효과**: 오늘 4건 중 4건, 10거래일 57/58건이 사라진다. 진성 1건(`range=0.0040`)은 그대로 통과.
- **계측 4원칙 ③ 준수**: 억제 건수를 `_mh_const_out_by_hz` 와 **별도 카운터**
  (`const_out_suppressed_bias`)로 남긴다 — 지웠다고 안 세면 안 된다.
- **검증**: 다음 거래일 `[ConstOut] … 억제` 가 BiasReset 직후에만 뜨고,
  장중 재학습이 0~1회로 떨어지는지.
- **회귀 가드**: `tests/test_564_constout_bias_suppression.py` — uniform fallback
  상태를 주입했을 때 재학습 예약이 **일어나지 않을 것**.

### P0-2 — uniform fallback 이 방향을 만들지 않게 한다 · **정책 변경 · 섀도 선행**

`_apply_horizon_calibration()` 의 `best = max(...)` 가 `up == down` 동률을
`+1` 로 깨뜨린다. 두 가지 수정안:

- **(a) 최소**: 동률이면 입력 `direction` 을 보존한다.
  ```python
  if abs(up - down) < 1e-12 and flat <= up:
      best = (up, direction)     # direction=0 유지
  ```
- **(b) 정직**: fallback 행에 `no_signal=True` 를 달고 보정 자체를 건너뛴다.
  `WEIGHT_COLLAPSE_HONEST_MODE` 와 같은 취지(계측 4원칙 ④ 폴백 가시화).

권고는 **(b)** 지만, `direction` 소비처(체크리스트·라우터·DB·F1 가중)를 먼저
훑어야 한다. **섀도 로그 1주 → 주간회의 승인 → 전환** 순서.
⚠ P0-1 을 먼저 넣으면 P0-2 는 급하지 않다 — 사슬이 이미 끊긴다.

### P0-3 — 재학습의 BiasReset 초기화를 **scope 안으로 제한** · 저위험

`main.py:5743`:

```python
_scope = result.get("scope") or list(HORIZONS)      # scoped intraday 는 ['3m']
for _bh in _scope:
    self._bias_override_horizons.discard(_bh)
    self._bias_fl_streak[_bh] = 0
    self._bias_override_timer[_bh] = 0
    self._bias_buf[_bh].clear()
```

- **근거**: D4. 3m 전용 재학습이 1m·15m 쿨다운을 지우는 것은 원 주석의 의도
  (「새 GBM 기준으로 초기화」)와도 어긋난다 — 그 호라이즌들의 GBM 은 바뀌지 않았다.
- `CONST_OUT_RETRAIN_SCOPED=True` (457차)가 이미 학습 쪽은 scope 로 좁혀놨는데
  **상태 초기화만 전역으로 남아 있다.** 457차 조치의 누락분이다.

### P1-1 — ConstOut 이 **보정 전 GBM raw conf** 를 보게 한다 · 근본 수정

지금 `_hz_conf_hist` 에 들어가는 값은 `GBM → SGD 블렌드 → RF 블렌드 →
BAR_CACHE_DECAY → bias fallback → Platt 보정` 을 전부 통과한 뒤의 값이다.
**GBM 을 진단하겠다면서 GBM 출력이 아닌 값을 본다.**

`main.py:7458` 이 이미 `_gbm_raw_conf` 를 뽑아 두고 `[CONF⚠]` 로그에만 쓴다.
그 값을 `horizon_proba[h]["gbm_raw_conf"]` 로 실어 보내고 ConstOut 버퍼가 그것을
읽게 한다.
⚠ **임계 재보정 필수** — raw conf 분포는 보정 후 분포와 다르다.
`_CONST_OUT_RANGE=0.005` 를 그대로 쓰면 안 된다. 사전등록 → 섀도 2주 → 전환.

### P1-2 — ConstOut → **GBM 재학습 예약** 자체를 재검토

- 증거 2-4: 재학습이 실패한 날에도 ConstOut 은 1분 만에 해소됐다.
- ConstOut 의 명시적 처방은 「스케일러 재적합」이고(수초), GBM 재학습은
  「scaler 재적합 후 트리 구조 갱신 필요」라는 **추론**으로 덧붙은 것이다.
- 그 재학습은 40,818행 CV 검증본을 4,800행 무검증본으로 바꾼다(D1).
- **제안**: `range == 0.0` (아티팩트 지문)이면 재학습을 예약하지 않는다.
  P0-1 이 들어가면 자동으로 충족되지만, **P0-1 의 이중 안전망**으로 남길 가치가 있다.

### 🔴 그런데 통과한 1건도 오탐이다 — **BiasReset 과 무관한 제3의 계열**

```
10:59:00 [ConstOut] ['3m'] 상수 출력 확정 → 스케일러 재적합 시작
         | bias_override=N gbm_raw(3m=0.3623)
10:59:00 [ConstOut] 3m 상수 출력 5분 감지 (range=0.0000 dir=+0)
```

`dir=+0` 이다 — 어제 아티팩트 8건은 전부 `dir=+1` 이었다. `predictions.db` 실측:

| ts | flat(=conf) | up | down | up:down |
|---|---|---|---|---|
| 10:52 | 0.3603 | 0.3375 | 0.3022 | 1.12 |
| 10:53 | 0.3602 | 0.3354 | 0.3044 | 1.10 |
| 10:55 | 0.3601 | 0.3016 | 0.3383 | **0.89** |
| 10:56 | 0.3601 | 0.2951 | 0.3448 | **0.86** |
| 10:58 | 0.3598 | 0.3387 | 0.3015 | 1.12 |
| 10:59 | 0.3597 | 0.2978 | 0.3425 | **0.87** |

**최댓값 채널(flat)만 상수이고 방향 채널(up:down)은 1.12 ↔ 0.86 으로 뒤집힌다.**
모델은 살아 움직이는데 ConstOut 이 「붕괴」로 읽었다.

원인은 **감지 정의가 1차원**이라는 것이다 — ConstOut 은 `(direction, max_prob)` 만 본다.
`dir=0` 구간에서 `max_prob` 은 곧 `flat = cal_conf`(Platt 출력)이고, 그 값이 4자리에서
거의 멈추면 3자리 반올림에서 `range=0.0000` 이 된다. 그동안 up/down 이 무엇을 하든
감지기는 보지 않는다.

⚠ **상수의 출처는 이 로그만으로 가릴 수 없다.** 「GBM 의 flat 확률이 원래 멈춰 있었다」와
「Platt 이 raw 변동을 압축했다」가 구분되지 않는다. `[CONF⚠]`(보정 전 conf 고착) 부재는
근거가 못 된다 — `BAR_CACHE_DECAY` 가 `0.97^bar_age` 로 3분 주기 변조를 걸어
**3m·5m 에서는 그 경보가 구조적으로 발화할 수 없다**(별건 결함, 아래 등록).
⇒ 가리려면 **분당 raw conf 계열**이 필요하다. 그게 정확히 **P1-1** 이 만드는 것이다.

**함의 세 가지**
1. **P1-1 의 우선순위가 올라간다.** 오늘 근거가 라이브에서 나왔다 — 더 이상 이론이 아니다.
2. **이 계열은 `dev` 에도 있다.** 464차 P5-a(감지기 bias 제외)도 `dir=0` + Platt 압축
   경로는 막지 못한다. §9 의 「dev 가 앞선다」는 P0-1 계열에 한정된 이야기다.
3. **P2-1 이 하루 만에 값을 했다.** `gbm_raw` 병기가 없었으면 이 1건을 어제 8건과
   같은 것으로 묶어 「1건 남았네」로 끝냈을 것이다.

**신규 등록 (P1-1 에 합류)**
- `[CONF⚠]` 고착 경보는 `BAR_CACHE_DECAY` 변조 때문에 3m·5m 에서 발화 불가다
  (`abs(curr-prev) < 1e-6` 를 `0.97^age` 주기가 항상 깬다). FP-CRITICAL·TOX 섀도와 같은
  **죽은 계측** 계열 — 발화한 적이 있는지 이력으로 확인할 것.
- `bias_override=N` 은 **하드코딩된 리터럴**이다(그 로그는 필터를 통과한 것만 찍으므로
  구조상 참이지만 측정값이 아니다). 계측 4원칙 취지상 실제 상태를 찍도록 고칠 것.

### 설계 판단 세 가지

**① raw 를 `horizon_proba` 에 얹지 않고 곁채널로 넘긴다.**
그 dict 는 블렌드·bias 폴백·배포필터·보정에서 **네 번 통째로 재생성**된다. 키를 얹으면
한 곳만 빠뜨려도 조용히 사라지는데, 그건 미측정이 아니라 **오측정**이다. 대신
`self._gbm_raw_conf_last` / `_dir_last` 를 **매분 비우고** 블렌드 루프 한 곳에서만
채운다 — 못 채우면 `None`(미측정)으로 남는다.

**② 미측정 호라이즌은 전환해도 live 판정을 유지한다.**
raw 를 관측하지 못한 호라이즌까지 raw 기준으로 판정하면, GBM 미준비 구간에 감지가
**통째로 사라진다**. 미측정을 "정상"으로 읽는 계측 4원칙 ② 위반이다. `_raw_seen` 이
그 경계다.

**③ `const_output_horizons_live` 는 플래그와 무관하게 항상 현행 규칙 결과다.**
전환은 **지표 재정의**라 그 날짜에 471차 G-2 채널 시계열이 끊긴다. live 축을 남겨 두면
앞뒤를 같은 잣대로 이을 수 있다(461차 `mdd_pct` 교훈).

### 사전등록 판정 기준 (스크립트 상단에 고정 — 결과 보고 고치지 말 것)

```
P1 표본   : ≥10 거래일 AND 호라이즌별 raw 관측 ≥1,000분
P2 방향   : 0 < raw 발화 분 < live 발화 분   (오탐은 줄되 감지는 남는다)

            — "우연히 못 잡았다"가 아니라 "명백히 변동 중이었다"
P4 안정성 : 선택 임계 ±20% 에서 P2·P3 유지
선택      : 통과 후보 중 **가장 큰** 임계 (range < 임계 → STUCK 이므로 클수록 민감)
```
