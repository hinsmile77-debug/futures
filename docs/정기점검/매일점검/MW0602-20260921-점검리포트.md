## 세션 자가진단 — 이 세션이 만든 `.git/index.lock` 1건, 즉시 회수함

이 점검 세션이 규약을 스스로 어긴 사례가 하나 있었다. `--no-optional-locks` 없이
`git -c core.autocrlf=true status --porcelain`(CRLF 노이즈를 걷어내고 실질 변경만
세기 위한 조사용 명령)을 직접 실행했는데, 이 마운트에서는 그 옵션 없는 호출이
`.git/index.lock`을 만들고 그 `unlink`가 `EPERM`으로 실패한다(SKILL.md §0 경고 그대로).
`ls -la`로 즉시 확인: 생성 16:36:34, 발견 16:36:40(6초 경과) — 이 세션의 직전 명령이
만든 것임이 명백해 `invariants.md` §0-B의 rename 우회(`mv .git/index.lock
.git/index.lock.stale.$$`)를 바로 적용했고, 이후 `git --no-optional-locks status`가
정상(rc=0) 동작함을 확인했다. 이후 모든 git 호출은 `--no-optional-locks`를 지켰다.

- **영향**: 매매·리포트 내용에는 영향 없음. 회수도 이 세션 안에서 끝났다.
- **영향(기술)**: 회수 후에도 `.git/index.lock.stale.5`라는 이름 바뀐 빈 파일이 남아 있다
  (이 마운트는 이름을 바꾼 뒤에도 `rm`을 `EPERM`으로 거부한다 — 더 이상 `.lock` 이름이
  아니므로 git 동작에는 지장이 없는 순수 잔여물). 삭제는 사용자 조치로 아래에 올린다.
- **교훈**: SKILL.md §0의 규약("모든 git 명령, 세션이 손으로 치는 것도 예외 없이")을

**4-2. 313차 다섯 갈래 — 전부 적용**

① **일자단위**: 오늘은 관측 거래일 **1일**뿐이다. 포지션 4건은 독립 관측치가 아니라
같은 날 같은 레짐·같은 모델 스냅샷을 공유한다 — 아래 모든 서술은 "관찰"이지 "결론"이 아니다.

② **overlap 보정**: 4포지션은 09:34→09:39, 09:53→10:00, 10:59→11:00, 11:10→11:12로
**전부 순차 진행(비중첩)**이다. 표본을 부풀리는 중첩 문제는 해당 없음.

③ **이상치 분해(drop-worst)**: CASE-01(-205,178원)을 제외하면 나머지 3건 합계는
**+23,418원(흑자 전환)**이다. 오늘 하루의 순손실은 **단일 이상치 1건에 전적으로
의존**한다 — 평균만 보면 "오늘은 손실"이지만 중앙값 관점(4건 중 3건 소액~중폭 이익)은
다른 그림을 보여준다.

④ **사전등록**: 이번 절에서 새 임계·파라미터 변경을 제안하지 않는다. CASE-02가
시사하는 "Loss Tier1과 TP1의 순서 경합"은 기존 설계(363차)이며 §13에 등록된 판정이
없으므로 **관찰로만 등록**하고(§9P), 표본이 쌓이기 전에 문턱을 만들지 않는다.

⑤ **부호 일관성**: 관측 1일뿐이라 기간 전후 비교가 불가능하다 — **판단 보류.**

**결론 표현 수위** (postmortem.md §4-2 표 그대로 적용):

| 상황 | 이번 리포트의 표현 |
|---|---|
| 당일 포지션 4건, 요인별 n<10·관측일<3 | "관찰", "가설 등록"만 사용. "원인이다"·"조인다" 미사용 |
| CASE-01 손실이 하루 전체를 좌우 | "이상치 1건 의존" 명시, 파라미터 변경 근거로 쓰지 않음 |

**함정② 재확인**: 이 절에서 2026-08-01 §9-3 이벤트 단위 사이징 통계, 2026-06-25
