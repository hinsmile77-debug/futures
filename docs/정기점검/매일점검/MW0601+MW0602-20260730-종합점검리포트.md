## 1-C. **정정이 필요한** MW0602 진단 1건

### ⑧ 손익비 3:1 역전의 원인은 `trend` 배수가 아니다 — **전 버킷 상시 구조**

MW0602 P1-5는 `HURST_REGIME_ATR_MULT["trend"]`(1.20)가 stop만 넓혀 3:1을 만들었다고 진단했다. **설정값을 실제로 계산해 보면 hurst 배수는 비율에서 약분된다.**

```
stop = ATR × ATR_STOP_MULT(1.5)          × hurst_mult
TP1  = ATR × ATR_HORIZON_TP1_MULT[hz]    × hurst_mult   ← 같은 배수가 곱해짐
```

| hurst | 1m | 3m | 5m |
|---|---|---|---|
| trend (×1.20) | **5.00 : 1** | **3.00 : 1** | **2.14 : 1** |
| neutral (×1.00) | **5.00 : 1** | **3.00 : 1** | **2.14 : 1** |
| mean-revert (×0.85) | **5.00 : 1** | **3.00 : 1** | **2.14 : 1** |

MW0601 오늘 207번(hurst=**mean-revert**, 3m, ATR=5.5929)으로 검산:
```
stop = 5.5929 × 1.5 × 0.85 = 7.131  → 878.67  ✓ (로그 손절=878.67)
TP1  = 5.5929 × 0.5 × 0.85 = 2.377  → 869.16  ✓ (로그 1차=869.16 ×0.42)
비율 = 3.00 : 1                              ← trend 아님에도 동일
```

**진짜 원인은 `ATR_STOP_MULT=1.5` vs `ATR_HORIZON_TP1_MULT`(1m 0.3 / 3m 0.5 / 5m 0.7)이고, hurst 버킷·시장 상황과 무관하게 전 거래에 상시 적용된다.** MW0602가 생각한 것보다 훨씬 광범위한 문제다.

**그리고 1계약에서는 더 나쁘다.** MW0601 SYSTEM_AUTO 57건 중 **56건(98%)이 qty=1**이다. qty=1이면 TP1 부분청산이 불가능해 `synthetic_partial_exits` 경로로 **본전 스톱 전환만** 일어난다. 실질 페이오프는:

```
상방: TP1(0.5×ATR) 도달 → 스톱이 본전으로 → TP2(1.5×ATR)까지 가야 실익
      그 사이 되돌리면 = +0
하방: −1.5×ATR
```

**즉 1계약 포지션의 상방은 사실상 0으로 캡되고 하방만 열려 있다.** 이것이 ④(틱스톱 이익 6건 평균 +1.01pt = 본전 긁기)와 ⑦(캡처율 9.7%)의 공통 뿌리다.

```
09:47  1m w=0.000(FLAT)  3m w=0.0721(FLAT)  30m w=0.000(FLAT)  → 앙상블 SHORT
09:56  1m w=0.000(FLAT)  3m w=0.0646(SHORT) 30m w=0.000(FLAT)  → 앙상블 SHORT
```
**09:47은 세 호라이즌이 전부 FLAT인데 앙상블이 SHORT를 냈다**(마이크로게이트 `soft_adjust` −0.196이 밀어냄). 그리고 그 유일한 실효 호라이즌 3m은 오늘 `[ConstOut] ['3m'] 상수 출력 확정`이 **8회** 찍혔다 — 유일한 의사결정자가 8번 자진 신고한 셈.

**→ 조치: 즉시 변경 금지.** `BAR_ONLY_RELAX`(401차) 판정이 08-03에 나오므로 그 결과를 먼저 볼 것. 다만 **"유효 가중합"을 `weight_collapsed`(0/1)와 별개 연속값으로 계측**해 대시보드·DB에 남길 것을 권한다 — 현재 `weight_collapsed`는 완전붕괴(합=0)만 잡아 중앙값 0.15의 준붕괴를 놓친다.
