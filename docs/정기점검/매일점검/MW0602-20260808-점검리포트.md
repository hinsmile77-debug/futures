## 1. 검토 — 결함이 이 PC에 내재돼 있었는가

441·442차는 **스크립트 3종의 코드 결함**이다. 이 저장소는 두 PC가 공유하므로
PC별 데이터·환경과 무관하게 그대로 내재된다. cherry-pick **전** dev 코드에서
세 지점을 직접 확인했다.

| 결함 | 내재 | 확인 위치 (수정 전) |
|---|---|---|
| ⓐ 판정식 단위 3중 불일치 | ✅ | `sim_fidelity_gate.py:103` — `SELECT entry_ts, SUM(pnl_pts)` (레그별 계약당 pt의 **무가중 합**인데 시뮬은 1계약, 게다가 시뮬만 왕복비용 차감) |
| ⓑ close 세대 TP 체결가 자기모순 | ✅ | `exit_replay.py` — 트리거는 `hit = (cl >= px)`(종가)인데 체결은 `realized += sgn * (px - entry_px) * send`(**목표가**) |
| ⓒ [3-B] 자체 시뮬의 TP1 만점 처리 | ✅ | `quantile_tp_shadow.py:_simulate` — `if hit_tp: return "TP1", (tp1_px - entry_px)` (TP1 목표거리를 **확정이익으로 계상하고 즉시 종료**) |

ⓒ가 특히 위험한 이유는 442차가 지적한 그대로다 — 이 채널의 질문이 "TP1 거리를
무엇으로 정하나"인데, 시뮬이 **TP1을 넓힐수록 공짜로 점수가 오르는 구조**라
답을 직접 오염시킨다.

> ※ 참고: 직전 `fbd94be`(0807 리포트 복구)의 py310_64 BLAS 파손은 **런타임 환경**
> 문제라 성격이 다르다. 그건 이 PC에서 음성이었다(PATH 최소화 재현에도 `np.dot` 정상,
> `MireukiEODRetrain` 작업 미등록, 0807 리포트 정상 생성). 441·442차는 그와 달리
> **코드**라 음성일 수 없었다.

### 충돌 처리 — 미존재 채널 등록 회피

441차 diff는 채널 로더에 두 항목을 등록한다. 그중 `entry_context_shadow`는
**MW0601 436차**가 만든 것이라 diff에 컨텍스트로 딸려온 것이고, 이 PC에는
`scripts/entry_context_shadow.py`가 없다(dev의 436차는 [MW0602] 0806 일일점검으로
번호만 겹치는 별개 작업).

→ 441차가 실제로 신설한 `tp_fill_overshoot_watch`만 등록했다. 그대로 가져왔다면
로더가 매주 `INSUFFICIENT + ModuleNotFoundError`를 찍었을 것이다(try/except로
격리돼 리포트 전체가 죽지는 않지만 무의미한 오류 행이 남는다).

**같은 계열 선례**: 311차 후속4·403차 종합에서 v9-dev 전용 `SoftGateScorer`/
