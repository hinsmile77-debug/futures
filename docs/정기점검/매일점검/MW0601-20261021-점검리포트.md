- **근거**: `data/db/trades.db`의 `exit_stage='TRAIL_AFTER_TP1'` 레그는 오늘 7건(포지션 기준 7건 — 1개 포지션은 신동 자체 1차청산 레그와 함께 2레그 구성). 시스템 자체 자기대사 로그가 이것을 그대로 지적한다:
  ```
  2026-10-21 15:40:14 [WARNING] SYSTEM: [ExitStageRecon] 오늘 TRAIL_AFTER_TP1 7레그 / 7포지션 중 TP 이벤트 대응 0 · 단일계약 보호전환(설계) 0 · 미대응 7 ⚠ 미대응 합계 +1,264,203원 (진입 09:34:13, 10:48:13, 11:30:13, 11:37:13, 12:25:13 외 2건)
  ```
  이 7건을 포지션 단위로 나누면 승 3(+1,038,595 / +196,576 중 일부 / +751,609) · 패 4(−196,412 / −81,408 / −236,396 / −208,361)다. **승패를 가른 것은 트레일 전환 뒤 가격이 계속 유리하게 갔는가 반전했는가뿐**이고, 7건 전부에서 신동 자체의 1차 목표가(`t1`, `strategy/shindong/live_legs.py:poll()`)에 닿아 1계약을 먼저 떼어 놓는 처리는 **한 번도 일어나지 않았다**(2개 레그로 쪼개진 포지션 1건을 빼면 전부 단일 레그로 전량 청산). 즉 외부 손절(틱 하드스톱, `strategy/position/position_tracker.py:613`의 `tp1_armed` 판정)이 신동 자신의 1차 목표가보다 **먼저** 발동해 트레일 모드로 넘어간 뒤, 신동의 1차 분할청산 기회 자체가 발생하지 않았다.
- **기준 위반**: 명시적 절대원칙 위반 아님. 설계 간극(신동의 가격 목표 기반 분할청산 로직과, 외부 ATR 기반 TP1 트레일 전환 로직이 서로 독립적으로 작동) 가능성.
- **영향**: 오늘은 이 패턴에 걸린 7건의 합계가 +1,264,203원으로 순이익이었다(3승이 4패보다 금액이 커서). 하지만 이것은 우연한 결과다 — 트레일 전환 뒤 반전해 손실로 끝나는 비율이 4/7(57%)이었다는 것은, 트레일 전환 시점에 1계약만 먼저 이익을 확정해 두는 처리가 있었다면 그 4건의 손실 폭이 줄었을 수 있다는 뜻이다.
- **영향(기술)**: 신동 실집행(`strategy/shindong/live_legs.py`)의 레그 분할은 전적으로 자기 자신의 `t1`(1차 목표가)에만 반응하고, 외부 포지션 트래커의 `tp1_armed`/`TRAIL_AFTER_TP1` 상태 전환을 구독하지 않는다. 두 메커니즘의 상대적 거리(어느 쪽이 가격에 더 가까운가)에 따라 어느 쪽이 먼저 발동하는지가 매 포지션 갈린다 — 오늘 표본에서는 외부 트레일이 7/7 전부 먼저 발동했다.
- **신규 여부**: 신규. `dev_memory` 전체를 "TRAIL_AFTER_TP1"+"신동" 키워드로 검색했으나 신동 채널에 한정해 이 조합을 다룬 기존 기록은 없었다(기존 P5-06은 **엔진(SYSTEM_AUTO) 채널 전용** 항목이라 신동과는 별개 — 혼동 금지).
- **313차 주의**: 표본 1거래일(7레그/7포지션)이다. "손절 지연"이나 "확률"로 단정하지 않는다 — 관찰 등록만 한다.
