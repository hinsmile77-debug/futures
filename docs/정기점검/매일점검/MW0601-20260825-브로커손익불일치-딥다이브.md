## 4. 왜 기존 대사가 못 잡았나 — gross끼리 비교하는 사각지대

477차 F-4의 EOD 대사([main.py:11772-11797](main.py#L11772-L11797))는
CpTd6197 실현손익이 **수수료 차감 전(gross)** 이라는 실측(0818) 위에 설계됐다.
그래서 `broker gross vs engine gross`를 비교하고 — 이 축은 완벽히 일치한다.
**수수료는 엔진 가정값이 그대로 net이 되어 어떤 대조도 받지 않는다.**

계측 4원칙 ④의 전형이다: 가정값(수수료 6,235원)이 로그·DB·패널에 정상값처럼 흘렀고,
"대사 일치" 문구가 오히려 신뢰를 보증했다. 예탁현금이라는 **정답지가 매일 로그에 찍히고
있었는데도**([Sizer] 실제잔고) 아무 계측도 그것과 net을 대조하지 않았다.

   (`_normalize_trade_pnl`)에서 요율 세대를 분기하거나 `commission_rate_used` 컬럼을
   신설해 행마다 남긴다(계측 4원칙 ④ — 어떤 가정으로 계산했는지 행에 쓴다).
5. ⚠ **모의투자 요율 ≠ 실전 요율일 수 있다.** 실전 전환 기준 ⑧(자본 재설정)에
   "실전 계좌 수수료율 확인·재설정"을 함께 묶을 것.

### F-2. 대사 축 확장 — net/현금 대사 신설 [P0, 재발방지 본체]

gross 대사(477차)는 유지하되, **예탁현금 축 대사**를 EOD에 추가:

```
전일 예탁현금 + 엔진 gross − 엔진 수수료 ≈ 당일 예탁현금
잔차 > 임계(예: max(5,000원, 엔진 수수료의 20%)) → WARNING [BrokerPnl] net 불일치
```

- 필요 데이터는 이미 있다 — 잔고 TR은 매일 조회 중이고 `[Sizer]` 로그에도 찍힌다.
  예탁현금 일별 스냅샷 테이블(또는 daily_broker_pnl 확장)만 있으면 된다.
- 이 대사가 있었다면 이번 결함은 **첫날 하루 만에** 잡혔다(매일 6.54배 잔차가 일정하게
  보였을 것). 수수료·세금·기타 현금흐름 계열의 미래 결함도 같은 그물에 걸린다.

### F-3. 비용 모델 소비처 일괄 재실행 [P1 — 주간회의 안건]

- 요율 확정 후 §5-2 소비처(L2 tradability, 캠페인 리포트 비용 항, cost_edge 계열,
  TP1 경제성·TOX 20틱 역산)를 새 요율로 재실행.
- ⚠ **사전등록 합격선 자체는 무변경**(458차 D6). 비용 상수는 "계측 정정"이지만 채널
  판정값을 움직이므로, 임의 적용하지 말고 **주간회의 승인 → 일괄 적용 → 적용일 마커**
  절차로. 적용 전후 리포트 직접 비교 금지 주석 필요.
- 26주 WFA 재검증 목록의 L1→L2→L3 절차에 "수수료율 실측 재확인"을 1줄 추가 검토.

### F-4. 실전 전환 기준 ①의 판정 원천 재정의 검토 [P1 — 주간회의 안건]

"4주 통산 수익률 양수"의 원천을 엔진 net이 아니라 **브로커 net(예탁현금 Δ 또는 정산
실현손익 − 실제 수수료)** 로 못박을 것을 제안. 엔진 net은 어디까지나 추정치이며, 이번
사례처럼 가정 하나로 ±50만원/6일이 움직인다.

### F-5. P&L 패널 이중 표기 [P2]

창4 P&L 패널에 `엔진 net (브로커 net, 대사 잔차)` 병기 — F-2가 계산하는 값을 그대로
표시만 하면 된다. 사용자가 오늘처럼 HTS와 눈으로 대조할 때 즉시 판별 가능해진다.

성공 로그에 **무엇을 비교했는지** 축 이름을 박아라 /
외부 원천이 **이미 주고 있는데 안 보고 있는 것**은 아닌지 먼저 확인하라.

### 9-9. 요율 근거 확장 + 오염일 처리 (구현 중 확장)

`--verify`가 처음에는 `logs/*_SYSTEM.log`만 훑어 **24거래일**이었다.
그런데 `SYSTEM`은 Tier B(압축) 채널이라 30일 뒤 `YYYYMM_SYSTEM.zip`으로 묶이고
원본이 지워진다 — **26주 주기 도구가 소급 표본을 조용히 잃는 구조**였다.
(기존 `tests/test_479_log_retention_tiers.py`가 이것을 자동 검출해줬다.)
→ 압축본 동시 소비로 고쳐 근거가 **39거래일 / 약정대금 447.3억원**으로 늘었다.

**압축본을 읽자 6일이 요율에서 크게 벗어났다** — 그리고 그중 하나는
**음수 수수료(2026-06-22, −0.0092%)** 였다. 수수료로는 불가능한 값이므로 원인은
수수료가 아니다. `예탁현금`(CpTd6197 idx=1)이 **당일 시가 고정**이라,
(a) 장중 입출금 (b) trades.db 미기록 체결(수동·복구 진입 → 약정대금 과소)
(c) 마지막 TR 판독이 최종 정산 전 — 중 하나가 섞이면 차이에 수수료 아닌 금액이 든다.

| 날짜 | 실효요율 | 중앙값 대비 |
|---|---:|---:|
| 2026-06-17 | 0.015075% | +54% |
| 2026-06-22 | **−0.009221%** | −194% |
| 2026-06-25 | 0.032485% | +231% |
| 2026-07-03 | 0.010392% | +6% |
| 2026-07-09 | 0.008963% | −9% |
| 2026-07-16 | 0.035023% | +257% |

이 6일을 그대로 합산하면 요율이 0.010467%(+6.7%)로 끌려가고 **R²가 1.000 → 0.563**,
게다가 잡음이 **레그당 362원의 허위 고정비**로 잡혔다 — "요율 상수 하나로는 재현
불가"라는 잘못된 결론에 닿을 뻔했다.

→ 추정기를 **중앙값 기준 견고화**로 바꾸고(중앙값에서 5% 초과 이탈 시 제외),
  🔴 **제외분은 날짜·수치·추정 원인까지 전부 인쇄**한다(계측 4원칙 ③ 탈락 가시화 —
  개수만 세고 숨기면 458차 `missing[:5]` 사고와 같아진다).
  정상 39일 기준: 요율 **0.009810%** · **R² = 1.000000** · 최대 잔차 **13.9원** ·
  고정비 성분 **+0.08원/레그 ≈ 0**.

⚠ **이 제외는 요율 추정에서만이다** — 손익 집계에서 빼지 않는다.
⚠ 오염일 6건의 정확한 원인(입출금인지 미기록 체결인지)은 **미규명**이다.
   전환기준 ① 4주 창(2026-07-28~)에는 오염일이 없어 판정에는 영향이 없다.
   전 기간 합계를 쓸 일이 생기면 그때 규명할 것.
