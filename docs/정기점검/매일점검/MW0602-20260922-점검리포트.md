## 2. Fix 작업 구현계획

### F-586-1 (P0) — `AdaptiveKelly.compute_fraction()` 0-분모 방어 + `PositionSizer` NaN 방어(2중 방어)

**함정① 확인**: `grep -rn "isnan\|isfinite" strategy/entry/adaptive_kelly.py strategy/entry/position_sizer.py` → 0건. 기존 방어 코드 없음, 신규 Fix 확정.

1. **1차 방어(근본 수정)** — `strategy/entry/adaptive_kelly.py:76-78`. 손실 리스트가 비어있을 때만 `0.001` 기본값을 쓰는 현재 로직을, **평균이 사실상 0인 경우까지 확장**한다.
   ```python
   avg_loss = (np.mean([l["loss"] for l in losses]) if losses else 0.001)
   if avg_loss < 1e-6:
       avg_loss = 0.001   # [586차] 손실=0(본전 청산)만 있는 경우도 "손실 표본 없음"과 동일 취급
   ```
   `avg_profit`도 대칭적으로 같은 가드를 추가(현재는 우연히 발생 안 하지만, 모든 승리가 0.0인 극단값도 이론상 같은 문제를 만들 수 있음).
2. **2차 방어(방어적 프로그래밍)** — `strategy/entry/position_sizer.py:220-223`. `raw_qty`가 유한하지 않으면(`nan`/`inf`) 크래시 대신 최소 수량으로 폴백하고 경고 로그를 남긴다.
   ```python
   raw_qty = (base_risk * conf_mult * regime_mult * grade_mult
              * adaptive_kelly_mult * safety_mults) / stop_risk
   if not math.isfinite(raw_qty):
       logger.warning("[Sizer] raw_qty 비정상(%s) — adaptive_kelly_mult=%s 등 입력 확인 필요, 최소수량 폴백", raw_qty, adaptive_kelly_mult)
       raw_qty = float(min_qty)
   kelly_advised_skip = raw_qty < 1.0
   quantity = max(min_qty, min(int(raw_qty), MAX_CONTRACTS))
   ```
   이 방어는 **오늘 못 찾은 제3의 NaN 유입 경로**가 있어도 크래시 대신 안전하게 최소수량으로 계속 거래를 이어가게 한다(계측 4원칙 ④ — 폴백을 썼다는 사실을 로그로 남긴다).
3. **회귀 위험**: 낮음. 1차 방어는 "손실=0인 표본만 있을 때"라는 매우 좁은 조건에서만 동작이 바뀌며, 그 경우 기존에도 의도했던 "데이터 부족 시 보수적 0.6배" 취지와 동일한 방향(손실 관측이 사실상 없으므로 과도한 승수를 주지 않음)이다. 2차 방어는 정상 경로에서는 절대 발동하지 않는다(`math.isfinite` 체크는 오버헤드 무시할 수준).
4. **검증**: `strategy/entry/adaptive_kelly.py`에 신규 단위테스트 추가 — 손실 전부 0.0인 20건 시나리오, 승리 전부 0.0인 시나리오, 정상 혼합 시나리오 3종에서 `multiplier`가 항상 `[0.1, 1.5]` 범위의 유한값인지 검증. `position_sizer.py`에도 `adaptive_kelly_mult=float('nan')` 입력 시 크래시 없이 `min_qty`를 반환하는지 검증하는 테스트 추가.
5. **적용 시점**: 장후 발견이므로 **지금 적용 가능**(라이브 프로세스는 15:47 종료됨, 16:35 재시작은 장후 리플레이용). 단, 이 세션(예약 실행)은 코드를 직접 수정하지 않는다 — Fix 계획만 제시하고 실제 적용은 사용자 확인 후 별도로 진행할 것을 권고한다(자동조치 예약이 등급 제한 안에서 처리할 수도 있으나, 이 변경은 진입 판단 로직에 직접 관여하므로 사용자 검토를 권장).

한 번 이름을 거칠 뿐 같은 기준이다.)

**근본 원인(0-손실 패배 → `b=inf` → `kelly_f=nan`)은 그대로 옳다.** 바뀌는 것은
**결함 표면의 크기**다:

| | 트리거 조건 | 해당 레그(전수 502) |
|---|---|---|
| 리포트 서술(KRW 기준) | pt 는 벌었는데 수수료로 KRW 마이너스인 레그 포함 | 4 + **6** = 10 |
| 실측(pt 기준) | **`pnl_pts` 가 정확히 `0.0` 일 때만** | **4** (07-22·08-31·09-11·09-22) |

pt 기준이므로 `win=False` ⟺ `pnl_pts <= 0` 이고, `loss = abs(min(pnl_pts,0))` 이 0 이
되는 것은 정확히 `0.0` 일 때뿐이다. 리포트의 「4건」 집계 자체는 맞았다 — 틀린 것은
그 옆의 설명이다. **KRW 쪽을 고치러 가면 헛다리를 짚는다.**
