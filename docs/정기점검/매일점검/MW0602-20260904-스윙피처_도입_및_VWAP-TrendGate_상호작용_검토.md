## 1. 피처 설계

### 1-1. 정의 (`features/technical/swing_extremes.py`)

윈도우 N ∈ {20, 60} 과 세션 전체(`day`) 각각에 대해, **당일 봉만**으로:

| 키 | 정의 | 범위 |
|---|---|---|
| `swing{N}_range_pos` | (close − L_N) / (H_N − L_N) | 0=저점 … 1=고점, 범위 0이면 0.5 |
| `swing{N}_high_dist_atr` | (H_N − close) / ATR | ≥0, 20 클립 |
| `swing{N}_low_dist_atr` | (close − L_N) / ATR | ≥0, 20 클립 |
| `swing{N}_high_age` | 고점 봉 이후 경과 봉 수 / N | 0=이번 봉이 고점, 동률이면 **가장 최근** |
| `swing{N}_low_age` | 저점 봉 이후 경과 봉 수 / N | 동상 |
| `swing{N}_ready` | 윈도우 N봉 충족 | 세션은 경과 봉 ≥ min_bars 이면 True |
| `swing_measured` | 당일 ≥ `SWING_EXTREME_MIN_BARS`(5)봉 | False면 전 키가 중립 폴백 |

세션 블록은 `swing_day_*`, 나이 분모는 당일 경과 봉 수.

⚠ **항등식** — `range_pos ≡ low_dist / (high_dist + low_dist)`. 한 윈도우의 셋은 자유도 2다.
재검증(26주 WFA L1)에서 독립 신호 3개로 세면 Bonferroni 분모가 틀린다(500차 OFI 3종 교훈).
셋을 다 내보내는 이유는 GBM 표현(유계 비율 vs ATR 스케일 거리)이 다르고 게이트 임계는
유계 쪽이 다루기 쉽기 때문이다.

### 1-2. 설계 판단

| 판단 | 이유 |
|---|---|
| **당일 봉만** 사용, `reset_daily()`에서 초기화 | 전일 봉이 섞이면 일간 갭이 "스윙 극점"으로 잡혀 개장 직후 값이 오염된다 — 317차가 Hurst 버퍼를 비운 이유와 같다 |
| 개장 후 N봉 전까지 **부분 윈도우**로 계산 + `ready=False` | "세션 고점/저점까지"는 개장 직후에도 의미가 있다(오프닝 레인지). 계산을 안 하면 개장 60분이 통째로 폴백이 된다. 대신 폴백/부분 여부를 플래그로 드러낸다(계측 4원칙 ④) |
| ATR 미계산이면 거리 0 + `ready=False` | 거리 0은 "극점에 있다"로 읽힌다 — 폴백이 신호로 위장하는 502차 U-1 유형을 선치 |
| 장중 재기동 워밍업 `set_intraday_ohlc_history()` | 494차 F-5(Hurst 버퍼 복원)의 자매. `main.py:_load_intraday_close_history_at_restart()`가 같은 질의에서 high/low를 함께 읽어 주입한다. 없으면 재기동일에 세션 극점이 재기동 시각부터 시작된다 |
| 20봉 유지 | `bb_position`과 r=+0.95라 GBM에는 중복이지만, 사용자 요청의 "N분" 그 자체이고 §3의 게이트 분해(극점 나이)가 20봉 기준이다 |
| 윈도우는 `config/settings.py:SWING_EXTREME_WINDOWS` | 바꾸면 키 이름이 바뀐다 — 학습/추론 정합 주의 주석 병기 |

## 3. 파트 2 — 두 순환 장치(3_vwap·TrendGate)와 스윙 피처

### 3-1. 장치 정리 (코드 실측)

| 장치 | 동작 | 방향성 |
|---|---|---|
| **3_vwap** (`checklist.py:148-171`) | LONG은 `vwap_position>0`, SHORT는 `<0` 이어야 통과. 미통과 → **강제 X**(단·중기). 예외: `|vwap_position|>1.5 ∧ 탈진강도≥0.60` → MR 분기 | 순환(멀리 위일수록 통과가 "쉬운" 게 아니라 **부호만** 본다 — 0.01 위나 2.0 위나 같다) |
| **TrendGate** (`trend_persistence.py`) | `above_vwap ∧ ret_5m>0` 10분 연속(조건 A는 500차 D-2 동결) → 그 방향 `min_conf`를 0.44(가격구조 부스트 시 0.38)로 완화 + 앙상블 TrendBoost·FlatCap·합의도 패널티 면제·Coherence 임계 0.50 | 순환(강화) |
| 10_chase (`checklist.py:236`) | \|close − close_{−10}\|/ATR > 2.0(횡보 1.5) 순방향 → pass −1 | **역순환**(기존 "조심") |
| 11_countertrend | hurst≥0.55 ∧ 반대방향 연장>2ATR → pass −1 + 1계약 캡 | 역추세 억제 |
| RegimeExhaustion(섀도) | 60분 연장 >1.5ATR ∧ hurst<0.45 ∧ 10/11 소프트 실패 | 역순환(섀도) |

즉 시스템에는 이미 역순환 장치가 셋 있고, 전부 **"N분 전 대비 변위"** 축이다. 스윙 피처가
새로 주는 축은 **"극점이 언제였나(age)"와 "극점에서 얼마나 떨어졌나(dist)"** 다. 10분 변위가
2ATR인 두 봉이라도 하나는 신고점이고 하나는 고점에서 1.5ATR 되돌린 뒤일 수 있다 — 변위
축은 이 둘을 구분 못 한다.

### 3-2. 전 분봉 실측 (일자단위 평균, 전방 수익 pt, 비용 미차감)

**(A) 3_vwap 통과측 × 20봉 위치** — LONG 통과측(`vwap_position>0`)은 **모든** 버킷이 음수:

| range_pos | 5m | 15m |
|---|---|---|
| 0.0–0.2 (저점 근처, 상승 중 되돌림) | −0.26 (t −1.7) | −0.78 (−2.5) |
| 0.2–0.5 | −0.58 (−3.2) | −0.95 (−3.2) |
| 0.5–0.8 | −0.55 (−3.5) | −1.24 (−3.5) |
| 0.8–1.0 (고점 근처) | −0.28 (−2.8) | −0.86 (−3.2) |

SHORT 통과측은 저점 근처(0–0.2)만 음수(5m −0.34, t −3.0), 나머지 ≈0. 이는 "vwap_position
IC 음수 = 통과측이 평균적으로 불리"라는 **이미 알려진 사실**(SOP 부록 A-5)의 재확인이다.

**(B) LONG 통과측 & 고점 근처(≥0.8) × 고점 나이** — 15m: 신고점(age≤0.1) **−0.75**(t −2.9)
→ 0.1–0.3 −0.54 → 0.3–0.6 −0.15 → 오래됨(>0.6) **+0.85**(t +2.6, 47일). 단조다. "고점 아래에서
오래 다지다 고점 근처로 다시 온 봉"만 양수.

**(C) TrendGate UP 활성(조건 B 재구성, streak≥10) × 위치** — 5m: 극단(≥0.8) **−0.46**(t −2.9) /
중간 **+0.02** ; 15m: 극단 −0.93(t −2.1) / 중간 +0.42(t +1.5). DN 측 5m도 극단 −0.43(t −2.0).

### 3-4. 왜 전 분봉과 진입 코호트가 반대인가 — 선택 효과

전 분봉 IC는 "임의의 분봉"의 조건부 평균이다. 진입 코호트는 앙상블 방향·신뢰도 하한·
체크리스트 CORE 3종·MetaGate·Toxicity·Hurst·시간대 필터를 **전부 통과한 분봉**이다.
그 필터들이 통과시키는 신고점 분봉은 모집단의 신고점 분봉과 다른 분포다(오더플로 정렬
+ 추세 지속 확인이 붙어 있다). 반대로 통과했는데 되돌림 구간이라는 것은 "추세 신호는
살아 있는데 가격은 이미 극점에서 물러난" 상태 — 신호와 가격의 불일치이며, 그 코호트가
진다.

따라서 **스윙 피처 하나에 부호를 박아 게이트로 쓰면 어느 쪽이든 틀린다**:
- 모집단 부호(고점 근처 → 차단)로 쓰면 +461만원 코호트를 막는다.
- 코호트 부호(고점 근처 → 허용)로 쓰면 모집단에서 평균회귀에 역행한다 — 게이트를 통과하는
  표본의 구성이 바뀌는 순간 코호트 부호가 유지된다는 보장이 없다.

이 피처가 진짜 갈라내는 것은 **"신호가 가리키는 방향의 극점이 지금 신선한가(돌파 진행) vs
낡았는가(재시험·되돌림)"** 이고, 그 판별은 게이트가 아니라 **다른 게이트의 조건화 입력**으로
쓰일 때 손익에 닿는다(§3-5).

### 3-5. 손익 최적 방안 — 제안 (우선순위 순)

**P-0 (지금, 라이브 무변경)** — 피처 배선·POOL 등록·섀도까지. 게이트 배선 금지(S9 테스트 고정).

**P-1 (사전등록 섀도 채널, 주간회의 승인 요청)** — `VALIDATION_CAMPAIGN["swing_entry_cohort_watch"]`
