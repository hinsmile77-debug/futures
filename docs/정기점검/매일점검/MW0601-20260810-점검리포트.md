### F1 `[계측·P0]` daily_stats 승패 판정이 포지션 순손익이 아니라 최종 레그 부호로 결정된다

**증상**
오늘 `daily_close()`가 8승 2패(80%)로 보고했으나 포지션 순손익 기준은 7승 3패(70%).
09:58 포지션(순 **−273,410원**)이 **승**으로 기록됐다.

**원인** — [position_tracker.py:551-557](strategy/position/position_tracker.py#L551)

```python
is_final = quantity == self.quantity
if is_final:
    self._daily_trades += 1
    if pnl_pts > 0:          # ← 이 레그의 pnl. 포지션 누적이 아니다
        self._daily_wins += 1
```

`partial_close()`는 의도적으로 `_daily_trades`를 올리지 않는데(:692 주석), 승패 판정에
쓰이는 `pnl_pts`도 **최종 레그 것만** 본다. 09:58은 손실 −3.04pt×2계약을 부분청산으로
털어내고 잔여 1계약이 +0.70pt로 끝나 "승"이 됐다.

`restore_daily_stats()`(:1282-1293)도 **행 단위**로 같은 판정을 해 재시작 시 더 어긋난다.

**영향 범위 실측** (2026-06-01~08-10, 194 포지션)

| 지표 | 값 |
|---|---|
| 실제 승률(포지션 순손익) | 59.3% (115승) |
| 집계 승률(최종레그 부호) | 57.2% (111승) |
| 다레그 포지션 | 60건 |
| **오분류** | **10건 / 60건 = 16.7%** |

> ⚠ **정직한 단서**: 집계 오차는 **양방향**이며 누적 편향은 −2.1%p로 작다
> (순익인데 패로 센 것 7건, 순손실인데 승으로 센 것 3건). 즉 *"승률을 체계적으로
> 부풀린다"는 주장은 성립하지 않는다.* 문제는 **정밀도**이고, 건별 금액은 클 수 있다
> (오늘 −273,410원 포지션이 승). CLAUDE.md ⑧ 417차 정정이 경고한 "이벤트 단위 vs
> 포지션 단위" 혼동 계열의 **다섯 번째 재발**이다.

**구현계획**

1. `PositionTracker.__init__`에 포지션 누적기 추가
   `self._pos_acc_pnl_pts: float = 0.0`, `self._pos_acc_fwd_pnl_pts: float = 0.0`
2. `partial_close()` — 청산 시 `self._pos_acc_pnl_pts += pnl_pts * qty` 누적
   (`_daily_trades`는 기존대로 미증가 — 그 설계는 옳다)
3. `close_position()` `is_final` 블록 — 판정을 누적값으로 교체
   ```python
   _pos_total = self._pos_acc_pnl_pts + pnl_pts * quantity
   if _pos_total > 0: self._daily_wins += 1
   ```
   forward 계열도 동일 처리
4. `_reset_position()` — 누적기 0으로 초기화
5. `restore_daily_stats()` — 행 루프를 `entry_ts` 기준 `groupby`로 바꿔 포지션 단위 판정
6. **동률(0.0) 규약 명시** — 현행 `> 0`은 0을 패로 센다. 기존 동작 유지하되
   docstring에 명시(변경하면 과거 통계와 불연속)

**검증**
- 단위테스트: 3레그 포지션(−3.04×2, +0.70×1) → 1패로 집계되는지
- 회귀: 오늘 데이터 재집계 시 7승 3패가 나오는지
- 과거 194 포지션 재집계 → 115승(59.3%)과 일치하는지

### F2 `[계측·P0]` SHS의 "CORE 통과율"이 구조적으로 0%로 계측되고, 경보 문구가 실제 동작과 다르다

**증상**
오늘 SHS 경보 8회 전부 `CORE 통과율: 0%`, SHS 44~60점, 문구는 매번
`(기준 60점 미만 → 진입 차단)`. 그런데 **실제로는 10건이 진입됐다.**

**원인 ①** — [main.py:8974-8978](main.py#L8974)

```python
_core_pass_cnt = sum(
    1 for k in ("3_vwap", "4_cvd", "5_ofi")
    if (_cr is not None and bool(_cr["checks"].get(k)))
) if _cr is not None else 0
self.system_health.update_core_pass(_core_pass_cnt / 3.0)
```

`_cr`(체크리스트 결과)은 [main.py:6875](main.py#L6875) `if direction != 0 and
self.position.status == "FLAT":` 안에서만 만들어진다. 따라서

- 앙상블이 **FLAT**인 분 (오늘 189회)
- **포지션 보유 중**인 분

에는 `_cr is None` → `core_pass = 0/3 = 0%`. **"체크리스트를 안 돌린 분"과
"CORE 3개 전부 실패한 분"을 구분하지 않는다.**

`_recompute()`([system_health.py:359](safety/system_health.py#L359))가
`score -= (1.0 - core_pass_rate) * 25.0` 이므로 그 분은 **무조건 −25점**.
재시작 1회(−8) + z경고 3개(−7.5)만 겹쳐도 100−8−7.5−25 = **59.5 → 임계 60 미달**.
오늘 SHS가 60 언저리에 붙어 있던 게 정확히 이 산식이다.

**원인 ②** — [notify.py:181](utils/notify.py#L181)의 `(기준 60점 미만 → 진입 차단)`은
**무조건 출력되는 고정 문구**다. `entry_blocked`는 전수 검색 결과
[main_dashboard.py:10958](dashboard/main_dashboard.py#L10958) **배지 색상에만** 쓰이고
어떤 진입도 막지 않는다(실제 차단은 EKS `kill_switch_active`만 — main.py:7249/7289).
SHS=60일 때도 "60 미만"이라 찍는 부등호 오류까지 있다.

**구현계획**

1. `main.py:8974` — `_cr is None`이면 **직전 유효값 유지 또는 계측 건너뛰기**로 변경.
   `update_core_pass(None)` 오버로드를 만들어 `system_health` 쪽에서 "미측정"을
   명시적으로 다루게 한다(0%와 구분).
2. `system_health.py` — `_core_pass_rate`에 `_core_pass_measured: bool` 동반.
   미측정 구간은 감점 0. `to_dict()`에 `core_pass_measured` 노출.
3. `notify.py:181` — 문구를 실제 동작에 맞춘다.
   `SHS = {shs:.0f}점 (임계 60 · 현재 {'진입차단' if entry_blocked else '경고만'})`
   그리고 CORE 항목은 미측정 시 `CORE 통과율: 미측정`으로.
4. **결정 필요** — `entry_blocked`를 실제 게이트로 승격할지, 아니면 표시 전용임을
   명문화할지. 지금은 "차단한다고 알림 → 안 막음"이라 어느 쪽이든 정리해야 한다.
   **권고: 표시 전용 명문화.** SHS 산식이 미캘리브레이션(감점 계수 8/2.5/25/5 모두
   근거 미기재)이라 지금 게이트로 승격하면 F2 수정 전 상태에서 상시 차단이 된다.

- 알림 문구가 실제 `entry_blocked`와 일치하는지

### 고도화 1 — 방향 신호의 근본 부재: "모델 개선"이 아니라 "정보원 추가"가 필요하다

**증거**
- 종일 6 호라이즌 적중률 **33.4 ~ 42.1%** (3클래스 랜덤 33.3%)
- 진입 80%를 담당한 3m = **34.4%**
- 40일 L1 스크리닝 종합: **Bonferroni 통과 ∧ 전·후반 부호 일치 = 전 호라이즌 `vwap_position` 단 1개**
  (h=5 IC −0.108 t=−6.4 / h=15 −0.195 t=−7.6 / h=30 −0.280 t=−8.9)
- 그런데 오늘 실제 진입은 그 `vwap_position`이 아니라 conf 기반으로 났고,
  **10건 전부 SHORT** — 방향 다양성 자체가 없다

즉 **피처 풀 전체에서 통계적으로 살아남는 방향 정보가 사실상 1개**다.
이 상태에서 앙상블 가중·게이트·사이징을 아무리 조율해도 상한이 낮다.
`dailycheck_prompt.txt`가 이미 도달했던 결론 —
*"모델링이 아니라 피처 세트 자체에 활용 가능한 방향 정보가 없다 / 해법은 CORE 재배치가
아니라 새로운 정보원 도입"* — 이 오늘 데이터로 재확인됐다.

**제안 1-A. 국내 변동성 축을 파이프라인에 편입** (근거 실측 있음)

| 항목 | 실측 |
|---|---|
| VKOSPI (오늘) | **69.87 ~ 75.59** (극단) |
| 미국 VIX (전일 종가) | 14.9 |
| `macro_vix` (10m·30m 프로덕션 피처) | **종일 상수 0.0** (293/293행) |
| `vkospi` 피처셋 포함 | **6 호라이즌 전부 미포함** |

`macro_vix=0`은 버그가 아니라 산술이다 —
[macro_feature_transformer.py:65](features/macro/macro_feature_transformer.py#L65)
`clip((14.9−15)/(40−15), 0, 1)` → 하한 클립. 그러나 결과는 **10m·30m 모델의 11개
피처 중 하나가 종일 정보량 0**이고, 정작 KOSPI200 옵션 IV 기반 국내 지표는 어디에도 없다.
레짐 판정마저 미국 VIX 14.9로 **RISK_ON**을 찍는다(국내 VKOSPI 71과 정반대 방향).

`vkospi` 실측 IC (19일 창, 455차 하네스):

| 호라이즌 | IC | t | 전반/후반 | 안정 |
|---|---|---|---|---|
| 5분 | +0.0799 | 2.44 | +0.0787 / +0.0810 | **O** |
| 15분 | +0.1181 | 2.10 | +0.1498 / +0.0896 | **O** |
| 30분 | +0.1215 | 1.46 | +0.1546 / +0.0918 | **O** |

Bonferroni(|t|>6.03) **미통과 — 확정 알파 아니다.** 다만 전·후반 부호가 일치하고
(`macro_vix`는 고유값 부족으로 **스크리닝 입구조차 못 든다**) 후보 자격에서 우열이 분명하다.

→ **F3 수정 후** L1 → L2(`horizon_signal_tradability`, 비용차감) → L3(purged CV)
순서로 정식 심사. 통과하면 10m·30m의 `macro_vix` 슬롯 교체. 통과 못하면 폐기 —
CLAUDE.md 455차 재검증 절차 그대로.

**제안 1-B. VIX 정규화 밴드 재캘리브레이션**
`_VIX_BASE=15 / _VIX_FEAR=40`은 근거 미기재 상수다. 현 체제에서 VIX는 몇 주째
하한 근방(0.0324~0.0344 = VIX 15.8~15.9)이라 사실상 상시 0이다.
26주 WFA 재검증 항목으로 편입 권고(CLAUDE.md "주기적 재검증" 형식).

**제안 1-C. F3이 되살릴 20개 피처의 일괄 심사**
`vpin`·`kyle_lambda`·`rv_iv_spread`·`basis_pt`·`opt_gex_bn` 등은 미시구조/옵션 축의
**서로 다른 정보원**이다. F3 수정 즉시 L1을 재실행해 후보군을 다시 세울 것.
⚠ CLAUDE.md 455차 경고 준수 — `basis_pt`는 소표본 유의 후 소멸한 전례가 있다.
**반드시 L2 비용차감까지 통과한 것만** 채택.

### 고도화 2 — 손익 비대칭: 이익 절단이 손실보다 정교하다

**증거** (오늘)

```
이익 실현 평균   +0.66pt  (7건 스크래치)
손실 실현 평균   −3.16pt  (3건)
최대 이익        +4.58pt  (유일하게 TP2까지 간 1건)
```

손절은 ATR×1.5로 **한 번에** 나가는데, 이익은 ATR×0.25 보호스톱이 **초 단위로** 잘라낸다.
게다가 CLAUDE.md ⑧에 등록된 417차 재분해 결과 — *"진입수량 vs 계약당손익 상관 rho=+0.004
(무관), 유일하게 유의한 것은 손절폭 초과 비율 rho=+0.318"* — 은 **손실 쪽도 설계대로
집행되지 않고 있음**을 이미 지적했다.

**제안 2-A**: F4 Phase A 섀도로 "TP1 이후 경로"를 10거래일 계측. 그 데이터가
Phase B의 세 후보(시간유예 / 레인지연동 / 단계완화) 중 무엇이 맞는지 결정한다.

**제안 2-B — 손절 집행 축 조사** (417차가 열어두고 미착수한 것)
417차 가설 *"미니선물 호가 깊이를 여러 계약이 한 번에 훑는 슬리피지"* 는 **미검증**이다.
오늘 `exit_fill_slippage` 테이블이 이미 존재하므로, 하드스톱 주문가 대비 체결가
괴리를 계약수별로 분해하면 검정 가능하다. **F4 Phase A와 같은 배치로 진행 권고** —
같은 청산 경로를 두 각도에서 보는 것이라 데이터 수집 비용이 공유된다.

**제안 2-C — 손익비 목표를 명시적 파라미터로**
현재 TP1/TP2/보호스톱/하드스톱 배수(0.5 / ? / 0.25 / 1.5 ATR)가 각자 다른 세션에서
개별 조정돼 왔다. **기대 손익비를 먼저 정하고 배수를 역산**하는 구조로 바꾸면
파라미터 간 정합성이 유지된다. 지금은 손절 1.5 vs 이익 0.25 락이라 **암묵 손익비가
6:1로 불리**하다 — 승률 70%로도 적자가 나는 이유가 여기 있다.
