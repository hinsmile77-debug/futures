## 9. 🔴 커밋 미실행 — 사용자 조치 필요 (`.git/index.lock` 스테일)

**본 세션은 커밋하지 못했다.** 산출물(리포트·다이제스트·dev_memory 2종)은 디스크에 정상
기록됐으나 git 인덱스가 잠겨 있다.

```
$ git add docs/정기점검/매일점검/MW0602-20260819-점검리포트.md ...
fatal: Unable to create '.../.git/index.lock': File exists.

$ ls -la .git/index.lock
-rwx------ 0 Aug 19 09:07 .git/index.lock      ← 0바이트 · 09:07 생성
$ rm -f .git/index.lock
rm: cannot remove '.git/index.lock': Operation not permitted
```

**원인.** 이 예약 점검은 코웍의 **리눅스 샌드박스 마운트**에서 돈다. 그 마운트는
파일 **생성·추가는 되지만 삭제(unlink)가 안 된다.** 09:07 첫 `git status` 가 인덱스
갱신을 위해 `index.lock` 을 만들었고 스스로 지우지 못했다
(`warning: unable to unlink '.git/index.lock': Operation not permitted`).
**P1-2(수집기 DB 축 실패)와 같은 뿌리** — 예약 점검이 이 환경에서 도는 한 매번 재발한다.

> ⚠ **다른 git 프로세스가 도는 것이 아니다.** 메시지가 그렇게 안내하지만
> 실제 원인은 마운트의 unlink 불가다. 라이브 프로세스를 죽이지 말 것.

**사용자 조치 (윈도우에서, 1회)**

```bat
cd /d C:\Users\pc1\PycharmProjects\futures
del .git\index.lock
git add docs\정기점검\매일점검\MW0602-20260819-점검리포트.md ^
        docs\정기점검\매일점검\evidence_MW0602-20260819_pre.md ^
        dev_memory\DECISION_LOG.md dev_memory\NEXT_TODO.md
git commit -m "[MW0602] 476차: 0819 장전 점검 리포트 + dev_memory (G-1 사이드카 label_scheme 유실 규명)"
```

⚠ 이때 **1-4의 이월 미커밋 7건**(475차 산출물 · `TASK_CLAUDE_WAKE_*` ·
`0816_주간회의_검토보고_MW0602.md`)도 함께 정리하는 것이 좋다. 특히 주간회의 검토보고는
