## 1. 딥다이브 결과 — 비대칭의 두 가지 코드적 원인

### 원인 ① TP/Stop 배수 설계 자체가 비대칭 (`config/settings.py:671-698`)

```python
ATR_STOP_MULT = 1.5                                   # 손절: ATR × 1.5
ATR_HORIZON_TP1_MULT = {"1m":0.3, "3m":0.5, "5m":0.7}  # 1차 목표(호라이즌별)
ATR_TP2_MULT = 1.5                                     # 2차 목표: 손절과 정확히 1:1
ATR_TP3_MULT = 2.5                                     # 3차 목표: 1.67:1
PARTIAL_EXIT_RATIOS = [0.33, 0.33, 0.34]
```
5m 기준 첫 이익실현선(TP1)이 손절폭의 절반도 안 되는 0.47R 지점에서 끊긴다.

### 원인 ② (더 결정적) 사이징이 항상 1계약으로 바닥나 분할청산 자체가 무력화

`Sizer` 로그 기준: 기본리스크 300,000원 × 신뢰도배수(0.6) × 레짐배수(0.8) = 유효리스크
144,000원. 손절폭(4~6pt) × pt_value(50,000원) ≈ 계약당 리스크 200,000~300,000원 →
144,000 ÷ ~250,000 < 1 → **최소 1계약 강제**. 7/15 8건 전부 1계약.

`main.py:10233`(당시 라인) `if total_qty == 1 and stage == 1:` — 1계약 포지션이 TP1에
닿으면 "33% 부분청산"이 아니라 `arm_tp1_single_contract_with_mode()`로 대체되는데,
기본 모드가 `"breakeven"`(실현이익 0)이었다. 그 결과 실전에서 벌어지는 경로는 3가지뿐:

| 경로 | 결과 | 7/15 사례 |
|---|---|---|
| TP1도 못 찍고 반전 | 풀 손절 (-1.5R) | 4건 전부 (-4~5pt대) |
| TP1 찍고 반전 | 본전+α (+0.1~0.2R) | 2건 |
| TP2까지 논스톱 | 전량 익절 (+1.5R) | 1건 |

→ 손실은 항상 최대 리스크 단위, 이익은 대부분 0.1~0.2R로 캡. PF 0.36은 이 회로의
필연적 산출물.

### 🥈 TP1 배수를 Stop과 최소 1:1 근처로 재조정
5m TP1을 0.7R → 1.0R대로 올리거나, 1계약 상황에선 TP1 개념을 없애고 곧장
TP2(1:1) + 트레일링만 쓰는 단순화 검토.
