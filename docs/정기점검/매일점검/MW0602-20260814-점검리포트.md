### P2 — 운영 부담·기술부채

#### 2-1. 🔴 수집기 "미커밋 520건"은 **계측 오류**다 — 리포지터리는 정상. 실제는 7건

> **이 절은 초안을 스스로 반증한 결과다.** 본 리포트 초안은 어제 리포트를 따라
> "워킹트리가 CRLF로 오염됐다"고 쓰고 `.gitattributes` + `git add --renormalize .`(518파일)을
> 권고했다. **그 권고는 철회한다 — 고칠 것이 없는데 518파일을 건드릴 뻔했다.**

- **증상**: 수집기 §2·§11이 `미커밋 변경 520건`을 보고하고 적신호로 올린다.
- **실제**: 같은 워킹트리에서 Windows git 설정을 적용해 다시 세면 **7건**이다.
  ```
  $ git -c core.autocrlf=true status --short | wc -l
  7
   M dev_memory/DECISION_LOG.md          ← 본 세션 산출
   M dev_memory/NEXT_TODO.md             ← 본 세션 산출
   M docs/정기점검/매일점검/dailycheck_prompt.txt
  ?? MIREUK_DAILYCHECK_HANDOFF.md
  ?? docs/정기점검/매일점검/MW0602-20260814-점검리포트.md      ← 본 세션 산출
  ?? docs/정기점검/매일점검/evidence_MW0602-20260812_post.md
  ?? docs/정기점검/매일점검/evidence_MW0602-20260814_pre.md    ← 본 세션 산출
  ```
- **원인**: **점검이 도는 환경이 두 곳이고, git 설정이 다르다.**

  | 실행 위치 | 다이제스트 헤더 | `core.autocrlf` | 보고된 미커밋 |
  |---|---|---|---|
  | Windows (사용자 수동) | `PC MW0602 (DESKTOP-MW0602)` | Git for Windows 기본 `true` | **2건** (08-12) |
  | 리눅스 샌드박스 (예약작업) | `MW0602 (override · host=claude)` | **미설정** (`~/.gitconfig`·`/etc/gitconfig` 둘 다 없음) | **517건**(08-13) / **520건**(08-14) |

  Windows git은 `autocrlf=true`로 **체크아웃 시 CRLF·커밋 시 LF**로 변환한다. 따라서
  워킹트리가 CRLF·HEAD가 LF인 것은 **정상 상태**다. 샌드박스 git은 그 설정이 없어 같은 바이트를
  "전 파일 수정됨"으로 읽는다.
- **반증 근거**: ① 517건이 처음 나타난 08-13 장후는 **예약작업이 샌드박스에서 처음 돈 날**이다
  (`0f44477` 467차 "수집기 `--pc` override"가 바로 그 샌드박스 대응 커밋). 리포지터리에서 무슨 일이
  일어난 게 아니라 **관측 위치가 바뀐 것**이다. ② 어제 01:13 사용자가 Windows에서 커밋한
  `9d6f85f`의 `CLAUDE.md`는 HEAD에 **LF로 저장**돼 있다 — Windows 쪽이 CRLF를 커밋하지 않는다는 증거다.
- **영향**:
  - **리포지터리 위험 0.** 고칠 것이 없다.
  - 대신 **점검의 눈이 멀었다** — 진짜 미커밋 7건이 520건 노이즈에 묻혀 수집기가 자동으로 드러내지 못했다.
  - 🔴 **더 중요한 파생 위험**: 샌드박스에서 `git commit`을 하면 autocrlf가 없으므로
    **CRLF 바이트가 그대로 리포지터리에 들어간다.** `dev_memory/DECISION_LOG.md` 하나만 커밋해도
    **+22,796 / −22,641줄** 짜리 가짜 diff가 생긴다. → **§2 커밋 계획을 전면 수정했다**(아래).
- **신규 여부**: **어제 리포트를 정정**한다. `MW0602-20260813-점검리포트.md:4`는
