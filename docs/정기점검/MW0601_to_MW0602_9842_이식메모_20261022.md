## 3. MW0602에서 켜는 절차

⚠ 각 단계에서 막히면 **거기서 멈추고 `False` 유지**. 추측으로 넘기지 말 것.

**① 판별 프로브(장후 권장, 장중도 요청 수 적음)**
```
conda run --no-capture-output -n py37_32 python scripts\probe_cpsvr9842.py
```
- `ServerType`과 `call_day` 결과를 본다. 「계좌등급 … 제한」이면 **MW0602 로그인이 실계좌가 아니다** → 중단(모의 미사용 결정).
- CREON 로그인에서 처음 재는 것이다 — MW0601(CYBOS 경로)과 등급 정책이 다를 수 있다.
- `L2(b)`는 `data/db/option_hts/`의 직전 `_P`와 대사한다(686차 미러). 9842는 시장 전체 값이라 계좌와 무관하게 같아야 한다.

**② 기간 스냅샷 대사(장후 15:50 이후)**
```
conda run --no-capture-output -n py37_32 python scripts\strike_investor_snapshot.py --end <미러에 있는 최근 _P 날짜>
```
기대: `C/1 rows=343 … unmapped=0 inv_bad=0  P/1 rows=343 …  | HTS 대사 2744/2744칸`(행사가 수는 월물에 따라 다름).
⚠ 미러 `_P`가 15:45 이전 저장본이면 개인·외인 몇 칸이 어긋난다 — 그 날은 다른 날짜로 대사.

**③ 켜기** — `config/settings.py: STRIKE_INVESTOR_FLOW_ENABLED = True` + 재기동.
첫날 로그 `[StrikeInvestor] stored=… (오늘 첫 수집 — 전체 저장)` · 상태 테이블 `strike_investor_flow_status` 의 `ok=1` 비율 · `BLOCKED`/`EMPTY` 0건 확인.

**④ 예약작업(선택)**
```
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\strike_investor_snapshot_task.ps1 -Action Register [-RunLevel Highest] [-At 16:25]
```
- 🔴 **RunLevel은 API 세션과 같은 무결성 수준이어야 한다.** 다르면 COM이 로그인 안 된 DibServer를 새로 띄워 **매일 조용히 실패**한다(MW0601 OptionFlowBackfill 8거래일 실패 전례).
  MW0602에서 **이미 정상 동작 중인 COM 예약작업의 RunLevel을 그대로 따를 것**:
  `Get-ScheduledTask -TaskPath '\Mireuk\' | Select TaskName,@{n='rl';e={$_.Principal.RunLevel}}`
  (기본값은 Limited — MW0601 실동작 기준. CREON coStarter가 승격으로 돌면 Highest, 관리자 PowerShell에서 등록)
- 시각은 MW0602의 다른 COM 작업(조회 한도 15초당 60건 공유)과 겹치지 않게. MW0601은 16:20 백필(16:23 종료) 뒤 16:25.
- MW0601에는 16:30 API 세션 정리(`eod_session_cleanup.ps1`)가 있어 대기 목록에 넣었다 — **dev에는 그 스크립트가 없어 이식하지 않았다.**
