# 신규 피처 발굴 표준 절차 (Feature Discovery SOP)

> 🔹 **범위 구분** — 이 문서는 **신규 피처를 심사해 편입**하는 절차다.
> **기존 피처셋의 26주 주기 재검증**과 **호라이즌 배정**은 같은 폴더의
> `피처_재검증_및_호라이즌배정_원칙.md`를 따른다. 그 문서는 이 문서의 Phase 3 검정 기준
> (일자단위 IC·Bonferroni·split-half)을 계승하되, 그 **앞단에 유형 분류·중복 축약·데이터
> 정제**를 추가한다(2026-08-24 오측정 10건에서 역산).

> 근거: `docs/미륵이고도화2/`(2026-07-12~14), `docs/미륵이고도화3/`(2026-07-27) 두 딥다이브
> 세션에서 실제로 겪은 성공/실패 패턴을 절차로 고정한 문서. 새 피처 후보가 생길 때마다
> 이 문서의 Phase 0~6을 순서대로 거친다. 개별 피처의 심사 기록은 이 문서가 아니라
> `dev_memory/DECISION_LOG.md`(차수별) 및 `config/constants.py` 주석에 남긴다 — 이 문서는
> "어떻게 심사하는가"의 절차 표준이지 심사 결과 로그가 아니다.

## 0. 배경 및 원칙

고도화2는 "피처를 정제하면 무스킬이 풀린다"는 전제로 접근했으나, 고도화3의 63피처
전수검증(Bonferroni 보정)에서 그 전제 자체가 반증됐다 — 계측 결함을 고친 뒤에도
CORE 피처(cvd_divergence·ofi_norm)가 노이즈와 구분되지 않았다. 두 세션을 관통하는
교훈은 하나다: **"신호가 있어 보인다"와 "신호가 실제로 있다" 사이의 간극을 좁히는
절차가 없으면, 계측 인프라만 늘어나고 알파는 늘지 않는다.** 이 문서는 그 간극을
좁히기 위한 6단계 게이트다.

절대 원칙(변경 불가, `CLAUDE.md` §6과 동일):
- **자동 통합 금지** — 어떤 단계에서도 검증 스크립트가 `active_features`나 CORE 체크리스트를
  직접 수정하지 않는다. 최종 편입은 사람이 대시보드에서 승인한다.
- **읽기 전용 검증** — Phase 2~5의 모든 스크립트는 `raw_data.db`/`SHAP_DB`만 읽거나 로그만
  쓴다. 모델 파일·설정·학습 파이프라인에는 관여하지 않는다.

## Phase 0 — 발굴 (가설 수립)

새 피처 후보는 아래 세 경로 중 하나로 발생한다. 어느 경로든 **산출물은 "계산식 +
원천 데이터 + 이론적 근거 + 예상 부호/방향"을 명시한 후보 명세**여야 한다 — 근거 없이
"넣어보고 보자"는 시작하지 않는다.

| 경로 | 방법 | 예시 |
|---|---|---|
| A. 문헌 조사 | 학술/업계 논문에서 이론적 근거를 먼저 확보 | Cont-Kukanov-Stoikov 다층 OFI, Baltussen(2021 JFE) GEX 모멘텀/되돌림 스위치, Kolm et al.(2023) 알파 감쇠곡선 |
| B. 전수 스크리닝 | `scripts/core_feature_discovery.py`로 raw_features의 모든 수치 피처를 동일 잣대(일자단위 IC/hit)로 훑어 미탐지 후보 발견 | vpin·kyle_lambda 등 7종 후보 발굴 |
| C. 실전 이상 관측 | 버그/이상치 조사 과정에서 우연히 발견 | `cvd_direction` 오배선 발견 → `cvd_delta_norm` 정정 |

문헌 경로(A)로 나온 후보는 스크리닝 도구(B)로 실측 재현을 반드시 거친다 — 설계 시점
논문 수치가 이 시장·이 표본에서 재현된다는 보장이 없다(§Phase 3 참조).

## Phase 1 — 데이터 가용성 확인 및 등록

1. **원천 데이터 실취득 가능성을 실측으로 확정한다.** "이론상 계산 가능"과 "이 계좌/API로
   실제 수신 가능"은 다르다 — `cancel_ratio` 사례가 정확히 이 함정이었다: 시장 전체 취소
   이벤트 TR이 없다는 것도, 대안(`FutOptRest`)이 계좌등급 제한에 걸린다는 것도 실계정
   프로브 스크립트(`scripts/probe_futoptrest.py` 유형)로만 확정됐다. 문헌/설계 문서만
   보고 "가능하다"고 판단하지 않는다.
2. 계산 모듈을 신설한다 (`features/technical/` 또는 `features/supply_demand/` 등, 기존
   피처와 동일한 네이밍/인터페이스 관례를 따른다).
3. `config/constants.py:DYNAMIC_FEATURES_POOL`에 등록한다 — 이 등록은 "주간 SHAP 심사가
   교체 후보로 제안할 수 있게 문을 여는 것"일 뿐, `active_features`에는 자동 편입되지
   않는다.
4. `raw_features` DB에 값 기록을 시작하고, 최소 축적 기간(Phase 3 표본 요건 참조)이
   찰 때까지 대기한다.

## Phase 2 — 상시 건강도 계측 (Health Instrumentation)

통계적 유의성 검정에 앞선 전제조건이다 — 배선이 죽어 있으면 아무리 정교한 검정을 해도
무의미하다(exhaustion 6종·`macro_nasdaq_chg`가 2개월간 전부 0으로 방치된 사례).

`scripts/feature_health_report.py`로 계측한다.

| 계측 항목 | 기준 | 등급 |
|---|---|---|
| 분산 | 전 구간 동일값 | DEAD |
| zero-rate 또는 최빈값 비중 | ≥ 95% | CRITICAL |
| zero-rate 또는 최빈값 비중 | ≥ 80% | WARN |
| 그 외 | — | OK |

최소 표본 `MIN_SAMPLES=200`, 관찰창 기본 20거래일. 상태/품질 플래그류(`quality_*`,
`is_*` 등)는 "항상 같은 값이 정상"이므로 별도 분류해 경보 피로를 피한다. 이 단계를
통과하지 못하면(DEAD/CRITICAL) Phase 3로 넘어가지 않고 배선부터 수리한다.

## Phase 3 — 통계적 예측력 검증 (IC / Hit-rate)

**1차 스크리닝 (선별용, 최종 근거 아님)**: `scripts/ic_probe_pending_features.py` —
Spearman IC + 반분(전/후반) 안정성. 다중비교 보정 없이 명목 p값만 표시한다. 이 결과만으로
채택 판단을 내리지 않는다 — "다음 단계 검증에 올릴 후보 선별" 용도로 한정한다.

**2차 정식 검증 (필수)**: `scripts/core_feature_discovery.py` 방법론을 그대로 적용한다.
이 방법론 자체가 372차(고도화2)의 실패에서 나온 교정이다.

| 요건 | 값/방법 | 이유 |
|---|---|---|
| 관측 단위 | **일자단위(day-level) 독립관측** — 신호단위 풀링 금지 | 하루 수백 개 분봉은 서로 상관돼 있어, 풀링하면 표본수가 부풀려져 t값이 과대평가된다(372차 교훈) |
| 다중비교 보정 | Bonferroni (피처수 × 호라이즌수) | 63피처×3호라이즌처럼 대량 스크리닝 시 우연한 유의를 걸러낸다 |
| 안정성 | 전/후반 분할(split-half) 일치 확인 | 특정 구간 우연 적합 배제 |
| 최소 표본 | `MIN_DAYS=20`거래일, `MIN_DISTINCT=20`(상수·이진 플래그 제외) | 소표본 과최적화 방지 |
| 지표 | IC(Spearman), Hit rate(중심화 후 부호일치) | 게이트로 쓸 경우 hit rate가 더 직접적 |

이 단계를 통과해도 "다음 단계 후보"일 뿐 채택 근거는 아니다.

## Phase 4 — 강건성 검증 (Robustness)

Phase 3의 유의성은 실전 배치·비용·다른 피처와의 상호작용을 보지 않는다. 아래 네 가지를
전부 확인해야 한다.

1. **Purged Walk-Forward CV** — `scripts/validate_feature_set_purged_cv.py`. 프로덕션과
   동일한 레이블 함수(`_path_conditioned_label`)·전처리(`apply_robust_preprocess`)·모델
   (`HistGradientBoostingClassifier`)을 재사용하고, `TimeSeriesSplit(n_splits=3)` +
   레이블 룩어헤드 purge를 적용한다(AFML ch.7). 3클래스 정확도와 방향적중률을 병행
   보고하고, 폴드별 편차가 크면 평균만으로 판단하지 않는다.
2. **Ablation (단독 vs 순계 기여 분리)** — `scripts/feature_ablation_purged_cv.py`.
   단독 지표만으로 판단하지 않는다 — `cvd_delta_norm`은 단독 ablation으로는 -2.72%p였지만
   다른 피처와 결합한 순계 기여는 개선이었다(389차). 반대로 단독으로 좋아 보여도 다른
   피처와 겹쳐 순계가 상쇄될 수 있다.
3. **비용 조정(cost-adjustment)** — 왕복 거래비용을 차감한 뒤에도 기대값이 양(+)인지
   확인한다. `vwap_position`은 IC가 압도적(t=-14.7)이었지만 비용 차감 후 양방향 모두
   손실로 확정됐다 — 통계적 유의성과 실전 수익성은 다른 질문이다. 게이트(필터)로 쓸
   경우에도 클리핑으로 인한 해상도 손실(예: ±2.0 클리핑에 51.6%가 몰려 게이트가 사실상
   상시 통과/차단으로 고착)이 없는지 확인한다.
4. **표현형 다양성 검증** — magnitude/sign/ratio 등 여러 변환 형태를 함께 테스트한다.
   `opt_gex_bn`의 magnitude 계열은 설계 시점 IC(0.198)가 최신 구간에서 재현 실패(0.013)
   했지만 sign/ratio 계열(`opt_gex_sign`·`opt_atm_pcr`)은 생존했다 — 한 형태의 실패가
   전체 개념의 실패를 의미하지 않는다.

**표본확대 재검증(필수, 1회 이상)**: 최초 유의성이 표본이 늘어나면 소멸하는 패턴이
반복 확인됐다(`basis_pt`: 소표본 시 유의 → 표본 확대 후 전 호라이즌 비유의로 전환).
최초 검증(Phase 3) 대비 표본을 최소 2배 이상 확대한 시점에 동일 검증을 재실행하기 전에는
"채택"으로 확정하지 않는다.

## Phase 5 — 라이브 섀도 모니터링

Phase 4까지 통과해도 라이브에서 재현된다는 보장은 없다 — 오프라인 재생 검증과 라이브
경로는 다르다(371차 PSI 비닝처럼 "재생검증은 정상이나 라이브 미검증" 상태로 보류되는
경우가 흔하다). `scripts/compute_canary_1m_ic.py` 방식을 표준으로 한다.

- **최소 모니터 기간**: 4주(28거래일) 롤링 창.
- **소비 경로**: 학습 피처셋·게이트 어디에도 자동 반영하지 않고, `SHAP_DB`의 전용 테이블
  (예: `canary_1m_ic_scores`)에만 일별 IC를 누적한다.
- 이 기간 중에도 Phase 2 건강도 계측을 병행해 라이브에서 새로 죽지 않는지 재확인한다.
- 하루 1회 자동 계측 워커(예: `main.py`의 `EffectReports` 주기 워커)로 무인 축적하고,
  사람이 주간 단위로만 확인한다.

## Phase 6 — 승격 심사 및 최종 판정

**정식 편입 경로**: 주간 SHAP 심사 → 대시보드에서 사람이 "후보 적용" 수동 승인
(`main.py:_on_apply_shap_candidate_requested`). 이 경로 외에는 `active_features`를
직접 편집하지 않는다. CORE 피처(`CLAUDE.md` §3) 승격은 별도로 더 높은 기준(사용자 승인
필수)을 적용한다.

**승격 검토 대상이 되기 위한 체크리스트** (전부 충족 필요):
1. Phase 2 건강도 OK (최근 20거래일 기준)
2. Phase 3 일자단위 IC/hit가 Bonferroni 보정 후에도 유의 + split-half 안정
3. Phase 4 Purged CV에서 순계(ablation) 기여 확인
4. Phase 4 비용조정 후 양의 기대값, 또는 게이트로서 실질적 해상도 확인
5. Phase 4 표본확대 재검증에서 신호 유지(소멸하지 않음)
6. Phase 5 라이브 섀도 4주 이상 관찰에서 재현

**최종 판정은 아래 5개 카테고리 중 하나로 명시적으로 종결한다** — "계속 지켜보는 중"
상태로 무기한 방치하지 않는다.

| 판정 | 의미 | 기록 위치 |
|---|---|---|
| **채택** | 체크리스트 전부 충족, `active_features` 정식 편입 | `dev_memory/DECISION_LOG.md`(해당 차수), 필요 시 `CLAUDE.md` §3 |
| **조건부채택(섀도 유지)** | 통계적 근거는 있으나 실거래 알파 미확정 — 라이브 소비는 열지 않고 로그만 지속 (예: exhaustion 6종) | `config/constants.py` 주석 + `DECISION_LOG.md` |
| **보류(표본부족)** | 추가 축적 필요, 재검증 예정일 명시 | `dev_memory/NEXT_TODO.md` |
| **기각(반증)** | 표본확대·일자단위 재검증에서 신호 소멸, 또는 비용차감 후 손실 확정 | `DECISION_LOG.md`에 반증 근거와 함께 "재시도 금지 사유" 명시 |
| **구현불가(데이터원천 문제)** | 실측으로 데이터 취득 자체가 불가 확정 | `config/constants.py` 주석에 사유 남기고 사장 처리 |

## 부록 A — 안티패턴 체크리스트 (고도화2·3에서 실제로 발생한 함정)

새 피처를 심사할 때 아래 8가지를 순서대로 자문한다.

1. **계측 결함 수정 ≠ 본질 검증** — PSI 계측을 고쳤다고 그 피처가 유효하다는 뜻은
   아니다(371차 계측 수정이 394차에 가서야 "애초에 정보가 없었다"로 정정됨).
2. **신호단위 풀링 과대평가 금지** — 반드시 일자단위로 재확인한다(372차).
3. **소표본 초기 유의 맹신 금지** — 표본 확대 재검증 없이 채택하지 않는다(`basis_pt`).
4. **단독 ablation만으로 판단 금지** — 순계 기여를 확인한다(`cvd_delta_norm`).
5. **비용 미차감 지표 단독 채택 금지** — IC가 커도 비용 차감 후 손실이면 기각한다
   (`vwap_position`).
6. **배선됐다고 작동한다고 가정하지 않는다** — 게이트/플래그가 실제 소비 경로까지
   연결됐는지 확인한다(CB③-P4 우회경로 재발 사례).
7. **"이론상 가능"과 "실측 가능"은 다르다** — 실계정 프로브로 확정한다(`cancel_ratio`).
8. **자동 통합 금지** — 아무리 강한 신호라도 사람의 대시보드 승인 없이 편입하지 않는다.
