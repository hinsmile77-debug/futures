## 0. 용어

**WFA = Walk-Forward Analysis(전진 검증)** — 과거 데이터를 시간 순서대로
"학습 구간 → 검증 구간"으로 밀고 나가며 재는 방식.

미륵이는 이걸 **26주(약 6개월) 주기**로 돌린다(`CLAUDE.md` 「주기적 재검증 항목
(26주 Walk-Forward 편입)」). 실전 전환기준 ③이 여기 걸려 있다.

**L1·L2·L3는 그 주기에 돌리는 "검정 배터리"의 층(Layer) 번호**다.
전체는 **L0~L5 7층**이고, 26주 주기에 도는 것은 그중 **L1 → L2 → L3** 세 층이다.

## 1. 전체 사다리 (L0~L5)

각 층은 **서로 다른 질문 하나씩**을 맡는다. 아래로 갈수록 질문이 까다롭고 비용이 크다.

| 층 | 묻는 질문 | 스크립트 | 주기 |
|---|---|---|---|
| **L0** 건강 | 값이 **살아 있나?** (분산 0 · 최빈값 비중 · 갱신 간격 · 결정론) | `scripts/feature_health_report.py` | 주간 |
| **L1** 정보 | 미래 수익률과 **상관이 있나?** | `scripts/core_feature_discovery.py` | 월간 |
| L1´ 후보 | 아직 안 쓰는 후보 피처도 같은 잣대로 (+ 노이즈 벤치마크) | `scripts/ic_probe_pending_features.py` | 월간 |
| **L2** 수익성 | **비용 빼고도 돈이 되나?** | `scripts/horizon_signal_tradability.py` | 월간 |
| **L3** 모델 | 그 피처셋으로 **모델이 실제로 좋아지나?** | `scripts/validate_feature_set_purged_cv.py` | **26주** |
| L3´ 분해 | 좋아졌다면 **어느 피처 때문인가?** | `scripts/feature_ablation_purged_cv.py` | 필요 시 |
| L4 신뢰도 | 확신도가 높을 때 **정말 더 맞나?** (conf-층화 z검정) | `scripts/horizon_conf_stratified_test.py` | 주간 |
| L5 정합 | SHAP 중요도와 L1 IC가 **일치하나?** (2×2 분면) | 월간 리포트 내 합성 | 월간 |

부속: `scripts/ic_decay_catalog.py` — 전 격자 h∈{1,3,5,10,15,30}의 IC 감쇠 곡선
카탈로그(peak_h · τ · 유형). L1의 3점 스냅샷(h=5/15/30)과 별개 가족이며 **advisory 전용**
(채택·탈락 효력 없음). 월간 수동.

## 2. 왜 세 층으로 나누나 — 깔때기

**각 층은 앞 층이 답할 수 없는 질문을 맡는다.** 순서가 뒤집히면 의미가 없다.

```
전체 피처 (약 140개) × 6개 호라이즌
   │
   ├─ L1  "상관이 있나?"          ← 싸다(읽기 전용, 분 단위). 넓게 훑는다
   │      통과 못 하면 여기서 끝
   ↓
   ├─ L2  "비용 넘고도 남나?"     ← 중간. L1 통과분만
   │
   ↓
   └─ L3  "모델이 좋아지나?"      ← 비싸다(py310_64 재학습 필요). 그래서 26주에 한 번
```

## 3. L1 — 정보가 있나

**재는 것**: 시각 t의 피처값과 t→t+h분 수익률의 **Spearman 상관(IC)**, 그리고
부호 적중률(hit-rate, 중심화 후 부호 일치).

**핵심은 "일자단위"다.** 분봉 수천 개를 한 통에 넣고(풀링) 재면 안 된다 — 같은 날
분봉들은 서로 강하게 닮아서 표본 수만 부풀고 유의성(t값)이 과대평가된다.
그래서 **하루에 상관계수 하나씩 뽑고, 그 일자별 값들로 검정**한다.
372차의 교훈이 코드에 박힌 부분이다.

**사전 필터** (`core_feature_discovery.py:55-62, 164-177`)

- `MIN_COVERAGE` — 커버리지 미달 제외
- `MIN_DISTINCT = 20` — 고유값 20 미만은 상수·플래그로 제외
- `MIN_DAYS_SINCE_FIRST_SEEN = 15` — 첫 관측 후 15거래일 경과
- `MIN_DAYS = 20` — 최소 20거래일

**합격선**

- **Bonferroni 보정** — 피처 수 × 호라이즌 수만큼 검정하므로 α를 그만큼 나눈다
- **전·후반 분할 부호 일치** — 우연한 구간 적합 배제
- 미래참조 없음 · 오버나이트 제외(일중만)

현행 CORE도 **같은 잣대로 함께 평가**해 비교 가능하게 한다(`INCUMBENT` 기준선).

**실행**

```
python scripts/core_feature_discovery.py                 # 최근 120거래일, h=5/15/30
python scripts/core_feature_discovery.py --days 60 --top 30
```

> ⚠ `--days`가 결과를 크게 흔든다 — 2026-08-10 실측: `--days 40` 62개 vs
> `--days 19` 82개. 차이 20개는 신호가 아니라 **도입일 때문**이다.
> 2026-08-25부터 **노이즈 하한선 병기 + 중복 군집 표기**가 추가됐다
> (둘 다 판정 무영향, `--no-noise`/`--no-dup`로 끌 수 있음).

## 4. L2 — 비용 넘고도 돈이 되나

**L1을 통과해도 못 쓴다.** 이 층이 존재하는 이유가 실측으로 남아 있다:

> 394차 — IC가 유의한 신호 후보 **189개를 비용 차감했더니 189개 전부 전멸**했다.
> (`docs/미륵이고도화3/방향신호_발굴계획_2026-07-27.md` §1-2)

**재는 것**: 피처를 "**당일 러닝 중앙값** 위/아래" 이진 게이트로 바꿔 실제 매매를
흉내 낸다. 시점 t까지의 당일 값만 쓰므로 미래참조가 없다.

- **비중복** — 체결 후 h분간 신규 진입 금지(같은 움직임을 여러 번 세지 않기).
  진입 `close[t]` → 청산 `close[t+h]`
- **당일 내만** — 오버나이트 제외(절대원칙 §1)
- **왕복비용 차감** — `2×가격×수수료율 + 2×슬리피지틱×TICK_SIZE`
  (`horizon_signal_tradability.py:75`, 캠페인 정본 산식과 동일)
- **집계** — 거래 pnl을 **일자 단위 합산 → 일평균 ± t**. 거래 없는 날은 0으로 포함.
  전·후반 분할 병기

**비용 가정 두 벌 병기** — 394차 문서의 `0.133pt`는 슬리피지를 일반선물 틱(0.05)으로
잡은 구 가정이고, 캠페인 정본은 미니선물 틱(0.02)으로 약 `0.07pt`다. 어느 쪽을 판정
기준으로 삼을지는 **주간회의 결정 사항**이라 그때까지 **둘 다 출력**한다
(조용한 기준 변경 방지).

> ⚠ **방향(orientation) 함정** — 스크립트는 +1(피처↑→LONG)·−1 두 방향의 순손익을
> 모두 출력한다. **더 좋은 쪽을 고르는 것은 in-sample 선택이다.** 후보 심사에서는
> 사전에 예상 부호를 명세에 적고 **그 방향만** 읽을 것
> (`피처_발굴_표준절차.md` Phase 0 — 예상 부호 명시 요건).

**실행**

```
python scripts/horizon_signal_tradability.py --days 120 --horizons 5,15,30
```

## 5. L3 — 모델이 실제로 좋아지나

**L2까지 통과해도 못 쓴다.** 피처 하나가 단독으로 돈이 돼도, 이미 있는 다른 피처와
정보가 겹치면 **모델에 넣어도 개선이 0**일 수 있다. L3는 "피처 **셋** 전체"를 놓고 잰다.

### purged가 무엇인가

```
      학습 구간                    │  검증 구간
 ...  [t-2] [t-1] [t]              │  [t+1] [t+2] ...
                    ↑
        t의 레이블 = "t+30분 뒤 가격이 올랐나?"
        ↑ 이 레이블은 검증 구간을 이미 훔쳐봤다
```

레이블이 **미래 N분 가격**으로 만들어지기 때문에, 폴드 경계 근처 학습 표본의 정답지에
검증 구간 정보가 섞여 들어간다 → 성적이 실제보다 좋게 나온다.
**경계 근처 학습 표본을 잘라내는 것(purge)** 이 이 층의 본질이다(AFML 7장).

> 🔴 **프로덕션 재학습(`learning/batch_retrainer.py`의 `TimeSeriesSplit`)에는
> purge가 없다.** 이 스크립트가 그걸 재는 **유일한** 도구다.
> embargo는 이 분할 구조(train이 항상 test보다 앞섬)에서는 불필요하다 —
> 반대 방향 유출 경로가 없다.

### 프로덕션과 같게 맞춘 것 / 다르게 한 것

| | 내용 |
|---|---|
| **같게** | 레이블(`_path_conditioned_label` + `HORIZON_THRESHOLDS`), 전처리(`apply_robust_preprocess`), 모델(`HistGradientBoostingClassifier(**HIST_GBM_PARAMS)`), `sample_weight`, CV 골격(`TimeSeriesSplit(n_splits=3)`) — **실제 프로덕션 함수를 그대로 재사용** |
| **다르게** | ① PURGE 추가 ② 지표 두 벌 병기 — (a) 3클래스 정확도 (b) 방향적중률 |

### 한계 (스크립트 헤더가 스스로 고지)

- 3폴드 단발이라 폴드별 편차가 크다 — **평균만 보고 결론짓지 말고 fold별 수치도 볼 것**
- 피처 자체의 lookback(`bb_position`·`hurst` 등)에서 오는 워밍업 오염은 다루지 않는다.
  여기서 purge하는 것은 **레이블 룩어헤드**뿐이다
- 결과가 좋아도 라이브를 보장하지 않는다 — 최종 판단은 재학습 + 모의투자 관찰까지

### 차이가 나면 → L3´

`feature_ablation_purged_cv.py`로 피처를 하나씩 넣고 빼서 원인을 특정한다.
**순계·단독 둘 다 병기**한다(3m `poc_distance`/`bb_position` 사례 방지).

**실행** — 둘 다 **py310_64** 권장(재학습 수반)

```
python scripts/validate_feature_set_purged_cv.py
python scripts/feature_ablation_purged_cv.py
```

## 6. 판정의 효력 — 여기가 중요하다

**L0~L5 어느 것도 자동으로 아무것도 바꾸지 않는다.** 전부 읽기 전용 진단이고,
산출물은 **제안**일 뿐이다.

- KEEP / DROP / ADD 제안 → **주간회의 수동 승인** → EOD 재학습 경로
- `active_features` · CORE 체크리스트 · `feature_names.pkl` · `horizon_feature_sets.json` ·
  registry 어디에도 스크립트가 직접 쓰지 않는다
- 근거: `CLAUDE.md` 절대원칙 §6 「알파 리서치 봇 — 자동 통합 절대 금지」

**DROP 제안 조건**: active 피처가 ① L0 DEAD/CRITICAL, **또는**
② L1 비유의 **2회 연속**(월간 2회 ≈ 2개월) + L5 ⚠️분면
→ 한 번의 나쁜 달로 피처를 버리지 않는다.

**ADD 제안 조건**: POOL/pending 피처가 ① L0 OK ② L1´ Bonferroni 유의 **2회 연속**
+ split-half 안정 ③ L2 통과(비용차감 양) 또는 게이트 해상도 확인 ④ 표본 20거래일 이상.

## 7. 🔴 L1을 그냥 돌리면 안 되는 이유 — 사전 필터의 사각지대

L1의 사전 필터는 **커버리지 · 고유값 ≥20 · 첫관측 15일**, 이 셋뿐이다
(`core_feature_discovery.py:164-177`). **최빈값 비중도, 중복도, 시간축 오염도 보지 않는다.**

2026-08-30 CVD·OFI 계열 조사에서 확인된 병든 컬럼 6개를 그 필터에 넣어보면
(실측 n=5,289, `raw_features` 2026-08-10~08-28, 14거래일):

| 피처 | 고유값 | L1 사전필터 | 실제 상태 |
|---|---|---|---|
| `cvd_direction` | 2 | ✅ 걸러짐 | — |
| `ofi_pressure` | 3 | ✅ 걸러짐 | — |
| `cvd` | **22** | 🔴 **통과** | 98.8%가 1.0인 사실상 상수 |
| `ofi_imbalance` | **199** | 🔴 **통과** | `ofi_norm/3` 항등식 (5,289/5,289) |
| `cvd_slope` | **1,769** | 🔴 **통과** | 시각 함수 (08시 0.62 → 15시 0.02) |
| `cvd_divergence` | **828** | 🔴 **통과** | 시각 함수 × 가격기울기 부호 |

**6개 중 4개가 그대로 통과한다.** 통과한 뒤 벌어지는 일:

- `cvd_slope`·`cvd_divergence`에 IC를 매기면 → **"시각과 미래수익률의 관계"** 를 잰다
- `ofi_norm`·`ofi_imbalance`·`ofi_pressure`를 3개로 세면 → 같은 신호를 **3표로 계수**해
  Bonferroni 분모가 틀리고 계열 검정의 **유효 자유도가 무너진다**
  (SOP §1 오측정 #9 — 수급 5피처를 독립 5개로 세어 판정 미달(p=0.1426)을 자초한
  그 사례와 **완전히 같은 형태**)

⇒ 그래서 SOP `피처_재검증_및_호라이즌배정_원칙.md`가
**"L1→L2→L3를 바로 돌리지 말 것 — 앞에 유형 분류(§2) → 중복 축약(§3) → 데이터
정제가 선행해야 한다"** 고 못 박았고, `CLAUDE.md`도 재검증 착수 전 그 문서를 먼저
열라고 지시한다.

**올바른 순서**

```
정제 (CVD·OFI 계열 정리)  →  §2 유형 분류 · §3 중복 축약  →  L1 → L2 → L3
```

## 8. 주기 배치 요약

| 주기 | 트리거 | 도는 층 | 산출물 |
|---|---|---|---|
| **주간** | 금요일 EOD 체인 (`campaign_steps.py`) | L0 + L4 + 후보 축적 현황판 | `featureset_health_YYYYMMDD.md` |
| **월간** | 같은 체인, 매월 첫 금요일 분기(`today.day <= 7`) | L1 + L1´ + L2 → KEEP/DROP/ADD 제안 | `featureset_proposal_YYYYMMDD.md` |
| **26주** | 기존 WFA 재검증 주기 (**사람 세션**) | **L3 + L3´ 전면 재검증** | `DECISION_LOG` 차수 기록 |

- **L0가 주간인 이유**: 배선 사망은 빨리 잡아야 한다(exhaustion 6종 사례)
- **L1/L2가 월간인 이유**: L1 최소 표본이 20거래일(약 4주)이라 주간으로 돌려도
  표본이 회전하지 않는다
- **L3가 26주인 이유**: py310_64 재학습을 수반해 체인 밖(사람 세션)에서만 돈다
