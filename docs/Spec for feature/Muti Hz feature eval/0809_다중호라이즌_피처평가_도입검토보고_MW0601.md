## 2. 사용자 요구 ②③에 대한 답 — "챔피언-챌린저 표준화"는 이미 설계돼 있다

승격·탈락 표준화 요구를 장치별로 매핑하면:

| 요구 | 담당 장치 | 상태 |
|---|---|---|
| N분 호라이즌별 최적 피처 선택 | 호라이즌별 `feature_names_hz` + L1(IC)~L3(purged CV) 배터리 + 월간 KEEP/DROP/ADD 제안 | 배터리 도구 있음 / **월간 합성 리포트(Phase C) 미구현** |
| 주기적 평가 | 3단 주기 — 주간(L0 건강)/월간(L1·L2 제안)/26주(L3 전면) | 주간 완료(410차) / **월간 미구현** / 26주 편입 설계됨 |
| 승격(챌린저→챔피언) 표준화 | ADD 규칙: L0 OK + L1' Bonferroni 유의 **2회 연속** + split-half + L2 비용차감 통과 + 표본 20일 → P2 오프라인 A/B → P3 섀도 A/B → **사람 승인**(§6) | 규칙 사전등록 완료 / 리포트 미구현 |
| 탈락(챔피언 강등) 표준화 | DROP 규칙: L0 DEAD/CRITICAL 또는 L1 비유의 2회 연속 + L5 ⚠분면. CORE는 경보만(§3 교체 불가) | 동일 |
| 판정≠결정 분리·재발 방지 | `FEATURE_SET_DECISIONS` 레지스트리(411차, 14건 등록) + 📌 렌더링 + orphan 검출 | **구현 완료** |
| 전략 수준 챔피언-챌린저 | `challenger/` 5종 + 레짐 전문가 + 수동 승격 | 구현 완료 (별도 계층) |

즉 **부족한 것은 프레임워크가 아니라 실행이다**: ① 07-30 실행계획 1단계의 신설 스크립트
2종(`horizon_conf_stratified_test.py` L4, `horizon_signal_tradability.py` L2)이 아직 없고
(Phase A 리포트의 L4 칸이 "⚠ 미배선"인 이유), ② Phase C 월간 제안 리포트가 미구현이며,
③ D-day(08-14 예정) 기준선 고정이 남아 있다.

리뷰 문서를 "채택"한다는 것은 이 미구현분을 대체하는 게 아니라, **Phase C를 구현할 때
N1~N4를 그 리포트의 advisory 열로 함께 넣는 것**이어야 한다.

## 3. 신규 5요소 도입 방식 (상세)

### N1. 비용 문턱 IC\*(h) 표 — advisory, 반나절

- **산식**: IC\*(h) = c / (E[z|top q]·σ₁√h). c는 반드시 캠페인 공통 왕복비용 산식
  (`settings.py:3048` — 수수료 2×price×rate + 슬리피지 2×틱)에서 **단일 출처로** 가져온다.
  ⚠ 문서 간 상이 수치 주의: L2 계열 0.133pt vs ATB min_edge 0.0711pt — 슬리피지 가정/시점
  차이로 보이나, N1 구현 전에 두 값의 정의를 대조해 어느 쪽이 공통 산식 현행값인지 확정하고
  괴리 원인을 리포트 각주로 남길 것.
- σ₁은 자기 데이터 실측(최근 120거래일 1분 수익률 std), q는 실제 진입률 근사(예: 상위 5%).
- **출력**: 월간 제안 리포트 상단 고정표 + 각 (피처, 호라이즌) IC 옆에 "IC\* 대비 배율" 열.
- **한계 명시 필수**: 이 근사는 신호비례 포트폴리오 가정이다. 미륵이는 게이트형 진입 +
  ATR 손절/TP라 정확한 손익 환산이 아니다 → **판정 기준이 아니라 advisory**. 판정은 여전히
  L2 비용차감 시뮬(사후 실측)이 한다. [1] 채널 IC 합격선(0.03/0.05)·`atb_v2` 사전등록값은
  일절 무변경.
- 부수 효과: "1m 호라이즌은 거의 항상 비용 장벽에 막힌다"는 리뷰 결론이 미륵이 실측
  (1m 앙상블 영구 퇴역, 189/189 비용차감 전멸)과 정합하는지 정량 확인된다.

### N2. IC 감쇠 곡선 전 격자 카탈로그 — 신설 사전등록 채널, 1일

- `core_feature_discovery.py`의 방법론(일자단위·Bonferroni·split-half)을 그대로 상속하되
  `HORIZONS`를 [5,15,30] → **[1,3,5,10,15,30]** 전 격자로 확장한 별도 스크립트(또는
  `--grid` 모드). h=60은 넣지 않는다(15:10 강제청산 + 30m 퇴역 이력과 모순).
- Bonferroni 가족 수가 피처×3 → 피처×6으로 늘어난다 — **신설 채널의 사전등록값**으로
  고정하고, 기존 3점 채널의 판정과 섞지 않는다(§9-4: 기존 채널 기준 무변경).
- 산출: 피처별 `(peak_h, peak_IC(부호 포함), τ(지수 피팅), R², 유형)` 카탈로그.
  유형 = 단조감쇠 / 봉우리 / **부호반전** / 무정보. **IC는 절댓값 금지, 부호 유지.**
- **부호반전형 발견 시 처리**: 진입 피처 제안이 아니라 **청산/역추세 후보로 별도 섹션**에
  보고 → 챌린저 계층(규칙 기반, 예: cvd_exhaustion 계열)의 개선 입력으로 회부. 자동 반영
  없음.
- 변동성 정규화(일중 U자형 보정) 타겟은 이 채널 안에서 **원시 타겟과 병행 열**로만 출력 —
  두 열이 크게 갈리는 피처는 "특정 시간대 의존"으로 플래그.
- 주기: 월간(Phase C와 동일 트리거). 반복 관측 부풀림 통제도 동일(2회 연속 규칙).

### N3. 노이즈 벤치마크 피처 — 반나절

- 실피처 셔플 3개 + 위상 무작위화 2개를 L1/L1'/N2 스크리닝에 상시 삽입.
- 규칙(사전등록): **노이즈 피처 최고 순위보다 아래인 실피처는 ADD 후보 자격 자동 상실**
  (탈락 "제안"이지 자동 조치 아님 — §6). 노이즈가 Bonferroni 유의로 뜨면 그 달 스크리닝
  전체를 의심하라는 자동 경보.
- 시드 고정 필수(월간 재현성). raw_features에 쓰지 않고 스크리닝 시점 메모리 생성 —
  수집 계층 오염 금지(`feedback_no_schema_fallback_in_collection` 취지).

### N4. SHAP 부호 일관성 필터 — 소규모

- `feature_ablation_purged_cv.py` 실행 시 폴드별 corr(feature_value, shap_value) 부호를
  기록, 폴드 간 뒤집힘을 리포트에 ⚠ 병기. "중요도 높으나 방향 불명" 피처의 승격 제안 차단
  근거로만 사용.

### N5. bid-ask bounce 1회성 검증 — py310_64 오프라인

- **동기**: 리뷰 지적 중 미륵이에 가장 뼈아픈 부분 — 1m/3m에서 CVD·OFI의 IC 일부는
  "매수 체결 몰림 → 종가가 ask에 찍힘"의 **정의상 항등식**일 수 있다. CVD·OFI는 단기 CORE라
  해석 오류의 파급이 크다.
- **방법**: 단기 호라이즌(1m/3m/5m) 타겟을 `Close_t` 기준과 `Open_{t+1}`(다음봉 시가 진입)
  기준 두 벌로 계산해 CORE 피처 IC를 대조. 격차가 크면 그만큼이 bounce 성분.
  (Mid 기준은 분봉 마감시점 호가 이력이 저장돼 있어야 가능 — SOP Phase 1 원칙대로
  **데이터 가용성 프로브 먼저**, 없으면 다음봉 시가 방식으로 충분.)
- **효력**: CORE 교체 근거가 아니다(§3 — CORE 강등은 사용자 승인 사안). 결과는 "단기 IC
  해석 시 할인율" 문서화 + 향후 단기 피처 ADD 판정 시 다음봉 시가 IC 병기 여부 결정 입력.
