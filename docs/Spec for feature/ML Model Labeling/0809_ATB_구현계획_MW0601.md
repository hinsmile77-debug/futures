# ATB 도입 구현계획 — A → (5m 판정 대기) → B → C

- **작성**: MW0601 454차, 2026-08-09
- **상위 문서**: `0809_ATB_도입검토보고_MW0601.md` (동 폴더) — 권고 순서
  A(즉시) → 5m 첫 판정 확인 → B(ATB v2 사전등록) → C(WFA·알파봇 편입)
- **이번 세션 구현 범위**: A 전체 + B의 코드·사전등록(판정 개시는 게이트) + C 전체.
  "5m 첫 판정 확인"은 대기 상태이므로, B는 **[1] 채널을 건드리지 않는 형태로 코드만
  준비**하고 EOD 체인 연결·리포트 배선은 5m 첫 판정 후로 명시적으로 미룬다.

## Phase A — 즉시: 학습 CV 퍼징 + 누출 자가진단 (라벨 무변경)

### A-1. CV 경계 누출 제거 (3곳)

시간순 분할(TimeSeriesSplit)이라 셔플 누출은 없지만, **train 꼬리 h_min봉의 라벨이
val/holdout 구간의 미래를 이미 본** 경계 누출이 남아 있다. 세 곳 모두 같은 1줄 처방:
train 꼬리에서 h_min행 절단.

| # | 위치 | 수정 |
|---|---|---|
| a | `learning/batch_retrainer.py:_run_cv_folds` | `tscv.split()` 직후 `train_idx = train_idx[:-h_min]` (h_min = `HORIZONS[horizon_key]`). 이후의 MAX_CV_FOLD_BARS 절단·`X_full[train_idx][-len(X_tr):]` 미러 로직은 무변경으로 정합 유지 |
| b | `retrain_shadow_triple_barrier` CV 루프 | 동일 패턴 (h_min 루프 변수로 이미 보유) |
| c | `_measure_fair_holdout` | 도전자 학습을 `src[:-H]` → `src[:-(H+h_min)]` — 홀드아웃 직전 h_min행이 홀드아웃의 미래를 라벨로 봤던 갭 제거 |

- **행수 ≈ 분수 가정**: 분봉 결측이 있으면 h_min행이 h_min분 이상을 커버 → 퍼지가
  과잉 방향(안전)으로만 어긋난다. `feature_ablation_purged_cv.py:purge_train_tail`과
  같은 가정.
- **최종 모델 학습(전체 데이터 fit)은 무변경** — val이 없으므로 누출 개념 자체가 없다.
- **라벨 정의 무변경** → 섀도 TB 모델 산출물 의미 불변, [1] 채널 시계 리셋 아님.
  (b는 "다음 재학습부터 CV 수치만 정직해지는" 계측 수정이다.)

### A-2. 누출 자가진단 (`[LeakGuard]`, 판정 무영향)

- `_leak_overlap_count(train_idx, val_idx, h_min)` 모듈 함수 신설 — train 라벨 창
  `[i, i+h_min]`이 val 시작과 겹치는 표본 수. 퍼징 후 0이어야 정상.
- `_run_cv_folds`·섀도 TB CV에서 폴드마다 호출, 0이 아니면 WARNING 로그
  (스펙 `leakage_selftest`의 위치 기반 경량판 — 향후 누군가 퍼지 로직을 건드려
  깨뜨리면 즉시 드러난다). 재학습 자체는 절대 막지 않는다.

### A-영향 예고 (첫 EOD 관찰 항목)

- cv_acc가 소폭 변동할 수 있다(누출분 제거 + train 소폭 축소). 퍼지량은 폴드 train의
  0.1~1% 수준이라 EOD 모델가드 허용폭(2.5%p) 내로 예상하지만, **적용 후 첫 EOD에서
  6개 호라이즌 가드 판정이 전량 HOLD로 쏠리는지 확인할 것** — 쏠리면 acc.txt 기준값이
  구(누출 포함) 체계라는 뜻이므로 1회 force 갱신을 검토(사용자 승인 후).
- GuardShadow/GuardFair 계측치도 같은 방향으로 미세 이동 — 정의 변경을 dev_memory에 기록.

### A-검증

- `tests/test_454_purged_cv_atb.py`: ① 퍼징 후 `_leak_overlap_count`=0, ② 퍼지 전
  합성 데이터에서 overlap>0이 실제로 검출됨(가드가 살아 있음), ③ fair holdout 경계
  갭 확인, ④ ATB 라벨러·가중치·통계 모듈 단위 검증(아래 B·C 포함).

## Phase B — ATB v2 병행 트랙 (오프라인 코드 준비 + 사전등록)

> **[1] 채널 보호 원칙**: 기존 `shadow_triple_barrier/` 디렉터리·라벨 정의·재학습
> 스케줄에 일절 손대지 않는다. ATB v2는 별도 디렉터리(`shadow_atb_v2/`)·별도 채널
> 키(`atb_v2`)·수동 실행 스크립트로만 존재한다. **EOD 체인 연결과 리포트 배선은
> [1] 5m 첫 판정(현재 706/800) 이후** — 그 전까지 주간 자동 판정 없음.

### B-1. `model/atb_labeling.py` (신규 모듈, 순수 함수)

| 구성요소 | 내용 |
|---|---|
| CUSUM 이벤트 필터 | 로그수익률 누적편차 > k×σ(ATR%) 시점만 이벤트. k=3.0 출발(스펙 권장) |
| σ 하한 클리핑 | ATR 롤링 분위(20%) 하한 — 점심 횡보에서 배리어 붕괴 방지 |
| 수직 배리어 세션 클립 | **당일 15:10(강제청산)을 절대 넘지 않음** — 절대원칙 §1 정합. 클립 후 잔여 창 < 1분이면 라벨 제외 |
| min_edge 필터 | `tp_mult×ATR < 왕복비용(pt)` 이벤트 폐기 — 캠페인 공통 가정(`_roundtrip_cost_pt`)과 동일 산식 |
| 경로 스캔 | 기존 TB와 동일: 동시터치 손절 우선(conservative), 시간 배리어 → FLAT |
| 고유성·수익귀속 가중치 | 스펙 STEP 6 이식(동시성 카운트 → 평균 고유성, r_t/c_t 귀속). 최종 가중치 = 클래스 역빈도 가중 × 수익귀속(평균 1 정규화) |
| 시간 기반 퍼지드 스플릿 | CUSUM 이벤트는 비등간격이므로 행수 절단이 아니라 **[t0, t1] 실터치 시각 기반** 퍼징(스펙 `purged_train_indices` 이식) |

### B-2. `scripts/atb_v2_build_and_eval.py` (py310_64 수동 실행, 읽기 전용 + 산출물 격리)

1. raw_candles + raw_features 로드 (418차 백필행 제외 `_shadow_tb_row_is_live` 재사용)
2. 3m/5m ATB 라벨 생성 (357차 해석: 실질 승격 검토 대상 한정. `--horizons`로 확장 가능)
3. 진단 출력: 이벤트율, 라벨 분포, **평균 고유성(전봉 TB 대비 대조)**, min_edge/세션클립 제외 수
4. HistGBM 학습(결합 가중치) → 시간 기반 퍼지드 CV
5. OOS IC 평가 — [1]과 동일 방법론(스피어만, P_up−P_dn vs h_min분 실현 pt 변동),
   **이벤트 분/비이벤트 분 분리 IC** 병기 (CUSUM 학습·매분 추론 분포 불일치 검증)
6. 모델 `{HORIZON_DIR}/shadow_atb_v2/` 저장(pickle protocol=4), 리포트 `data/atb_v2/`
   (런타임 산출물 — 커밋 금지 규약 대상)

### B-3. `config/settings.py` 사전등록 — `VALIDATION_CAMPAIGN["atb_v2"]`

데이터를 보기 전인 지금이 등록 시점이다(§9 원칙). 합격선은 [1]과 동일 축으로 고정해
비교 가능성 유지 + ATB 고유 가드 2개 추가:

```python
"atb_v2": {
    "ic_delta_min": 0.03,        # [1]과 동일
    "ic_abs_min": 0.05,          # [1]과 동일
    "min_samples_hz": 800,       # [1]과 동일
    "target_horizons": ["3m", "5m"],
    "min_horizons_pass": 1,      # 대상 2개 중 1개
    "uniqueness_min": 0.30,      # 스펙 합격선 — 미달 시 라벨 설계 회귀
    "nonevent_ic_min": 0.025,    # 비이벤트 분 IC 하한 (분포 불일치 가드, abs_min의 절반)
    "judgement_start": "[1] 5m 첫 판정 이후",  # 그 전 주간 자동 판정 없음
}
```

리포트 생성기(`generate_validation_campaign_report.py`)는 등록된 키만 읽으므로
`atb_v2` 키 추가는 현행 리포트에 무영향(inert). 배선은 판정 개시 시점에 별도 커밋.

## Phase C — 검증 통계 모듈 + 배선 (라벨링과 독립)

### C-1. `learning/validation_stats.py` (신규, py37_32 호환)

스펙 `Validation · PY`에서 이식: `sharpe_ratio` / `max_drawdown` /
`expected_max_sharpe` / `deflated_sharpe_ratio` / `probability_of_backtest_overfitting`.
py3.10 문법 제거(`tuple[...]`→typing), scipy 1.5.4 `norm`만 사용. CPCV·순차부트스트랩은
이식하지 않는다(오프라인 연구 전용 — 필요 시 ATB 스크립트에서 자체 구현).

### C-2. 26주 WFA — DSR 병기 (판정문 무변경)

`backtest/walk_forward.py` `WalkForwardValidator.run()` / `AnchoredWalkForwardValidator.run()`
결과에 `dsr_advisory` 필드 추가: 검증창 주간 PnL 시계열(PPY=52) + 창별 샤프 분포로
DSR 계산, `n_trials` 인자(기본 1 — 호출자가 정직하게 셀 것). **`passed` 판정 로직
무변경** — Phase 5 조건 ③에 DSR≥0.95를 정식 편입할지는 실측 후 사용자 결정 사항.

### C-3. 알파봇(챌린저) — 선택편향 진단 advisory (게이트 아님)

- `challenger/challenger_db.py`: `get_daily_pnl_matrix()` 신설 —
  `challenger_daily_metrics`를 (date × challenger_id → total_pnl_pt) 행렬로 피벗.
- `challenger/promotion_manager.py`: `evaluate_selection_bias()` 신설 —
  ① DSR: 챌린저별 거래 PnL 시계열, `n_trials` = 등록된 챌린저 총수(유전 진화 시도 수의
  하한 — 보수적이지 않음을 명시), `sharpe_trials` = 전 챌린저 샤프 배열.
  ② PBO: 일자×챌린저 PnL 행렬로 CSCV. 챌린저 2개·블록 데이터 부족 시 "판정불가" 반환.
  기존 Bonferroni 보정(감사 P3)과 상호보완 — **자동 승격 금지 원칙 그대로**, 이 수치는
  수동 승격 검토 시 사용자에게 보여줄 진단 자료다.
