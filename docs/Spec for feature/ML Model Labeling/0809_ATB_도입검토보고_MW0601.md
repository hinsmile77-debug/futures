## 결론 요약

스펙의 제안 중 **절반은 미륵이에 이미 있다**(트리플 배리어 섀도, 메타라벨링, 동시터치 보수 처리,
IC 기반 비교, 사전등록 문화). **진짜 새로운 것은 4가지**다:

1. CUSUM 이벤트 필터
2. 고유성(uniqueness)·수익귀속 표본 가중치
3. 학습 CV의 퍼징(purging)
4. DSR/PBO 선택편향 방어

이 중 ③은 즉시 적용 가능한 저비용 수정이고, ①②는 기존 [1] TB 채널을 건드리지 않는
**별도 병행 트랙(ATB v2)** 으로 도입할 것을 권고한다. ④는 라벨링과 무관하게 26주 WFA와
Phase 6 알파봇에 편입할 가치가 크다. 거래량 바(STEP 0)와 옵션 특화 항목(§1.3)은 부적합/보류.

**권고 순서**: A(즉시: CV 퍼징 + leakage_selftest) → 5m 첫 판정 확인 → B(ATB v2 사전등록)
→ C(WFA·알파봇 편입).

## 2. 가장 중요한 발견 — 표본 중복이 장기 호라이즌을 구조적으로 부풀리고 있다

스펙 Part 2의 "문제 1"(라벨 구간 중복)이 미륵이에 실재하며, 정량화하면:

- 전 봉 라벨링 + h분 윈도우 → 평균 고유성 ≈ **1/h**. 1m은 1.0으로 문제없지만
  **30m은 ≈0.033** — 스펙 합격선(≥0.3)의 1/10.
- `MIN_TRAIN_BARS_PER_HORIZON["30m"]=500`은 독립 사건 기준 **약 17개**에 불과.
  15m(1000봉)도 독립 ~67개.
- 296차에서 30m이 "acc 0.3052 랜덤 이하"로 퇴역했는데, 그 원인의 일부가
  **소수 사건 과적합 + 부풀려진 검증**이었을 가능성이 있다.
  → **CB③-P4 재설계(실전 전환 기준 ⑥, 30m 재도입 여부) 재론 시 이 관점을 반드시 포함할 것.**
- [1] 채널의 OOS n(예: 5m 706건)도 인접 분끼리 윈도우를 공유하는 중복 표본이다.
  IC 값 자체는 유효하지만 `min_samples_hz=800`이 주는 통계적 안정감은 실제보다 크다
  — 합격선을 바꾸자는 뜻이 아니라(사전등록 불변), 판정 해석 시 유의사항.

CV 누출도 같은 뿌리다. `_run_cv_folds`의 TimeSeriesSplit은 셔플이 없어 스펙의 최악
시나리오(AUC +0.13 착시)는 피하지만, **train 꼬리 h_min봉의 라벨이 val 구간의 미래를
이미 봤다**는 경계 누출은 남아 있다. 30m 기준 폴드당 30봉 — acc에 미치는 영향은 작지만,
EOD 모델가드 허용폭이 2.5%p로 타이트한 만큼 공짜로 제거할 가치가 있다.

## 3. 도입 권고 — 우선순위순

### A. 즉시 적용 (저비용·거버넌스 무위험)

1. **학습 CV 퍼징**: `_run_cv_folds`와 섀도 TB CV에서 train 꼬리 h_min봉 절단.
   `scripts/feature_ablation_purged_cv.py:78`의 `purge_train_tail`을 그대로 옮기면 된다.
   라벨 정의 무변경 → [1] 채널 시계 리셋 없음. TimeSeriesSplit은 train이 항상 test 앞이라
   embargo는 불필요, 퍼징만으로 충분. 신·구 모델을 같은 폴드로 재채점하는 모델가드
   구조상 비교 공정성도 유지된다.
2. **`leakage_selftest` 이식**: 스펙 `Validation · PY`의 코드를 EOD 체인 계측에 추가 —
   파이프라인 변경 시 퍼징 파손을 1줄로 검출. 소비 0, 읽기 전용.

### B. 중기 — "ATB v2" 병행 트랙 신설 (기존 [1] 채널 보호가 핵심)

> ⚠ **기존 섀도 TB의 라벨 정의를 지금 고치면 안 된다.** 라벨 변경 = 모델 재학습 =
> mtime 리셋 = OOS 누적 소멸. 5m이 706/800으로 **첫 판정 1~2주 전**이고, 383→384차가
> 힘들게 고친 "평가창 리셋" 결함을 손으로 재현하는 꼴이 된다. 개선은 별도 디렉터리·
> 별도 채널로 한다.

- **구성**: CUSUM 이벤트 필터(k=3.0 출발) + 고유성·수익귀속 가중치
  + `min_edge` = 실측 왕복비용 0.0711pt + ATR 하한 클리핑(점심 횡보 배리어 붕괴 방지)
  + **수직 배리어 15:10 클립**.
- **15:10 클립은 스펙 §1.3 "만기 클립"의 미륵이 유사물**이다. 현행 라벨러는 14:40 이후
  30m 라벨이 15:10 강제청산으로 **실행 불가능한 거래**를 정답으로 가르치고, 세션
  경계에선 결측 봉을 건너뛰다 FLAT으로 침묵 처리한다 — 절대원칙 §1과 라벨 정의가
  어긋나 있는 지점.
- **평가**: [1]과 동일한 IC 방법론 + 퍼지드 CV, 합격선은 데이터 보기 전 사전등록
  ([1b] 채널, §9 원칙). py310_64 오프라인 실행이라 32-bit 메모리 제약 없음.
- **주의 — 학습/추론 분포 불일치**: CUSUM은 학습 표본만 솎아내고 추론은 매분 그대로다.
  "이벤트에서 학습한 모델이 비이벤트 분에 내는 예측"의 품질이 관건이므로, ATB v2 평가 시
  OOS IC를 **이벤트 분/비이벤트 분으로 나눠** 함께 볼 것. 비이벤트 분에서 무너지면
  매분 파이프라인엔 못 쓴다.
- 참고: 스펙의 `sequential_bootstrap`은 O(n²)라 4만 봉엔 비실용 — 스펙 자신이 권한
  근사(RF `max_samples ≈ 평균 고유성`)로 충분하며, EOD RF 경로에 한 줄로 적용 가능.

### C. 검증 프레임워크 — 라벨링과 독립적으로 가치 있음

- **DSR(Deflated Sharpe)**: Phase 5 조건 ③(26주 WFA Sharpe ≥ 1.5) 판정 시 병기 권고.
  미륵이는 이미 DECISION_LOG로 시도 이력을 남기는 문화가 있어 `n_trials` 정직 집계의
  전제가 갖춰져 있다.
- **PBO**: **Phase 6 알파 리서치 봇에 가장 절실하다.** 유전자 진화는 정의상 n_trials
  수천의 최댓값 선택 — 스펙이 말하는 "샤프가 실력이 아니라 최댓값 통계량"이 되는 바로
  그 구조다. "자동 통합 절대 금지" 원칙은 유지하되, 사용자 검토에 올라오는 후보에
  PBO/DSR 통과를 전제조건으로 걸면 검토 부담 자체가 줄어든다.
- CPCV는 py310_64 오프라인 연구용으로만 — 15폴드 학습을 라이브 체인에 넣을 이유가 없다.

### D. 도입 보류 / 부적합

- **STEP 0 거래량·달러 바**: 매분 파이프라인 9단계 전면 재설계 필요 — 스펙 스스로
  "성능 정체 시 나중에"라 했고, 지금은 그 단계가 아니다.
- **§1.3 옵션 특화 항목**(세타 조정 배리어, 만기주간 분리학습, 프리미엄 vs 기초자산):
  미륵이는 미니선물 매매라 대부분 해당 없음. 살릴 것은 15:10 클립(위 B)과 롤오버 주간
  인지 정도.
- **메타라벨링 재추진**: [2] 채널 탈락 확정(2026-08-01)을 뒤집을 신규 근거가 스펙에 없다.
  다만 스펙의 메타라벨 정의(1차 방향에 TB (1,1) 배리어를 걸어 이진 타깃 생성)는 현행
  entry_quality_prob 타깃과 다르므로, **먼 훗날 재도전한다면 "타깃 재정의"가 첫 후보**라는
  메모 정도의 가치는 있다.

## 5. 종합 의견

이 스펙의 기술적 품질은 높고(López de Prado 정통 구현, 동시터치 보수 처리·비용 필터 등
실무 함정을 정확히 짚음), 미륵이가 이미 같은 방향으로 절반쯤 와 있다는 것이 확인됐다.
따라서 "ATB로 갈아타기"가 아니라 **"현행 섀도 TB 검증을 방해하지 않으면서 누락된 4요소
(퍼징·고유성 가중치·CUSUM·DSR/PBO)를 채우는 것"** 이 올바른 도입 방식이다.

```
순서:  A (즉시: CV 퍼징 + leakage_selftest)
     → 5m 첫 판정 확인 (706/800, 1~2주 내)
     → B (ATB v2 병행 트랙 사전등록·오프라인 검증)
     → C (26주 WFA에 DSR 병기, Phase 6 알파봇에 PBO 필수화)
```
