# 정답지(Label) 설계와 검증 프레임워크

> 라벨링과 검증은 **완전히 분리된 두 개의 공정**이다.
> 라벨링은 "무엇을 맞출 것인가"를 정의하고, 검증은 "그 점수가 진짜인가"를 심문한다.
> 아래 Part 1과 Part 2는 서로 독립적으로 읽고 독립적으로 교체할 수 있게 썼다.

# Part 1. 추천 라벨링 — 적응형 트리플 배리어 (ATB)

## 1.1 설계 사상: 4가지 기법을 배타적으로 고르지 않는다

기존 4가지 방법은 서로 경쟁 관계가 아니다. **각각이 잘하는 부분을 다른 위치에 배치**하면 하나의 구조로 합쳐진다.

| 기존 기법 | 무엇을 잘하는가 | ATB에서의 배치 |
|---|---|---|
| 트리플 배리어 | 경로 의존성 | **뼈대** — 라벨 생성 로직 그 자체 |
| 변동성 조정 | 위험 정규화 | **배리어 폭** — 익절/손절선을 σ 배수로 |
| 방향성 분류 | 노이즈 내성 | **라벨 y** — 최종 출력은 {-1, 0, +1} |
| 회귀 | 수익 규모 반영 | **가중치 w** — 라벨이 아니라 표본 가중치로 |

핵심은 마지막 줄이다.

```
y = 방향          ← 아웃라이어에 흔들리지 않는다
w = |수익| × 고유성 ← 손익비를 학습에 반영하면서 중복 표본을 눌러준다
```

회귀의 "수익 규모"를 정답에 넣으면 +5% 이상치 하나가 모델을 찢는다. 같은 정보를 **가중치**로 넣으면, 모델은 여전히 안정적인 분류 문제를 풀면서 "이 자리는 크게 먹는 자리였다"는 사실을 배운다. 시험 문제는 O/X로 내되, **배점을 다르게 주는** 것이다. 이 한 수로 "방향성 분류는 손익비를 무시한다"는 단점이 사라진다.

## 1.2 구현 절차 (7단계)

### STEP 0. 바(Bar) 구성 — 선택이지만 권장

시간봉은 정보량이 불균등하다. 개장 직후 1분과 점심 1분은 같은 "1분"이 아니다. **거래량 바 / 거래대금 바**로 바꾸면 수익률 분포가 정규에 가까워지고 자기상관이 줄어든다. KOSPI200 옵션이라면 거래대금 바를 권한다.

기존 시스템이 시간봉 기반이면 이 단계는 나중으로 미뤄도 된다. 다만 성능이 정체되면 여기부터 손대라.

### STEP 1. 변동성 추정 — 모든 것의 기준 자(尺)

```python
sigma = ewma_volatility(close, span=100, floor_quantile=0.20)
```

**반드시 하한을 클리핑한다.** σ가 0에 수렴하는 횡보 구간에서 배리어가 무한히 좁아져 노이즈만 잡는 것을 막는다. 갭이 잦은 시장에서는 `atr_volatility()`가 더 안정적이다.

### STEP 2. CUSUM 이벤트 필터 — '언제' 라벨을 붙일지 고른다

```python
t_events = cusum_filter(close, threshold=3.0 * sigma)
```

모든 봉에 라벨을 붙일 필요가 없다. 아무 일도 없는 구간의 라벨은 순수 노이즈이고, 그것이 데이터의 대부분이다. 간호사가 5초마다 체온을 재는 게 아니라 이상 징후가 보일 때 정밀검사를 하는 것과 같다.

- `k = 1.0` → 이벤트 40%대 (너무 많다)
- `k = 3.0` → 이벤트 10%대 (권장 출발점)
- 목표: 표본이 80~95% 줄어들되, 라벨 수가 최소 3,000~5,000개는 남을 것

**부수 효과가 크다.** 이벤트를 솎아내면 라벨 구간 중복이 자연히 줄어, 뒤에 나올 누출 문제 자체가 작아진다. (실측: 전 구간 라벨링 시 평균 고유성 0.37 → CUSUM 적용 시 0.99)

### STEP 3. 수직 배리어 (시간 만기)

```python
t1 = add_vertical_barrier(t_events, close, num_bars=120, expiry=option_expiry)
```

`expiry`를 주면 옵션 만기를 넘지 않도록 자동으로 클립된다. **옵션에서는 이게 필수**다. 만기를 넘어간 라벨은 존재할 수 없는 거래를 정답으로 가르친다.

### STEP 4. 동적 수평 배리어 + 비용 필터

```python
pt_sl = (2.0, 1.0)      # 익절 2σ / 손절 1σ → 손익비 2:1을 라벨에 각인
min_edge = 0.0003       # 왕복비용(수수료+슬리피지+호가스프레드) 하한
```

- 배리어를 σ 배수로 잡으면 변동성 레짐이 바뀌어도 클래스 비율이 안정된다. 고정 임계치(±0.05%)를 쓰면 모델이 "시장 패턴"이 아니라 "오늘 변동성이 큰가"를 학습한다.
- `min_edge`는 **먹을 게 없는 자리를 학습 데이터에서 아예 제거**한다. 외가 옵션처럼 스프레드가 기대수익보다 큰 구간을 걸러내는 장치다. 이걸 빼면 백테스트에서만 존재하는 수익을 배운다.

### STEP 5. 경로 스캔 — 동시 터치는 반드시 손절 우선

```python
labels = build_events(close, high, low, sigma=sigma,
                      cusum_k=3.0, num_bars=120, pt_sl=(2.0, 1.0),
                      min_edge=0.0003, conservative=True)   # ← 이 플래그
```

한 봉 안에서 고가가 익절선을, 저가가 손절선을 **동시에** 터치했을 때 무엇이 먼저인지 OHLC로는 알 수 없다. 대부분의 구현이 무의식적으로 익절을 먼저 잡고, 그 결과 수익률이 구조적으로 부풀려진다. **가장 흔하고 가장 조용한 치명적 버그다.**

> 실측: 낙관 처리 시 평균수익 +0.26bp → 보수 처리 시 −0.02bp.
> 0.28bp가 통째로 착시였다. 고빈도 전략에서 이 정도면 수익과 손실을 가른다.

정밀하게 하려면 틱/체결 데이터로 봉 내부 순서를 확인하고, 안 되면 반드시 보수 처리한다.

### STEP 6. 표본 가중치 — 손익비 반영 + 중복 제거를 한 번에

```python
w = make_sample_weights(close.index, close, labels, last_weight=0.5)
model.fit(X, y, sample_weight=w["weight"])
```

수익 귀속 가중치의 정의는 한 줄이다.

```
w_i = | Σ_{t ∈ [t0_i, t1_i]}  r_t / c_t |
```

- 분자 `r_t` → 큰 수익/손실 구간의 표본이 큰 배점을 받는다 (**손익비 반영**)
- 분모 `c_t` (그 시점 동시 라벨 수) → 겹친 라벨끼리 수익을 나눠 갖는다 (**중복 제거**)

`last_weight`로 시간 감쇠를 준다. 0.5면 가장 오래된 표본이 최신의 절반 비중.

**진단 지표**: `w["uniqueness"].mean()`이 평균 고유성이다.
- 0.7 이상 → 건강
- 0.3 이하 → 라벨 구간이 심하게 겹침. `num_bars`를 줄이거나 CUSUM 임계치를 올려라. 이 상태로 학습하면 표본 수를 3배 부풀려 착각한 채 훈련한다.

### STEP 7. 메타 라벨링 — 정밀도와 베팅 사이즈

```python
meta = make_meta_labels(close, high, low, primary_side, pt_sl=(1.0, 1.0))
# 2차 모델은 방향을 다시 맞추지 않는다. "이 신호를 취할까?"만 학습한다.
prob = model2.predict_proba(X_meta)[:, 1]
size = bet_size_from_probability(pd.Series(prob), step=0.05)
```

의사와 검사기의 관계다. 1차 모델(또는 기존 룰)이 "폐렴 같다"고 진단하고, 2차 모델이 "그 진단이 맞을 확률"을 판정한다. 진단과 확신도를 한 모델에 몰아넣지 않는 것이 핵심이다.

- 재현율은 1차 모델이, **정밀도는 2차 모델이** 담당한다
- 2차 확률을 그대로 베팅 사이즈로 쓰면 "10틱 자리와 1틱 자리를 똑같이 취급"하는 문제가 최종적으로 해소된다
- `step=0.05`로 이산화하면 불필요한 리밸런싱 매매가 줄어든다

## 1.3 KOSPI 200 옵션 적용 시 필수 수정

| 항목 | 처리 |
|---|---|
| **라벨 대상** | 옵션 프리미엄이 아니라 **K200 선물(기초자산)**에 건다. 프리미엄에 라벨을 붙이면 세타 때문에 구조적 하방 편향이 섞이고, 모델은 방향이 아니라 잔존만기를 학습한다. 옵션은 실행 도구일 뿐이다. |
| **수직 배리어** | `expiry` 인자로 만기 클립 필수. 나아가 보유 시간이 길수록 필요 익절폭이 커지도록 **세타 조정형 배리어**를 검토한다. |
| **min_edge** | 호가 스프레드 × 2를 하한으로. 외가 옵션 대부분이 여기서 걸러진다. |
| **만기 주간** | 별도 분리 학습. 더미 변수로는 부족하다. 만기 효과가 평시 패턴을 오염시킨다. |
| **변동성 모델 분리** | 옵션 매수는 결국 변동성을 사는 것이다. "방향" 모델과 "변동성 확대" 모델을 따로 두고 둘 다 켜졌을 때만 진입하는 구조가 논리적으로 정합하다. |

# Part 2. 검증 — 3중 방어선

## 2.1 설계 사상: 누출은 3개의 다른 문에서 들어온다

한 가지 방어로는 막을 수 없다. 경로가 서로 독립적이기 때문이다.

| 누출 경로 | 증상 | 방어 |
|---|---|---|
| **① 시간적 누출**<br>검증셋 라벨의 미래가 학습셋에 있음 | 검증 AUC가 부풀려짐 | **Purging + Embargo** |
| **② 표본 중복**<br>겹친 라벨을 독립 표본으로 착각 | 통계적 유의성이 부풀려짐 | **고유성 가중치 + 순차 부트스트랩** |
| **③ 선택 편향**<br>여러 번 돌려 최고를 고름 | 샤프가 부풀려짐 | **CPCV + DSR + PBO** |

**③번이 가장 많이 방치되는 구멍이다.** 파라미터 100개 조합을 돌려 제일 좋은 걸 골랐다면, 그 샤프는 실력이 아니라 최댓값 통계량이다. ①②를 완벽히 막아도 ③에서 그대로 샌다.

## 2.2 구현 절차 (8단계)

### STEP 1. 전제 — 모든 표본의 `[t0, t1]` 구간을 보존한다

```python
t1 = labels["t1"]   # index=진입시각, value=실제 청산시각(배리어 터치 시각)
```

이게 없으면 아래 전부가 불가능하다. **수직 배리어 시각이 아니라 실제 터치 시각**을 써야 한다. 5분 만에 손절된 거래는 5분짜리 정보만 쓴 것이므로, 나머지 구간까지 퍼징하면 학습 데이터를 과하게 버린다.

### STEP 2. Purged K-Fold + Embargo — 1차 방어선

```python
from validation import PurgedKFold, purged_kfold_splits

cv = PurgedKFold(t1, n_splits=6, embargo_pct=0.01)   # sklearn 호환
for tr, te in purged_kfold_splits(t1, n_splits=6, embargo_pct=0.01):
    ...
```

- **셔플 금지.** 테스트 폴드는 반드시 시간 연속 블록이다.
- **Purging**: 학습 표본의 `[t0, t1]`이 테스트 블록과 조금이라도 겹치면 제거
- **Embargo**: 테스트 블록 직후 1% 구간을 학습에서 배제 (자기상관 차단)

### STEP 3. 누출 자가진단 — 파이프라인을 바꿀 때마다 돌린다

```python
print(leakage_selftest(t1, n_splits=6, embargo_pct=0.01))
```

```
 fold  n_train  n_test  train_kept_pct  overlap_count   ok
    0     4780     968            98.8              0 True
    ...
```

`overlap_count`가 0이 아니면 퍼징이 깨진 것이다. **조용히 새는 누출이 가장 비싸다.** 이 한 줄을 CI에 넣어라.

> 실증: 전 구간 라벨링(평균 고유성 0.37) 데이터에서
> 셔플 K-Fold AUC **0.6361** vs Purged+Embargo AUC **0.5037**.
> **+0.13이 통째로 착시였다.** 0.636이면 "발견"이고 0.504면 "동전 던지기"다.
> 고유성이 낮을수록 이 격차는 커진다.

### STEP 4. 순차 부트스트랩 — 배깅 모델을 쓴다면

```python
ind = build_indicator_matrix(close.index, labels)
picks = sequential_bootstrap(ind, size=len(labels))
```

RandomForest/Bagging의 기본 부트스트랩은 겹친 표본을 그대로 중복 추출해 독립성 착각을 키운다. 계산 비용이 크므로, 표본이 많으면 `max_samples = avg_uniqueness` 로 근사해도 대부분의 효과를 얻는다.

### STEP 5. CPCV — 샤프 하나가 아니라 샤프의 분포를 얻는다

```python
for tr, te, combo in cpcv_splits(t1, n_groups=6, n_test_groups=2, embargo_pct=0.01):
    ...
# 6그룹 중 2개 테스트 → 15개 폴드 → 5개의 독립 백테스트 경로
```

단일 백테스트는 **한 번의 운**이다. CPCV는 여러 개의 대체 역사를 만들어 성과의 **분포**를 준다.

보아야 할 것은 평균이 아니다.
- **5% 분위 샤프** — 최악의 경로에서도 버티는가
- **음수 비율** — 몇 %의 역사에서 손실이 나는가

평균 샤프 2.0인데 5% 분위가 −0.5라면, 그 전략은 운이 좋았던 것이다.

### STEP 6. Walk-Forward — 운영 리허설

```python
for tr, te in walk_forward_splits(len(X), n_folds=5, min_train=0.4, anchored=True):
    ...
```

CPCV가 통계적 검증이라면 Walk-Forward는 현실 시뮬레이션이다. 시간 순서를 그대로 지킨다. **둘 다 필요하다.** 폴드별 샤프가 들쭉날쭉하면(예: 18.3 / 5.5 / 19.0 / 10.7 / 22.7) 레짐 의존성이 있다는 신호다.

### STEP 7. Deflated Sharpe Ratio — 점수 부풀림 최종 방어

```python
dsr = deflated_sharpe_ratio(pnl, n_trials=40,          # 정직하게 셀 것!
                            periods_per_year=PPY,
                            sharpe_trials=cpcv_sharpes)
# {'sharpe': 14.00, 'sr_threshold': 9.60, 'dsr': 0.928, 'pass': False}
```

- `sr_threshold` = **실력이 0이어도 N번 시도하면 우연히 나오는 최대 샤프**
- 관측 샤프가 이걸 넘지 못하면 발견이 아니라 잡음이다
- 왜도(음수 = 나쁨)와 첨도(팻테일 = 나쁨)까지 벌점으로 반영된다
- **통과 기준: DSR ≥ 0.95**

`n_trials`를 정직하게 세는 것이 전부다. 실패한 시도를 빼고 세면 이 방어선은 무의미해진다. 시도 로그를 자동으로 남겨라.

### STEP 8. PBO — "전략 선택 과정 자체가 과적합인가"

```python
pbo = probability_of_backtest_overfitting(returns_matrix, n_splits=12)
# returns_matrix: (시점 × 시도한 파라미터 조합)
# {'pbo': 0.052, 'median_oos_percentile': 0.83, 'pass': True}
```

인샘플 1등이 아웃샘플에서 중앙값 이하로 떨어질 확률.

- **PBO < 0.2** → 견고
- **PBO > 0.5** → 파라미터 선택 자체가 과적합. 결과 전체를 폐기한다

DSR이 "이 전략 하나"를 심문한다면, PBO는 **"고르는 방식"**을 심문한다.

## 2.3 최종 통과 체크리스트

배포 전 전부 통과해야 한다. 하나라도 실패하면 배포하지 않는다.

```
[ ] leakage_selftest 의 overlap_count 전부 0
[ ] 평균 고유성 ≥ 0.3 (미만이면 라벨 설계로 되돌아갈 것)
[ ] 동시 터치 보수 처리(conservative=True) 적용 확인
[ ] 백테스트에 수수료 + 슬리피지 + 호가스프레드 반영
[ ] CPCV 5% 분위 샤프 > 0
[ ] CPCV 음수 경로 비율 < 20%
[ ] Walk-Forward 전 폴드 샤프 > 0
[ ] DSR ≥ 0.95  (n_trials 정직하게 집계)
[ ] PBO < 0.2
[ ] 거래 횟수 ≥ 300 (통계적 유의성의 필요조건)
[ ] 상위 피처가 경제적으로 설명 가능
```

## 2.4 절대 하지 말 것

| 금지 | 이유 |
|---|---|
| 정확도 / F1 으로 **라벨링 기법을 비교** | 라벨 정의가 다르면 시험 자체가 다르다. 국어 90점과 수학 70점을 비교하는 것과 같다. |
| `KFold(shuffle=True)` | 미래가 과거로 새어 들어간다. 위 실증에서 AUC +0.13 착시. |
| 테스트셋을 보고 파라미터 조정 | 그 순간 테스트셋은 학습셋이 된다. `n_trials`에 반드시 포함시켜라. |
| 실패한 백테스트를 `n_trials`에서 제외 | DSR이 무력화된다. |
| 표본 가중치 없이 겹친 라벨 학습 | 표본 수를 수 배 부풀려 착각한 채 훈련한다. |

**4가지 라벨링 기법을 비교하는 유일하게 정당한 방법**은, 동일한 백테스트 엔진(비용 포함)에 태우고 → 동일한 Purged/CPCV로 검증하고 → **DSR과 PBO를 통과한 아웃오브샘플 샤프와 MDD**로 줄을 세우는 것이다. 시험 점수가 아니라 입사 후 실적으로 평가하는 것이다.
