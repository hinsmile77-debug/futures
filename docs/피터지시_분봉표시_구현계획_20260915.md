# 피터 지시 — 분봉 앵커 표시 구현계획 (2026-09-15)

## 0. 요구

> 원문을 올리면 정리해서 **해당 분봉에** 지시 내용을 표시한다.
> 「언제 · 무슨 지시가 내려왔는가」만 필요하다. 손절·익절 결과는 ② 거래내역으로 본다.

## 1. 진단 — 왜 지금은 안 읽히는가

맥점은 **시각이 없는 전폭 가로선**이다. 그래서 화면이 이렇게 된다:

- 09-14 차트에 `목표 1059` · `손절 1047` · `손절 1046` · `진입(돌파)` 칩이 우측 끝에 쌓인다.
- **어느 것이 09:16 지시고 어느 것이 10:17 지시인지 알 수 없다.**
- 장 시작 전부터 하루 종일 그어져 있다 — 아직 하지도 않은 말이 아침부터 차트에 있다.

정작 시각은 **이미 붙여넣어져 있다.** 트윗을 복사하면 `9:16 AM · Sep 14, 2026` 줄이
딸려온다. 파서가 읽지 않을 뿐이다.

### 실측 (저장된 ① 원문 2일치)

| 날짜 | 시각줄 | 지시 | 결과 | 미분류 |
|---|---|---|---|---|
| 2026-09-14 | 3 | 2 | 2 | 0 |
| 2026-09-15 | 11 | 3 | 7 | 1 |

시각 줄 인식률 **11/11 (100%)**. 형식은 `H:MM AM|PM · Mon DD, YYYY` 로 일정하다.

### 🔴 선행 과제 — 진입 레벨 추출에 구멍이 있다

측정 중 두 줄에서 **진입 레벨이 안 뽑혔다**(손절만 뽑힘):

```
1045 매수 손절가 1040        → 손절 1036 만.  진입 1041 누락
1035에서 매수. 손절 1033     → 손절 1029 만.  진입 1031 누락
```

`PETER_RULES` 에 「N 매수」·「N에서 매수」 형태가 없다. 앵커를 붙여도 찍을 레벨이
없으면 소용없으므로 **이것부터 고친다**(A단계).

## 2. 설계 — 지시 하나 = 「깃발」 하나

전폭 가로선을 버리고, 지시를 **그 분봉에 꽂힌 깃발**로 바꾼다.

```
        ①09:16 ▽눌림매수 1046
        ┌──────────────
   ─────┤· · · · · · · · · · · · · · · ·   ← 레벨 스텁 (09:16 부터 오른쪽으로만)
        │▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒   ← 리스크 면 (진입~손절)
   ─────┤- - - - - - - - - - - - - - -    ← 손절 스텁 (붉은색)
        │
      09:16 봉
```

| # | 요소 | 무엇을 답하는가 |
|---|---|---|
| ① | **분봉 앵커** — 그 봉 x 에 짧은 세로 눈금 | **언제** 말이 나왔나 |
| ② | **레벨 스텁** — 그 시각부터 **오른쪽으로만** 점선 | 어느 가격에서 |
| ③ | **칩** — `①09:16 ▽눌림매수 1046` (시각을 칩 안에) | 무슨 지시인가 |
| ④ | **손절 스텁 + 사이 면** | 감수할 폭이 얼마인가 |
| ⑤ | **일련번호 ①②③** | 여러 지시를 서로 가른다 |
| ⑥ | **최신은 진하게 · 지난 것은 흐리게** | 지금 유효한 게 무엇인가 |

### 세부 규칙

- **방향 기호**: 눌림(내려와서 사라) `▽`, 돌파(뚫으면 사라) `△`.
  가격이 **어디서 오는지**를 기호가 말한다. 삼각형 방향은 584차 체결 마커와
  같은 문법을 쓰되 **속을 비운다** — 지시는 계획이고 체결은 사실이다.
- **스텁 길이**: 다음 지시가 나올 때까지. 마지막 지시는 마지막 봉까지.
- **칩 충돌**: 기존 `_place_chip` / `_chip_rects` 재사용. 좁으면 `①09:16 ▽1046` 로 축약.
- **결과 줄은 ① 에서 그리지 않는다.** 체결·청산·손절은 ② 거래내역의 몫이다.
  지금은 「1046 매수 체결」이 맥점 2개를 만들어 화면을 채우고 있다 — 이게 혼선의 절반이다.

## 3. 파싱 규칙

붙여넣은 원문을 **블록**으로 자른다. 블록 = 본문 줄 + 바로 다음 시각 줄.

```
1050까지 내려오면 매수. 손절가 1047     ← 본문
9:16 AM · Sep 14, 2026                 ← 시각 (이 블록에 속한다)
```

블록을 셋으로 분류한다:

| 분류 | 판별 | 처리 |
|---|---|---|
| **지시** | 돌파시 / 내려오면 / N에서 매수 / 매수. / 수정 / 취소 | 깃발로 그린다 |
| **결과** | 체결 / 청산 / 익절 / 손절(단독) | **그리지 않는다** (② 의 몫) |
| **미분류** | 그 외 | 버리지 않고 입력창에 목록으로 보여준다 |

### 가드

- **날짜 가드** — 시각 줄의 날짜가 세션 날짜와 다르면 앵커하지 않고
  「다른 날(Sep 14)」로 표시한다. 어제 트윗을 붙였는데 오늘로 찍히면 안 된다.
- **시각 없는 지시** — 앵커를 만들 수 없다. 버리지 말고 **전폭 선 + 「시각 미상」**
  으로 종전처럼 둔다(계측 4원칙 ②: 미측정 ≠ 0건).
- **분봉 없음** — 그 분 봉이 없으면 직전 봉에 앵커하고 칩에 원래 시각을 적는다.

### ⛔ 하지 않는 것

- 「1042 돌파시 매수로 **수정**」이 이전 지시를 대체한다고 **자동 판단하지 않는다.**
  「수정」이라는 낱말은 칩에 그대로 붙이고(`13:27 △매수 1038 · 수정`), 이전 깃발을
  지우거나 회색으로 죽이지 않는다. 무엇을 대체하는지는 사람이 본다.
- 지시 ↔ 체결을 짝지어 거래를 만들지 않는다(계획서 §6 D1).

## 4. 단계

| 단계 | 내용 | 검증 |
|---|---|---|
| **A** | `PETER_RULES` 보강 — 「N 매수」·「N에서 매수」 진입 레벨 | 2일치 원문에서 진입 누락 0 |
| **B** | 블록 분할 + 시각 파싱 + 지시/결과/미분류 분류 | 시각 인식 11/11 · 오분류 0 |
| **C** | 깃발 렌더 (①~⑥) · 전폭 가로선은 지시에 한해 폐기 | 09-14/09-15 렌더 대조 |
| **D** | 입력창에 분류 결과 미리보기 (지시 n · 결과 n · 미분류 n + 목록) | 미분류 줄이 화면에 보이는가 |

## 5. 검증 방법

- **A·B**: 저장된 2일치 원문으로 단위 검증. 진입/손절 레벨과 시각을 표로 찍어 대조.
- **C**: 오프스크린 렌더 후 픽셀 차분 — 깃발 레이어 on/off 로 그려진 양을 잰다.
  칩이 캔들에 가리지 않는지 확인(584차 교훈: 라벨은 캔들 **뒤에** 그린다).
- **D**: 미분류 줄을 일부러 넣고 화면에 뜨는지 확인.
