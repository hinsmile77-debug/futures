## STEP 6 — 앙상블 진입 판단

### 1) 앙상블 확률 통합 — `EnsembleDecision.compute()` (`main.py:5401`, `model/ensemble_decision.py`)

6개 호라이즌(1m/3m/5m/10m/15m/30m) 확률을 받아 최종 `direction / confidence / grade`를 산출한다.

- **호라이즌 가중합 + HorizonDecorrelator**: 상관계수 역수로 30분 롤링 동적 가중치 조정 후 UP/DOWN/FLAT 점수 합산.
- **AdaptiveEnsembleGater(미시구조 게이트)**: 위 가중합 직후, 등급 산정 이전에 6개 미시구조 신호로 up/down/flat_score를 한 번 더 보정 (`ensemble_decision.py:634`). 대시보드 "gate" 열이 바로 이 결과다. 상세는 [상세설명 0)](#0-adaptiveensemblegater-step-6-내부-미시구조-게이트) 참조.
- **CascadeCoherence 게이트**: 단기~장기 호라이즌 방향이 서로 어긋나면 `coherence_blocked=True` → grade 강제 X (`ensemble_decision.py:878`).
- **Platt 보정**: `ensemble_calibrator`(fit 완료 시) 또는 `horizon_calibrator`로 confidence 2차 압축, `min(conf, 0.85)`로 상한 클립.
- **레짐별 min_conf**: `zone_mc`(시간대 DynMC + FQAdj 실시간 조정 반영값)를 1차 기준으로, RISK_OFF만 `REGIME_MIN_CONFIDENCE`와 max 취함 (`ensemble_decision.py:872-874`).
- **등급 산정** (`ensemble_decision.py:878-910`):
  - `coherence_blocked` 또는 `!regime_ok` → **X**
  - conf ≥ 0.70 → **A** (단, 고신뢰 롤링 정확도가 `_HC_GUARD_ACC_THR` 미달이면 B로 강등 — conf 0.7+ 실측 acc가 conf 0.4대보다 낮은 역전 현상 대응)
  - conf ≥ 0.60 → **B**
  - conf ≥ min_conf → **C**
  - 그 외 → **X**

### 2) 진입 전 min_conf 보정 체인 (`main.py:5543-5580`)

`actual_min_conf`가 여러 단계로 조정된다: `zone_mc` → TrendGate(추세 지속 시 완화) → Layer2 IntradayRegime(DAY_RISK_OFF +5%p / CRASH +12%p 상향).

### 3) Checklist 선행 평가 (`main.py:5609`)

FLAT 포지션 + 방향 신호가 있을 때만, MetaGate가 쓸 `checklist_grade`를 미리 계산한다(뒤에서 재사용해 이중 계산 방지). 9항목 체크는 STEP 7에서 상세 설명.

### 4) MetaGate 평가 (`main.py:5637`)

`strategy/entry/meta_gate.py`의 학습된 메타 신뢰도로 `action`(take/reduce/skip)을 결정한다. 상세는 [2) MetaGate](#2-metagate) 참조. skip된 비-FLAT 신호는 selection bias 방지용으로 `_meta_shadow`에 보존된다 (`main.py:5655-5659`).

### 5) 순차 오버라이드 게이트 (§14~§20, `main.py:5666-5772`)

직렬로 하나라도 걸리면 `direction=0, grade=X`:

1. **레짐-파라미터 오버라이드**(§14) — 레짐×미시레짐 조합 진입 금지
2. **RegimeFingerprint CRITICAL**(§19) — PSI 드리프트 (현재 `FP_CRITICAL_GRADE_BLOCK_ENABLED=False`로 차단만 비활성, 감시는 유지 — 실투 전환 전 재검토 대상, `CLAUDE.md` 참조)
3. **레짐 챔피언 게이트**(§20) — 미시레짐에 챔피언 미설정 시 차단
4. **최적 진입시점 게이트** — 09:20 이전 진입 전면 금지, 09:20~09:29는 A등급만 허용
5. **ATR 진입 호라이즌 선택**(`select_entry_horizon`) — 저변동성이면 차단

## 0) AdaptiveEnsembleGater (STEP 6 내부 미시구조 게이트)

파일: `model/ensemble_gater.py`

**다른 4~5종 게이트와의 결정적 차이**: ExecutionGovernor·MetaGate·ToxicityGate·SoftGateScorer·HealthPolicy는 모두 앙상블 direction/confidence/grade가 **확정된 이후**(STEP 6 후반~STEP 7)에 개입하는 반면, `AdaptiveEnsembleGater`는 `EnsembleDecision.compute()` **내부**에서 호라이즌 가중합 직후·등급 산정 이전에 개입해 up/down/flat_score 자체를 조정한다. 즉 **최종 방향(direction)을 바꿀 수 있는 유일한 게이트**다.

- 인스턴스화: `EnsembleDecision.__init__`에서 `self.gater = AdaptiveEnsembleGater()` (`ensemble_decision.py:272`)
- 호출: `compute()` 내부 `self.gater.apply(...)` (`ensemble_decision.py:634`)
- 결과(`gating` dict)는 `decision["gating"]`으로 담기고, DB `ensemble_decisions` 테이블에 `gate_reason / gate_strength / gate_delta / gate_blocked` 컬럼으로 저장됨 (`learning/prediction_buffer.py:41-49, 165-223`) → 대시보드 "금일 conf → 진입단계 추적" 위젯의 **"gate" 열**이 이 컬럼을 그대로 표시한다.

### 입력 — 6개 미시구조 신호 (`ensemble_gater.py:135-144`)

방향 부호를 맞춘 뒤(`sign = +1 UP / -1 DOWN`) 학습된 가중치로 합산:

| 신호 | 기본가중치 | 원본 피처 |
|---|---|---|
| micro_bias | 0.28 | microprice_bias |
| mlofi_norm | 0.28 | mlofi_norm |
| queue_signal | 0.16 | queue_signal |
| cancel_add_ratio | 0.10 | cancel_add_ratio |
| depth_bias | 0.10 | microprice_depth_bias |
| mlofi_slope | 0.08 | mlofi_slope |

가중치는 고정이 아니라 **거래 결과 피드백으로 온라인 갱신**된다(`record_outcome()`, learning_rate=0.005, [0.02, 0.60] 범위 클립, 10건마다 `data/ensemble_gater_weights.json`에 저장, `ensemble_gater.py:196-244`).

### 판정 로직 (`ensemble_gater.py:72-133`)

```
gate_strength = Σ(aligned_signal × weight)
hard_support  = 신호 중 ≥0.6인 것 개수
hard_adverse  = 신호 중 ≤-0.6인 것 개수
```

| 조건 | reason | 동작 |
|---|---|---|
| direction=FLAT 또는 features 없음 | `inactive` | 조정 없음 |
| `gate_strength ≈ 0` (delta도 0) | `neutral_noop` | 조정 없음 |
| `gate_strength ≤ -0.28` AND `hard_adverse ≥ 2` | **`blocked_by_microstructure`** | `gate_blocked=True`, target 방향점수 깎고 flat_score↑ |
| `gate_strength ≥ 0.22` AND `hard_support ≥ 2` | `boosted_by_microstructure` | target 방향점수 강화(delta 최대 +0.12) |
| 그 외 | `soft_adjust` | 미세 조정(delta ±0.04 이내) |

조정된 up/down/flat_score로 direction·confidence가 **재계산**된다 — CascadeCoherence 게이트나 등급(A/B/C/X) 산정보다 앞선 시점이므로, 여기서의 조정 결과가 이후 모든 단계(min_conf 비교, Checklist, MetaGate 등)의 입력값이 된다.

### 대시보드 표시 매핑 — `_fmt_gate()` (`dashboard/panels/conf_trend_widget.py:420-426`)

```python
def _fmt_gate(self, gate_reason, gate_blocked, conf, mc):
    if conf < mc:            return "conf↓"
    if gate_blocked:         return "blocked"
    r = str(gate_reason or "")
    return r[:10] if r and r != "inactive" else "pass"
```

- `"soft_adjus"` = `"soft_adjust"`가 10자 제한으로 잘린 표시 — 미시구조 신호가 방향과 약하게 일치/불일치해 점수를 소폭 조정했다는 뜻이며, **차단이 아니다**.
- `"blocked"` = `gate_blocked=True`, 즉 `blocked_by_microstructure` — 이 경우만 실제로 방향점수가 깎이는 부정적 조정.
- `"pass"` = `inactive`(FLAT 신호 또는 features 없음) 또는 `gate_reason`이 비어있는 경우.

> ExecutionGovernor/ToxicityGate와 이름이 비슷해 혼동하기 쉽지만, "gate" 열은 이 미시구조 게이트 전용이고 나머지 4~5종은 별도의 "meta/tox" 열 또는 STEP7 로그로 확인해야 한다.

## 1) ExecutionGovernor

파일: `strategy/runtime/execution_governor.py`

**입력** (STEP 6 초입에서 산출, `main.py:5326-5338`):

- `confidence` = 6개 호라이즌 confidence 평균 (`_gov_conf`)
- `quality_score` = `features["feature_quality_score"]` (데이터소스 품질)
- `latency_sec` = `self.latency_sync.offset_sec` (서버-로컬 시간 오프셋)

**점수식**:

```
tradability = confidence×0.40 + quality_score×0.35 + latency_score×0.25
```

`latency_score`는 계단함수: ≤0.3초→1.0, ≤1.0초→0.8, ≤1.5초→0.6, ≤3.0초→0.35, ≤5.0초→0.1, 초과→0.0

**판정**:

| 조건 | action | size_mult |
|---|---|---|
| `latency_sec ≥ 5.0초` (하드블록, 점수 무관) | **block** | 0.0 |
| `tradability ≥ 0.65` | pass | 1.0 |
| `0.45 ≤ tradability < 0.65` | **reduce** | 0.6 |
| `tradability < 0.45` | **block** | 0.0 |
| pass인데 `latency_sec ≥ 1.5초` | reduce로 강등 | min(0.7, 기존값) |

**설계상 알아둘 점**(코드 주석에 명시): 정상 운영 중 `quality_score`는 95.9%가 0.94 이상, latency도 거의 항상 <0.3초라 quality+latency 기여만으로 기본 tradability가 ~0.60에 도달한다. 즉 **confidence 항은 사실상 판정에 거의 관여하지 못하고**, 이 게이트는 사실상 "인프라 장애(데이터 결손·API 지연) 전용 비상정지"로 동작하도록 311차 후속에서 확정됐다(재설계 안 함, `execution_governor.py:11-25`).

## 2) MetaGate

파일: `strategy/entry/meta_gate.py`

**핵심**: `MetaConfidenceLearner`(학습형 컨텍스트 신뢰도)와 앙상블 confidence를 등급별 가중치로 블렌딩한다.

**Step A — meta_conf 산출**: `hurst, atr_ratio, hour_minute, recent_accuracy, signal_strength(=confidence), horizon_agreement`를 피처로 `learner.predict_confidence()` 호출. 결과가 `<0.20`이면 cold-start/과소붕괴로 판단해 규칙기반 하한(≥0.45)으로 보정, 5회 연속 발생 시 경고만 로그.

**Step B — 등급별 블렌딩** (`_GRADE_CFG`, `meta_gate.py:30-48`):

| grade | ens_w | meta_w | take_floor~ceil | reduce_base | 의미 |
|---|---|---|---|---|---|
| A | 0.75 | 0.25 | 0.43~0.55 | 0.27 | 구조적으로 강한 신호 → 메타 의존 ↓ |
| B | 0.65 | 0.35 | 0.44~0.56 | 0.28 | 중간 |
| C/X | 0.60 | 0.40 | 0.45~0.57 | 0.30 | 메타 의존 ↑ (엄격) |

```
blended_conf = confidence × ens_w + meta_conf × meta_w
```

**Step C — 방향 편향 패널티**: 최근 30개 예측 중 동일 방향이 70% 초과하면 `(ratio-0.70)/0.30 × 0.05`만큼 blended 차감(최대 0.05). TrendGate 활성 구간(진짜 추세)에서는 이 패널티를 끔.

**Step D — 임계값**:

```
take_thr   = clamp(min_conf + take_add, take_floor, take_ceil)
reduce_thr = max(reduce_base, min_conf × reduce_mult)
```

STABLE_TREND/LUNCH_RECOVERY 시간대는 `reduce_thr`를 추가로 -0.04(하한 0.36) 완화.

**최종 판정**:

| blended_conf | action | size_mult |
|---|---|---|
| ≥ take_thr | **take** | clamp(learned값, 0.9~1.25) |
| reduce_thr ~ take_thr | **reduce** | clamp(learned값 or 0.5, 0.35~0.75) |
| < reduce_thr | **skip** | 0.0 |

부가: `entry_quality_prob`(meta_label 분류기)·`quantile_estimate`(q10/q50/q90)도 함께 계산하지만 **로깅/섀도우 전용**이며 action 결정에는 관여하지 않는다.

## 4) SoftGateScorer (읽기전용 섀도우)

파일: `strategy/entry/soft_gate_scorer.py`

**목적**: Checklist + Degraded + ExecutionGovernor + MetaGate + ToxicityGate 5종이 지금은 **직렬 AND**라 하나만 걸려도 등급이 X로 강등되는데("30일 실측 A/B등급 0건" — 코드 주석), 이를 **가중 점수 합산**으로 바꾸면 어땠을지 계산만 하는 순수 계측 모듈이다. `_final_grade`/`_qty_display`에는 전혀 영향을 주지 않고 `entry_gate_json`에 로그만 남는다.

**5개 성분** (0~1로 정규화 후 가중합):

| 성분 | 가중치 | 계산 |
|---|---|---|
| checklist | 0.40 | `pass_count / 9` |
| degraded | 0.15 | 비활성 시 1.0, 활성 시 `confidence / degraded_min_conf` |
| execution | 0.15 | `tradability_score` (ExecutionGovernor 결과) |
| meta | 0.15 | `meta_confidence`(blended_conf, action 무관하게 원값 사용) |
| toxicity | 0.15 | `1 - toxicity_score` (좋음=1 방향으로 반전) |

```
soft_score = Σ(가중치 × 성분)
soft_grade: A(≥0.65) / B(≥0.50) / C(≥0.35) / X
soft_size_mult = 0 (X) or min(1.25, soft_score×1.5)
```

가중치·컷오프는 "잠정값"이며, 표본이 쌓이면 `scripts/generate_soft_gate_shadow_report.py`로 사후 재보정할 예정이라고 명시돼 있다.

## 5) HealthPolicy Degraded Mode

`HealthPolicy Degraded Mode`는 시스템 자체의 상태(지연·데이터품질·캐시노후·예외밀도)를 감시해 자동으로 켜지는 방어 모드다. "모드 전환 판정"과 "진입 시점 적용"이 분리돼 있다.

### 5-1) Degraded Mode 진입/해제 판정 — `_update_degraded_mode()` (`main.py:1698`)

매 사이클(STEP 9 이후) `_emit_runtime_health()` (`main.py:1605`)에서 호출된다.

**Step A — 4개 지표로 health_level 분류** (`_classify_health_level()`, `main.py:1673`, 기본값):

| 지표 | WARNING | CRITICAL |
|---|---|---|
| 파이프라인 지연(latency_ms) | ≥ 1,000ms | ≥ 5,000ms (CB⑤ API지연과 동일 기준) |
| feature_quality_score | < 0.70 | < 0.55 |
| 캐시 노후(macro/investor 중 큰 값) | ≥ 180초 | ≥ 300초 |
| 최근10분 예외밀도(WARNING+ERROR+CRITICAL 로그 수, 특정 태그 제외) | ≥ 6건 | ≥ 12건 |

4개 중 **하나라도** CRITICAL 기준 넘으면 `CRITICAL`, 아니면 하나라도 WARNING 기준 넘으면 `WARNING`, 전부 정상이면 `INFO`.

**Step B — 가중치 누적(warn_streak)**:

- `WARNING`이고 latency < 1,300ms(`degraded_soft_latency_ms`)면 가중치 **0.35**(연성 경고)
- 그 외 WARNING/CRITICAL은 가중치 **1.0**
- INFO면 가중치 0, `warn_streak`는 즉시 0으로 리셋

**Step C — 진입 조건**: `warn_streak ≥ 2`(`degraded_enter_streak`)가 되면 Degraded Mode ON. 단, **09:00~09:10 장 시작 초기는 진입 유예**(개장 직후 구조적 지연/버스트로 오탐 방지).

**Step D — 해제 조건**: 최근 5분(`degraded_window`) 슬라이딩 윈도우의 warn 가중치 평균(`warn_ratio`)이 **0.5 미만**(`degraded_exit_ratio`)이면 OFF. (`HEALTH_DEGRADED_EXIT_STREAK`는 주석상 "미사용", 실제로는 이 슬라이딩 윈도우 비율 방식으로 대체됨.)

**1사이클 지연 문제**: `_health_degraded_mode` 플래그는 STEP 9 이후 계산되므로 진입 판정 시점엔 "1사이클 전" 값이다. 이를 보정하기 위해 진입 게이트 쪽에서 **현재 사이클 지표로 선제 판단(lookahead)**을 별도로 수행한다 (`_is_degraded_entry_blocked()`, `main.py:1849-1869`).

### 5-2) 진입 시점에 실제로 적용되는 부분 — STEP 7

Degraded Mode는 **세 지점**에서 각각 개입한다(직렬 적용됨에 주의).

**① 사이즈 산출 직후 첫 축소** (`main.py:6263-6279`)

```
if self._health_degraded_mode:
    _dg_mc = max(actual_min_conf, 0.30)   # zone_mc 기준, 절대 하한 0.30
    if confidence < _dg_mc:
        _final_grade = "X"; _qty_display = 0     # 진입 자체 차단
    elif _qty_display > 0:
        _qty_display *= HEALTH_DEGRADED_SIZE_MULT (0.60)   # 사이즈만 축소
```

여기서 쓰는 최소신뢰도는 **동적**(`actual_min_conf` = zone_mc 기준, 하한 0.30)이다 — 고정 0.62를 쓰면 현재 Platt 보정 conf 분포(32~42%대)에서 상시 차단되기 때문에, 311차 후속에서 이렇게 바뀌었다(주석 참조).

**② 자동진입 최종 게이트** (`_is_degraded_entry_blocked()`, `main.py:1830`, 호출부 `main.py:6474`)

①과 별개로, **자동진입 전용** 최종 차단 여부(`_auto_blocked`)와 표시용 최소신뢰도(`_deg_min_conf`)를 계산한다.

- 여기서는 **고정값 `HEALTH_DEGRADED_MIN_CONF = 0.62`**를 씀
- `HEALTH_DEGRADED_BLOCK_AUTO_ENTRY = True` → 자동진입만 차단 (수동진입은 `HEALTH_DEGRADED_BLOCK_MANUAL_ENTRY = False`라 차단 안 함)
- `confidence < 0.62`이면 `_auto_blocked=True` → 최종 진입 게이트(`_final_entry_ok`)에서 차단 사유 `"[차단] 자동진입 Degraded 최소신뢰도 0.62 미달"`로 표시

**③ 두 번째 사이즈 축소** (`main.py:6481-6483`)

```
_qty_auto = _qty_display   # ①에서 이미 ×0.60된 값
if self._health_degraded_mode and _qty_auto > 0:
    _qty_auto *= _hp["degraded_size_mult"]   # 다시 ×0.60
```

즉 Degraded Mode가 켜져 있고 conf가 두 임계값을 모두 통과하면, **①과 ③이 같은 배수를 두 번 곱해** 최종 수량은 원래 사이즈 대비 실질 0.60×0.60 = **0.36배**까지 줄어든다(①에서 X로 차단되지 않은 경우에 한함).

### 5-3) 요약 흐름

```
health_level 분류(4지표) → warn_streak 누적(2분 연속) → Degraded Mode ON
  ↓ (진입 시)
① conf < max(zone_mc,0.30) → grade=X, qty=0
   else qty × 0.60
② conf < 0.62(고정) → auto_blocked=True (자동진입만 최종 차단)
③ qty × 0.60 (다시 한번, 자동/수동 무관)
```

Degraded Mode 해제는 최근 5분 창의 WARNING 비율이 50% 미만으로 떨어져야 하며, 이 역시 1사이클 지연이 있어 진입 게이트 쪽에서 별도 lookahead 보정을 둔다.
