두 등급의 산정 방식이 완전히 달라:

앙상블 등급	체크리스트 등급 (_final_grade)
산정	앙상블 conf·게이트 기반 (ensemble_decision 내부)	9개 체크 항목 통과 개수 (checklist.py:268-275, ENTRY_GRADE min_pass 기준)
기록 위치	ensemble_decisions.grade	trades.db grade, [진입체크] 로그
역할	판단 참고·대시보드	진입 허용 여부 + grade_mult(사이징)
실제로 07-09 10:41 사례에서 두 값이 갈렸어 — ensemble_decisions에는 grade=C(conf 0.38)로 기록됐는데, 체크리스트는 9개 중 8개 통과(sign✅ conf✅ vwap✅ cvd✅ ofi✅ fore❌ prev✅ time✅ risk✅)로 A급을 부여했고, 그 A급이 grade_mult 1.5를 타고 Sizer 산출 10계약 풀사이즈 진입으로 이어졌어.

그리고 "5m 기반"의 의미: _entry_horizon은 main.py:5735에서 select_entry_horizon(threshold_feasibility) — 현재 ATR 대비 임계 도달 가능성으로 고른 진입 호라이즌이고, 이게 체크리스트에 전달돼 CORE 그룹(단기 1m·3m·5m → CVD·OFI·VWAP 체크)을 결정해. 손절·TP 폭도 이 호라이즌 기준으로 잡혀 (로그의 horizon=5m).

정리하면 대형 손실 3건의 구조는: 앙상블은 C급 수준 확신(38~41%)이었는데, 체크리스트가 "방향 정합 항목 8/9 통과"만으로 A급을 부여 → grade_mult 1.5 → 풀사이즈 10계약. 체크리스트 등급은 항목 통과 개수라 확신 강도(conf)와 무관하게 A가 나올 수 있고, ①에서 본 대로 5m 예측 자체가 무스킬이라 "체크 항목이 모두 정렬된 순간"이 곧 "이길 확률이 높은 순간"이 아니었던 거야. A급 산정에 앙상블 conf 하한을 결합하거나(예: A급은 conf ≥ 일정 수준 동반 필수), grade_mult 1.5를 앙상블 등급과 교차 검증하는 개선을 검토할 만해.

1. "ATR 대비 임계 도달 가능성으로 고른 진입 호라이즌"의 의미
ensemble_decision.py:222-237의 로직:


feasibility = atr / threshold_1m
if feasibility < 0.8:   return None   # 진입 자체 차단
elif feasibility < 1.5: return "1m"
elif feasibility < 2.5: return "3m"
else:                   return "5m"
threshold_1m은 "1분 안에 방향 판정으로 인정할 최소 가격 변화폭"(고정값, 0.00057×현재가 수준)이고, atr은 방금 관측된 실제 변동성이야. 즉 **"지금 이 순간 시장이 1분 만에 임계값을 얼마나 여유 있게 넘길 수 있는가"**를 재는 비율이야.

ATR이 임계값보다 조금 큰 정도(0.8~1.5배) → 변동성이 낮아서 1분 안에야 겨우 방향이 결정되는 수준 → "1m" 선택 (짧게 보고 빨리 판단)
ATR이 임계값의 2.5배를 넘음(변동성이 큼) → 1분 안에도 노이즈로 과도하게 흔들릴 수 있으니, 방향을 좀 더 넉넉한 시간(5분)에 걸쳐 판단 → "5m" 선택
정리하면: 호라이즌 선택은 예측 정확도나 모델 성능과 무관하게, 순전히 "지금 변동성 크기"만 보고 "얼마나 긴 창으로 방향을 판정할지"를 정하는 거야. 변동성 高 → 긴 호라이즌, 변동성 低 → 짧은 호라이즌.

2. CORE 그룹 체크 — "5m의 값을 본다"가 아니라 "1m·3m·5m이 같은 규칙을 공유한다"
여기서 오해가 하나 있어. settings.py:424-428:


HORIZON_CORE_GROUP = {
    "1m": "short", "3m": "short", "5m": "short",   # 셋 다 "short" 그룹
    "10m": "mid", "15m": "mid",
    "30m": "long",
}
1m·3m·5m은 서로 다른 CVD·OFI·VWAP 값을 갖지 않아. 세 호라이즌 모두 "short" 그룹으로 묶여서 완전히 동일한 CORE 체크 세트(cvd_delta_norm, vwap_position, ofi_pressure — 전부 현재 시점 1개 값)를 사용해. entry_horizon이 1m이든 3m이든 5m이든, 체크리스트에 들어가는 CVD·VWAP·OFI 값은 바뀌지 않아.

그럼 entry_horizon이 하는 일이 여기선 뭐냐면 — 그룹 자체를 결정하는 거야. 만약 진입 호라이즌이 10m·15m로 선택됐으면 CORE 그룹이 "mid"로 바뀌어서 VWAP만 강제항목이 되고 CVD·OFI는 면제, 30m이면 "long"으로 옵션 PCR 기준으로 바뀌어. 1m·3m·5m 사이에서는 체크 내용에 차이가 없고, 그 경계를 넘어(10m 이상) 선택됐을 때만 체크리스트 내용 자체가 달라져.

3. 손절·TP 폭이 호라이즌 기준으로 잡힌다는 의미
settings.py:562-574:


ATR_STOP_MULT = 1.5              # 손절: ATR × 1.5 (호라이즌 무관 고정)
ATR_HORIZON_TP1_MULT = {
    "1m": 0.3,   # 1차 목표: ATR × 0.3
    "3m": 0.5,   # 1차 목표: ATR × 0.5
    "5m": 0.7,   # 1차 목표: ATR × 0.7
}
여기서는 반대로 1m·3m·5m이 서로 다른 폭을 써. 같은 ATR(예: 3pt)이라도:

진입 호라이즌	1차 목표(TP1) 거리	의미
1m	3pt × 0.3 = 0.9pt	짧게 보고 진입했으니 아주 조금만 먹고 빨리 익절
3m	3pt × 0.5 = 1.5pt	중간
5m	3pt × 0.7 = 2.1pt	길게 보고 진입했으니 좀 더 먹을 때까지 버팀
손절(스톱)은 호라이즌과 무관하게 ATR×1.5로 고정이고, TP1(첫 부분청산)만 호라이즌별로 다르게 잡혀. 직관적으로: "5m 기준으로 진입했다"는 건 "이 판단은 5분짜리 흐름을 보고 낸 거니까, 목표도 5분짜리 흐름에 맞게 좀 더 크게 잡자"는 논리야. 반대로 1m 진입은 아주 짧은 흐름만 보고 낸 판단이니 목표도 짧게(0.9pt) 잡아서 빨리 확정짓고 나오게 설계된 거지.

지난 딥다이브에서 문제가 됐던 07-09·07-10 대형 손실 세 건은 전부 horizon=5m로 선택돼 TP1이 가장 넉넉하게(ATR×0.7) 잡혔던 케이스이기도 해 — 목표는 크게 잡았는데 정작 5m 예측 자체엔 스킬이 없었다는 게 지난 결론이었지.
