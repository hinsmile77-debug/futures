결론
이건 버그로 인한 "죽은 게이트"가 아니라, 가중치 설계(conf 40%)가 실제로는 quality/latency의 구조적 근사-상수 특성(거의 항상 1.0)에 압도당해 의미를 못 내는 설계상 사각지대입니다. 이 기간에 데이터 결손이나 심각한 지연이 없었을 뿐이고, 진짜 장애(옵션/매크로 데이터 끊김, API 지연 급증) 상황에서는 정상 작동할 걸로 보입니다 — 즉 "평상시엔 거의 항상 통과, 진짜 인프라 장애 때만 발동"하는 비상 서킷브레이커로서는 의도대로 동작 중이라고 볼 수 있습니다. 다만 docstring이 "confidence + data quality + API latency"를 대등하게 묶어놓은 것과 실제 동작(confidence는 사실상 무의미)이 어긋나 있어, "저신뢰도 상황에서 사이즈를 줄인다"는 의도였다면 재설계가 필요하고, "인프라 장애 전용 비상정지"가 원래 의도였다면 지금 상태로 두되 문서/이름을 명확히 하는 정도로 충분합니다.
