# 서버 측 스톱(감시) 주문 — Cybos/CREON Plus API 지원 여부 조사

- 작성: 2026-10-24 (MW0602)
- 계기: V4 재난손절 경로 조사 ④「청산 실패·동결」 — 신동·피터 손절은 **프로그램이 2초마다 가격을 보고 내는 주문**이라 프로그램이 동결되면 청산 시도 자체가 없다. 브로커 서버에 걸어 두는 스톱이 있으면 동결 구멍이 닫힌다.
- 근거: Cybos Plus 공식 도움말(비공식 변환판) `cybosplus.github.io` 의 CpTrade 객체 목록 65개 전수 · `CpTd6831`·`CpTd9081`·`CpTd9085` 페이지 원문 · 저장소 `docs/CyBos ref/CYBOS_FUTURES_ORDER_TR_MAP.md`(공식 테스트 xls 실측 캡처)

---

## 결론

**Cybos/CREON Plus API로는 서버 측 스톱(감시) 주문을 낼 수 없다.** 가격 조건에 닿으면 서버가 대신 주문을 내는 객체가 API에 없다.

## 1. 확인한 것

| 확인 대상 | 내용 | 스톱으로 쓸 수 있나 |
|---|---|---|
| CpTrade 객체 65개 전체 | 이름·설명에 스탑·스톱·감시·조건주문 객체 없음. 선물 주문 계열은 신규(6831)·정정(6832)·취소(6833) · 스프레드(6841~6843) · 예약(9081~9085)뿐 | — |
| **`CpTd6831` 신규주문** | 주문유형 = 지정가 · 시장가 · **조건부지정가** · 최유리지정가 / 주문조건 = 없음 · IOC · FOK | ❌ 트리거 가격 입력이 없다. 「조건부지정가」는 장중 지정가로 있다가 장 마감 단일가에서 시장가로 바뀌는 KRX 호가 유형이지 스톱이 아니다 |
| **`CpTd9081` 선물 예약 신규주문** | 입력 = 매매구분 · 계좌 · 종목 · 수량 · 단가 · 주문유형(지정가·시장가·조건부지정가·최유리) · 상품관리구분. 출력 = 예약번호 | ❌ **감시가격(트리거) 입력이 없다.** `CpTd9085` 현황 조회 항목이 「**주문예정일**」 · 처리구분 · 거부코드 → 정해진 날 장 개시에 서버가 내주는 **시간 예약주문**이다 |
| `CpTd9082`·`9083`·`9084` | 예약 취소 · 옵션 예약 신규·취소 | ❌ 같은 예약주문 계열 |

## 2. 쓸 수 없는 우회 — 미리 걸어 두는 지정가

매수 포지션을 지키려면 「가격이 떨어지면 판다」는 **스톱 매도**가 필요하다. 현재가보다 **낮은** 가격의 매도 지정가는 접수 즉시 체결되고, 높은 가격의 매도 지정가는 익절이지 손절이 아니다. **스톱은 지정가로 흉내 낼 수 없다.**

## 3. 대안 — 동결 구멍을 다른 방법으로 줄인다

| 대안 | 무엇 | 장점 | 한계 |
|---|---|---|---|
| **① 동결 시 강제 재기동 + 기동 직후 손절 재판정**(권장 1순위) | 동결 감시가 동결을 확정하면 하드 종료 → 런처 재기동 → 세션 복원 → 복원 포지션의 손절·트레일을 즉시 재판정해 필요하면 청산 | 기존 장치(`freeze_sentinel` · 런처 · 포지션 복원) 위에 2단계만 얹는다 | 동결 판정 300초 + 재기동 시간만큼 무보호. `FREEZE_SENTINEL_KILL_ENABLED` 는 「미구현 · 주간회의 승인 전 금지」 — **결정 필요**. 보유 중에는 판정 시간 단축(예: 120초) 검토 |
| ② **옵션 보호(풋·콜 매수)** | 선물 매수 진입 때 재난손절가 근처 행사가 풋을, 매도 진입 때 콜을 사 둔다 | **프로그램·통신과 무관한 진짜 서버 밖 보호.** 동결·청산 거부와 상관없이 손실 상한이 생긴다 | 매 진입마다 프리미엄 비용(하루 최대 3건) · 행사가·만기 선택 · 미니선물과 승수 차이 · 주문이 둘이 되어 집행이 복잡해진다. **비용 대비 효과를 반사실로 재야 한다**(미착수) |
| ③ HTS 의 서버 자동감시주문을 사람이 걸기 | HTS 화면에서 보유 포지션에 서버 스톱을 수동으로 건다 | 동결과 무관 | API 로 자동화할 수 없다(이 조사 범위의 결론). 대신 HTS 에 이 기능이 있는지와 미니선물 지원 여부는 **HTS 화면에서 별도 확인 필요** — 있다면 진입마다 사람이 거는 운영 절차가 되어 현실성이 낮다 |
| ④ 사람 호출 강화 | S-04(동결) · S-07(손절선 통과 뒤 미청산 — 2026-10-24 추가) 메일 | 이미 장착 | 사람이 PC·HTS 앞에 있어야 한다 |

## 4. 권고

1. **서버 측 스톱은 API로 불가** — 이 방향의 구현은 하지 않는다.
2. 동결 구멍의 1차 처방은 **① 강제 재기동 + 기동 직후 손절 재판정**이다. → **[2026-10-24 구현 · 사용자 결정]** 보유 중 · 09:00~15:05 · FZ-1 신호 2종 180초 정체 · PID 확인 · 하루 2회 조건으로 센티넬이 끊고, 새 프로세스가 첫 실시간가로 손절을 재판정한다(가격 미수신 90초면 S-08). 상세 `dev_memory/DECISION_LOG.md` 2026-10-24(654차).
3. **② 옵션 보호**는 유일한 「프로그램 밖」 보호라 반사실로 비용을 재 볼 가치가 있다 — 21일 V4 거래에 진입마다 재난손절가 행사가 위클리 옵션을 산다고 놓고 프리미엄 비용과 꼬리 절감을 비교한다(별도 과제).
4. ③은 HTS 화면 확인 한 번으로 정리할 수 있다 — 사용자 확인 요청.
