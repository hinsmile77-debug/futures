- 요청: 현재 미륵 체계(`main.py` 단일 프로세스)에 붙어 있는 신동을 **완전히 독립시켜 새 엔진으로 분리 운영**하는 경우의 이득과 손실 조사.
- 성격: **읽기 전용 조사 · 제안.** 코드·규격·설정 무변경. 결정은 사용자 몫.
- 선행: [미륵 장점 도입 검토](신동_V4_미륵장점_도입검토_MW0602-20261024.md)(같은 날) — 그 문서 §3-1 「CB④·⑤ 결합」·§5 「가져갈 것/끊을 것」을 이어받는다.
- 근거: 이 브랜치 코드(줄 수·호출 경로는 `wc -l`·`grep` 실측) + 커밋된 점검·딥다이브 문서 인용. ⚠ 클라우드 세션이라 **로그·DB 가 없다** — 빈도(몇 번 막혔나·몇 번 얼었나)는 측정하지 못했고 §6 실측으로 넘긴다.

## 0. 결론

| # | 결론 |
|---|---|
| 1 | **가장 큰 이득은 수익이 아니라 위험 — 「미륵이 무거워지거나 얼면 신동도 무방비가 된다」를 끊는 것이다.** 신동 손절은 서버에 걸 수 없고(Cybos/CREON API 에 스톱 주문 없음 — 같은 날 조사) **프로그램이 2초마다 가격을 보고 내는 주문**이다. 그 프로그램이 23,083줄 `main.py` 의 단일 Qt 이벤트 루프이고, 거기서 미륵 파이프라인(재학습 중 3~4초/분)·EOD 마감(10/14 동결)·대시보드(18,328줄)가 같이 돈다 |
| 2 | **가장 큰 손실은 「사고로 굳은 집행층」을 다시 짜야 한다는 것이다.** 주문·체결·대기주문·청산 재시도·잔고 동기화·증거금·강제청산 경로가 `main.py` 안 `_ts_*` 함수군 약 **5,500줄** + `position_tracker` 1,833줄 + `cybos/api_connector` 2,091줄 + `freeze_sentinel` 1,234줄이고, 집행 사고 회귀 테스트가 **34개 파일**이다. 이것들은 `self`(미륵 메인 윈도) 상태에 엮여 있어 그대로 들어내기 어렵다. 새로 짜면 이미 고친 사고(청산 거부 113분 · 대기주문 고착 · 15:10 경로 6개월 도달 불가)를 다시 밟을 위험이 있다 |
| 3 | **「완전」 독립은 데이터 때문에 생각보다 크다.** 신동이 읽는 원천 4종 — `raw_candles`(1분봉) · `option_flow.db`(7222 개인 콜·풋) · `premarket_levels`(08:50 맥점·ATR14 + EOD 이력 캐시) · `raw_investor_futures`(외국인 선물) — 이 **전부 미륵이 쓴다.** 미륵을 끄면 수집기·맥점 계산(`premarket_levels` 677줄 + `levels_store` 1,132줄)·EOD 캐시까지 옮겨야 하고, 미륵을 켜 두면 데이터 의존이 남아 「완전」이 아니다 |
| 4 | **계좌는 하나다.** 두 엔진이 같은 계좌에서 동시에 주문하면 안 되고, 지금 그것을 막는 장치(거래주체 선택 · FLAT 일 때만 전환 · CB② · ProfitGuard 계정축 = 3주체 실현 net 합)는 **한 프로세스 안의 메모리 상태**다. 분리하면 이 셋을 프로세스 사이 공유 상태로 다시 만들어야 한다 |
| 5 | 그래서 권고는 **한 번에 이사하지 말고 3단계로 가르는 것**이다(§5): ① 같은 프로세스 안에서 결합부터 끊고(싸다 · 이득의 일부를 바로 얻음) → ② 미륵을 「수집 + 섀도(주문 금지)」로 내리고 신동 엔진이 계좌를 갖는 2프로세스(집행층은 **재작성 말고 추출**) → ③ 신동이 자기 최소 수집을 갖고 미륵은 선택 운영. ⚠ **V4 첫 20거래일 판정 창(10/26~) 안에는 집행 엔진을 바꾸지 말 것** — 실거래 대사가 「규칙 탓인지 새 엔진 탓인지」를 가를 수 없게 된다 |

비유: 지금 신동은 **큰 저택(미륵)에 세 든 사람**이다. 전기·수도(데이터)·경비 시스템(안전장치)·현관 열쇠(계좌)를 집주인과 같이 쓴다. 집주인이 공사(재학습)를 하면 신동 방 전기도 깜빡이고, 집 전체가 정전(동결)되면 신동 방 방범장치(2초 손절)도 꺼진다.
독립해 나가면 조용하고 내 일정대로 산다 — 그러나 **전기·수도를 새로 끌어와야 하고, 저택의 경비 시스템을 그대로 떼어 가지 않으면 6개월간 도둑맞으며 손본 그 경험을 다시 치러야 한다.** 그리고 현관 열쇠(계좌)는 여전히 하나라서, 집주인과 열쇠 쓰는 규칙은 새로 정해야 한다.

| L8 | **판정 해석 오염(시점 문제)** | 규칙이 같으니 V4 재생 채점은 이어지지만, **실거래 대사**는 엔진이 바뀐 날을 경계로 불연속이 된다 | V4 첫 판정 창 10/26 ~ 20거래일 | 판정 창이 끝난 뒤 전환. 전환일에 `strategy_events` 불연속 마커(461차 관례) |

## 4. 저울질 — 목적별

| 목적 | 분리의 효과 | 판정 |
|---|---|---|
| 방향 정확도 | **변화 없음**(같은 규칙·같은 데이터) | 분리의 이유가 못 된다 |
| 수익률 | G2·G3 의 간접 효과(놓친 진입·슬립 감소) — 크기 미측정. 반대로 L1 재작성 결함이 생기면 즉시 손실 | 실측(§6 ①②) 전에는 「작은 +, 꼬리 −」 |
| **위험** | G1·G4·G5·G6 이 크다 — 서버 스톱이 없는 구조에서 「보호 장치가 같은 프로세스의 남의 짐 때문에 꺼지는」 경로를 없앤다. 대신 L1·L4 를 잘못하면 새 꼬리(이중 주문·청산 실패)가 생긴다 | **분리의 진짜 이유.** 단 추출·검증을 전제로 |
| 경량 운영 | 3단계 끝에서 크게 좋아진다. 1~2단계 동안은 오히려 무겁다(L7) | 중장기 이득 |

→ **「분리할 것인가」보다 「어떻게 가를 것인가」가 손익을 정한다.** 재작성으로 가면 L1 이 G1 을 잡아먹고, 추출로 가면 G1 을 거의 공짜로 얻는다.

## 5. 권고 경로 — 3단계

| 단계 | 내용 | 얻는 이득 | 감수하는 손실 | 들어가는 조건 |
|---|---|---|---|---|
| **0. 실측** | §6 ①~③ — CB 결합으로 지워진 신동 진입 · 동결/지연 중 신동 보유 여부 · COM 2프로세스 가능 여부 | 결정 근거 | 없음 | 지금 |

| **3. 신동 최소 수집 자립** | 신동 엔진이 1분봉·7222·외국인 선물·08:50 맥점/ATR14 를 직접 수집 · 미륵은 장후 연구/선택 운영 | 경량 운영 완성 · L2·L3 해소 | L2(수집 이식) · 미륵 연구 데이터(97피처) 축적 중단 여부는 별도 결정 | 2단계 20거래일 무사고 |

## 6. 결정 전에 잴 것 (Windows MW0602 — 이 세션에는 로그·DB 가 없다)

```bat
:: ① 미륵 CB 때문에 지워진 신동 진입 (G2 크기)
findstr /C:"[ShindongLive]" logs\*.log | findstr /C:"기각" /C:"쫓지 않음"
findstr /C:"[CB]" logs\*.log | findstr /C:"파이프" /C:"ATR"
::   → 기각·SKIP_STALE 시각 ±5분에 CB 「파이프라인 지연」·「ATR 급등」 PAUSE 가 겹친 건수.

:: ② 동결·지연 중 신동 보유 여부 (G1 크기)
::   freeze_sentinel 동결 판정 시각 × 신동 집행 기록(data\<날짜 폴더>\shindong_exec.json OPEN 구간) 교차.
::   + 분 파이프라인 경과(CB⑤ 입력) 분포를 신동 보유 분 / 비보유 분으로 나눠 본다.

:: ③ Cybos COM 2프로세스 (L3 · 2단계 전제)
::   모의 서버에서 읽기 전용 두 번째 프로세스(CpCybos.IsConnect · 시세 1건 · GetLimitRemainCount)를
::   미륵 장중 실행 상태로 띄워, 한도 잔여가 공유되는지·첫 프로세스에 영향이 없는지 확인. 주문 TR 은 쓰지 않는다.
```

판독 규칙(사전 고정): ①·② 가 **둘 다 0건**이면 분리의 위험 이득(G1·G2)은 「잠재」로만 두고 1단계까지만 한다. 어느 하나라도 1건 이상이면 2단계 설계에 착수한다. ③ 이 실패하면 2단계는 「미륵 프로세스 정지 + 신동 단독」(= 3단계 직행, L2 를 먼저 치른다)으로 바뀐다.
