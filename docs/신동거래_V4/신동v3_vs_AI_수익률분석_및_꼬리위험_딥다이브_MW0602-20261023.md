## 6. Q&A — 본전청산 뒤 진입 규칙과 방향

**Q1. 본전청산 뒤 진입은 FLOWR60 규칙인가? → 예.**
`families._run_signal`은 `len(trades) >= 1`부터 신호를 `sig_after`(FLOWR60)로 바꾼다 — 첫 거래가 본전·트레일·손절 무엇으로 끝났든 같다. 청산 다음 분부터 판단하며, 60분 창이 09:00 이후만 쓰므로 R60은 **빨라야 10:00**(10/23: 09:11 본전 → 10:00까지 공백).

**Q2. 방향은 본전 반대만 가능한가? → 아니다, 양방향 가능.**
방향 금지(`banned`)는 청산 사유 `"SL"`에서만 누적된다. 본전(`BE`)은 금지를 걸지 않으므로 R60이 가리키면 같은 방향도 재진입한다(10/20: 매도 본전 → 매도 본전 → 매도 +6.41).

**「본전 방향도 금지」 비교 (본전@3)**

- **손절 = 방향이 틀렸다는 증거**(0.6×ATR 역행) → 금지가 맞다.

## 8. 사이징 표 해설

### 8-1. X% ↔ 계약수 — 읽는 법 (정정 반영)

질문은 하나다: **「최악의 경우 한 거래에서 자본의 몇 %까지 잃어도 되나」** = X.

1. 1계약 최악손실 = 0.6 × ATR14 × 5만원 (ATR 30 → 18pt → 90만 · ATR 45 → 27pt → 137만)
2. 한도 = 1,500만 × X% (6% → 90만 · 12% → 180만 · 18% → 270만)
3. 계약수 = 한도 ÷ 1계약 최악손실, 소수점 버림, 최소 1 · 최대 2

| X (한도) | ATR 30 (1계약 90만) | ATR 45 (1계약 137만) |
|---|---|---|
| 6% (90만) | 1.0 → **1계약** | 0.66 → 최소 1 → **1계약** ⚠ 실제 위험 137만(9.1%) 한도 초과 |
| 12% (180만) | 2.0 → **2계약** | 1.3 → **1계약** |
| 18% (270만) | 3.0 → 상한 **2계약** | 1.97 → **1계약** |

> 🔴 **정정 ①** — 세션 초판은 「18% · ATR 45 → 2계약(지금과 같음)」이라 적었으나 **틀렸다**(270 ÷ 137 = 1.97 → 1계약. 2계약이면 274만으로 한도 초과). 지금 MAIN(변동성 무관 항상 2계약)은 X로 치면 **약 18.3% 이상**으로 운영되는 셈이다.

**더 쉬운 형태 — X는 「2계약 허용 ATR 상한」과 같은 말이다**

```
2계약 허용 ATR 상한 = X × 250   (X 는 % 숫자)
```

| X | 2계약 허용 ATR | 9/21~10/23 21일 중 2계약인 날 |
|---|---|---|
| 12% | ≤ 30.0 | 7일 (10/01 · 10/06~10/14) |
| **15%** | **≤ 37.5** | **15일** — 1계약은 10/16~10/23 고변동 6일 |
| 18% | ≤ 45.0 | 20일 — 1계약은 10/23 하루 |

> 🔴 **정정 ②** — 세션 초판은 「평소엔 12%든 18%든 똑같이 2계약 · 목적에 맞는 값 12%」라 적었으나 **틀렸다.** 12%면 ATR 30.5인 날(9/29·9/30·10/02)도 1계약이 되어 21일 중 14일을 줄인다. **「평소 그대로, 고변동만 축소」가 목적이면 15%**다. §7-2의 ATR 정규화(1계약 날 = 10/20~10/23)가 15%와 거의 같은 동작이므로 그 결과(수익 약 −10%, 노출 212 → 164만)가 15%의 대략적 효과다.

⚠ 표는 **최악 손실**이다. 재난손절이 실제로 걸린 것은 21일 중 2번(10/07·10/23, 기준선 기준)뿐이고 대부분 손실은 훨씬 작다. 반대로 급변동 시 손절가보다 미끄러질 수 있어 실제 최악은 표보다 약간 클 수 있다.

### 8-2. ATR14 — 설정값이 아니라 매일 계산되는 값

`features/levels/premarket_levels.py:atr_of()` (저장: `premarket_levels.atr14`, stage `0850`)
