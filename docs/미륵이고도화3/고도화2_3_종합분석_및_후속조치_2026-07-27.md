## 3. 고도화2가 부족했던 점 → 고도화3가 필요해진 이유

고도화2는 "무스킬 문제"를 **피처셋 품질**의 문제로 규정하고 해결하려 했다. 그러나
고도화3의 63피처 전수검증(Bonferroni 보정)에서 그 전제 자체가 반증됐다:

- 계측 결함으로 취급했던 `cvd_divergence`·`ofi_norm`(단기 CORE)이, 계측을 다 고친
  뒤에도 여전히 노이즈와 구분 불가능(t=0.93~0.65, t=0.54~-1.33) — **CORE 피처
  자체에 방향 정보가 없다**는 더 심각한 결론.
- 등급 A/B 부재의 실제 원인은 05-19 이후 2개월간 6개 호라이즌 전부가 랜덤급
  정확도(31~34%, 3-class 랜덤 33.3%)에 머무른 것 — 특정 파라미터 문제가 아니라
  **시스템 전체가 무엣지 상태**.
- 등급 척도를 실측 기반(EdgeScore)으로 바꾸려던 시도도 평균회귀로 반증 — 메타층을
  고쳐도 원천 데이터에 신호가 없으면 소용없음이 실측으로 확정.

결국 고도화2는 "있는 피처를 정제"했지만, 고도화3는 "애초에 방향 정보가 있는
피처가 거의 없다"는 것을 증명하고 새 정보원(옵션 포지셔닝)을 찾아야 한다는
결론에 도달했다.

### 6-1. SHAP 계측 구조적 실패 최종 회복 확인 (394차)

311차(2026-07-12)가 지목한 SHAP 계측 구조적 실패(TreeExplainer 다중클래스
미지원·HGB 속성부재·길이체크 실패 — "ofi_norm 지배" 관측이 깨진 계측기
산출물이었던 사건)의 코드 수정 자체는 당일 자체검증됐으나, 이후 332차·337차가
같은 하위시스템에서 후속 결함("매분 조용히 실패")을 재차 발견해 "완전 회복"이
공식 확인된 적이 없었다.

**실측(2026-07-27)**: `shap_tracker.db`(`shap_scores`, 1,204,799행) 직접 조회 —
오늘 00:00~15:09(270분봉) 1m 10개 피처 전부 매분 정상 스코어링, 공백 없음.
`shap_tracker_history.json`도 3주 연속(07-16·07-24·07-27) `n_samples=120`으로
끊김 없이 기록. importance 값 대부분 0.0인 것은 버그가 아니라
`np.clip(importances_mean, 0.0, None)` 설계(음수 permutation importance
클리핑) — 고도화3의 "대부분 피처 무정보" 결론과 정합.

**결론**: 311차→337차 계보의 계측 실패 자체는 **회복 확인됨**. 단 312차·332차의
**재기동 cold-start 크래시**(별개 코드 경로)는 이번 조사 범위 밖으로 남겨둠.

### 6-2. `horizon_feature_sets.json` pkl 필드 6개 호라이즌 전수감사 (395차)

389차·337차가 각각 개별 사례로 지목했던 "계획 문서 pkl 필드 ≠ 실제 배포 모델"
패턴이 구조적으로 반복되는지 6개 호라이즌 전체를 배포 pkl과 전수 대조.

**17건 불일치 발견, 두 하위 패턴**:
- **승격 성공, 표기 누락(4건)**: 1m `queue_directional_depletion`·
  `cvd_delta_norm`·`micro_regime_code`, 3m `cvd_delta_norm` — `need_add`인데
  실제로는 이미 배포됨.
- **강등 후 표기 잔존(13건, 전부 `include_pending_validation`)**: 15m 옵션
  magnitude 4종(F4 재현실패 결론과 일치), 5m/10m/15m/30m의 macro_* 계열 등 —
  `in_pkl`인데 실제로는 배포에서 빠짐. 다른 호라이즌 배포분이 잘못 전사된
  정황으로 추정(예: 15m 항목에 30m·10m 배포분이 복붙된 흔적). 10m
  `cvd_direction`은 2026-06-25 project-wide 폐기된 피처가 후보 목록에 남아있던
  잔존 항목.

**조치**: 17건 전부 정정, 재검증 스크립트로 불일치 0건 확인. `_feature_status_

### 6-3. 297차 "퇴역 시 소비경로 누락" 패턴 전수조사 + CB③-P4 우회경로 수정 (396차)

재귀적인지 확인하기 위해 `is_grade_restricted()`(CB③-P4 상태)의 전체 소비처를
grep 전수확인.

**발견**: `main.py`에 정확히 2곳 — 메인 C등급 게이팅(`:6305`, 플래그 게이트
정상)과 C등급 실험적 자동진입(`:7603`, `ENTRY_GRADE_C_AUTO_EXP` 기본 `True`로
**활성 상태**, 플래그 게이트 없음). 즉 `CB3_P4_GRADE_BLOCK_ENABLED=False`(297차가
"차단만 비활성"으로 결정)로 설정돼 있는데도, 이 실험적 경로는 퇴역 확정된 30m
정확도로 계속 억제되고 있었다 — **297차의 수정 자체 안에서 패턴이 재발**.

**조치**: 사용자 승인 확인 후 Phase1이 사전에 남겨둔 스펙대로 플래그 게이트 추가

제어한다"고 주장하나 실제 소비처는 대시보드 표시뿐이었던 저위험 인스턴스)도
함께 정정.

**검증**: `py37_32`(실런타임) py_compile 통과. `pytest` 미설치 확인(회귀테스트
