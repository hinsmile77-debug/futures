## 1. 타임라인 정정 — "6일"이 아니라 "약 2개월"

`data/db/predictions.db`의 `ensemble_decisions` 테이블을 직접 쿼리한 결과:

```sql
SELECT MAX(ts) FROM ensemble_decisions WHERE grade IN ('A','B');
-- → 2026-05-19 10:10:00
```

- 전체 누적: A=474건, B=310건, C=3116건, X=14364건 (2026-05-08~07-27 전체 기간)
- **2026-05-19 10:10 이후**로는 A/B **0건** — 07-10~07-27 일별 집계(369~370건/일)도 전부
  C/X만 존재.
- 05-19 당일 오전만 봐도 09:02~10:10 사이에 A 1건·B 25건이 몰려 있다가 10:10을 마지막으로
  뚝 끊김.
- 방향성(direction≠FLAT) 신호가 confidence 0.60을 넘긴 사례 자체가 05-19 10:10 이후
  단 한 건도 없음(0.60+ 방향성 레코드 26건은 전부 05-19 당일 오전).

즉 정기점검 메모가 관측한 "6일"은 최근 관측창이 좁아서 생긴 과소평가이며, 실제로는

## 2. 387차는 원인이 아니다 — 근거 2가지

### 2-1. 타임라인 불일치

387차 반영일은 2026-07-26(일). 등급 소멸은 2026-05-19부터 시작됐다. **2개월 먼저 시작된
현상을 2개월 뒤의 변경이 일으킬 수 없다.**

### 2-2. 구조적으로도 등급 산출 경로에 영향이 없음

`config/settings.py:USE_ROLLING_SIGMA_THRESHOLD = True` 이므로, `main.py:4282-4296`이
**매 분봉마다** `HORIZON_THRESHOLDS`를 rolling σ×K(방법3) 값으로 실시간 덮어쓴다:

```python
if runtime_settings.USE_ROLLING_SIGMA_THRESHOLD and self._sigma_20 > 0:
    _cfg_s.HORIZON_THRESHOLDS.update({
        "1m":  self._sigma_20 / 100.0 * _K * math.sqrt(1),
        ...
    })
```

387차가 `config/settings.py`에 손으로 써넣은 정적값(1m=0.00075 등)은 라이브에서:

- **등급(grade) 산출과는 무관** — `model/ensemble_decision.py:956-990`의 grade 로직은
  Platt 보정된 `confidence`가 0.70/0.60 고정 컷을 넘는지만 보며, `HORIZON_THRESHOLDS`를
  참조하지 않는다.
- 실제 라이브 효과는 (a) 다음 배치/EOD 재학습의 레이블 생성(`USE_FIXED_LABEL_THRESHOLD=True`
  일 때만) (b) `select_entry_horizon()`의 1m/3m/5m 버킷 분류(`threshold_feasibility`
  피처를 통해 간접 반영, 이 피처 자체도 rolling σ 값 기준으로 매분 재계산됨) 두 곳뿐이며,
  둘 다 등급 A/B 발생 여부와는 별개 경로다.

**결론**: 387차를 원복해도 등급 부재는 전혀 개선되지 않는다.

## 3. 진짜 원인 — Platt 보정기가 "정직하게" 반영 중인 랜덤급 모델 정확도

### 3-1. 오늘(07-27 11:51) 자 calibration_report.md 실측

```
⚠️ 신뢰도 역전 경고 (Confidence Inversion Alert)
- 저신뢰(0.3~0.5) 정확도: 32.96%
- 고신뢰(0.6+) 정확도:   28.52%  ← 4.43%p 낮음
- 고신뢰 ECE: 0.3833 (표본 2538건)
- 등급 A 자동진입이 B보다 오히려 정확도 낮은 역전 상태
```

호라이즌별(최근, Platt 도입 이후=2026-06-04~, n=45,648건) 전 구간 정확도:

| 호라이즌 | 전체 정확도 | 0.6~0.7 bin acc | 0.7~0.8 bin acc |
|---|---|---|---|
| 1m | 34.17% | 23.53%(n=17) | 10.0%(n=10) |
| 3m | 31.87% | 21.71%(n=152) | 38.30%(n=47) |
| 5m | 33.04% | 31.54%(n=279) | 33.33%(n=30) |
| 10m | 31.77% | 29.95%(n=217) | 50.0%(n=8) |
| 15m | 32.27% | 30.71%(n=609) | 41.38%(n=116) |
| 30m | 32.54% | 25.42%(n=720) | 12.39%(n=113) |

6개 호라이즌 **전부** confidence bin(0.3~0.9)에 관계없이 정확도가 31~34%대 — 3-class
랜덤(33.3%)과 통계적으로 구분되지 않으며, 고신뢰 구간일수록 오히려 더 나쁜 경우가 더 많다.
이는 어제오늘 새로 생긴 문제가 아니라 이미 진단된 문제의 연장선이다.

### 3-2. 05-19 폭락일이 최초 발화점

`dev_memory/DECISION_LOG.md` 60차(2026-05-19) 기록:

> "5/19 세션에서 conf 48~83%인데 30분 정확도 0%인 Overconfidence 현상 확인"

이날(국내 선물 -1.8% 급락)의 극단적 overconfidence-미스매치가 이후 2개월간 이어진 일련의
보정 강화 조치(HCGuard 도입, Platt WINDOW 100→200, C 1.0→0.1→0.05→0.02, 261차/06-29)의
직접 계기였다. `dev_memory/NEXT_TODO.md` 275차(07-02) 기록이 정확히 이 인과를 명문화한다:

> "① conf 하락(06-29~) 근본 원인 특정 — [DONE] 276차에서 확정. ... 진짜 원인은 261차
> (06-29) Platt 보정 강화(WINDOW 100→200, C 0.05→0.02)가 그동안 가려져 있던 랜덤급
> 정확도를 정직하게 반영한 것. 06-29 전후로 꺾이지 않고 6월 내내 랜덤 근방(25~40%)이었음"

즉 `PredictionCalibrator`(Platt, C=0.02)와 `HCGuard`는 버그가 아니라 설계대로 작동
중이다. "등급 A/B 부재"는 안전장치가 **모델이 실제로는 방향성 예측 엣지를 갖고 있지
않다**는 사실을 정직하게 반영한 결과이며, 오늘 새로 생성된 리포트는 이 상태가 **2개월째
전혀 개선되지 않았음**을 재확인해줄 뿐이다.

### 3-3. CB③과의 연결

같은 이유로 CB③(30분 정확도<35%→당일정지)도 06-25부터 코드 레벨로 비활성 상태이며
(`CB3_P4_GRADE_BLOCK_ENABLED=False`, CLAUDE.md 절대원칙 §2 참조), 재활성화 조건
("30m acc≥35% 5거래일 연속 유지 + conf_inversion 미발동", 277차 결정)은 오늘 리포트
기준(30m acc=32.54%, conf_inversion=inverted:true)으로도 여전히 미충족이다.

## 4. 개선 제안

1. **정기점검 절차 보강(재발방지, 최우선)** — 등급/신뢰도 이상 발견 시 최근 재보정
   커밋을 먼저 의심하기 전에 `calibration_report.md`와 `predictions.db.ensemble_decisions`
   실측부터 확인하는 순서를 dailycheck 절차에 명문화. 오늘처럼 "최근 변경 탓"으로
   잘못 짚으면 2개월 된 근본 문제가 계속 방치된다.

2. **CB③/CB③-P4를 "30m 전용"에서 "다중 호라이즌 공통 게이트"로 재설계 검토** —
   CLAUDE.md의 CB③-P4 비활성 사유는 "30m만의 문제라 다른 정상 호라이즌까지 막는 부작용"
   인데, §3-1 표는 **정상인 호라이즌이 사실상 없음**을 보여준다. 전제가 달라졌으므로
   실전 전환 기준 ⑥ 재검토 시 "30m 재도입"보다 "6개 호라이즌 공통 정확도 기준으로
   CB③ 자체를 재설계"를 우선 옵션으로 검토할 것.

3. **근본 원인 조사 착수(가장 중요, 아직 미착수)** — 왜 05-19 이후 6개 호라이즌 중
   단 하나도 랜덤 이상을 회복하지 못했는가. 후보 가설:
   - 05-19 폭락 이후 시장 미시구조/변동성 체제가 근본적으로 바뀌어(387차가 지목한
     "변동성 자체의 전반적 재확대"와 동일 계열) 기존 피처셋이 새 레짐에서 정보력을
     잃었을 가능성
   - 앙상블 로그(`detail` JSON)에서 종종 `weight: 0.0`으로 나타나는 호라이즌(decorrelation/
     adaptive weighting이 상시 배제) — 애초에 기여 기회 자체를 못 받는 호라이즌이
     있는지 전수 확인 필요
   - rolling σ 방법3(HORIZON_THRESHOLDS 매분 자동조정, FLAT 34% 타겟)이 예측가능성과
     무관하게 레이블을 항상 랜덤에 가깝게 재단하는 순환논리 구조는 아닌지 점검
   - 이 조사는 파라미터 재보정(387차류)으로는 해결 불가하며 피처/레이블/모델 구조
     수준의 별도 세션이 필요하다 — `docs/미륵이고도화2/` 계획에 최우선 항목으로
     등록할 것을 제안.
