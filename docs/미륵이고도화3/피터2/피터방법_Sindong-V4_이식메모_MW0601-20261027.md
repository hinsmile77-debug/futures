## 4. PC 별로 따로 해야 하는 것

1. **사전등록 파일** — `피터방법_사전등록_MW0602.json` 을 만든다. MW0601 파일을 복사해 `id`·`pc`·`registered_at` 을 바꾸고 **백필 전에 커밋**할 것.
   없으면 snapshot 블록이 「계산 실패(미측정)」로 뜬다(일부러 그렇게 했다 — 남의 PC 기준을 조용히 쓰지 않게).
2. **백필 재실행** — `conda run --no-capture-output -n py310_64 python scripts/peter_method_backfill.py`(장외). MW0602 DB 의 10100 이력이 다르면 수치도 다르다.
   ⚠ 결과를 보고 문턱을 바꾸지 말 것(458차 D6).
3. **지표 ID** — `indicators_MW0602.json` 은 I1–I5 를 쓰고 있다(I4 = 외인 선물×미결제, I5 = 먼스리 풋−콜). 이식 시점에 I6–I8 이 비었는지 확인하고, 겹치면 파일명·`META.id` 를 바꾼다.
   MW0601 에서 실제로 I4·I5 충돌이 나서 I6–I8 로 옮겼다.

## 5. MW0602 고유 주의 — 피터 실시간 수집이 꺼져 있다

MW0602 는 2026-10-20(639차)부터 **피터 실시간 수집을 정지**하고 16:30 `peter_pull` 로 MW0601 사료(`peter-feed`)를 받는다.
그래서 이 섹션의 피터 부분은 MW0602 에서 이렇게 된다:

| 기능 | MW0602 동작 |
|---|---|
| 장중 snapshot 「피터 HH:MM」 줄 · 피터 관점 이벤트 | **없음** — 블록에 「오늘 수집 파일 없음(미측정)」. 「관점 없음」으로 읽지 말 것 |
| follower `VIEW`/`NOFACT` 이벤트 | 라이브 수신이 없어 생기지 않는다(무해) |
| I6(피터 편향) | 장중 None |
| 15:55 `pmethod` 의 피터 관점 채점 | **16:30 pull 전이라 비어 있다** → `pmethod --date <그날>` 을 pull 뒤(예: 16:40)에 한 번 더 돌리면 같은 날 줄을 교체한다(하루 1줄 규칙) |
| 다음 날 장전 brief 「전일 장후 피터 관점」 | pull 이 끝났으면 정상 |

P층·상자·봉 신선도는 피터 수집과 무관하게 그대로 동작한다.
