# 피터2 사전등록 — 판정 기준 고정 (2026-10-07 · MW0601 668차)

> 집행 시작 **전에** 합격선을 고정한다. 결과를 본 뒤 문턱을 바꾸지 않는다(458차 D6 원칙).
> 바꿔야 하면 새 문서(새 날짜)를 만들고 이 문서는 사료로 남긴다.

## 1. 무엇을 판정하나

「피터리 트윗 지시를 기계가 실시간 추종하면, 그의 성과를 얼마나 재현하는가.」
피터 본인의 매매 실력을 판정하는 것이 **아니다.** 추종 장치(수집 지연, 해석, offset, 집행)의 품질을 판정한다.

## 2. 표본·기간

- 시작: 2026-10-08 (첫 모의 집행일)
- 단위: **포지션**(entry_ts 키, 레그 합산 — 계측 4원칙 ①)
- 판정 표본: 실추종 **20포지션**. 도달 전에는 판정하지 않는다(중간 수치는 기록만 한다).
- 제외: `offset_src`가 `rollover_unsafe`이거나 `safe=False`인 날(진입 자체가 없다). 미륵이 보유로 건너뛴 신호(`engine_busy`)는 **건수만 따로 센다.**

## 3. 지표 정의

| 지표 | 정의 | 원천 |
|---|---|---|
| 추종 효율 | Σ실추종 pt ÷ Σ피터 pt (그가 트윗한 진입·청산가, 피터가) | `일일/피터2_일일_*.md` |
| 진입 슬리피지 | (우리 체결 미니가 − 그의 지시가 + offset) × 방향 부호, 중앙값 | trades.db + signals.jsonl |
| 수신 지연 | `seen_at` − 트윗 게시 시각(live만), 중앙값 | `_raw` |
| 해석 보류율 | 그가 체결한 진입 중 우리가 대기조차 못 건 비율 | signals.jsonl vs `_tr` |
| 오진입 | 그가 진입하지 않았는데 우리가 진입한 포지션 수 | trades.db vs `_tr` |

## 4. 합격선 (20포지션 도달 시)

| # | 조건 | 합격 |
|---|---|---|
| ① | 추종 효율 | **≥ 0.60** |
| ② | 진입 슬리피지 중앙값 | **≤ 1.0pt** |
| ③ | 수신 지연 중앙값 | **≤ 30초** |
| ④ | 오진입 | **0건**(1건이라도 있으면 원인 규명 전까지 `shadow`로 강등) |
| ⑤ | 해석 보류율 | **≤ 20%** |

- **판정**: ①–⑤ 모두 충족이면 PASS다. 하나라도 미달이면 `PETER2_FOLLOW_MODE="shadow"`로 강등하고, 원인을 수집·해석·offset·집행 중 하나로 분해한다.
- **즉시 정지(표본과 무관)**: 오진입 1건, 또는 같은 지시로 2회 진입(중복 집행)이 관측되면 그날 장후에 `shadow`로 내리고 원인을 규명한다.

## 5. 고정 파라미터 (판정 기간 중 변경 금지)

```
PETER2_QTY = 1 · PETER2_CHASE_MAX_PT = 1.0 · PETER2_OFFSET_TOL_PT = 0.2
PETER2_ARM_EXPIRE_MIN = 10 · PETER2_DEFAULT_STOP_PT = 4.0 · PETER2_STOP_CAP_PT = 8.0
PETER2_DAILY_STOP_LIMIT = 0(해제) · PETER2_DAILY_MAX_ENTRIES = 6
```

예외: `PETER2_DAILY_STOP_LIMIT`는 **사용자 결정으로만** 바꾼다(재생 근거: 구현계획 §4). 바꾸면 그 날짜를 이 문서 끝에 기록하고, 판정 표본을 그 날짜 앞뒤로 나눠 보고한다.

## 6. 해석하지 말 것

- 효율 > 1을 「피터보다 낫다」로 읽지 말 것. 그의 트윗 기준 손익이 일부 거래를 놓친 탓일 수 있다.
- 피터2 손익을 미륵이 성과(전환기준 ①)에 섞지 말 것. 출처 `PETER2`는 `external`이다.
- 재생(섀도) 수치는 실측이 아니다. 판정은 **실추종**으로만 한다.

## 7. 변경 기록
