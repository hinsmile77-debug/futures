## 1. 현재 구조 (실측 2026-10-20)

```
[장중 — 실시간]                                         [장후 — 사료]
Chrome 확장(15초 새로고침)                              16:30 작업 스케줄러 scripts\peter_pull_MW0602.bat
  └POST 127.0.0.1:8766 → tools/peter2_live/receiver.py    └ tools/peter_pull.py
       ├ _raw/<날짜>.jsonl  (src=live, seen_at)               ① fetch origin/peter-feed (MW0601 푸시)
       └ peter2_live/<날짜>/collector.json (하트비트)         ② _lv/_tr 받기 + _raw 병합(이 PC 없는 id만 src=pull)
main.py _peter2_tick_body (2초, 08:30~15:40)                 ③ peter_build_day --rebuild-all (이 PC 캔들로 오프셋)
  ├ 해석(parse) → Peter2Follower                            ④ _check_today (미도착 rc=2)
  ├ 주체=PETER 이면 실주문 / 아니면 VirtualBook(가상)        ⑤ _self_build: peter2_eod → peter_build_day --date 오늘
  ├ 오프셋 장중 실측(_peter2_measure_offset)
  ├ 하트비트 감시 → 90초 초과 시 신규 진입 금지·경보
  └ 실시간 차트 사료(_peter2_write_feed)
15:40 daily_close → peter2_eod.build (FOLLOW_MODE≠off 일 때)
```

- 설정: `PETER2_FOLLOW_MODE="live"` · 거래주체 `SHINDONG`(2026-10-12 17:45~) → 피터2는 **가상(섀도)** 으로만 돈다.
- 10-16·10-19 `_raw` 는 전부 `src=live`(38·29건) — 이 PC 수신기분. `peter-feed` 는 10-19까지 정상 도착
  (`.pulled = b588cd9`), 10-19 `peter_pull` rc=0, 자체 확정 4거래 반영.
- 장후 경로는 **이미 실시간 없이도 성립하도록 만들어져 있다**(610차: 이 PC 파일이 없던 날도 전부 `src=pull` 로 병합,
  `_self_build` 가 그 원본으로 확정). 즉 이번 작업의 본체는 「장후 신설」이 아니라 **실시간 경로를 깨끗하게 끄는 것**과
  **실시간이 하던 일 중 장후로 옮길 것을 옮기는 것**이다.

## 3. 구현 단계

### P1 — 실시간 경로 정지 (코드 3곳 + 설정 2줄)

**P1-1 설정** `config/settings.py`
```python
PETER2_COLLECT_MODE = "eod"     # 신설: "live"(Chrome 확장+수신기) | "eod"(장후 peter-feed 만)
PETER2_FOLLOW_MODE  = "off"     # live → off — 추종은 실시간 피드가 전제다
PETER2_COLLECT_STOP_DATE = "2026-10-21"   # 신설: 장부 경계(§3 P2). 사용자 확정값
```
- 불변식 테스트: `COLLECT_MODE=="eod"` ⇒ `FOLLOW_MODE=="off"`. 피드 없이 follow 를 켜면
  매 진입이 `collector_stale` 로 기각되는 「켜진 척하는 게이트」가 된다(FP-CRITICAL·TOX 섀도와 같은 계열).

**P1-2 수신기** `tools/peter2_live/receiver.py`
- 기동 직후 `PETER2_COLLECT_MODE != "live"` 이면 `logs/peter2_receiver_<날짜>.log` 에
  「비활성(COLLECT_MODE=eod) — 기동하지 않음」 1줄 남기고 `exit 0`.
- `start_mireuk.bat` 6-D 는 그대로 두고 로그 문구만 「설정에 따름」으로 갱신(배처 구조 무변경 — CMD 패턴 함정 회피).
  → 설정 한 줄로 되돌릴 수 있다.

**P1-3 엔진** `main.py`
- `_peter2_tick_body`: `FOLLOW_MODE="off"` 이면 이미 즉시 return — 하트비트 경보·장중 오프셋 실측·가상 진입 모두 멎는다(추가 코드 불필요).
- `_on_principal_change_requested`: 대상이 `PETER` 이고 `FOLLOW_MODE=="off"` 이면 **전환 거부** + WARNING
  「피터2 추종 꺼짐(장후 수집 모드) — 피터를 거래주체로 고를 수 없다」.
- 기동 시 `trade_principal.json` 이 `PETER` 인데 off 면 ERROR 1줄(현재 SHINDONG 이라 실영향 없음 — 방어용).
- `daily_close` 15:40 `peter2_eod` 는 `FOLLOW_MODE` 게이트로 자연히 건너뜀 → 16:30 `_self_build` 가 담당.
  로그에 「[Peter2EOD] 장후 수집 모드 — 16:30 peter_pull 이 확정」 1줄(폴백 가시화 ④).
- 대시보드 `_peter2_mode()` → `"off"` 표기. 피터2 버튼/지표가 「꺼짐(장후 수집)」으로 보이는지 offscreen 스모크로 확인
  (CLAUDE.md 557차: paint 경로는 실제로 그려볼 것).

**P1-4 수동 조치(사용자)** — MW0602 Chrome `chrome://extensions` 에서 **피터2 확장 비활성화**.
수신기가 없으면 POST 는 실패할 뿐 무해하지만, X 검색 탭 15초 새로고침은 계속 돈다(계정 레이트리밋 부담·불필요 트래픽).

### P2 — 장후 피터 섀도 원장 (가상장부 대체)

정지일부터 「피터였다면」 비교 수치가 끊기지 않게 장후 재생으로 채운다.

- `peter_pull._self_build` 3단계 추가: `tools/peter2_backfill.py` 를 **`--until <내일>`** 로 실행
  (인자 신설. 설정값 `PETER2_BACKFILL_UNTIL` 은 건드리지 않는다 — `test_615` 가 `UNTIL==LIVE_START` 를 고정한다).
- 원천: A = 그의 확정 `_tr`(사료) · B = `peter2_replay`(라이브와 같은 cfg, 지연 20초 가정).
- 🔴 **이중계상 경계**: `2026-10-12 ≤ d < COLLECT_STOP_DATE` 는 VirtualBook(실시간 섀도)이 원천이므로 백필에서 제외,
  `d ≥ COLLECT_STOP_DATE` 만 백필. 행마다 `origin='eod_replay'` 표기 —
  실시간 섀도와 장후 재생은 **다른 측정**이라 정지일 전후를 직접 비교하지 말 것(불연속 마커
  `strategy_events METRIC_REDEFINITION` 1행).
- `guard_intraday` 가 이미 있어 장중 실행은 막힌다. 16:30 이후라 충족.

### P3 — 장후 산출물 정합

## 5. 위험

1. **MW0601 공급 단일 의존.** MW0601 이 푸시를 빠뜨리면 그날 MW0602 피터 사료는 0이다(rc=2 로 드러나긴 함 — 09-21 전례).
   2026-08-23 멀티PC 조율 폐기와는 별개 채널(09-17 사용자 결정 `peter-feed`)이라 정책 충돌은 없지만, 실시간 수집이
   지금까지 하던 **2차 원천** 역할은 사라진다.
2. **삭제 트윗.** 장후 X 검색은 지워진 트윗을 못 본다. MW0601 실시간분이 `src=pull` 로 들어오므로 원본은 대개 남지만,
   MW0601 수집기도 놓친 날은 영구 손실(skill 「08-18 장중 전체 소실」 전례).
3. **피터2 실거래 옵션 상실.** 정지 중에는 피터를 거래주체로 쓸 수 없다. 되돌리기 = 설정 2줄 + Chrome 확장 재활성.
4. 장후 재생(B)은 1분봉·지연 20초 가정이라 실시간 섀도보다 낙관/비관 어느 쪽으로도 틀릴 수 있다 — 주체 비교에 쓸 때 원천 표기 필수.

## 6. 사용자 결정 필요

1. **정지 시작일** — 권고 `2026-10-21`(내일 장전 기동부터). 오늘 장중분은 이미 수집됐으니 그대로 둔다.
2. **엔진 측 처리** — 권고 (A) `FOLLOW_MODE=off` + 장후 재생 원장.
