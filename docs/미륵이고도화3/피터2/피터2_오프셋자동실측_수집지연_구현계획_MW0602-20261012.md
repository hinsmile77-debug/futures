## 2. 구현계획

### A. 오프셋 자동 실측 (MW0602 독자 — MW0601에 없음)

**A1. 순수 함수** `strategy/peter2/offset_live.py` (신설)
- `measure(mini_bars, reg_bars, window=("08:46", now)) -> (value, n, spread, info)`
  - 같은 분 타임스탬프끼리 `mini.close − reg.close`, 중앙값.
  - `spread` = 5분 슬롯 중앙값의 최고 − 최저(596차 「드리프트를 숨기지 않는다」).
  - 표본이 모자라면 `value=None` + 사유(계측 4원칙 ②).
- 판정: **`n ≥ 8` 그리고 `spread ≤ 0.30`** → `safe=True`.
  ⚠ 두 임계는 10-07·10-08·10-12 슬롯 분포에서 잡은 **초기값**이다. 2주 관측 후 재검토(§4).

**A2. 정규 10100 장중 조회**
- 기존 헬퍼 `collection/cybos/chart_backfill.py`의 `FutOptChart` 래퍼(스레드 + 타임아웃 + 메시지 펌프,
  main에서 이미 사용 중)를 재사용해 `code="10100"`, 당일 1분봉을 받는다. **읽기 전용 시세 TR**만 쓴다.
- 미니 쪽은 엔진의 당일 `raw_candles`(메모리 버퍼 우선)를 쓴다.
- 주기: **08:47 ~ 11:30 5분마다**, 이후 30분마다(오후 드리프트 감시용). 하루 약 40회로 TR 한도(15초 60건)와 무관하다.
- `regular_candles.db`에는 **쓰지 않는다** — 장후 수집기(`collect_regular_futures.py`)가 정본이고,
  장중 부분 데이터를 섞으면 595차 신선도 감시를 오염시킨다. 결과는
  `data/peter2_live/<날짜>/offset_live.json`(`{value, n, spread, safe, window, measured_at}`)에만 남긴다.

**A3. 우선순위** — `store.load_offset()` 확장
1. 당일 수동 `offset_override.json` (후속7, 사람이 이긴다)
2. **당일 자동 실측 `offset_live.json`** (`safe` 판정 그대로)
3. 직전 실측일 `peter_paste` (만기를 넘으면 `safe=False` — 현행)

- main 쪽은 후속7의 `_peter2_apply_override()`와 같은 방식(mtime 변화 시 재기동 없이 반영)으로
  `_peter2_apply_live_offset()`를 둔다. 값이 `PETER2_OFFSET_TOL_PT`(0.2) 이상 바뀌면 옛 오프셋으로 잡은
  ARM은 DISARM(`why="offset_live"`)하고 `OFFSET_LIVE` 이벤트 + 로그를 남긴다(계측 4원칙 ④).
- **평일에도 적용**한다. 596차 실측상 하루 안 드리프트가 0.3 ~ 0.6pt라, 직전일 값보다 당일 실측이 낫다.
  직전일 값과 **1.0pt 이상** 다르면(만기 다음 날이 아닌데) WARNING을 남긴다 — 롤·수집 이상 탐지용.
- 만기 다음 날 08:47 첫 실측 전에는 현행대로 `safe=False`라 진입이 없다. 피터의 첫 지시는 대개 09:00 이후다.

**A4. 교차확인(판정 무영향)**

- 만기일(10-08)처럼 장 초반이 흔들리는 경우 `spread` 판정.
- 우선순위 1 > 2 > 3, 깨진 JSON 무시, 표본 부족 시 `None`.
