## 0. 한 줄 결론

「15:45까지 안 보인다」는 **한 가지 문제가 아니라 서로 독립인 결함 3건**이다.
**D1(화면)은 코드 2줄**, **D2(데이터)는 이미 있는 함수를 오늘 날짜로 한 번 더 부르는 것**,
**D3(갱신)은 어댑터 1개**다. 세 개를 다 해야 「지금 보고 있는 오늘 차트가 15:45에서 끝난다」가 된다.

그리고 **565차가 폐기한 Phase 2(수명 +6분)를 되살리지 않는다** — 되살릴 필요가 없다(§3).

## 1. 현황 — 구간별로 어디서 끊기는가 (코드 실측)

| 구간 | `session_bars`(DB) | **당일 차트 화면** | 원인 |
|---|---|---|---|
| 08:45~15:08 | ✅ `rt` | ✅ 실시간 | 정상 |
| **15:09~15:34** | ✅ `rt` (533차·550차) | ❌ **안 붙는다** | **D1** — 차트 피드가 force-exit 가드 **뒤**에 있다 |
| 15:35~15:44 | — (행 없음) | — | **정상.** 단일가 호가접수 구간이라 체결이 없다. 차트 TR 도 행을 안 준다 |
| **15:45 (CLOSE_FILL)** | ❌ 당일 없음 → **다음날 08:41** | ❌ | **D2** — 15:40 에 구독이 끊기고, 보충은 익일 08:41 뿐 |

### 1-1. 근거

- `session_bars` 적재는 **모든 분기보다 앞**이라 15:10~15:34 도 DB 에는 들어간다
  — [main.py:5394](main.py#L5394) `_persist_session_bar(candle)`.
- 그런데 **차트 피드는 가드 뒤에 있다** — [main.py:5421](main.py#L5421) `if is_force_exit_time(now): … return`
  이 걸리고, 차트로 보내는 줄은 [main.py:5517](main.py#L5517) 이다. 즉 15:10 부터 화면은 멈춘다.
  (프리장 경로만 별도로 [main.py:5272](main.py#L5272) 에서 먹인다.)
- `flush_stale_bar` 로 회수되는 **15:34 봉**은 콜백이 15:36 에 도착해
  [main.py:5418](main.py#L5418) `is_market_open`(≤15:35) 에서 **force-exit 가드보다 먼저** 멈춘다.
- 실시간 구독은 `daily_close` 진입과 함께 끊긴다 — [main.py:15254](main.py#L15254) `realtime_data.stop()` (15:40).
  **15:45 체결틱은 도달할 수 없다.**
- 15:45 봉의 유일한 원천은 차트 TR 이고, 호출 시점은 **익일 08:41 · 전 거래일 대상**뿐이다
  — [main.py:14988](main.py#L14988) 대 `backfill_day(prev_trading_day(...))`.
- 차트는 DB 리로드 때만 마감구간을 집는다 — [main_dashboard.py:11671](dashboard/main_dashboard.py#L11671)
  `_merge_session_tail`. 그런데 리로드 트리거는 **다이얼로그 열기·날짜 변경·자정 롤오버**뿐이고
  **주기 타이머가 없다**([main_dashboard.py:12572](dashboard/main_dashboard.py#L12572)) → **D3**.

### 1-2. 이미 되어 있는 것 (다시 만들지 말 것)

- 마감구간 **경계 표시**: `_draw_session_tail` 이 절단선·「수집 절단 → 마감구간 N봉 · 종가단일가 N」을
  이미 그린다 — [main_dashboard.py:9645](dashboard/main_dashboard.py#L9645).
- **멱등 보충 함수**: `backfill_day()` / `reconcile_and_insert()` — 기존 행은 **덮지 않고** 결손만 INSERT
  ([chart_backfill.py:157](collection/cybos/chart_backfill.py#L157)). 몇 번 돌려도 같다.
- **수동 실행판 CLI**: `scripts/session_bars_chart_backfill.py --date <날짜>` (565차).
- **EOD 재학습 여유**: 사용자가 2026-09-06 에 `MireukiEODRetrain` 을 15:45 → **15:50** 으로 옮겨 뒀다
  ([settings.py:438](config/settings.py#L438)). 그때 만든 **4분 여유가 지금 그대로 비어 있다** — 이 계획이 그 자리에 들어간다.

## 2. 결함 3건

### D1 — 차트 라이브 피드가 15:10 에 끊긴다 〔화면〕

`is_force_exit_time` 가드의 원 의도는 **「예측 파이프라인 중단」**인데, 같은 `return` 이
**대시보드 차트 갱신까지** 끊고 있다.

🔴 **471차 F-1 과 같은 유형이다.** 그때도 같은 가드가 STEP 8(청산 감시)을 함께 끊어
15:10 강제청산 1차 경로가 6개월간 도달 불가였다. 가드 하나가 의도보다 넓게 걸리는 패턴이 반복됐다.

### D2 — 15:45 봉이 당일 DB 에 없다 〔데이터〕

구독은 15:40 에 끊기고, 차트 TR 보충은 **익일** 08:41 이다. 그래서 오늘 차트에서 15:45 는 **구조적으로 도달 불가**다.

### D3 — 보충해도 열려 있는 차트가 모른다 〔갱신〕

`_merge_session_tail` 은 **리로드 때만** 돈다. 주기 갱신이 없어 D2 를 고쳐도 화면은 그대로다.

## 3. 설계 결정 — 565차 「Phase 2 폐기」와 충돌하지 않는다

`풀타임수집_검토및구현계획_2026-09-06.md` §4 Phase 2 는 **실시간 구독 수명을 15:46 까지 늘리는** 안이었고,
565차가 「차트 TR 이 15:45 봉을 주므로 불필요」라며 폐기했다.

**그 폐기는 유지한다.** 이 계획은 구독을 건드리지 않는다:

| | Phase 2 (폐기) | 본 계획 |
|---|---|---|
| 실시간 구독 종료 | 15:40 → **15:46** | **15:40 그대로** |
| COM 이벤트 구독이 `daily_close` 와 겹침 | 겹침 (DBWriter 센티널 경합) | **안 겹침** — 구독은 이미 끊긴 뒤 |
| `FREEZE_WATCHDOG_WINDOW` | 15:45 → 15:47 | **무변경** |
| 08:44:30 조기 구독 | 필요 | **불필요** |
| 15:45 봉 원천 | 체결틱 | **차트 TR**(565차가 채택한 바로 그 경로) |

565차가 부정한 것은 **「수명을 늘려 체결틱을 받는 것」**이지 **「차트 TR 을 당일에 부르는 것」**이 아니다.
후자는 565차 결정의 **연장**이다 — 같은 함수를 `prev` 대신 `today` 로 한 번 더 부른다.

### D2 실행 위치 — 두 안

| | **안 A (권장) — 프로세스 안, 15:46 스케줄러 틱** | 안 B — 프로세스 밖, 작업 스케줄러 15:47 |
|---|---|---|
| 코드 | `_scheduler_tick` 에 1회성 블록 (기존 08:41 블록 복제) | **코드 0줄** — 기존 CLI 를 트리거만 |
| 차트 자동 갱신(D3) | ✅ 같은 프로세스라 바로 가능 | ❌ 불가 — 사용자가 다시 열어야 |
| 매매 프로세스 영향 | 구독 종료 뒤·파이프라인 종료 뒤. BlockRequest 1회 | 없음 |
| 새 리스크 | 자동 종료가 15:46 전에 올 수 있다 → §4 P2-b 가드 필요 | OS 트리거 1개 추가 · Cybos 로그인 생존 전제 |
| 실패 시 | **익일 08:41 이 그대로 메운다**(기존 경로 온존) | 동일 |

→ **안 A 를 권장한다.** D3 가 안 A 에서만 가능하고, 실패해도 기존 익일 보충이 안전망으로 남아
**순수 가산(purely additive)**이기 때문이다. 안 B 는 안 A 가 막힐 때의 대안으로 남긴다.

### P2 — 당일 15:46 차트 TR 보충 〔D2〕 · 난이도 중

**P2-a. 스케줄러 1회성 블록** — [main.py:15008](main.py#L15008) 의 flush 블록 **바로 뒤**에 추가.

```python
        # ── [MW0601 589차] 당일 마감 체결(15:45) 당일 보충 ────────────────────
        # 565차 Phase 3 와 **같은 함수**를 오늘 날짜로 한 번 더 부른다. 구독(15:40 종료)은
        # 건드리지 않으므로 폐기된 Phase 2(수명 +6분)의 부활이 아니다.
        # 실패해도 익일 08:41 보충이 그대로 메운다 — 순수 가산.
        # BlockRequest 는 COM 콜백 밖(스케줄러 틱)이다 — 절대원칙 §4.
        # ⚠ `is_expiry_day` 는 main.py 상단(190)에 import 돼 있지 **않다** — 바로 위
        #   550차 flush 블록과 같이 지역 import 한다.
        from utils.time_utils import is_expiry_day as _is_exp
        if (
            not self._chart_backfill_today_done
            and is_trading_day(now)
            and datetime.time(15, 46) <= now.time() < datetime.time(15, 49)
            and not _is_exp(now)                    # 만기일은 15:20 마감 — 15:45 봉이 없다
            and self.broker is not None and self.broker.is_connected
        ):
            self._chart_backfill_today_done = True
            try:
                from config.settings import SESSION_BARS_ENABLED as _sb_on
                if _sb_on:
                    from collection.cybos.chart_backfill import backfill_day
                    _st = backfill_day(now.date())
                    if _st is not None:
                        log_manager.system(
                            "[SessionBackfill] 당일 마감구간 보충 — chart=%d existing=%d "
                            "inserted=%d mismatch=%d"
                            % (_st["chart"], _st["existing"], _st["inserted"], _st["mismatch"]),
                            "WARNING" if _st["mismatch"] else "INFO")
                        if _st["inserted"]:
                            self.dashboard.minute_chart_reload()      # P3
            except Exception as _cb_e:
                logger.warning("[SessionBackfill] 당일 보충 실패 (무해, 익일 08:41 이 메움): %s", _cb_e)
```

- `self._chart_backfill_today_done: bool = False` 를 기존 `_chart_backfill_done` **바로 아래**
  ([main.py:1127](main.py#L1127))에 **명시 초기화**한다 — `getattr(self, "x", default)` 금지(계측 4원칙 ④).
- 만기일 제외: `is_expiry_day` 면 15:20 이 최종 체결이고 15:45 봉 자체가 없다
  ([time_utils.py:117](utils/time_utils.py#L117)). 그날은 **0봉이 정상**이지 결함이 아니다.

**P2-b. 자동 종료가 15:46 을 앞지르지 않게** — [main.py:13947](main.py#L13947) `_schedule_auto_shutdown`

`daily_close`(15:40 시작)가 6분 안에 끝나면 **15:46 전에 프로세스가 죽어** P2-a 가 영영 안 돈다.
지연분만 보정한다(수명 연장이 목적이 아니라 **보충 1회 보장**이 목적이다):

```python
        # [MW0601 589차] 당일 마감구간 보충(15:46)이 아직이면 그 뒤로 미룬다.
        # 늘어나는 시간은 최대 ~6분이고, EOD 재학습(15:50)보다 앞에서 끝난다.
        _delay = 15_000
        from utils.time_utils import is_expiry_day as _is_exp
        _nw = datetime.datetime.now()
        if (not self._chart_backfill_today_done and is_trading_day(_nw)
                and not _is_exp(_nw)):
            _left = (datetime.datetime.combine(_nw.date(), datetime.time(15, 47))
                     - _nw).total_seconds()
            if 0 < _left < 600:
                _delay = int(_left * 1000) + 15_000
                log_manager.system("자동 종료 지연 — 당일 마감구간 보충(15:46) 대기 %.0f초" % _left)
        QTimer.singleShot(_delay, self._auto_shutdown)
```

⚠ **`EOD_RETRAIN_SCHEDULE_HM = "1550"` 과의 순서를 깨지 말 것.** 최악(15:47 + 15초)이어도 15:50 보다 앞이다.
이 상수를 바꾸면 이 계획도 함께 바꾼다([settings.py:438](config/settings.py#L438) 주석과 상호 참조).

### P3 — 보충 후 차트 리로드 어댑터 〔D3〕 · 난이도 하

### P4 — (선택) x축을 15:45 까지 예약

현재 x축은 **`마지막 봉 + 10봉`**까지만 잡힌다
([main_dashboard.py:9405](dashboard/main_dashboard.py#L9405) `padded_count = len(candles) + RIGHT_PADDING_BARS`).
「15:45까지 표시」를 **「x축 격자를 미리 15:45 까지 고정」**으로 읽는다면 별도 작업이다.

- 장점: 하루의 진행률이 한눈에 보이고, 봉이 늘어도 가로 스케일이 안 흔들린다.
- 단점: 장 초반에 화면 대부분이 빈칸이 된다. **현행 동작이 사람 눈에 바뀌는 변경**이다.
- ⇒ **§8 미결정 안건**으로 올린다. P1~P3 과 독립이며 나중에 따로 해도 된다.
