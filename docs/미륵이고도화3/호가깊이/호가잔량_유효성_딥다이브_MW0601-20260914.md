## 0. 결론 — 스케일은 정상이다. 문제는 **추정량**이고, 그것이 판정기를 오작동시킨다

| 질문 | 답 |
|---|---|
| 단위가 이상한가 | **아니다.** 계약 수(잔량)가 맞다. 미니선물 호가가 원래 얇다 |
| 5~15 범위가 이상한가 | **아니다.** 5단 각 1~2계약이 정상. 하한 5 = 5단 × 1계약 |
| 10:19 의 93 은 결함인가 | **아니다.** 실제로 그 순간 호가에 그만큼 있었다(로그 원천 대조 완료) |
| 그럼 아무 문제 없나 | 🔴 **있다.** `book_*_tot` 은 봉당 494회 스냅샷 중 **1개만** 쓰는 점표본이다 |
| 중복인가 | 🔴 **그렇다 — 단 `avg` 로 재야 보인다.** `tot` 으로 재면 잡음에 가려 「독립」으로 오판한다 |

## 1. 컬럼 정의와 단위 — 코드에서 확정

`collection/cybos/realtime_data.py:_handle_hoga` · `utils/db_utils.py:_book_depth_cols`

| 컬럼 | 정의 | 단위 | 표본 수 |
|---|---|---|---|
| `book_bid_tot` | **봉의 마지막 스냅샷** 5단 매수잔량 합 | 계약 | **1** |
| `book_ask_tot` | 〃 매도 | 계약 | **1** |
| `book_bid_avg` | 봉내 전 스냅샷의 5단 매수합 **평균** | 계약 | 봉당 중앙 **494** |
| `book_ask_avg` | 〃 매도 | 계약 | 〃 |
| `book_snaps` | **양변 유효** 스냅샷 수 (호가 이벤트 수가 아니다) | 건 | — |

🔴 **`_tot` 이라는 이름이 두 가지 「합」을 섞는다.** 실제 의미는 「**한 시점**의 5단 합」인데,
이름은 「봉 전체의 합계」로 읽힌다. 계측 4원칙 ① (단위·의미를 이름에 박아라) 위반이다.
`_tot` → `_last` 가 정직한 이름이다.

**단위가 잔량(계약)이 맞다는 근거 셋**

1. **가격 단조성으로 필드 매핑이 검증된다.** 매도 2~6 이 오름차순
   (`1047.72 → 1047.74 → 1047.76 → 1047.78`), 매수 19~23 이 내림차순
   (`1047.66 → 1047.64 → 1047.62 → 1047.60`). 가격 축이 맞으면 그 짝인 7~11·24~28 이
   잔량 축이다.
2. **Cybos 는 잔량과 건수를 별도 필드로 준다**(`docs/미륵이고도화2/cancel_ratio_Cybos_
   데이터가용성_재조사_2026-07-14.md` §3 — `FutOptRest` 가 「1~5차 매수잔량」과
   「1~5차 매수건수」를 나란히 노출). 우리가 읽는 축은 잔량 쪽이다.
3. **5단 합 > 1단 잔량이 항상 성립**한다(`session_bars` 대조, 비 ≤1.0 인 봉 **0건**).
   1단이 5단 합을 넘는 모순이 없다.

⚠ **남은 미확인**: `FutureJpBid` 의 12~18·29~ 대역에 **총잔량·건수**가 있는지 확인하지
않았다. 있으면 우리 5단 합을 그 총잔량과 직접 대사할 수 있다(완전 검증). COM 프로브는
장중에 추가하지 않는다 — 장 마감 후 항목으로 남긴다.

## 2. 스케일 실측 — 원천 로그 121,066 스냅샷 (2026-09-14, 206분)

```
5단 매수합 : n=121,066  min=5  중앙=8  평균=9.12  max=120
5단 매도합 : n=121,225  min=5  중앙=8  평균=8.98  max=117
active_levels = 5/5 : 100.00%   (단계 결손 0)
종목코드 : A056A 단일 (월물 혼입 없음)
```

| 구간 | 비중 |
|---|---|
| 0~9 | **72.63%** |
| 10~19 | 25.21% |
| 20~99 | 1.99% |
| 100~109 | 0.12% |

**하한이 정확히 5인 이유**: 5단이 항상 활성이고 각 단에 최소 1계약이 있기 때문이다.
`5~15 범위`는 **얇은 미니선물 호가의 정상 모습**이다. 1단 잔량 분포가 그것을 뒷받침한다 —
1계약 85,617회 · 2계약 26,310회로 **92%가 1~2계약**이다.

**큰 물량의 성격**: 5단 합 ≥40 인 1,255 스냅샷에서 최대 물량이 실린 단계는
L1 30.0% · L2 17.5% · L3 16.4% · L4 17.1% · L5 19.0% 로 **특정 단계 쏠림이 없다**.
단계별 개별 최댓값은 L1~L5 전부 **101~102** 근방이다.

실례 (10:19:57):

```
bid_tot=58  [2, 4, 50, 1, 1] @ 1042.80 / 1042.78 / 1042.76 / 1042.70 / 1042.64
```

L3 에 50계약이 한 덩어리로 서 있고 나머지는 1~4계약이다. **큰 지정가 주문 하나**의
전형적 모습이며, 100 근방 군집(0.12%)은 **라운드 로트 100계약**으로 보인다.
⇒ 데이터 결함이 아니라 시장 현상이다.

## 3. 🔴 진짜 결함 — `_tot` 은 봉을 대표하지 못한다

사용자가 본 「10:19 의 93」이 정확히 이 문제다.

| 2026-09-14 10:19 | 값 |
|---|---|
| `book_bid_tot` (마지막 스냅샷) | **93** |
| `book_bid_avg` (봉 평균) | **12.31** |
| `book_snaps` | 566 |
| 로그 원천 그 분의 분포 | min 5 · 중앙 **8** · max 109 |

같은 봉을 두 추정량이 **7.6배** 다르게 말한다. 중앙값이 8인 분 안에서 마지막 한 장면이
93 이었을 뿐이다.

**전 구간(3거래일 958봉) 실측**

| 지표 | 값 |
|---|---|
| `tot/avg` 비 — 중앙 | 0.88 ~ 0.95 (평소엔 비슷하다) |
| 〃 p95 | 1.47 ~ 1.56 |
| 〃 **최대** | **4.66 / 8.65 / 7.56** (일자별) |
| `|tot−avg|/avg` — 중앙 / p90 / p99 / max | 0.144 / 0.367 / 1.045 / **4.554** |
| **2배 이상 어긋난 봉** | 11 / 958 (**1.1%**) |
| `tot ≥ 40` 인 봉 | 09-10 **1** · 09-11 **6** · 09-14 **3** |
| `avg ≥ 40` 인 봉 | **0 · 0 · 0** |

마지막 두 줄이 요점이다. **「스파이크」는 `tot` 에만 존재한다.** 봉 평균으로 보면
40계약을 넘는 봉이 3거래일 내내 하나도 없다.

**표본 수 비교** — 봉당 스냅샷 중앙 **494**(47~1,074). `tot` 은 그중 **1개**를 쓴다.

> ⚠ 덧붙여, `tot` 의 그 「1개」는 봉의 마지막 순간도 아니다. 봉 전환은 **체결 틱**이
> 일으키는데 호가 이벤트는 그와 무관하게 들어오므로, 다음 분 첫 호가가 이전 봉에
> 실릴 수 있다. 실측: 10:19 봉의 `book_snaps=566` vs 로그 10:19 버킷 562건 —
> 경계에서 4건이 넘어왔고 그 안에 93 이 있었다(로그 10:19 마지막 값은 100 이다).
> 즉 `tot` 은 **「임의의 한 시점」**이지 「봉 마감 시점」조차 아니다.

## 4. 🔴 중복 판정이 뒤집힌다 — 판정기가 잡음 낀 컬럼을 쓴다

사용자 지적대로 `scripts/book_depth_duplication_check.py` 는 이 데이터의 중복을 의심해
만들어진 Phase 3-0 판정기다. 사전등록 임계는 `|rho| ≥ 0.90 DUPLICATE` / `≥0.70 PARTIAL` /
`<0.70 INDEPENDENT` 이고, 원축은 이미 라이브인 `microprice_depth_bias` 다.

**같은 958봉에서, 추정량만 바꿔 잰 결과**

| 비교 | Spearman rho | 사전등록 임계에 대입하면 |
|---|---|---|
| `book_net_ratio` **tot 기반** vs `microprice_depth_bias` | **+0.177** | INDEPENDENT |
| `book_net_ratio` **avg 기반** vs `microprice_depth_bias` | **+0.902** | **DUPLICATE** |

판정기는 `scripts/book_depth_duplication_check.py:146` 에서
**`SELECT ts, book_bid_tot, book_ask_tot`** 을 읽는다 — 즉 **tot 기반**이다.
(2026-09-13 실행 실측 출력도 `분봉 rho +0.1696` 으로 위 tot 값과 일치한다.)

⇒ **20거래일이 쌓이면 이 판정기는 「INDEPENDENT」를 낼 것이고, 그 근거는 정보가 아니라
잡음이다.** 326차가 `lob_imbalance_decay` 를 중복으로 기각했던 바로 그 양이, 이번에는
1점 표본의 잡음에 가려 새 축으로 통과하게 된다.

**절대 깊이 축은 진짜로 새 정보다 — 그건 버리면 안 된다**

| 비교 | rho | 해석 |
|---|---|---|
| 총깊이(avg) vs `microprice_depth_bias` | **+0.068** | 독립 — 척도 없는 비율이 못 담는 축 |
| 총깊이(tot) vs 총깊이(avg) | **+0.288** | 같은 양의 두 추정량인데 이 정도다 |

둘째 줄이 `tot` 의 품질을 가장 잘 말한다. **같은 것을 재는 두 값의 상관이 0.29** 다.
