## 0. 결론

1. **주문 단위 취소 메시지(MBO)는 받을 수 없다.** Cybos가 주는 것은 가격대별 집계 호가(MBP)뿐이다.
   ⇒ 취소율은 **직접 관측이 아니라 추론**이다.
2. 다만 추론에 필요한 재료는 **Cybos에 이미 있고, 미륵이가 버리고 있다.**
   - `CpSysDib.FutureJpBid`(실시간) 헤더 **13–17 / 30–34 = 매도·매수 5단 호가 「건수」**,
     **18 / 35 = 총건수**, **12 / 29 = 전체 총잔량**(5단 밖까지). 미륵이는 가격·잔량 20개만 읽는다
     (`collection/cybos/realtime_data.py:546–549`).
   - 장후 프로브로 **값이 실제로 채워져 있음을 확인**했다(§2).
3. 🔴 **이름에 「cancel」이 붙은 기존 피처는 취소를 재지 않는다.**
   - `cancel_add_ratio` · `cancel_churn_ratio` · `toxicity_cancel_stress`(`features/technical/queue_dynamics.py`)
     = **1호가 잔량의 감소분 vs 증가분**일 뿐이다. 체결로 줄어든 잔량, 호가 가격이 바뀌어 생긴 증감이
     전부 「취소」로 섞인다.
   - `features/supply_demand/cancel_ratio.py`의 `CancelRatioTracker.on_cancel()`은 **호출처가 0곳**인
     죽은 코드다.
   - 계측 4원칙 ①(이름에 단위·의미를 박아라) 위반 소지 — 「취소」라는 이름이 판단을 오도한다.
4. **수집 가능 — 다만 추정치다.** 1–2일 작업 규모의 섀도 수집으로 「호가 감소분 중 체결로 설명되지
   않는 부분」(취소 하한)을 분 단위로 만들 수 있다. 과거 소급은 거칠게만 가능하다(§4).

## 1. 무엇이 「취소율」인가 — 관측 가능한 것과 아닌 것

| 층위 | 내용 | Cybos |
|---|---|---|
| 주문 단위(MBO) | 개별 주문의 접수·정정·**취소** 메시지 | ❌ 제공 안 함 |
| 가격대 집계(MBP) | 가격대별 잔량·**건수** 5단 | ✅ `FutureJpBid` 실시간 / `FutureMst` 조회 |
| 체결 | 현재가·누적거래량·체결구분 | ✅ `FutureCurOnly`(틱별 체결량은 누적거래량 차분) |

**추론 식**(같은 가격대가 두 스냅샷 사이에 유지될 때):
`ΔQ(가격 p) = 신규 − 취소 − 체결(p)` → **취소 하한 = max(0, −ΔQ − 체결(p))**
건수까지 있으면: 체결이 없는데 건수가 줄었다면 그만큼은 **확정 취소**(정정 포함).

- 쓸모: §7-3 「매도벽이 체결로 사라졌나, 취소로 사라졌나」를 **사례 수준**으로 보는 정도.

## 5. 추론의 구조적 한계 (B를 해도 남는 것)

1. **스냅샷 사이 상계** — 1초 안에 들어왔다 나간 주문(스푸핑의 전형)은 안 보일 수 있다.

3. **부분 체결** — 체결로 줄어든 건수를 정확히 모른다(잔량 기준 하한은 유효).

5. **두 COM 객체의 이벤트 순서** — 호가·체결 이벤트의 상대 순서가 근사적이다.

### 7-3. 분해 규칙 (§1 추론 식의 구현)

- **관측 가능 가격**: 매도측은 `p ≤ 마지막 유효 단 가격`, 매수측은 `p ≥ 마지막 유효 단 가격`.
  창 안이면 표시 잔량, 최우선보다 안쪽이면 0으로 **안다**. 창 밖은 모른다.
  ⇒ **두 스냅샷 모두에서 관측 가능한 가격만** 분해한다 — §5-4(창 이동)를 이렇게 처리했다.
  매도벽이 체결·취소로 비면서 호가가 올라간 경우 그 가격은 새 스냅샷에서도 「최우선보다 안쪽 = 0」으로
  관측되므로 **벽 소멸이 정확히 잡힌다**. 반대로 창 밖으로 밀려난 잔량은 취소로 세지 않는다.
- **체결 귀속**: 체결구분 BUY → 매도측, SELL → 매수측, 판정 불가 → 직전 스냅샷 중간가 기준.
- **하한**: `net = ΔQ + 체결` → `cancel_qty_lb = max(0, −net)`, `add_qty_lb = max(0, net)`.
  건수: `cancel_cnt_lb = max(0, −ΔN − 체결)` (체결로 지워진 주문 수 ≤ 체결 계약수).
- **건수 유효성**: 유효 단마다 `1 ≤ 건수 ≤ 잔량`이어야 쓴다. 원천이 0으로 비워 보내면 미계측(②).
- **귀속 못 한 체결**: 관측 불가 가격·양 스냅샷 모두 잔량 0인 가격의 체결은 `exec_unmatched_qty`(③).
